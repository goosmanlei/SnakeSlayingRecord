# VPS 完整体验版发布

入口为 `https://leiguoguo.me/lijizhanshe/`，远端实例为 `vps:~/www/lijizhanshe/`。本机正式数据库仍是权威；体验库可真实写入，普通容器重启保留操作，显式发布才全量重置。完整要求见 [部署任务](../planning/vps-experience-deployment-task.md)。以下命令从当前受管故事 worktree 根目录执行，系统代码使用同一任务纳管的 desk worktree。

## 发布前准备

先完成两仓最新主干同步、候选提交和 `config/instance.json.review_desk_commit` 的准确引用，通过 `codex.task _prepare_integration --push` 准备整组候选。正式发布前由任务工具完成 `_deliver`，不要在主目录手工合并或推送。

远端复用 SSH 别名 `vps`、`nginx.me.leiguoguo` 容器与 `nginxmeleiguoguo_default` 网络。先回读架构、实际可用内存、磁盘、Xray、Nginx、已有实例、容器挂载和正在进行的发布。脚本在预检及进入维护前再次核对 x86_64、cgroup v2、至少 1.5 GiB 可用内存与 0.5 GiB 空闲 swap，以及既有 Xray、Nginx、网络和三个只读挂载的真实身份；余量不足时停止新增负载。磁盘按上传包三倍加 5 GiB 余量校验。脚本只管理本实例，拒绝符号链接、其他应用占用的容器名及未完成的另一发布；不购买资源、不增加 swap、不重启 VPS、不使用全局 prune。

维护者在远端 `~/my-config/lijizhanshe/credentials.env` 提供独立服务端密钥及已授权的累计调用上限，目录权限 700、文件 600。文件内容采用 Docker env-file 格式：`OPENAI_API_KEY=实际独立密钥`、`REVIEW_POLISH_MAX_ATTEMPTS=已授权次数`；不把密钥写入 Git、业务库、发布包、命令参数或聊天。调用计数保存在同目录 `usage/attempts.json`，包括失败或结果未知的实际请求尝试；业务重置与普通重启都不会清零。调整上限须依据新授权，不能借发布重新获得额度。未配置真实独立凭据时，发布预检拒绝继续，不能把 API 禁用或模拟称为完整体验版。

认证复用既有 Nginx htpasswd 文件。完整前缀需要认证，维护期间也保留认证；实际浏览器验收须使用现有凭据。凭据和共享 Nginx 配置在业务重置之外保留。

```bash
python3 scripts/vps_experience.py prepare \
  --publication lijizhanshe-YYYYMMDD-round1 \
  --desk "$DESK_WORKTREE" --formal "$FORMAL_STORY_ROOT"
```

`DESK_WORKTREE` 是任务纳管的系统工作区，`FORMAL_STORY_ROOT` 是本机正式故事目录。准备命令持有既有正式发布锁，以 SQLite 一致性备份读取活库，复制完整原件、配置和方法内容，不写正式业务库或导出。镜像在本机编译为 `linux/amd64`；发布包包含运行必需文件、完整数据库、镜像和逐文件摘要，排除任务目录、完整运行目录、密钥和调试资料。输出位于本任务 `.runtime/vps-experience/<发布身份>/`，已有身份拒绝覆盖。以备份后的库指纹、物理文件哈希和准确源码提交校验，不能用过期受管导出冒充活库。

## 全量发布

```bash
python3 scripts/vps_experience.py publish --publication lijizhanshe-YYYYMMDD-round1
python3 scripts/vps_experience.py status
```

顺序为上传、完整校验、维护、清除、重建、内部验证、开放、清理。远端 `publish.lock` 串行保护阶段操作，`state.json` 记录准确包、提交、发布身份和实际阶段；不同身份不能越过未完成发布。上传先使用 `.part` 文件，校验失败不进入维护或删除旧版。需要真实维护页验收时，以 `upload`、`maintain`、`replace`、`verify`、`open`、`cleanup` 按上述顺序分步执行。

维护页由共享 Nginx 独立提供，位于稳定的 `~/www/.lijizhanshe-control/`；所有业务入口在认证后返回 503，带 `Retry-After` 和禁止缓存策略。维护配置持久保存，应用、数据库不存在或机器普通重启时仍能保护前缀。Nginx 配置保持绑定文件的 inode，校验通过后平滑重载；其他站点与 Xray 保持原用途。

旧容器正常停止后按标签及实际挂载核验归属，再删除旧容器、专用卷、整个旧实例目录及无有效引用的旧专用镜像。数据库及旁文件、上传／生成文件、缓存、应用容器日志和实例内备份随旧实例清除，不保存上轮库、目录或镜像用于回滚。新包中的作品历史、真实原件和来源不是旧体验残留，不重复清理这些业务历史。

新版采用单个应用容器，不暴露公网端口；通过现有 Docker 内网反代。运行限制为 1 CPU、1 GiB 内存、内存与 swap 合计 1.5 GiB、64 个进程；容器日志最多三份 10 MiB 文件。读取缓存使用系统既有 128 MiB 容量限制。媒体上传流式处理，保留 8 GiB 单文件契约；并发上传同时预留空间，并保护至少 5 GiB 磁盘余量。服务端 API 总调用次数有独立持久上限。

内部验证核对完整业务表指纹、原件和内容哈希、容器实际限制、发布身份及正确架构，随后开放并做真实浏览器验收。普通重启通过绑定目录与 `unless-stopped` 启动机制保留当轮操作；不为测试擅自重启共享 VPS。页面验收失败时再次执行 `maintain`，保留准确新包向前修复。

## 失败与恢复

任何超时或中断后，先执行 `status` 并查询实际容器、维护状态与准确发布身份，不能盲目再次发布。上传未完整或摘要不符时，旧版继续运行；修复上传后对同一包重新校验。

旧版已经清除后的失败保持维护，准确新包留在 `~/my-config/lijizhanshe/incoming/<身份>/`。先查阶段，确认没有旧应用写入，再沿 `replace → verify → open → cleanup` 从该完整包重建；不寻找旧库或恢复旧部署目录。若新包丢失，可从本机同一已验证包重新上传。受控失败验收使用 `replace --fail-after-clear`，只在维护且有完整包时执行，调用后必须实际恢复。

`cleanup` 删除上传包、展开副本和无用暂存，并回读为空，随后阶段才变为 `complete`。开放访问或 Git 推送成功都不等于发布完成。必要保留项只有当前实例、稳定接入／维护配置、服务端凭据、累计 API 次数和最小阶段回执；不留下故障库或重复数据副本。

## 验收与收尾

至少两次完整发布。第一轮在真实页面验证故事、视听、实体、素材、专业知识、真实媒体，以及评论新增／修改／关闭／重开、采纳或选择、配置修改、已有删除和上传操作；验证普通容器重启保留操作。第二轮使用同源完整包及新发布身份，验证第一轮所有体验修改消失，原件及业务表回到快照，旧客户端持久数据被清除，旧打开标签页的请求被拒绝。

发布身份由服务器启动配置提供。前端所有本实例 API、媒体、附件、图标和静态资源留在 `/lijizhanshe/`；本机根路径仍适用。草稿、页面位置和配置待保存状态按前缀与发布身份隔离。访问新版会删除本前缀旧身份的存储，不删除同域其他实例的存储；离线设备无法主动擦除，但旧页面不能跨发布写入。真实验收还需覆盖深链、刷新、返回、桌面与窄屏、维护页及恢复页，以及独立 API 的真实响应。

保留准确包摘要、两仓 Git 交付回执、浏览器证据、业务与原件指纹、故障拒绝／重建、两次发布重置、清单清理及前后共享服务观察。运行回执只留任务本机目录或账本，不为补日志修改已交付候选。少量访问测试不证明代理高峰、购买带宽或大量并发容量。

任务收尾先清理本机测试容器、临时镜像、快照与重复包，按准确 ID／路径回读。当前准确恢复包仍有未完成验收或恢复用途时保留，并记录解除条件；成功后仅保留必要最小证据。正在使用的受管两仓 worktree 不强删，退出 TUI 释放锁后用 `codex.project task cleanup` 退役。

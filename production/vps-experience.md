# VPS 完整体验版发布

入口为 `https://leiguoguo.me/lijizhanshe/`，远端实例为 `vps:~/www/lijizhanshe/`。本机正式数据库仍是权威；体验库可真实写入，普通容器重启保留操作，显式发布才全量重置。完整要求见 [部署任务](../planning/vps-experience-deployment-task.md)。以下命令从当前受管故事 worktree 根目录执行，系统代码使用同一任务纳管的 desk worktree。

## 发布前准备

先完成两仓最新主干同步、候选提交和 `config/instance.json.review_desk_commit` 的准确引用，通过 `codex.task _prepare_integration --push` 准备整组候选。正式发布前由任务工具完成 `_deliver`，不要在主目录手工合并或推送。

远端复用 SSH 别名 `vps`、`nginx.me.leiguoguo` 容器与 `nginxmeleiguoguo_default` 网络。先回读架构、实际可用内存、磁盘、Xray、Nginx、已有实例、容器挂载和正在进行的发布。脚本在预检及进入维护前再次核对 x86_64、cgroup v2、至少 1.5 GiB 可用内存与 0.5 GiB 空闲 swap，以及既有 Xray、Nginx、网络和配置、网站根目录两个只读挂载的真实身份；余量不足时停止新增负载。磁盘按上传包三倍加 5 GiB 余量校验。脚本只管理本实例，拒绝符号链接、其他应用占用的容器名及未完成的另一发布；不购买资源、不增加 swap、不重启 VPS、不使用全局 prune。

用户已明确允许使用 VPS 现有 `OPENAI_API_KEY`，它与本机使用同一密钥。现有变量只在交互式 shell 加载；维护者在服务器内将其写入 `~/my-config/lijizhanshe/credentials.env`，目录权限 700、文件 600，不回显或经本机转存密钥。文件采用 Docker env-file 格式，设置 `OPENAI_API_KEY`、`REVIEW_POLISH_DAILY_LIMIT=100`、`REVIEW_POLISH_BUDGET_TIMEZONE=Asia/Shanghai`。不把密钥写入 Git、业务库、发布包、浏览器或命令参数。

AI 出网按用户 2026-10-09 的明确要求使用 VPS 自身 Xray 回环 HTTP inbound。当前入口为 `http-local`、`127.0.0.1:9090`，账户沿服务器现有受保护 Xray 配置取用；只在服务器内将编码后的认证代理 URL 写入同一 env-file 的 `HTTPS_PROXY`，另设 `REVIEW_USE_XRAY_LOOPBACK=1`。不回显代理认证信息。标准库的 OpenAI HTTPS 请求读取此变量，公网网站入口仍直接访问本站。每次发布前核对 Xray 监听和实际 Docker 桥接网关。

容器自身回环地址不能连接宿主回环入口，因此此模式使用宿主网络，但应用仅绑定现有 Nginx Docker 桥接网络的准确私有 IPv4 网关及 8765 端口。发布器拒绝公网地址、错误网络和其他服务占用，并核对实际启动命令与代理变量；Nginx 只在本实例前缀代理到该私有地址。Xray 现有配置、监听与服务保持原样。没有启用该模式的部署继续沿原容器网络运行。

用户授权北京时间每天最多 100 次 AI 润色请求。计数保存在同目录 `usage/attempts.json`，失败或结果未知的实际请求也计数；发版与普通重启都不清零当天次数。仅跨北京时间日期时恢复当天预算，累计总次数仍保留；达到上限时拒绝 AI 请求，其他操作和发布仍可继续。调整上限须依据新授权。未配置真实凭据时不能把 API 禁用或模拟称为完整体验版。

用户 2026-10-09 明确要求完全开放体验，`/lijizhanshe/` 不设置访客登录或 Nginx Basic 认证。页面、API、媒体与下载统一走应用反代，数据库与服务端凭据不通过静态根目录暴露。每日次数限制费用，不是访客授权机制。

```bash
python3 scripts/vps_experience.py prepare \
  --publication lijizhanshe-YYYYMMDD-round1 \
  --desk "$DESK_WORKTREE" --formal "$FORMAL_STORY_ROOT"
```

`DESK_WORKTREE` 是任务纳管的系统工作区，`FORMAL_STORY_ROOT` 是本机正式故事目录。准备命令持有既有正式发布锁，以 SQLite 一致性备份读取活库，复制完整原件、配置和方法内容，不写正式业务库或导出。镜像在本机编译为 `linux/amd64`；发布包包含运行必需文件、完整数据库、镜像和逐文件摘要，排除任务目录、完整运行目录、密钥和调试资料。镜像运行身份使用 `docker save` 内配置文件的 SHA-256，避免本机构建引擎的索引 ID 与 VPS 载入后的配置 ID 不同；载入后核对配置摘要、架构、归属和源码修订。恢复已有完整包时仍校验其原摘要，不改写包。输出位于本任务 `.runtime/vps-experience/<发布身份>/`，已有身份拒绝覆盖。以备份后的库指纹、物理文件哈希和准确源码提交校验，不能用过期受管导出冒充活库。

## 全量发布

```bash
python3 scripts/vps_experience.py publish --publication lijizhanshe-YYYYMMDD-round1
python3 scripts/vps_experience.py status
```

顺序为上传、完整校验、维护、清除、重建、内部验证、开放、清理。远端 `publish.lock` 串行保护阶段操作，`state.json` 记录准确包、提交、发布身份和实际阶段；不同身份不能越过未完成发布。上传先使用 `.part` 文件，校验失败不进入维护或删除旧版。需要真实维护页验收时，以 `upload`、`maintain`、`replace`、`verify`、`open`、`cleanup` 按上述顺序分步执行。

维护页由共享 Nginx 独立提供，位于稳定的 `~/www/.lijizhanshe-control/`；所有业务入口公开返回 503，带 `Retry-After` 和禁止缓存策略。维护配置持久保存，应用、数据库不存在或机器普通重启时仍能保护前缀。Nginx 配置保持绑定文件的 inode，校验通过后平滑重载；随后有界等待旧工作进程自然退出，确认过渡结束才允许清除实例。超时保留现场和完整包，不强杀共享工作进程或其他站点的连接；恢复先查实际维护状态。平滑切换与旧请求结束的机制见 [Nginx 官方说明](https://nginx.org/en/docs/control.html)。

旧容器正常停止后按标签及实际挂载核验归属，再删除旧容器、专用卷、整个旧实例目录及无有效引用的旧专用镜像。数据库及旁文件、上传／生成文件、缓存、应用容器日志和实例内备份随旧实例清除，不保存上轮库、目录或镜像用于回滚。新包中的作品历史、真实原件和来源不是旧体验残留，不重复清理这些业务历史。

新版采用单个应用容器，不暴露公网端口；通过现有 Docker 桥接网络内的私有地址反代，Xray 回环模式的网络与绑定规则见上文。运行限制为 1 CPU、1 GiB 内存、内存与 swap 合计 1.5 GiB、64 个进程；容器日志最多三份 10 MiB 文件。读取缓存使用系统既有 128 MiB 容量限制。媒体上传流式处理，保留 8 GiB 单文件契约；并发上传同时预留空间，并保护至少 5 GiB 磁盘余量。服务端 AI 润色按北京时间每天最多 100 次，计数跨发布保留。

内部验证核对完整业务表指纹、原件和内容哈希、容器实际限制、发布身份及正确架构，随后开放并做真实浏览器验收。普通重启通过绑定目录与 `unless-stopped` 启动机制保留当轮操作；不为测试擅自重启共享 VPS。页面验收失败时再次执行 `maintain`，保留准确新包向前修复。

## 失败与恢复

任何超时或中断后，先执行 `status` 并查询实际容器、维护状态与准确发布身份，不能盲目再次发布。上传未完整或摘要不符时，旧版继续运行；修复上传后对同一包重新校验。

旧版已经清除后的失败保持维护，准确新包留在 `~/my-config/lijizhanshe/incoming/<身份>/`。先查阶段，确认没有旧应用写入，再沿 `replace → verify → open → cleanup` 从该完整包重建；不寻找旧库或恢复旧部署目录。若新包丢失，可从本机同一已验证包重新上传。受控失败验收使用 `replace --fail-after-clear`，只在维护且有完整包时执行，调用后必须实际恢复。

`cleanup` 删除上传包、展开副本和无用暂存，并回读为空，随后阶段才变为 `complete`。开放访问或 Git 推送成功都不等于发布完成。必要保留项只有当前实例、稳定接入／维护配置、服务端凭据、累计 API 次数和最小阶段回执；不留下故障库或重复数据副本。

## 验收与收尾

至少两次完整发布。第一轮在真实页面验证故事、视听、实体、素材、专业知识、真实媒体，以及评论新增／修改／关闭／重开、采纳或选择、配置修改、已有删除和上传操作；验证普通容器重启保留操作。第二轮使用同源完整包及新发布身份，验证第一轮所有体验修改消失，原件及业务表回到快照，旧客户端持久数据被清除，旧打开标签页的请求被拒绝。

发布身份由服务器启动配置提供。前端所有本实例 API、媒体、附件、图标和静态资源留在 `/lijizhanshe/`；本机根路径仍适用。草稿、页面位置和配置待保存状态按前缀与发布身份隔离。访问新版会删除本前缀旧身份的存储，不删除同域其他实例的存储；离线设备无法主动擦除，但旧页面不能跨发布写入。真实验收还需覆盖深链、刷新、返回、桌面与窄屏、维护页及恢复页，以及真实 AI API 响应与每日计数。

保留准确包摘要、两仓 Git 交付回执、浏览器证据、业务与原件指纹、故障拒绝／重建、两次发布重置、清单清理及前后共享服务观察。运行回执只留任务本机目录或账本，不为补日志修改已交付候选。少量访问测试不证明代理高峰、购买带宽或大量并发容量。

任务收尾先清理本机测试容器、临时镜像、快照与重复包，按准确 ID／路径回读。当前准确恢复包仍有未完成验收或恢复用途时保留，并记录解除条件；成功后仅保留必要最小证据。正在使用的受管两仓 worktree 不强删，退出 TUI 释放锁后用 `codex.project task cleanup` 退役。

# 故事与制作页面统一候选

本候选把故事结构、剧本和制作页面统一到已认可的采编视觉基准，将实体／素材展示和评论收敛为同一张大卡，并将制作拆解与镜头制作改为整场逐镜阅读。实现、隔离页面验收和必要回归已完成；正式服务、双仓集成与推送须在用户确认准确候选及发布包后串行执行。实施验收不代表用户视觉接受或作品接受。

## 使用方式

故事结构在顶部常驻选择稿件、左侧选择六章，正文在固定阅读区内滚动。剧本仍按版本、集、概览和场阅读。制作设定三个子页与全剧制作子页采用同一页签形式，直接链接、刷新和返回保留所在页面。

实体管理可组合类型和采纳筛选；左侧小卡按类型排列，显示各媒体的素材需求数量。右侧大卡左边是基础信息、关系、完整状态和素材小卡，右边是选中素材、原件、真实生成信息与评论。宽屏增加左列表列数，窄屏按列表、实体信息、素材详情顺序阅读。

素材数量以持续需求为一项，不重复计算方案版本、候选或文件。素材管理平铺所有筛选及数量，数量保留其他维度筛选；清除按钮恢复全部，零结果也保留原类别。准确旧链接会定位所属需求的分页；若被当前筛选排除，另显示“当前链接素材（筛选外）”，不改变筛选计数。

从实体打开，默认基础状态整体图像、当前方案版本，该版本明确采用候选优先，否则最新候选；没有图像再选择其他媒体。当前版没有原件就显示未生成。可从局部版本和候选控件阅读旧结果，文件组成可切原件与回执，生成信息始终来自该结果的实际调用；不从新方案填补旧调用。

制作拆解与镜头制作顶部选集、左侧选场。整场始终显示，点击场卡边缘或单镜只改变选中范围；每镜先成行，再排列正文和素材。剧／集／场共用素材各集中一次，镜素材属于对应镜；层级筛选允许多选，初始全部选中。挂载和适用归属分别标明，场中出现人物不自动表示每镜使用其全部素材。

镜头制作正文显示视频方案或所选结果的真实提示词，上方准确输入与提示词内链接指向同一引用。右侧只展示视频素材，包括镜视频、场或集视频。仍由 Codex 后台生成，页面没有生成提交或进度入口。

正文和弹窗共用大卡及评论接口。文字圈选、整图／区域、音视频时间范围、定位、编辑、关闭／重开与快捷键保留。关闭弹窗停止其媒体并恢复外层位置、焦点和草稿；弹窗中的临时版本探索不覆盖外层原选择。输入框 ⌘+Enter 提交／保存，Esc 按既有规则取消当前编辑。

- [数据完整性](evidence/data-integrity.json)：13张历史表原有记录保留，1247个历史文件哈希一致，真实UI新评论的版本、文件和字符区间准确。
- [独立需求审查](evidence/requirements-review.md)、[独立兼容审查](evidence/compatibility-review.md)与[委派记录](delegation.md)：发现归属、修复及独立复验。
- [正式应用步骤](operations.md)：完整双仓候选、发布包、镜像、确认后顺序与恢复入口。

系统改动位于任务隔离系统 worktree `.runtime/ui-unification/system`，最终系统提交由 `config/instance.json` 固定。新增 API 仅是读取投影；无持久 Schema 或导出格式变更，不导入业务数据，正式业务增量为0。现有正文、关系、状态、原件、调用、采纳、采用、评论和历史继续使用原账本。

`.runtime/ui-unification/baseline` 和 `browser-fixture` 均含测试评论，后者还含技术媒体及验收实体，绝不导出或发布。生成技术夹具的脚本为 `scripts/ui_unification_browser_fixture.py`，只允许创建新隔离目录；它不调用外部模型。技术夹具只验证交互，不能当作作品或生成质量成果。

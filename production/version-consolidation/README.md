# 四类生产内容的 V1 基线

本次一次性收敛实体、完整状态、素材和镜头的历史版本。实体、状态、镜头保留最新内容；素材保留版号最新且有真实原件的版本，没有产物时保留最新方案。以后正常修改仍按原冻结规则继续产生 V2、V3，不再自动清除历史。

## 准确范围与结果

| 对象 | 核对数量 | 保留规则 |
| --- | ---: | --- |
| 实体 | 134 | 每个对象最新修订 |
| 完整状态 | 280 | 每个对象最新修订 |
| 素材身份 | 2,126 | 最新有真实产物版，否则最新方案；该版全部候选 |
| 镜头 | 297 | 每个对象最新修订 |

逐项身份、选择依据、各版候选、原件哈希、删除对象、文件动作和共享引用在 [plan.json](plan.json)。计划绑定迁移前全部业务表摘要；不是按名称或目录推断保留范围。素材管理显示 2,107 个当前身份：另有 16 个原已撤销需求、2 个已有合法别名和 1 个已归入需求的素材原件身份，详见 [列表口径](list-coverage.json)。本轮没有合并不同需求或完整状态。

隔离实际结果：删除 4,178 条修订、2,402 个仅有淘汰修订的对象、13 条专属评论及对应 13 条事件；清除 573 条归档索引和 54,508 个不再被使用的内容节点。删除 577 个文件，将 165 个旧完整包替换为只含身份、哈希和恢复入口的退役凭据；这些文件原占 516,640,842 字节，退役凭据占 64,693 字节。共享原件按保留引用闭包核验，290 个被多处引用的文件保留。完整表前后摘要在计划与 [tables.json](tables.json)，真实数据库动作在 [database-receipt.json](database-receipt.json)。正式结果须另读取本任务冻结包的 `run/applied.json`，不能把隔离结果当成正式发布。

[全量核验](verification.json)逐条比较全部 9,720 条保留旧修订，634 条保留真实调用修订的原始输入字节未变；另保留 33 个明确标记原始方案未登记的需求身份。它们只有放置和辨识信息，不能用被淘汰的后续草稿冒充原方案，也不能继续生成。272 条保留评论及其事件逐条比较，业务编号及准确候选身份保留。故事原型、小说、结构、剧本、集／场正文、系统配置和任务账本不在版本清理范围内。

## 删除导致的缺项

[缺项清单](missing-references.json)列出 6,566 个精确引用位置，包含保留真实调用的已失效来源；这是引用位置数，不是独立素材数。缺项所在正文保留原语义，引用标记不可用，旧采纳／选择涉及失效范围时不再授权新生成。没有自动替换成当前实体、状态或最新素材。

页面示例：SH001 显示 4 项准确素材引用已删除；歌曲大卡的历史实际调用可以阅读原参数，但被删的实体来源明确不可用。33 个缺原始方案的素材需求须补全新方案并重新审阅。保留内容的旧修订 ID 继续解析同一内容；被删 ID 返回不可用。新的素材数字链接带基线身份；被淘汰的旧 V1 数字链接不会冒用新的 V1。

## 发布与向前恢复

两仓均使用任务已纳管的工作区。先提交审阅台候选，再更新 `config/instance.json.review_desk_commit` 并提交故事候选，调用任务 `_prepare_integration --push`。候选或集成提交改变时重新同步准确引用和验收输入。

从任务 worktree 执行 `scripts/content_version_release.py prepare`，传入双仓准确候选与目标提交、系统 worktree、全新的 `.runtime/version-consolidation/release` 路径。它复用现有服务发布器冻结配置、源码、镜像基底和原运行身份，同时冻结计划及验证所需的准确原件。随后用 `scripts/material_review_release.py build --bundle ...` 构建，用 `scripts/content_version_release.py preflight --bundle ...` 核验正式库及文件仍与计划一致。

`content_version_release.py apply` 必须带 `--apply` 及服务清单、镜像回执、迁移清单的三个准确 SHA256。发布器取得共享发布锁，核对正式容器及数据库头，停止写入服务，调用任务 `_deliver` 按依赖顺序交付两仓，原子提交数据库迁移，完成文件动作、VACUUM 和缓存清理，再启动已冻结的新镜像并回读身份。已推送的准确交付直接复用。任一步失败保留现场，继续同一个准确包；不回灌旧库，不覆盖并发内容。

正式页面复验与资源清理后才能 `_complete`。本机回执在本任务 `.runtime/version-consolidation/release/run/`；它们不补写进已交付候选。

当前有效数据恢复入口为 `export/manifest.json` 指向的 Schema 8 完整导出及 [recovery.json](recovery.json)。后者仅保存故事发布的幂等回执，随 `generation_review.py export` 从准确实例同步；`production_review.py recover` 在新的空实例恢复并校验配置中的哈希。后续发布仍采用当前初始化基线的增量，不用旧任务快照覆盖正式库。

旧完整制作包已退役，不能按旧 README 的历史命令重放。`config/instance.json.version_consolidation_policy` 和数据库删除身份／发布基线共同拒绝旧数据入口。[其他本机恢复副本清单](retired-recovery-inventory.json)只记录路径、大小及用途边界，不读取或复制完整正文。它们属于其他任务或历史正式发布，不由本任务删除，已排除在现行有效恢复入口之外；原任务执行者在追溯用途结束、进程及挂载释放后另行退役。

Git 历史、分支和其他任务 worktree 未重写或强删。因此本任务证明的是当前有效数据与恢复入口的净化，不声称全盘不可恢复。本任务的旧基线、隔离库、预览服务、冻结核验原件和重复导出在正式验收后按准确路径清理，数量和回读保存在本机清理回执；保留净化后的受管交付、准确发布清单、镜像和最小证据。

# 素材版本与历史增量迁移

素材是一项持续存在的制作需求。新素材版本固定制作方式、模型、参数、提示词、准确输入及随机策略；开始实际调用后不再改写方案。同方案重复调用落入同版本不同候选。随机调用产生的实际种子记录在调用中；改变显式固定种子属于方案变化。评论、审阅、选择及重复回执不启动新版，新增候选不会改动已经采用的原件。

候选以真实调用身份和原件哈希识别；补标题或关联保留同一候选。准确使用继续引用不可变 ASSET 修订、组成文件与必要裁切／时间段，组合也不追随当前头。没有可用真实调用的历史独立保留，不用当前方案补写过去。

## 本次历史对应

[migration.json](migration.json) 保存全部 5515 条旧轮次成员的逐项对应，包含准确修订、新素材编号、方案版本、候选及依据；另列 7 条有旧轮次范围的评论对应及原锚点。其他评论仍按原准确对象、修订和锚点读取，没有补造旧时不存在的版本范围。

| 证据 | 结果与含义 |
| --- | --- |
| 旧成员映射 | 5515 条均有可核对对应；机械映射缺口为 0。旧轮次表原样保留，新索引另建。 |
| 历史方案版本 | 1633 个，其中 806 个有准确方案；827 个为当时没有生成配置的需求，明确标为 `unconfigured-plan`，不能当成执行成功或已知生成方案。 |
| 历史候选 | 418 个候选身份、435 条候选记录修订。元数据修订可多于实际候选；不把修订次数当作生成次数。 |
| 评论与认可 | 基线 271 条评论、300 条事件及已有 JUDGMENT／采用逐行保留。正文、事件、准确锚点和旧链接不重写。新索引只是定位辅助。 |
| 原件 | 完整导出包含 1307 个受管文件，含媒体与证据文件；逐一比对候选、Git 原件和空实例恢复后的 SHA-256，全部一致。该数字不是图像或视频数量。 |

“机械映射缺口为 0”只表示已有记录足以给出保守对应；不表示 827 个空方案已经补齐、不表示所有旧媒体被接受，也不代表候选可用于任何新镜头。方法为录制、人工制作或复用的记录保留其真实方法，不能改称 AI 生成。

## 数据与历史保护

新 Schema 5 增加 `material_plan_versions`、`material_plan_members`、`material_candidate_members`、`material_plan_comments`；旧轮次及评论索引继续保留。Schema 1—4 可读取恢复。实体类型允许通过明确标签和属性含义扩展；出现、适用、实际输入和采用分别校验。镜头保存直接场修订，场保存准确剧本输入锁；调整当前归属或排序不移动历史关系。

全剧编制仅新增／修订设计、场检查、需求与适用关系，另增加仓院器具和念读状态；不创建 CALL、ASSET、JUDGMENT 或媒体采用。候选数据库共 6236 个对象、10160 个修订；旧修订全保留。完整导出中的项目配置版本 15 来自冻结正式基线，承接前序部署，不是本任务更改用户配置。

发布包以准确修订和当前头作冲突保护，在同一事务增加表、索引和数据。验证已覆盖：基线增量重放与候选逐表相等；重复发布／迁移不增行；不相关并发评论与事件保留；受影响头冲突时包括 DDL 在内整批回滚；完整导出恢复到空实例后全部数据、引用与文件哈希相等。细节见 [data-verification.json](evidence/data-verification.json)。

正式应用时重新读取最新正式库作一致性备份并预演相同增量。冻结基线与导出供比较和空实例恢复，不能覆盖正式数据库；若准确依赖或受影响当前头变化，停止并重新准备候选。操作步骤见 [operations.md](operations.md)。

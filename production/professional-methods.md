# 从工作目的选择创作制作方法

方法正文通过审阅台“系统管理 → 工作方法”保存和选版；执行者经受管入口取得准确 `SKILL.md`、所需共用章节和工作输入。这里维护工作交接及入口，不另写一套方法正文。配置历史由 `content/managed-method-registry.json` 准确导出，迁移只追加，不覆盖活库的更新。实际可用范围与试用结果见本轮验证；正式生效以任务账本及发布回执为准。

## 每一步收到什么、交出什么

| 当前工作 | 必须取得的输入 | 交给下一步的产物 | 不能替上游猜的内容 |
| --- | --- | --- | --- |
| 故事结构设计或修订 | 已选方向、用户约束、准确旧稿与相关意见 | 人物选择、关系、空间、事件因果、时间线相互一致的完整结构稿 | 没有确认的方向、其他作品设定，不能冒充当前事实 |
| 逐段逐章小说 | 一个准确结构修订、当前已采用正文和作者检查点 | 当前自然片段及同步事实；章末复读；全书完成后发布干净稿 | 后章尚未发生的事情不能填成已发生；结构冲突须联动修订 |
| 影视剧本 | 全部故事与结构、明确改编范围、已采用前场 | 逐场可见可闻的动作、对白、声源与表演；集末和全稿复核 | 不能只写“解释、道谢、读回”就算完成表演原词；候选词不等于锁词 |
| 逐集视听设计 | 准确全剧及当前集场、必要前后衔接、制作输入锁 | 具有因果和观看顺序的场、镜方案，以及未完事项的负责阶段 | 不因旧镜数或自动字段机械切镜；局部任务不能擅改上游事实 |
| 实体、完整状态与素材需求 | 场镜用途、准确实体关系、实际图像或音频原件 | 复用／编辑／新制／无需独立素材的判断及具体用途 | 动作不自动产生新实体或状态；名称、历史认可不能证明新用途适配 |
| 图像、声音、视频和字层方案 | 当前表达、准确状态、可读原件、词句状态、实际渠道 | 给制作者的路线与检查，以及单独发给模型的 Prompt、参数、参考 | 未定原词交给负责创作阶段形成候选；未选原件和未验能力保持未就绪 |
| 真实生成准备 | 已审方案、准确原件与片段、输入锁、采纳及本次授权 | 可追溯的准备包或可操作的缺项；实际调用另有回执 | 方法使用、技术检查和准备不授予调用许可，也不证明生成效果 |
| 结果审阅与返修 | 实际原件、准确目标与输入、必要相邻镜 | 问题位置、原因判断、有限修订与复验范围 | 看不到／听不到就保留未验；不能用技术规格代替作品判断 |
| 独立读者、评论措辞润色 | 分别为截至当前位置的正文；或准确对象、圈选及原意见 | 有依据的读者发现；或保留原意的清楚措辞 | 读者不取后文和作者设定；润色不增加创作要求、不自动保存评论 |

本剧已确认结构与小说不在本次改写范围。方法试用仅产生隔离候选，不能作为全剧重做、媒体效果或用户采纳的证明。

## 共用资料按问题取用

[影视知识](filmcraft/README.md)的十二章、来源、案例与图示继续以项目文件为唯一正文；系统中的资源是准确只读投影。[视频手册](seedance-video-handbook.md)同样沿原正文维护。共用资源改版时，方法须显式引用新修订，已开始的步骤继续原快照。

先确定本次产物和问题，再选原理与制作路线。连续性用于视听设计、首帧／视频和审片；声音章节用于声源、角色和表演问题；视频手册先取方式比较，再读对应模板和案例。普通小说片段或评论措辞不加载整本视频手册。资料来源与跨集索引可供按需展开，不能当成已读原文。

具体管理、导出和恢复沿[受管方法](managed-methods.md)，隔离实例、增量发布和清理沿[生成工作区](generation-workspaces.md)。

## 实际入口与选择条件

| 工作类型 `work_type` | 入口 | 默认方法与按需资料 |
| --- | --- | --- |
| `story-structure` | `creative_method.py` | 结构设计；叙事与连续性 |
| `novel-writing` | `novel_writing.py begin` | 逐段逐章写作；连续性 |
| `screenplay-writing` | `screenplay_writing.py begin` | 影视改编与表演原词；叙事、表演、声音 |
| `audiovisual-design` | `creative_method.py` | 逐集逐场设计；按 `need_narrative`、`need_coverage`、`need_staging`、`need_performance`、`need_sound`、`need_editing` 等当前问题选章 |
| `material-assessment` | `creative_method.py` | 实体状态与用途；调度、美术，涉及声音加 `need_sound` |
| `media-plan` | `media_method.py begin` | 根据需求中的 image/audio/video 自动选图像、声音或视频方法；图像按需 `need_lighting`/`need_color` 等，演唱加 `need_song`；视频 `case` 选 action/dialogue/extension/style/song，并按需 `need_sound` 等 |
| `text-layer` | `creative_method.py` | 准确文字与后期字层；叙事、美术、剪辑 |
| `generation-preflight` | `creative_method.py` + 既有生成准备入口 | 准确方案、原件、采纳及授权核查；不调用生成模型 |
| `result-review` | `creative_method.py` | 实际原件审阅；调度、动画制作及连续性，按需声音和剪辑 |
| `reader-review` | `reader_review.py` | 既有逐段、摘要、有限回看及意见核对模式，由入口按阅读进度选择 |
| `comment-polish` | 审阅意见的“润色” | 保留原意；准确原文只帮助消歧，不新增创作要求 |

条件可先通过 `MethodClient.resolve(work_type, conditions)` 查看入口、资源与阶段，再 begin 冻结。只增加当前有用的章节；发现需要未加载章节时以新步骤取得准确包并复核受影响工作。完整命令与恢复方式见[受管方法](managed-methods.md)。

执行者必须实际读包和原件。程序能证明交付身份、输入及阶段先后，不能证明方法被正确理解。真实试用中的问题、修订、正确反例与未验边界见[本轮验证](professional-methods/VERIFICATION.md)。

## 读取契约和准确候选

唯一系统候选与集成目标维护在[双仓计划](system-delivery.json)，实例 `config/instance.json.review_desk_commit` 锁定同一提交。系统的 `docs/small-cards.md`、`docs/materials-and-relationships.md` 和 `docs/comment-checklist.md` 已吸收当前用法，不另建业务存储。

素材投影增加 `version_count`／`candidate_count`；实体和素材详细响应、通用索引的 `material_card_counts` 按素材身份提供同一计数。素材管理、拆解集合及镜头槽都采用它。字段为整数或 `null`；缺登记显示未登记，不能当成 0。版数按规范素材身份及真实版号去重；候选数按 `(版号, candidate_id)` 去重，多个文件和重复修订不增算。实体素材数按 `(实体身份, 规范素材身份)` 去重。采纳仍读取真实决定与当前范围，不从原件存在推断。

这些字段仅是增补的只读摘要。准确对象／修订、制作版本／候选、评论锚点、采纳／采用请求与历史存储契约不变。关系选择及缩放保存在当前大卡上下文，未写入业务表。恢复旧实例缺字段时显示未登记，不能伪造版本。

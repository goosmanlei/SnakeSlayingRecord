# 统一业务关系与准确方案

实体、状态、素材需求／原件和镜头等对象现在用同一种关系表达。一对稳定对象只有一个当前关系身份；不同方面和阶段写成连贯正文，摘要帮助找到重点。关系不替代方案选择、采纳、原件认可、真实调用或父子归属。

编号 `R-EN012->EN055` 表示后者依赖前者，`R-EN012-EN055` 表示相关，`R-M012<-EN055` 表示前者依赖后者。正反写指向同一身份，显示端点顺序稳定。人物行为不等于制作依赖，跨阶段不能用一个方向表达时保留相关；执行检查只沿本次已选输入。

实体图直接显示每对对象的摘要、编号和端点。素材参考与 Prompt 中的图片／音频链接共用准确方案固定的关系摘要：悬停或键盘聚焦后阅读，向下键进入、Esc 返回，点击仍打开准确素材。完整关系与意见从摘要进入；摘要不参与正文字符偏移。切版、候选、组成和返回时沿各自上下文，不能拿最新关系填充旧调用。

方案继续保存必需／可选、条件、择一路线、启用状态、准确版本与候选、组成、裁切和时间范围。普通关联不自动变成上传文件。受管方法读取完整关系修订、当前作品阶段及准确参考，把适用约束融入 Prompt；正确的既有表达保留，不按字段批量拼贴关系全文。

## 当前交付与证据

本次从实际正式库中 5,883 个旧关系身份整理出 5,850 对关系，其中 33 对原为重复。旧身份及修订仍只读可追溯，当前查询只返回统一模型，旧写入口退役。用户意见、冻结输入、真实 CALL、原件与认可历史不迁移归属。已物理清理的旧说明仍保持缺失，不从新正文倒填历史。

数据范围、具体前后例、实际浏览器操作和验证边界见 [验收记录](VERIFICATION.md)。原决定与历史取材范围见 [任务规划](../../planning/unified-relations-task.md)；通用契约以审阅台仓库 `docs/materials-and-relationships.md` 为准。

本目录的发布文件各有明确职责：

| 文件 | 内容 |
| --- | --- |
| `relations.json` | 全部对象对的准确内容、旧身份映射、来源与预期头 |
| `plan-bindings.json` | 1,396 份方案的关系绑定及原有逐项选择迁移 |
| `methods.json` | 方法定义历史和本次六份完成执行的准确方法／审查依据 |
| `authored-plans.json` | 六份显式方法绑定结果，含五份 Prompt 调整与一份保留正确 Prompt 的声音方案 |
| `av-bindings.json` | 344 镜、65 场、17 集自下而上的准确引用更新，正文不重写 |
| `scope-bindings.json` | 28 条素材适用关系对更新后镜头修订的准确绑定 |
| `release.json` | 上述六项摘要、预期头和完成头；迁移的唯一整组身份 |

`content/managed-method-registry.json` 是当前方法定义历史归档；本目录 `methods.json` 额外保留本次已公开的完成执行，不含后台未完成草稿。方法修订不会重绑旧执行。

## 隔离验证与正式发布

日常新增或修改用通用 `production-import`，对既有关系追加修订并携带预期版本。本次一次性增量由 `scripts/unified_relation_migration.py` 执行，路径以故事任务工作区为基准：

```bash
python3 scripts/unified_relation_migration.py \
  --system <受管审阅台目录> \
  --database <隔离实例>/.runtime/review.sqlite3 \
  --package production/unified-relations/release.json --validate-only
```

验证会执行完整事务后回滚。实际迁移核对全部预期头，在同一事务依次追加关系、方案绑定、方法、作者结果、集场镜引用和适用范围，再核对准确完成头与外键。重复包命中同一回执，过期头或任何末尾校验失败均拒绝整组写入。

正式迁移只能在受管双仓集成完成、共享写入窗口与当前库核验通过后执行。`scripts/material_review_release.py prepare` 增加 `--relations-package production/unified-relations/release.json`，把已提交的准确包和必要工具冻结进发布包；之后沿 [工作区流程](../generation-workspaces.md) build、preflight、apply。正式脚本先停止已核实的旧写入者，再迁移，逐表保全范围外数据和全部旧不可变行，核对原件哈希，最后切换准确镜像。不能用任务数据库覆盖活库。

迁移提交后按同一包向前恢复。回退服务镜像不能代替数据恢复，禁止回灌旧库覆盖后续意见。发生未知结果时先查 `business_relation_runs`、发布回执和实际服务，再决定继续。正式版本、镜像、挂载、只读浏览器验收及清理以任务账本和主项目 `.runtime/task-20261010-0018/` 的实际回执为准，不依赖此任务 worktree 长期存在。

## 完整恢复

当前完整导出使用 Schema 11，同时保存关系唯一索引、旧别名、迁移幂等凭据、全部准确历史与原件。缺索引或别名的包拒绝恢复，旧模型不能重新成为可写当前关系。日常恢复从 [完整导出与准确索引](../README.md#后台编制与恢复) 进入，只允许全新隔离实例。恢复完成后可继续正常追加关系修订，仍保持一对一。

任务的运行时库、测试评论、合成候选、临时媒体和预览服务不进入上述发布包。退出任务会话、释放锁后，双仓工作区沿受管 cleanup 退役；正式发布与恢复不依赖预览目录。

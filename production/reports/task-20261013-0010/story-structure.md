# 故事结构方法：五轮阅读与工作样例

故事结构方法的正文与自有参考已完成五轮真实顺序阅读。两轮修订解决了版本含义、操作入口和示例推理的缺口，之后三轮完整复读均保留原文。隔离库已保存第 8 版并绑定到故事结构工作；已在本机正式生效，交付与边界见[交付报告](delivery.md)。准确身份、原始证据摘要和阶段回执见[逐轮索引](story-structure.json)。

| 原有障碍 | 读者实际理解与修订 |
| --- | --- |
| “准确结构”没有说明是指定版本还是已经认可的稿件 | 第二轮结束时仍不能确定开工依据。改为本次指定版本，说明修订号或可回查标识只表示本次依据；从零构思没有稿件时，从素材与限制开始。后三轮能明确区分版本和质量认可。 |
| “沿作者入口”无法定位 | 补入故事项目根目录、`production/managed-methods.md` 对应小节和 `creative_method.py` 的工作类型，交接指向实际结构版本与待验证问题。隔离样例沿该入口完成草稿、判断和干净结果的保存与回读。 |
| “线压过湿墨，才知道有人补写”缺少支持结论的条件 | 原例没有证明新增发生在核账之后。改为读者先看见红线后的空白，后文该处出现欠粮条目；只据此确认核账后添写，不断言行为人或动机。后三轮准确理解这个证据边界。 |

方法保留人物欲望、选择与后果、配角诉求、支线作用、主题、伏笔、信息顺序和试写判断。人类读者有连续解释及短例可理解这些取舍，AI 也能找到输入、具体动作和交付检查。这里的依据是模型冷读及实际作者样例，没有真人用户测试。

[《交回那一页》样例](samples/story-structure.md)比较了“先补偿种粮，再公开纠错”和“先交回账页，再共同核对”两条路线，选择后者完成结构与转折试写。真实回读发现结构和试写的交钥匙顺序不同，以及澄清只说给受害者听还不足以回应公开质疑；干净稿同步了顺序与结尾的公开纠错。它还区分账页能证明的记录内容和粮袋清点能证明的实收数量。

样例使用本任务原创人物与文本，没有导入正式作品，也没有调用媒体生成。输入、草稿与检查记录已归入必要审计压缩包，原包内路径为 `.runtime/skill-cold-reader-fresh/story-structure/sample/`；正式故事内容未变。相同编辑请求重放返回同一版本，基于旧版本提交不同正文被拒绝；这是主动故障注入，不声称实际发生了网络丢失。

按用户新增要求，最终交付仍须清除本方法旧版本与历史使用记录，并验证仅剩准确最新版；本任务的五轮审计与上述样例留在任务证据中。最终正式身份以整体交付回执为准。

# SKILL 历史清理阶段演练

本任务已按用户要求准备一次性清理：十五个范围内的系统 SKILL 各保留准确最新版，清除其旧版本、关联使用记录和旧版评论。用户选择评论连同旧版删除，报告仅记录数量。当前只在独立数据库副本执行，工作隔离库与正式库尚未删除历史；阶段副本已完成完整公开导出与空实例恢复，最终候选及正式发布验收仍待全部方法定稿后完成。

本次副本清除了 147 份旧 SKILL 定义、115 份旧绑定和 1 份可独立清理的资料旧版本，以及 489 条方法执行、1,464 条阶段产物。清理评论 4 条，其中原用户评论 3 条、本任务隔离测试评论 1 条。最终正式数量以发布时准确方案与回执为准。

清理只移除了 454 份当前方案的旧方法依据字段和 277 条操作回执的相应出处。当前方案的其余正文、真实调用、候选、原件、作品和范围外评论均保留；旧成果不会被归因于本次新方法。逐表比较检查了准确行集合，读取缓存的失效代号单独说明。系统构想的原评论及其准确资料历史受到保护；已退役、范围外方法仍需引用的资料历史也保留。这不影响十五项范围内 SKILL 各只保留最新一版。

方法整包的原版号和准确修订保留。现有审阅台按剩余整包重建文件历史，因此本次清理的每个方法文件只留一份，文件序号重新从 1 开始；文件内容及所属整包不变。配置包在空实例恢复了 82 条配置记录，其中 27 个对象有明确的保留历史起点；方法头和独立文件映射一致。真实存储测试覆盖继续创建新步骤、追加下一版、同方案重试不删除后来工作、并发新增评论拒绝旧方案、错误后整笔回滚，以及检测范围外评论被改写。完整制作数据校验也已在副本通过。这里只证明本阶段配置恢复和清理范围，未将其当作最终公开作品包恢复或正式页面验收。

执行器为 `scripts/method_history_cleanup.py`，配置恢复沿 `scripts/method_migration.py`。受管发布现已接入一次性清理包：先在正式库只读副本准备准确方案，核对结果等于候选中的最新配置；发布窗口停止写入后，依次安装准确方法、复核范围、清理和压实，最后从清理后基线核对服务启动后的数据。清理已提交而后续步骤中断时，重试读取原回执，不重新安装已清除的版本，也不删除后来产生的新工作。此路径已用隔离测试验证，尚未在正式实例执行。

本任务只有故事仓可写。发布入口的 `--read-only-system` 复用准确且未改动的审阅台主干提交，受管 Git 交付只包含主故事仓；依赖版本或仓库范围变化即拒绝旧包。数据操作使用发布包中冻结的系统代码，不依赖发布期间可能变化的工作目录。

最终准备时，先从未清理的隔离方法库导出临时安装配置，再导出清理后应保留的准确配置作为受管注册表。以当前正式库、临时安装配置和最终注册表运行 `method_history_cleanup.py prepare-release`，只写任务 `.runtime/` 中的清理包；`material_review_release.py prepare` 同时指定 `--method-registry`、`--method-audit`、`--method-history-package` 和 `--read-only-system`。发布包、候选、准确清理数量与实际验收顺序全部准备并核验后，再按任务启动文件要求提交最终确认。

原始方案、实际清理回执、逐表比较与恢复证据位于本任务 `.runtime/skill-cold-reader-fresh/history-cleanup/`。包含清理前数据的临时副本和安装配置仅用于本次核对，正式清理验证完成后删除，不能用于回灌；逐轮读者审计与任务样例另按任务证据保留。最终候选的完整公开恢复、正式发布及页面验收仍未完成。

阶段副本另经实际 Schema 14 公开导出，再恢复到新建空实例：11,071 个对象、11,125 份修订及 882 个原件，原件总计 708,354,358 字节且逐份摘要一致。43 张持久数据表的行集合、主键与约束及配置均一致，未设主键的表也比较重复行数量。两张表的建表语句仅有空白和表名引号差异。读取缓存表及 129 个缓存失效触发器可在运行时重建，不由作品包携带；另外 2 个普通查询索引也未随包导出，不涉及唯一性或其他完整性约束。这些差异不属于作品或方法记录。两库完整性检查均通过。[逐表恢复证据](history-cleanup-recovery.json)记录准确范围；这份阶段演练不代替最终准确候选的恢复和页面验收。

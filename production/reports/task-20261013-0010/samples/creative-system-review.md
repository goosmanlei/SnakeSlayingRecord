# 镜头时间线与方法历史清理：实际结果复核

本次 Review 回到两个已经归属任务0010的目标：人和 AI 能从镜头 Prompt 看懂镜头内部怎样演绎；历史方法退役时，保留作品和仍有效的业务依据。使用第五轮完成后的准确 Review 包，复核真实已保存结果与默认 Chrome 操作，不另建任务，不启动持续运行，也不代签任务负责人的独立验收。

原问题不只是缺少几处秒数。早期手册把时间窗口写成按需，通用模板允许仅写“先／随后／最后”，方法检查也没有要求从0秒覆盖本镜时长。即使旁边另有分镜表，实际送给模型的 Prompt 仍可能缺少动作阶段、声音重叠和镜尾承接。这会让人难以判断表演安排，也让 AI 无法从同一份指令取得完整演绎。

当前唯一手册、视频方法与实际样例已经衔接。三个相邻镜的结果字段本身分别连续覆盖0–14、0–14、0–20秒；每段写清可见变化与同期声音，固定机位和持续底声先作共同约定，末段交出下一镜可继承的状态。实际保存的 Prompt 与公开样例逐字对应，三个执行的九个阶段已回读，相关正式制作方案未被覆盖。

ASH002提供了最直接的前后例：原来“持续收住这口气”可能被理解为已经结束，后面又补唱；现在8–12秒写同一次尾腔逐渐减弱但尚未收声，老汉的“二道——哎，到了？”发生在这声尾腔之中，12–14秒才唱完停声、扬下巴。归家句只在起唱处写一次。ASH001的翻页已经完成后才进入本镜，本镜不重做翻页；ASH003才接后续打趣。时间段表达动作与反应，不被当作切镜点。

这项修正服务于理解和取舍，没有把人变成逐字段验收员。AI 应调查准确输入、保持原词、设计声画先后并回读修正；系统保存完整结果和准确来源；人据完整方案判断表演与审美。已在默认 Chrome 中读到最终方法、实际文件版本差异和准确共享引用，页面能够呈现完整方法。此处没有真人参与测试，也没有根据页面可读就推定模型会逐帧服从。

三个视频样例仍不能直接提交生成。参考选择有缺项，ASH002随手选择的音频不作为有效依据；ASH003口头应答的准确原词未定，不能自行补“好”或改成无声动作。14秒与20秒仍是制作预算，不能据未试听的原件或字数证明负载可行。上述缺项已经保留在样例结果中，未扩大为本任务的新媒体生成工作。

历史清理方面，已经确认的具体问题是：同一个业务依据对象可能混有旧方法出处，整块清除会带走素材语义整理依据。修正实现只处理准确的内层方法引用，保留操作身份、原摘要和抽取判断。最终正式副本上已核对281条相关操作回执，其中215条嵌套的业务依据保持完整；454份当前方案只清除了方法依据。安装与清理前后逐表核对一致，十五个 SKILL 各留准确最新版，28个可清理文件各留一版，范围外准确依赖仍受到保护。

准确演练还发现压缩归档原件检查另开连接会与清理事务相锁。此问题已在故事仓清理入口修正：复用审阅台现有的事务内读取接口，原件仍逐份解码并核对原始摘要；没有绕过校验或改写原件。针对性11项检查及完整副本重跑均通过。两次失败事务的44张表逐行核对均已回滚。它说明必须实际运行完整数据，不能只靠小型测试宣告可发布。

清理范围仍以用户本次明确授权为准：十五个系统 SKILL 各留最新准确版本，清除旧版、旧使用记录及旧版评论；不把旧成果改称由新方法完成，不永久关闭未来记录。系统构想评论、准确目标、作品正文、真实调用、候选和原件要保全。旧版评论只报告删除数量，无需让用户逐条重读。

后续步骤已经明确，不需要新的审批或另发任务：按已演练的准确清理包沿现有受管入口集成、推送和本机发布；实际打开清理后的方法与核心页面，从最终完整导出恢复新空实例，确认退役历史不会回灌。旧演练数字和旧恢复结果不能替代这次最终验证。正式清理完成后，再以真实回执更新交付状态。

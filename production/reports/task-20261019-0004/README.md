## 资源与恢复依据

本机盘点包含 852 条路径：817 条业务资源路径迁入 OSS，35 条必要文字／轻量元数据继续由 Git 管理。迁移目录包含原件和派生的 1,672 个准确云版本，合计 9,380,644,955 字节；原件逻辑路径合计 9,353,410,063 字节。VPS 的 579 条资源路径全部包含在该目录中，内容身份一致；两端仍保有各自数据库、发布身份与计数，不互相覆盖。

[资源目录](../../../config/resource-catalog.json) 记录每个逻辑路径的准确 VersionId、SHA256、大小和 MIME。每次上传均完整读取远端准确版本校验；续跑核对同一身份及 MIME，复用先前完整读取回执。波形、图标和字幕 MIME 按明确契约保存，不以平台默认猜测或别名替代。

Schema 16 的 [恢复入口](../../../export/manifest.json) 引用 948,834,304 字节的一致性数据库快照，包含 43 张业务表；迁移前后逐表行数和内容指纹一致，包括 405 条评论、440 条评论事件、352 个候选及 27 条发布记录。剪辑队列和运行凭据属于各运行环境，不进入业务恢复快照。

完整离线介质位于维护者机器的 `$HOME/.local/share/story-review-recovery/lijizhanshe/task-20261019-0004`，共 1,673 个对象、10,329,479,259 字节；每个复制对象校验完整 SHA256 和大小。该介质独立于 Git、工作区和在线 OSS，责任人为项目维护者；只有更新的独立完整介质通过实际恢复并接替后，才可删除这一副本。继续编辑在另一个可写副本进行，不改变交付介质。

## Git 与运行边界

当前提交只保存代码、业务文字、轻量目录、恢复索引和准确提交引用，不保存业务资源字节或媒体 LFS 指针；历史 Git／LFS 未重写，历史仓库容量也未因此回收。旧导出中的分散数据库副本由完整快照接替。CI 和发布准备阶段用同一个检查器拒绝媒体、大快照和嵌入媒体回流。

凭据在仓外权限受限文件中，运行角色没有云对象删除权限；签名地址不进 Git、导出或镜像。本机与 VPS 升级保留各自最新数据并核对前后指纹，开放新服务后的恢复采用兼容代码向前修复，不能回灌旧数据库。成本限于既有账号余额，未开通 CDN、付费转码或新增订阅；余额观测不是本任务实际扣费，计费归集未确认时保持 UNKNOWN。

## 为什么最近读了这么多

小时计量接口明确给出了 Bucket 名称。对齐账单窗口后，`lijizhanshe` 的下行实际为 **100,099,724,827字节，约93.225133 GiB**；与账单93.225111 GB的差约24 KiB，处于小时用量保留六位小数的累计舍入范围。其他Bucket／地域的计量记录没有存储量或下行量，正金额计费行也全部属于香港，因此有证据将这次费用归到本项目。分账接口虽成功但未返回条目，不能把它当作零费用证明。

云监控的48个小时计量点与OSS小时接口逐点一致。账单窗口内流量最大的7个小时占全部下行字节的 **69.19%**，是明显的集中读取。20日05:00、16:00、22:00三个小时分别约10.03、11.61、13.04 GiB；这与当期确有多轮完整迁移、恢复和部署的记录相符。不过，小时总量没有访问者身份，**69.19%不是已精确归因给校验的比例**。

实际读取路径有三种，成本差异很大：

| 动作 | 实际行为与计费影响 |
| --- | --- |
| 浏览器查看、播放、下载 | 两端正式应用生成的资源地址均为 `lijizhanshe.oss-cn-hongkong.aliyuncs.com` 公网签名地址。浏览器需要从OSS重新取字节时产生下行；浏览器缓存命中可以减少重复传输。 |
| 后台制作和普通原件读取 | `materialize()` 校验本机缓存，命中可以复用；新工作区、新恢复实例或缓存未命中会重新下载。各实例的缓存不是一份共享缓存。 |
| 完整云校验 | `verify_catalog(full=True)` 调用 `verify_remote()`，直接GET准确云版本并完整计算SHA256，**即使已有本地缓存也会重新读取云端字节**。随后创建离线介质或在另一空实例物化时，还可能有额外读取。 |

本机正式系统版本为 `a9c6d5fc46fd`，VPS为 `4eb4a9ddee54`；两版本的连接函数均未设置内网端点。源码及运行核对范围保存在[脱敏输入](inputs.json)。这一结论基于实际运行版本和只签名、不发送请求的端点检查。

当前准确资源目录有948条逻辑路径、1842个去重云版本，共 **10.550859 GiB**。一次完整公网回读的流量费用约为：

`10.550859 GiB × 0.75元/GiB = 7.91元/遍`

这是当前目录的量级估算，不是声称某历史任务恰好花了7.91元。它尚未包含独立数据库快照、其他实例的读取或中断前已传输的重复字节。目录中约5.09 GiB是历史发布归档路径，全部JSON约6.20 GiB；**完整校验读到的也包括大业务文档和归档，并非只是播放视频。**

已有证据包括：

- [OSS迁移](../task-20261019-0004/README.md)：1,672个资源版本约8.74 GiB；连同数据库的完整介质约9.62 GiB，发生上传后校验、在线恢复及介质准备。上传流量本身免费，上传后的公网完整回读会收费。
- [20日完整同步](../task-20261020-0004/README.md)和[晚间完整同步](../task-20261020-0009/README.md)：均实际恢复独立空实例并核对准确云资源；这类操作会重复产生读取。
- [首集版本9修订](../task-20261021-0002/README.md)：发生新资源校验、完整导出、约1 GB快照回读以及介质准备；后续禁网空实例恢复不产生OSS流量。该任务还记录了冗余远端读取超时后复用既有准确证据，不能把所有验证步骤都算成新增下载。

Bucket未配置访问日志，访问追踪也关闭；现有计量没有每个IP、原件或RAM角色对应的传输字节。因此，本次能确认“公网下行收费”和“大量完整读取的真实机制”，但不能给出本机、VPS、浏览器各自占66.17元的精确比例，也不能据此认定存在异常访问。

## 以后应按什么成本预期

`GetBucketStat` 当前返回 **15,502,387,734字节，约14.437724 GiB**，1863个对象。它是带有统计时间的服务端容量快照，和当前资源目录的引用闭包是不同范围，不用两者差值判定哪些对象可以删除。

账单存储小时单价换算720小时约为0.136元/GiB。按现有规模保持30天：当前5 GiB免费容量继续适用时约 **1.28元**；保守不计免费容量约 **1.96元**。这是“已有数据保持不变、没有额外读取”的存储基线，不是整站所有活动的包月报价。

以下为**假设场景**：容量固定，按0.75元/GiB公网下行、30天计算；不扣新月份可能适用的免费下行，也不含请求费、其他云产品及新增制作资源。

| 日均公网下行 | 每日存储＋流量 | 30天存储＋流量 |
| ---: | ---: | ---: |
| 0 GiB | 约0.04—0.07元 | **1.28—1.96元** |
| 1 GiB | 约0.79—0.82元 | **23.78—24.46元** |
| 5 GiB | 约3.79—3.82元 | 113.78—114.46元 |
| 20 GiB | 约15.04—15.07元 | 451.28—451.96元 |

若月初仍有5 GiB免费下行且确实被用满，上表流量部分最多再少3.75元；这项小额度不能覆盖反复整库回读。当前已出账约5 GiB零单价下行已经用完。

以现有首集成片作直观对照：VPS版本6和本机版本9单版视频约81.6—86.3 MB，从OSS完整取一遍约 **0.057—0.060元**。假设每天完整取10遍，30天加存储约 **18.38—20.05元**，未计其他图片、音频、拖动回看或重复读取，也未扣免费下行。缓存可以降低，反复重新取字节可以提高，不能把该例当作真实访客预测。

继续制作时应另列验证预算：按当前目录每月做4遍公网完整回读，单是这些回读和存储约 **32.94—33.62元**；每天一遍约7.91元/天，更多遍数相应增加。这里“4遍”是预算假设，不是项目已有的固定排期。

因此，**日均一二十元反映的是每天十几到二十多GiB的公网读取活动，不是14.44 GiB数据的占位费用。** 当前每天仍有制作和发布，没有完整的安静观察日，尚未实测出纯体验访问的稳定日均值。停止密集活动后会少多少，取决于后续访问量及校验频率；保持相同开发方式则仍可能重复高费用。

## 建议优先做什么

1. **把VPS后台读取与浏览器签名分开选端点。** VPS云元数据确认地域为 `cn-hongkong`；用其现有项目凭据向香港内网端点，对一个准确版本执行HEAD，实际返回200、大小一致，业务对象正文下载0字节。这证明已有内网读取条件。后续可让后台物化、校验和恢复走内网，浏览器签名继续使用可访问的公网地址，避免统一改成内网后浏览器打不开。按[官方流量规则](https://help.aliyun.com/zh/oss/traffic-fees)，每转移1 GiB后台公网读取，理论少0.75元流量费；请求与存储仍按各自规则。**现有证据不能分出VPS流量占比，不能把66.17元全算成可节省金额。** 实施涉及通用系统仓、准确版本、Range／签名和恢复验证，需要另行授权。
2. **减少同一准确输入的重复全量回读，保留完整性门禁。** 制作、发布、介质准备和恢复各阶段先辨认已经完成的准确VersionId／SHA256／大小证据，仅对失效、新增或必须独立验证部分重新取字节；在可靠边界内复用完整校验和本地介质，避免每一步都再次读全目录。新空实例恢复与最终必要的完整验证继续保留。当前目录每少一遍不必要公网回读约少7.91元，实际收益按避免的字节核算。当前缓存只覆盖普通物化，不能把“已有缓存”误认为这一改进已经实现。
3. **先按访问量决定是否购买下行包或接CDN。** 如果后续日常体验只有少量完整播放，按量费用可能已经很低；若仍稳定几十GiB/天，再比较匹配香港外网下行的资源包、CDN新增费用和改造成本。存储包不能抵扣本次主要流量费。当前先处理读路径，比为每月约两元的存储做迁移或删除历史更有收益。对历史归档的任何清理必须另核准确引用与恢复用途，本报告不提出直接删除清单。

以上均为建议，本任务没有修改端点、校验流程、Bucket策略或购买任何产品。

原始响应与必要取证回执保留在任务工作区 `.runtime/task-20261022-0002/evidence/`，由本任务负责后续对账；用户接受且无继续对账用途后可按准确归属退役。没有新建服务、容器、镜像或恢复实例，没有待释放的远端运行资源；本次业务对象正文下载为0，少量元数据请求的独立最终费用未从账户总量中拆出。具体本机过程清理见[验证回执](verification.json)。

账单接口和小时计量存在更新延迟，最新空日账单不代表零费用；当月数据还可能调整，最终月账单需在次月形成后确认。此限制与本次已取得的完整分页、算术一致性是不同问题，详见[账单接口说明](https://help.aliyun.com/zh/user-center/developer-reference/api-bssopenapi-2017-12-14-describeinstancebill)和[OSS计费周期](https://help.aliyun.com/zh/oss/billing-overview)。Bucket级取证使用[OSS小时计量字段](https://help.aliyun.com/zh/oss/query-oss-billing-data-generated-on-an-hourly-basis)。

## 执行者按成稿进行的使用推演

以下为无副作用文本推演。每项从输入出发，只凭实际正文确定下一步及结束点，没有创建演示任务、调用独立模型或启动演示TUI。

| 输入 | 可从成稿取得的动作与结束点 |
| --- | --- |
| 已授权publish，补充导出重试 | 查重并确定前后行为、范围和验收；登记原件、完整仓库及字段；成功回读报告，到发布为止 |
| do明确要求修改故事仓文档 | 展示目标、范围和完成标准，附属空列表且complete=true；直接登记后报告编号并结束，由启动器接续同编号同会话 |
| do缺少要修的具体导出结果 | 只问影响目标或验收的缺口，保留原草稿和已明确回答；补齐后继续原登记 |
| mod增加系统改动并移除尚无资源的附属计划 | 核对执行次数为0；重审完整需求及所有仓库，原子保存整份范围；已有资源保留，成功不执行 |
| 工具源码只读、审阅台需要修改 | 工具仓不列交付范围；审阅台source相对主项目核验，明确修改用途、目标及交付依赖 |
| free的独立文档工作 | 保存无需长期公共锁的具体依据，仍保留依赖、防重、身份、会话和短期集成保护 |
| 用户free请求与共享写入条件冲突 | 完成范围后propose，说明冲突并等真实回复；resolve含最终类型、理由和user_quote；未解决不发布 |
| 用户补充隔离条件坚持free | 重核实际条件后可保持原类型，记录真实回复；范围再变重新核对，不伪造同意 |
| 非Git请求parallel | 说明仅支持mutual的分歧并保留草稿，取得共识前不登记 |
| 发布断线，写入结果未知 | 先查原草稿、账本、澄清提交和回执，确认是否登记或部分生效，再沿原入口继续 |
| 已登记但启动失败或写锁未释放 | 保留已发布身份和现场；发布不冒称执行；wait只等待领取，不重跑失败目标 |
| 普通run交付或恢复历史auto任务 | 完成本次本地交付及已保存远端义务，报告用户核验步骤，等待最终确认；旧auto不继承，不续领 |
| 冻结候选部分交付后目标前进 | 查成功回执；候选或未交付目标改变则重准备、合并和补验，同版本证据复用 |
| 本项目系统改进以auto执行 | 按AGENTS和工作区流程完成集成、必要推送、本机正式发布及真实验收，再按本次自动授权结项 |

主方法的三类任务例子分别帮助确定界面路径、行为正确性及跨镜创作关系，不作为每项任务的固定字段。较大方案先实践样例，关键方向未定保留草稿；成稿要求独立可读，修改摘要与修订讨论另行表达。上述判断均能从正文取得，未借额外聊天补足步骤。

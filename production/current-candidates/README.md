# 当前制作内容与生成候选

这份约定供创作者和 AI 编写、修改与使用制作方案时共同遵守。它帮助你分清当前方案、真实调用和候选原件，判断何时可以提交，以及内容变更后怎样保留准确依据。先理解需求、状态与参考的关系，再按后文的操作字段和命令执行。

故事资料、方向、结构、小说和文字剧本继续保留各自版本。实体、必要实体状态、业务关系、视听集场镜、输入锁和素材需求只维护当前内容。有效实体状态必须至少拥有一项真实独立素材需求；需求的 scope 是唯一制作出处，states 只是使用范围。先从准确原文和场镜目标判断独立素材职责，再抽取状态，不能为了保状态制造或复制需求。实体身份足以承担的基准形象不另造状态；纯表演、普通持放、账目阶段和连续性条件由实际实体、镜头或方案承接。结构、通行、干湿和声音差异确需独立准备时，保留有真实需求支持的必要状态。

正式导入和增量发布检查整笔提交后的当前树。状态与真实需求可同笔新增；移走或撤下最后一项需求时，同步承接状态条件、所有当前引用与关系，撤下或归并状态。隔离作者文件可以暂存未完成判断，不新增长期草稿库或审批。撤下前读准确原文和消费者，不能按零需求计数直接批删；历史调用、候选、原件、原意见与执行快照继续准确回查。

实体自身稳定的基础制作职责直接归实体，不按媒体类型、已有结果或是否有状态机械分类：图像身份、说话音色、空间布局、道具结构及歌曲完整演唱都可属于实体。只有确需独立准备的不同形态、结构、声音或演法才建状态及独占需求；完整歌曲与剧中省段、缺词、哼唱和角色演法分别判断。“基础状态”只是实体直属需求的列表分组名，不建立同名实体状态（ST）。确无独立制作职责的提及对象或由场景、字层、镜内动作承接的对象可以没有需求，保留身份和实际承接位置，不为计数补造素材。M 是素材／素材需求的持久业务编号，候选和调用各有自己的身份。迁移基础需求时保留 M 身份及其候选、原件、真实输入与意见，当前消费者按必要字段承接，历史快照和旧方法执行保持当时事实。

判断是否需要独立准备，先说明要单独交付什么、供哪次审阅或哪个镜头使用，以及实体基础素材为何不能承担这个用途。例如，只需在某镜表现疲惫时，把演法写入该镜头；湿袖完整形态确要单独准备图像、供审阅或镜头引用时，才有独立状态需求。声音演法同样要有单独准备声音参考的实际职责，不能只因表演文字不同就建状态。

当前稿更新使用稳定对象身份和并发标记，不再保存制作全文修订链，也不因改一个镜头推进场、集版本。

每个素材需求只有一个当前方案。一次真实调用返回原件后形成一个候选，候选保留提交前保存的完整方案、实际模型、参数、Prompt、有序参考及文件范围。同参数再次调用是另一个候选；回调、下载重试、状态推进和多文件组成仍归原调用。上传或外部制作保留真实来源，不虚构模型调用。未返回原件的失败或未知调用不产生候选；未知请求先查询原身份。

## 状态正文与按需属性

状态先用一份独立可读描述讲清同一实体此刻的完整形态与必要阶段差异，再保留后续方案与制作确实要用的属性。现行 `complete-v1` 状态格式不要求按类型填满属性；不相关项省略，不填“如上”“依场次”或重复整段。独有声音、真实未知与必要条件必须仍可读。来源与实体归属仍须准确，空正文不能用标题、用途或引文代替。当前方案只将本次模型需要的确定内容写入 Prompt；真实未知保存在 unknowns，确实阻断制作时同时写入既有 production_blockers 或 generation.blockers。这里的制作缺项包括本次所需但尚未确定的原词、准确原件、候选组成或输入锁等，不属于可以省略的不相关状态属性。缺项未补齐时保留阻断，不能靠删掉缺项记录或随意填入文件放行；原件选用按下文“唯一制作出处与准确参考”处理。

## 唯一制作出处与准确参考

需求的 `scope` 是唯一制作出处，指向一个实体、必要实体状态或镜头。`entities`、`states`、关系的场景上下文、计划输入与实际输入说明使用范围，不增加拥有者；通过集场筛选找到素材后，仍回到该出处。实体身份、状态差异和镜头产物各自列自己的需求，不复制共用身份。镜头的 `key_states` 只记录确需独立准备的关键画面或动作关系，可以为空；它不是人物状态清单。

每个当前候选只属于一个当前需求。引用卡、Prompt 和搜索通过同一准确身份核对原件旧编号、当前需求及候选号，保留原修订和文件组成；历史提交中的裁切与时间范围仍按当时事实保留。选用已有候选是准确原件引用，不因候选来自同一需求就变成未来依赖循环；未产出的需求自依赖仍须拒绝。

准备生成时，在当前消费方案的参考小卡或 Prompt 浮层中选定准确候选及原件组成，再回读确认选择落在本次输入位置。当前参考只使用完整原件，不选择局部区域或时间片段；旧当前输入的范围沿受管增量或重新选择原件清除，不改历史提交。查看候选、播放原件和历史质量意见都不代替这次选用。明确取消后保留准确出处，清除原件选择与范围；即使出处是本素材已有候选，也保持未选缺口，不改成需求自指。生成准备只检查本次实际启用的输入及已选路线；尚未启用的可选、条件或其他路线输入不因此成为必需。所需原件和其他制作条件均通过准备包校验后，才进入提交。

退役原件沿已保存提交说明当时需求与退出原因，不按相似外观或共用实体硬塞进当前需求。没有保存当时需求就保留未知；缺组件时显示已知名称、出处证据和不可用原因，不能用今天的相似原件补位。修复只能来自身份可核实的原件。有效输出不因历史输入缺口自动消失，历史缺口也不等于当前输入已就绪。

## 制作、提交与恢复

素材作者入口的 `request.json` 和 `record.json` 是本步骤的准确输入。先读 `begin` 交付目录中的 SKILL、专项文件和交付契约，结合本次任务范围确定要改的方案内容。这个入口可修改的方案输出为 `payload.generation`，以及字层的 `payload.blocks` 和 `payload.specification`；保留 `object_id`、`kind`、`expected_version`、原需求上下文及范围外准确引用。方法依据 `method_basis` 由 `finish` 写入。

`relation_readings` 与 `contextual_relations` 提供准确关系全文，摘要只用于定位；关系存在不自动选择或上传素材。参考应按当前阶段说明约束身份、完整状态、空间、动作、音色、旋律还是文字，不把关系全文和内码拼入模型指令。上下游使用稳定身份，准确候选及完整原件组成保留在具体输入选择中。

模型方案的 `generation.format` 为 `generation-plan-v1`，`method` 按实际路线取 `generate`、`reuse` 或 `external-edit`。模型、工具、参数、有序输入和随机策略各保留真实接口含义；数值不换成说明句。本地编辑与复用不填虚构模型。`prompt` 只写实际模型指令；`output` 保存名称、说明和检查目标；未满足项写 `blockers`。`conditions` 是既有条件标识到布尔值的映射，`selected_routes` 是真实路线选择，不放叙事说明或待办。`selection_state=unselected` 不能凭任意文件或自报认可变成就绪。字层在准确 `blocks` 和 `specification` 中保存原词、阶段和可编辑工程要求，没有模型调用就不建 `generation`。

保存草稿后实际全文回读，再登记本步发现和修订判断，最后交干净结果。`finish` 输出待导入的准确记录包，仍须当前目标、内容摘要、输入及方法依据校验通过；它不表示已生成或获质量认可。阶段成功后保留原事实，继续修改另起步骤；并发变化不能只修改版本数字重交。

1. 从当前对象读取 `edit_token`（并发编辑计数）和 `content_sha256`（当前内容摘要），通过现有 `scripts/media_method.py` 完成方法准备、草稿、回读和定稿，再 `production-import`。步骤不满足、输入已变或目标冲突时保留工作区草稿，回读后另起步骤。新制作方法的数据库记录只保存摘要、方法和执行事实；完整工作输入及草稿仅留在任务 `.runtime/`，恢复用途结束后清理。过去的方法执行事实保持原样。
2. 用 `production-generation-package` 取得准确准备包。对外提交前调用 `/api/production/submit`，提交唯一 `id`、`call_id`、`requirement_id`、`expected_content`、`package_sha256` 和实际 `tool`。返回后才可发起外部请求；同身份返回 `already_applied=true` 时只查询原调用。`scripts/generation_operation.py` 提供同一本机 API 的命令入口。Seed Audio 与 Lyria 的实际提交入口也先核验当前包并保存提交快照；规格中的 `production` 包含 `url`、`requirement_id`、`operation_id` 和 `call_id`。执行方在新调用前确定并保存这次操作及调用的唯一身份：`operation_id` 对应提交接口的 `id`，`call_id` 标识本次真实调用；重取准备包不产生新的调用身份，同一请求恢复时沿用原值。工具参数必须逐项等于方案参数：Seed Audio 使用完整 `audio_config` 与 `watermark`，Lyria 使用 `store` 与实际 `response_format`；参考按上传顺序核对完整原件身份与哈希。
3. 轮询或回调沿 `/api/production/result` 保存，携带唯一回执 `id`、`call_id`、`submission_sha256` 和真实 `status`。返回原件时提供已入库文件的 `asset` 元数据；其稳定身份由调用确定，补文件仍更新同一候选。真实请求、响应、费用和文件证据归原调用，不改已知事实。此接口不调用生成平台。
4. 通过 `/api/production/reuse-candidate` 将准确候选方案复制到当前需求，携带 `id`、`requirement_id`、`candidate_id` 和 `expected_content`。缺失原方案、引用过时或目标冲突会拒绝；不补用最新文件，不触发生成。进一步改稿仍走方法步骤。

`scripts/register_text_handoffs.py --operation 唯一本地制作身份` 登记可编辑字层工程；先通过方法流程准备需求，同身份恢复只补齐原操作，新制作使用新身份。它保留真实本地制作来源，不调用付费模型。

已有真实候选但没有当前方案的旧素材，可按故事项目根目录下 `production/generation-workspaces.md` 的“旧素材补齐当前方案”一节，从自己的确切提交补齐内部当前稿，包括仅有 ASSET 身份及原需求已退役的素材流。公共素材身份与 M 编号不变，退役需求不复活；已有当前稿不覆盖，历史缺口保留，非媒体历史依据不转成上传输入。

界面统一呈现“当前方案 | 候选 候选1…”；没有候选时只保留“当前方案 | 候选”。普通进入先读当前方案，准确候选与旧评论链接仍定位原候选。在上述导航中切换候选仅改变阅读目标，不改变生成所选输入。候选的 Prompt、参数和参考直接可读；未保存的历史参数显示缺口。

## 意见及实际整改

对当前制作内容保存意见时带 `expected_edit_token`，服务在事务中核对后保存当时原摘录。正文后来修改，原话、时间、作者及摘录保留；相似文字不视为原位置。候选音频时间段、图像区域仍绑定原件。`comment-handling-v1` 继续承担实际回应；后台在通用审阅台目录运行 `python3 -m review_desk --instance <实例目录> import-comment-evidence <回应列表JSON>` 登记，加 `--validate-only` 可先校验而不写入。当前制作回应另带 `expected_response_content`：它是回应所指制作对象的并发标记，包含 `edit_token` 和 `content_sha256`，从保存回应前实际回读的对象取得；已改稿时须用改稿后的值。提交时用它核对回应仍对应这份内容，并记录真实处置说明和必要局部改后锚点。原意见提供改前摘录，回应保存改后摘录及摘要；再次修改当前稿不会把当时处理结果冒充今天的正文。

## 物理清除与常规恢复

当前制作不再保留旧素材版本、轮次、旧方案全文及其专属索引。现有实例先在隔离库验证，再沿 `scripts/material_review_release.py prepare --remove-material-versions` 进入受管发布窗口：核验准确基线、停止写入应用，在事务中删除退役数据和缓存索引，保全候选提交、原件、评论及实际回应；随后压实数据库并检查旧数据确实不存在。事务失败时回滚，已完成清除不重复执行。

不制作或保留旧素材版本的物理备份。清除回执只记录计数、摘要和校验结果；之后使用兼容当前模型的服务前向恢复，不启动旧写入模型，也不把历史任务库覆盖正式库。并行任务的有效新增内容沿准确当前数据增量承接。

完整公开导出采用 Schema 14（公开作品包的结构版本）：保存当前制作单份正文、不可变提交快照、真实候选、意见／回应摘录、故事版本、独立 SKILL 文件历史及有效配置方法。通过现有 `restore` 入口恢复到新空实例；旧格式不能重新带入退役模型。私有执行是标记为私有的方法执行及其阶段产物，例如评论润色的执行记录和建议；公开作品包不包含它们，须按准确执行身份显式导出、另行恢复。任务 `.runtime/` 中的完整工作输入和草稿也不由公开作品包恢复，仍按原任务的有效恢复用途保留和清理。准确旧方法包保持原字节，不覆盖已经更新的方法头。原件及真实费用回执不因取消素材版本而删除。

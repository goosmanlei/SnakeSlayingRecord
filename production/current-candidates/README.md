# 当前制作内容与生成候选

故事资料、方向、结构、小说和文字剧本继续保留各自版本。实体、独立状态、业务关系、视听集场镜、输入锁和素材需求只维护当前内容；状态之间的剧情差异仍对应不同对象。当前稿更新使用稳定对象身份和并发标记，不再保存制作全文修订链，也不因改一个镜头推进场、集版本。

每个素材需求只有一个当前方案。一次真实调用返回原件后形成一个候选，候选展示提交前保存的完整方案、实际模型、参数、Prompt、有序参考及文件范围。同参数再次调用是另一个候选；回调、下载重试、状态推进和多文件组成仍归原调用。上传或外部制作保留真实来源，不虚构模型调用。未返回原件的失败或未知调用不产生候选；未知请求先查询原身份。

## 制作、提交与恢复

1. 从当前对象读取 `edit_token`（并发编辑计数）和 `content_sha256`（当前内容摘要），通过现有 `scripts/media_method.py` 完成方法准备、草稿、回读和定稿，再 `production-import`。步骤不满足、输入已变或目标冲突时保留工作区草稿，回读后另起步骤。新制作方法的数据库记录只保存摘要、方法和执行事实；完整工作输入及草稿仅留在任务 `.runtime/`，恢复用途结束后清理。过去的方法执行事实保持原样。
2. 用 `production-generation-package` 取得准确准备包。对外提交前调用 `/api/production/submit`，提交唯一 `id`、`call_id`、`requirement_id`、`expected_content`、`package_sha256` 和实际 `tool`。返回后才可发起外部请求；同身份返回 `already_applied=true` 时只查询原调用。`scripts/generation_operation.py` 提供同一本机 API 的命令入口。Seed Audio 与 Lyria 的实际提交入口也先核验当前包并保存提交快照；规格中的 `production` 包含 `url`、`requirement_id`、`operation_id` 和 `call_id`。工具参数必须逐项等于方案参数：Seed Audio 使用完整 `audio_config` 与 `watermark`，Lyria 使用 `store` 与实际 `response_format`；参考按上传顺序核对原件哈希及范围。
3. 轮询或回调沿 `/api/production/result` 保存，携带唯一回执 `id`、`call_id`、`submission_sha256` 和真实 `status`。返回原件时提供已入库文件的 `asset` 元数据；其稳定身份由调用确定，补文件仍更新同一候选。真实请求、响应、费用和文件证据归原调用，不改已知事实。此接口不调用生成平台。
4. 通过 `/api/production/reuse-candidate` 将准确候选方案复制到当前需求，携带 `id`、`requirement_id`、`candidate_id` 和 `expected_content`。缺失原方案、引用过时或目标冲突会拒绝；不补用最新文件，不触发生成。进一步改稿仍走方法步骤。

`scripts/register_text_handoffs.py --operation 唯一本地制作身份` 登记可编辑字层工程；先通过方法流程准备需求，同身份恢复只补齐原操作，新制作使用新身份。它保留真实本地制作来源，不调用付费模型。

仅有 ASSET 身份的旧素材可按 [工作区流程](../generation-workspaces.md#旧素材补齐当前方案) 从确切候选补齐内部当前稿，公共素材身份与 M 编号不变；已有当前稿不覆盖，无法准确还原则留空，非媒体历史依据不转成上传输入。

界面独立呈现“当前方案”和“历史候选”入口，在两者之间切换。选择候选仅改变阅读目标，不改变生成所选输入。候选的 Prompt、参数和参考直接可读；未保存的历史参数显示缺口。

## 意见及实际整改

对当前制作内容保存意见时带 `expected_edit_token`，服务在事务中核对后保存当时原摘录。正文后来修改，原话、时间、作者及摘录保留；相似文字不视为原位置。候选音频时间段、图像区域仍绑定原件。`comment-handling-v1` 继续承担实际回应；当前制作回应另带 `expected_response_content`，记录真实处置说明和必要局部改后锚点。原意见提供改前摘录，回应保存改后摘录及摘要；再次修改当前稿不会把当时处理结果冒充今天的正文。

## 准确迁移与常规恢复

迁移先在执行时最新正式库的隔离副本演练。批准的清单绑定全部制作当前头、历史行摘要及旧索引；正式服务停止接受写入后，在事务中重新核对清单，提取调用快照、候选组成、原意见和回应局部片段，再删除旧制作全文、方案版本、轮次与专属索引，并清理失去引用的内容节点。并发新增评论在该事务内保留；制作基线变化须重做清单和受影响验收。

`scripts/material_review_release.py prepare --production-current-package …` 沿既有双仓受管交付、共享发布锁和停机窗口应用准确包。旧库仅作为该次迁移的本机灾难恢复现场，直到当前服务验收和两轮空库恢复通过；不作为常规业务历史。迁移后只能向前恢复兼容服务，不能重启旧写入模型或把旧快照覆盖活库。

常规完整导出为 Schema 13：当前制作单份正文、不可变提交快照、真实候选、意见／回应摘录、故事原有版本及有效配置方法。空实例通过现有 `restore` 入口恢复；旧制作恢复包会被当前实例拒绝。迁移清单和发布包只保存摘要与准确输入，不另藏旧制作全文。原件及真实费用回执不因取消版本而删除。

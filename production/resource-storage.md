# 项目资源、发布与恢复

Git 保存代码、业务文字、轻量目录和准确版本引用。图像、声音、视频、图标、字幕、工程附件、历史大包及数据库快照保存到香港地域的私有 OSS Bucket `lijizhanshe`。业务实例仍为 `snake-slaying-record`；历史对象、修订、评论、采纳和来源身份不因存储位置变化而改写。

`config/resource-storage.json` 声明项目与缓存边界，`config/resource-catalog.json` 将原逻辑路径映射到准确云对象。每条原件和派生记录都有 key、显式 version_id、SHA256、字节数、MIME 和完整读取校验记录。旧路径是逻辑地址，不表示 Git 中仍有该文件；读取历史附件应经系统 `resources.materialize()` 或故事工具 `material_model_io.resource_path()`，不得自行拼接 latest、公开链接或旧本机目录。历史 Git/LFS 没有重写，也未因此回收历史仓库容量。

## 运行身份与读取

本机与 VPS 使用各自的项目级 RAM 身份；凭据由外置权限 600 的文件提供，目录权限 700，通过 `REVIEW_OSS_CREDENTIALS_FILE` 指向。运行身份只读本项目，写原件、派生及自身快照／测试前缀，没有删除权；账户级 CLI 凭据只用于已授权的本机管理操作。凭据、签名 URL 和私有代理配置不进入 Git、业务导出、镜像或日志。

网页经应用核对准确资源后，取得有效期 900 秒的签名 GET／HEAD 地址。普通图像小卡与大卡使用保留比例、方向和透明度的派生；完整查看、下载与制作输入读取原件。视频按需读取，封面使用派生；音频波形使用预计算轻量数据。签名失效最多自动刷新一次，保持播放位置、暂停、选段和未提交评论。OSS 本身的条件范围行为与应用契约不同；应用对无效 Range 返回 416，对 If-Range 使用准确本机缓存保持 200／206 语义。显式下载同样由应用从校验后的准确缓存提供附件，保留文件名并避免跨域跳转离开审阅页面。

FFmpeg、ffprobe 和制作工具通过统一解析层取得原件。默认缓存上限 16 GiB，单文件上传上限 8 GiB，下载流式校验后原子启用；文件租约保护使用中的输入。超过 128 MiB 的上传使用 32 MiB 分片和持久检查点。未知结果先查询同一 key／upload_id，不盲目新建；旧检查点身份不符时保留现场。大文件下载、全量哈希和媒体探测在业务写事务外完成，事务内只使用已冻结的准确输入，提交前再次核对物理身份。

## 新制作与受管发布

1. 在任务 `.runtime/` 写候选，完成文件格式、SHA256、大小及业务引用检查。
2. 上传原件及必要派生，完整读取准确 VersionId 校验字节与 MIME，再登记候选。上传不等于采纳。
3. 将资源目录、轻量发布包及代码提交受管任务；超过 1 MiB 的业务 JSON 保存 OSS，Git 留目录或小指针。`scripts/check_resource_git.py` 检查当前暂存树，拒绝媒体、LFS 指针、大快照和嵌入业务媒体；CI 使用相同检查。
4. 沿 [工作区流程](generation-workspaces.md#合并与正式发布) 完成双仓集成、准确系统 pin 和发布锁。发布器核对已合入的目录与准确云资源，不再要求媒体字节进入 Git。正式库增量应用保留其他评论和修订，不能从任务快照覆盖。
5. 从最新正式数据生成恢复快照，并核对导出、空实例恢复及真实页面。`generation_review.py`、`production_review.py` 和编辑 worker 均沿同一解析层工作。

修改历史逻辑路径代表的内容时，应创建新的准确资源／业务修订，不覆盖既有目录身份。图标离线设计脚本输出到 `.runtime/favicon/candidate-*`；检查后从系统图标上传入口登记，再保存配置。

普通需求合并保持可用。旧制作层／候选物理清空和本地文件删除工具拒绝云实例；云资源删除另行核对全部历史引用与独立恢复介质，不把本地缺失当作已完成删除。

## 在线与离线恢复

Schema 16 的 `export/manifest.json` 保存一致性 SQLite 快照的准确 OSS 描述、逐表指纹和资源目录摘要。快照保留完整业务历史，私有编辑队列与运行凭据不导出。恢复检查全部资源准确版本及完整字节；只允许向新空实例安装，安装前再次检查有无并发到达的数据。失败保留原数据库，不能把半完整恢复作为正式状态。旧 Schema 14／15 完整本地包仍通过原兼容入口恢复。

新 clone 不执行媒体 `git lfs pull`。使用 Python 3.12 和 FFmpeg／ffprobe，按配置固定的系统提交及其 `requirements.txt` 安装依赖，提供授权的项目读取凭据，再从故事根目录调用：

```bash
python3 scripts/production_review.py --system "$REVIEW_DESK_SYSTEM" recover \
  --destination .runtime/recovered
```

独立离线介质在 Git 外创建，包含轻量配置、准确快照及每个原件／派生的真实字节，不是一组临时链接：

```bash
PYTHONPATH="$REVIEW_DESK_SYSTEM" python3 -m review_desk \
  --instance "$SNAPSHOT_INSTANCE" offline-bundle --destination "$OFFLINE_MEDIUM"
```

在另一个空实例使用该介质恢复时设置 `REVIEW_RESOURCES_OFFLINE=1`，并禁用 OSS 网络。资源必须来自介质内 `resource-bundle/<SHA256>`，缺失或损坏直接拒绝，不借用旧媒体目录。实际介质位置、全量检查、保留责任与解除条件由本次任务交付回执给出；维护者在更新有效介质前不得删除唯一完整副本。OSS 版本控制不能替代独立介质。

离线继续编辑与渲染在另一个 Git 外可写实例完成，保留原恢复介质。新输出以 `offline-candidate` 保存真实字节，不伪造云端身份；恢复网络后经系统 `resource-promote` 完整上传与回读，再重新导出，才能沿受管流程发布。完整契约与命令见系统 `docs/resources.md`。

## 已运行实例的代码与存储升级

使用 `scripts/oss_runtime_release.py prepare/apply/finalize`，分别准备不可变代码／配置包、切换并核验、登记长期运行入口。镜像配置与有序文件系统层摘要固定准确镜像；所有执行使用核验后的镜像 ID。凭据不打包。本机与 VPS 复用各自数据库和发布身份，保存各自最新备份、业务表指纹及累计调用计数，切换不恢复或替换活库。

发布持共享锁及容器内 HTTP 写入锁，正常停应用、确认没有排队／运行的渲染，验证当前引用闭包，再切换配置和镜像。保留上一容器用于窗口内恢复；命令结果未知时查询实际容器身份。`rollback --release <准确目录>` 仅恢复未开放的中断切换，不回灌旧库。开放后新增数据继续有效，应通过兼容的向前发布修复，不能换回无法读取新资源的代码。

永久入口为实例控制目录的 `storage-runtime.json`，不可变文件位于 `storage-releases/<准确提交>/`。本机后续常规发布器保留资源配置和只读凭据挂载；VPS 的旧全量重置工具拒绝修改已迁移实例。具体双端命令及共享服务边界见 [VPS 操作](vps-experience.md)。原件、准确历史、必要回退与离线介质按用途保留；临时候选、重复缓存和测试对象只按准确归属清理。

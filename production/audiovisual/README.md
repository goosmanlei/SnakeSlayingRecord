## 阅读与修订

每集 `readings/eXX.json` 是本次镜头目的、状态分组、产物关联和集场工作稿的编制源。`eXX.md` 是同源可读稿，通过 `audiovisual_design.py render` 更新。JSON 中 `sources` 保留准确剧本段落，`products` 与 `key_states.requirements` 同时保留素材对象与修订；标签便于识别，准确引用决定内容。全剧每个锁定正文段落恰好覆盖一次。

逐集先读完整剧本，再按自然场与上下镜连读编写：

- **叙事目的**写观众的新理解、感受或关系变化，不将动作顺序、运镜或剧本复述改名充当目的。
- **关键状态**只收确需独立素材准备的镜内时刻。一状态可有多项不同需求；没有独立素材可以为空，同一首帧不复制成两个需求。ASH001 在摊本前复用 M2974，不为翻页结束制造空状态；ASH080 分别关联转牌前 M3211 与显名后的 M4082 字层工程。
- **产物顺序**只列本镜实际交付物，例如首帧、字层工程、视频。上游机位只作参考，不能变成额外产物。方案正文由准确素材需求提供，参考、模型参数和完整 Prompt 必须来自同一当前方案或候选提交快照；工程没有模型方案时如实留空。

集场工作稿只有一份当前说明，可原地修改，集场镜正文和组成也只维护当前内容。审阅界面从集／场导航悬停约一秒或键盘聚焦读取；不再复制成计划版本。场级／各镜共同条件、额外场镜设计采纳和重复用途意见已退出当前编制要求。真正执行的摄影、动作、声音与衔接保留在准确产物 Prompt；真实 CALL、原件、原有素材方案认可和反馈不因此改变。

`planned_seconds` 保留原镜头方案的预留时长，全剧合计由 audit 计算。它不是已经拍成、听审或观看验收的片长；不能为追平旧估时压缩对白、删掉有意义的重复或假定模型已能完成表演。

## 关键制作选择与复核方法

| 问题与条件 | 采用的制作方案 | 原理与检查 |
| --- | --- | --- |
| 李寄常急于替别人决定，阿蘅有自己的谋生与作证目标 | 给阿蘅完整拒绝、提问、走前与收证据的动作；李寄收脚、等她收纸或只托罐底 | [叙事与信息](../filmcraft/01-narrative.md)、[表演](../filmcraft/09-performance.md)：逐场查是谁提出目标、谁回答、谁完成行动，不以反应特写抢走行动主体 |
| 两份米、歌本与多种凭据在不同人手中流转 | 交接保留起点、接触、承重与放手；原件、抄件、凭记各自标明去向 | [调度](../filmcraft/05-staging.md)、[美术](../filmcraft/08-design.md)：按镜尾到下镜头逐项点物，不允许无来由换手、复原、消失或多出一只手 |
| 后院南北短道、前后门互锁与两侧人位必须让观众记住 | 先用成人膝与一步量尺度；东侧保持北右南左，转西侧前经正南全景；父亲绕南前门的路径完整给出 | [摄影](../filmcraft/03-cinematography.md)、[摄影机](../filmcraft/04-camera.md)、[调度](../filmcraft/05-staging.md)：回看门、闸、缝、饵、刀和人数；任何镜像或穿越石道都不通过 |
| 蛇头多数在封闭盖下，女孩不能提前知道成人窥缝所得 | 用擦声、闩震、成人口述和有限缝内细节；不给洞内全知镜头，不把传闻当实见 | [叙事与信息](../filmcraft/01-narrative.md)、[声音](../filmcraft/11-sound.md)：逐镜记录视点和声源，检查新增画面是否越过人物知情范围 |
| 七人不足、八人仍很吃力，李寄下刀并非突然无畏 | 先证明父亲不能离杠，再保留两次退缩、找缝、碰石停手、抽刀后退和群体反作用 | [表演](../filmcraft/09-performance.md)、[动画与生成](../filmcraft/12-animation-ai.md)：按接触点与受力顺序回看，刀、双手和脚不能在镜间跳位；不用加速掩盖失误 |
| 断开之后还有余声，不能立刻开门欢庆 | 留下观察、等待、同号慢卸与继续封门，分别给女孩和成人情绪释放 | [声音](../filmcraft/11-sound.md)、[表演](../filmcraft/09-performance.md)：检查口令前后动作和声源，不用胜利配乐抹掉等待 |
| 旧灯反复出现且本次进庙未点燃 | 清晨、后院、返家保持无内光；最终散场由母亲当面点亮，走路时照台阶和幕杆 | [灯光](../filmcraft/06-lighting.md)、[色彩](../filmcraft/07-color.md)：查灯芯、补纸、照射方向和持有人；情绪变化不擅改灯的物理状态 |
| 独立歌曲的已认可词稿与当前正式剧本演唱范围并不完全相同 | 保留歌曲实体与真实候选；剧中镜头只唱当前输入锁正文，不将旧同步提案自动写进剧本 | [视频生成手册](../seedance-video-handbook.md)：参考只锁定已明确用途，候选质量、旋律范围和故事改版分别审阅 |

## 准确素材与声音文字

[逐镜输入审查](video-inputs.json)记录直接参考职责、首帧收窄、后续入画与输入规则，并绑定实际产物引用，不再要求旧摄影条件字段。修改单项媒体方案使用[受管媒体方法](../managed-methods.md#单项媒体方案)，视频先读[视频生成手册](../seedance-video-handbook.md)。`audiovisual_materials.py` 只核对并保留已有准确产物，不再从旧共同条件批量重建全剧方案。

[发声事件表](vocal-events.json)保存源文中的对白、叙述发声、明确动作表达与动作／发声交错次序。原 `shot-contexts.json` 已退役：仍有实际 Prompt 消费用途的 `narration`、`action_order` 已移入发声表；空间、轴线、光色等共同条件副本不迁移。有意义的重复与不同人物的同句发声保持独立；语意明确而原词未知的句子仍是待准备项，不能凭简化界面补出对白。

[出现范围](appearances.txt)、[状态适用范围](state-ranges.txt)、[镜内变化](state-transitions.txt)与[首帧主体](frame-subjects.txt)保留已有准确输入依据。发声不等于入画，镜尾状态不能提前画进起点；普通参考也不保证固定首帧像素。已有音色、曲调及裁切／时段仍按各素材准确候选和原件核对。独立歌曲的认可不自动修改锁定剧本的演唱范围。

[文字交接目录](exact-text.json)关联 11 份已有工程，[逐集文字复核](text-review.md)说明原词、揭示次序及路线。工程在对应产物 Tab 中打开共用素材卡下载，不冒充已生成视频；透视、手部遮挡、显字时机和读时需后续实际画面验证。第16集清账末行缺准确原词，仍阻断逐字读回。

`scene_reading.py` 只维护完整准确 Prompt 中的文字区间与反馈定位，不再另设“动作与对白”镜卡。它验证同镜准确产物、源文与完整事件序列，不改 Prompt。

## 隔离编制与应用

在本故事受管任务 worktree 根目录运行，`--system` 指向本任务审阅台工作区：

```bash
python3 scripts/audiovisual_design.py audit
python3 scripts/audiovisual_design.py render
python3 scripts/revise_audiovisual.py prepare --system PATH_TO_DESK --instance .runtime/generation/review --plan .runtime/generation/av-revision.json
python3 scripts/revise_audiovisual.py validate --system PATH_TO_DESK --instance .runtime/generation/review --plan .runtime/generation/av-revision.json
python3 scripts/revise_audiovisual.py apply --system PATH_TO_DESK --instance .runtime/generation/review --plan .runtime/generation/av-revision.json
```

入口核对源文件摘要、输入锁、当前头、准确需求与工作稿并发版本，只写任务隔离库。修改镜头目的原地更新该镜头，不推进场、集；不会重编已有素材方案或发起生成。新镜头或新媒体制作按实际授权另行编制，不从缺失的旧字段猜测内容。认可素材方案、选择准确输入和实际调用授权仍在生成准备闸门内，场／镜设计采纳不再是前置条件。

新工作先取得 `method.skill.audiovisual-scene` 当前绑定，按 understanding、principles、design、handoff、review 保存并重读实际产物，入口见[受管工作方法](../managed-methods.md)。方法改版追加定义并显式更新绑定；冻结执行仍按原方法解释，不能补写它采用过新方法。

此次专属旧文字清理采用[准确迁移包](../audiovisual-three-part/migration.json)和 `audiovisual_publication.py`。它只改变清单指定的视听说明、关系冗文及旧设计决定；保留准确身份、组成、可执行关系和删除摘要，完整恢复需要 Schema 10。目标有新修订或被清理文字上新增评论时整次拒绝，须先处理变化；不得用任务旧库覆盖活库。

正式数据应用需另获对应发布授权，在[共享写入窗口](../generation-workspaces.md)核对最新准确目标、停写与恢复能力后执行。同一包重试检查已应用回执，不重复写入。代码集成、隔离验收、正式生效与独立复验分别报告。

本目录早期 `verification.md`、`stage-review.md` 等保留当时真实验证记录。其已退役的编制格式、计数或页面不是当前方法；当前入口以本页和本次验收为准，历史原件与 CALL 仍沿准确记录追溯。

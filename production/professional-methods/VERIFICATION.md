# 创作制作方法的实际接入与试用

任务 `task-20261009-0021` 解决的是：创作者取得准确方法和资料后，能完成一个自然工作单元，并把缺项交回具体负责阶段。它沿用已正式交付的基础任务 0020，不把基础加载能力、旧方案修复或后续全剧重做算成本轮创作成果。正式生效、部署和清理结果以主任务账本及本机发布回执为准。

## 工作入口与实际变化

[工作交接与选择入口](../professional-methods.md)覆盖结构、小说、剧本与表演原词、视听设计、素材判断、图像／音色演唱／视频／字层、生成准备、审片返修及独立读者／评论润色边界。方法正文和历史只在系统配置及其准确导出中维护；不在本报告复制。

- 剧本作者现在先 `begin` 取得方法、当前检查点和准确材料，再保存整场、实际回读、审阅采用。无方法的旧候选仍可读，不能伪装成新步骤。丢失准备响应后重试沿同一运行身份恢复。
- 结构、视听及其他外部创作使用 `creative_method.py`，保存真实阶段产物并回读。它只适配已有方法服务，不另选方法、不调用模型。
- 媒体准备可以按当前问题选择章节，并取得输入锁正文、相邻镜及原件记录。准确外层引用仍校验；原件记录里提及旧退役候选只作为历史文档，不重新激活为当前生产依赖。
- 影视知识十二章连同来源、示例及图示保留项目 Markdown 的唯一正文，系统只读投影。执行包按问题取章，并带所需 SVG 和来源文件，保持原相对路径；未选延伸资料仍须按需实读。视频手册保持单一正文；小说与评论不被迫装入手册。

加载、记录和测试只能证明技术契约；下面的源文与产物比较用于判断实际应用。

## 先做一个连续场，再改方法

先试版本四 E02/s004 完整自然场，再扩展方法和独立样本。按 understanding → principles → design → handoff → review 五阶段依次保存、服务登记和实际回读，没有把同时生成的成果补记为逐步试用。

这个场从唱曲失败、母亲咳血的信息，发展到归还多余米、袖口最后一粒、道谢和离店分歧。首轮提出 11 个试镜，回读发现两个具体问题：前镜“逐粒捻入”和后镜“已经放完”可能把最后一粒两边都省掉；下一镜人物已持纸包，但前镜没有交代从柜上取起。随后收窄镜间边界，并补“系袋道谢后提袋抱纸、转向未出店”，保留尚未和解的关系及关心湿衣的后续。

实际打开四幅原图后发现：阿蘅湿衣图的抱完整歌本姿势不能照搬为系袋；李寄的笑容和张手不能直接转成此刻表演；周掌柜围裙适合店内，不能延续到脱围裙的后场；湿书图不能证明散页已经包起。身份／衣着可借用与姿态／道具不适用分别交接。音色只做技术探测，没有实际听辨，明确未验。

视频方案沿真实 `media_method.py` 入口完成草稿、回读、审阅和登记。首次“图1／音频1”被渠道指代校验拒绝，按实际语法改为 `@图片1／@音频1`，并改进方法说明，没有放宽校验。最终视频方法第三版再次用于同一场，补齐输出摘要与 Prompt 落点的一致性，在隔离库形成需求第9版。前镜最后一粒、本镜落斗系袋、后镜持物成立的是文本交接；12秒仍只是能力内估计。

## 陌生连续场的独立前向试用

三个执行者使用无父会话任务，只取得真实工作请求、准确结构／剧本／输入锁和适用方法；不提供本报告结论、首轮答案、旧视听方案或下面的已知回归清单。执行者实读全剧，再展开目标集、完整自然场及必要前后原文。下列估时均不是成片测量。

| 样本 | 方法实际帮助 | 仍暴露的问题及修订 |
| --- | --- | --- |
| E06/s014 对话／信息场，20镜、235秒候选 | 区分门外发声、开门后显露身份；保留22处原对白、两处尚缺表演原词的发声事件；按借褥子、出门的顺序交接 | 首稿估时加总不一致；空碗到有水缺倒水，回忆切法含糊；后续审阅又发现母亲“起身”没有先坐下。分别补倒水放壶、明确同场侧面回看、坐下后起身。比原场176秒多59秒，须排演评估 |
| E08/s018 空间／动作场，24镜、209秒候选 | 保留交替门闸、两次推动、声停后仍等退去、手不松至下场及后场才交钥匙 | 首稿把从西向东看的画面南北写反；递盆被前镜与后镜同时省掉。修为北在画左、南在画右，并实际写出接触、承重、放手。比原场184秒多25秒，须动态验证 |
| E16/s037 文字场，完整26块 | 把遇害者纠正、阿蘅销名、停祭发粮分清；告示、账册、凭据、歌本分物；保留再念、核印和接米等待 | 草稿误把阿蘅本场获得回应理解为此前未主动；回查 s006 修正。原宣读18行和10处对白逐字核对；账页、末行、印记、署名和粮数保持候选或未知，没有补造 |

根执行者对照准确源文实读最终镜头及审阅文件。实际发现反过来收窄视听方法第四版：明确场地方位与画面左右的换算、姿势与空闲手前提、交接重量和释放的顺序、逐镜估时加总。文字方法第三版增加前史回查、原词与文书候选逐字区分、完整发声和持物链交接。

动作和文字执行者再次取得最终方法复用既有准确产物，仍逐阶段保存和回读。这轮明确是“改进后复用”，不计为另一次盲试，也不为体现价值编造新错误。文字最终交出18行告示候选、10处原对白、3处明确候选发声，以及读回→核印→折纸→转交→接米顺序。关键文书和原词缺项继续交原负责阶段。

## 真实入口、保护与验证范围

剧本检查点另以 E06/s014 做实际候选：给两处原来仅有语意的发声提出可审阅原词，保存、回读、采用并重开检查点。它是本机作者候选，未改正式剧本，未把候选词宣称用户锁定。

生成准备方法实际调用既有 `generation-ready`：当前视频方案没有方案认可、视听认可、起始图选择，音色新用途未听审，因此返回未就绪；补充引用可读和渠道组合可表达都不能把它改成可生成。没有取得调用许可、没有收费媒体调用、没有生成视频。

代码回归覆盖准确包恢复、资源变更后的旧快照稳定、来源及图示导出、补充材料变化拒绝、步骤顺序／不可覆盖、错误场次与输入拒绝、剧本响应丢失后的同身份恢复。基础读者与评论回归仍维持阅读边界和原意约束。完整系统 Python 回归486项通过；合入最新主干后前端833项通过。它们不代表文学、表演、图像或声音效果通过。

正式迁移只追加配置定义，通过 [在途核对](cutover.json) 和既有停写发布器执行。正式服务、无关历史数据比较、完整导出恢复、私有执行恢复和资源清理另有本机真实回执；没有把试用库写回正式库。配置包随 [受管导出](../../content/managed-method-registry.json) 交付。

## 如何复核与继续

准确公共输入来自 [制作输入锁](../source-lock.json)、[版本四](../../imports/screenplay-04.json)和[结构第十稿](../../imports/story-structure-01.json)。方法读取与恢复命令见 [受管方法](../managed-methods.md)。私有试用执行、冻结阶段、必要原件观察和最终回执归主项目 `.runtime/task-20261009-0021/`；保留用于本次方法验证与恢复，不作为后续任务基线。后续任务从当时最新主干及正式数据开始。

本轮小样能证明方法帮助发现并减少了特定遗漏，也暴露了文字检查无法确认的部分。后续仍须逐集重做、完成具体表演原词和准确材料、实际看听生成结果及相邻镜；本轮不代表全剧、真实音色适配、口型、动作物理或成片节奏通过。

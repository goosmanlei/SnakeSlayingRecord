## 共用入口及读取口径

系统 `reviewSmallCard` 是编号、名称、真实缩略图／类型图标和必要信息的共同表面；`entitySmallCard`、`materialSmallCard` 复用它。入口盘点覆盖实体管理、素材管理、制作拆解逐镜列表、镜头制作视频列表、大卡状态素材、无实体归属的大卡素材列表、引用及多层弹窗。`production.js` 保留组合／历史的通用制作记录列表和旧接口兼容分支，复用同一小卡表面；当前管理 API 使用新管理实现。关系图节点、状态选择、准确参考按钮各自承担专用动作，保留其语义，完整阅读仍用共用大卡或准确引用阅读器。

普通实体小卡打开该实体大卡，素材小卡打开该素材的共用大卡。唯一例外是大卡左侧底部状态素材列表：只切换右侧，保持实体、状态、阅读位置及草稿。准确对象、修订、实体、状态、素材版本、候选和历史评论目标优先，错误目标报错；关闭上层恢复下层，关闭管理页卡恢复筛选、页码、滚动和焦点。异步结果核对请求与工作区；下层读取不得在上层打开时激活并覆盖上层。

实体本体与所属状态的准确分集正文来源、场／镜明确列出的实体／状态／出场记录，以及 occurrence／applicability 关系共同产生集场匹配；状态归属沿准确 entity 引用，位置读取准确父场／分集。索引保留每条证据的记录、来源或范围，不靠名称、同场其他对象或父级向下展开。实体身份去重，即使多个状态或镜头匹配也只列一张。

完整状态数直接使用大卡的当前完整状态列表，按状态身份去重；阿蘅为 6 个当前状态，另有 5 个历史保留，不混计。采纳读取真实最新决定及当前范围，有效内容／方案采纳、未采纳和需重新采纳分别表达，存在原件不等于采纳。图标有文字、可访问名称及提示，不在小卡增加写入操作。

素材沿现有 canonical_id 合并需求与原件身份，保留无需求历史素材；真实挂载／适用／覆盖来源、当前有效方案的准确输入、历史 CALL 原始输入和明确采用共同产生位置。实际调用使用原需求范围，不拿新方案补历史。每个真实场按素材身份去重，跨场仍是同一素材；只有集归属的留“集素材”，剧范围留“全剧素材”，无集场／剧范围的留“未关联集场”。唯一素材数与分组展示项数分开；版本、候选、组成和同场重复引用不增算素材。

两个管理页使用 `groupedCardPage`／`reviewPagination`。实体按类型，素材按集场编号稳定排序；每组独立起行，组末不满三张仍算一行，标题和间距不计行，跨页续组保留标题。默认 10 行，提供 5／10／20／50 行，默认最多 30 个展示项。筛选或行数变更回首页，结果收缩钳制页码，空结果与单页禁用首末按钮。窄屏只改 CSS 排列，当前页集合不变；大卡内部和逐镜侧栏不强制三列。

## 串行交付、正式验收和恢复

从本故事任务 worktree 执行，使用 `scripts/material_review_release.py` 现有代码发布流程。两个目标均为 main；系统唯一 upstream 为 origin 的 `refs/heads/main`，准备时核对并冻结准确推送 URL。故事唯一 upstream 由 `codex.project task _prepare_integration --push` 核对记录。自动启动授权覆盖本任务序列，验收仍由实际结果决定。

1. 提交双仓候选、配置 pin、本包、KNOWLEDGE／STATE；执行 `_prepare_integration -g creative -p SnakeSlayingRecord --task task-20261005-0003 --push`。冲突在当前 worktree 解决并提交、重新准备；候选变化按影响补验。
2. `material_review_release.py prepare --task task-20261005-0003 --push-system --system-worktree .runtime/small-cards/system --bundle .runtime/small-cards/release --story-candidate <准备回执候选> --story-target <回执目标头> --system-candidate <双仓计划候选> --system-target <双仓计划目标>`。冻结准确源码、配置、旧服务镜像／挂载、辅助脚本及两个摘要；`build` 使用已核对旧镜像离线构建，`preflight` 校验全部输入并预演系统 fast-forward。阶段不写正式数据库。
3. 候选验收通过后 `_deliver --note '候选与实际验收依据'` 受控集成并推送故事 main。随后 `material_review_release.py apply --bundle .runtime/small-cards/release --manifest-sha256 <摘要> --image-receipt-sha256 <摘要> --apply`，持共享发布锁，核对目标／服务未漂移，正式库一致性备份，系统受控 fast-forward，安装不可变配置挂载与新镜像，健康、源码及挂载回读，再核对全库历史保全。无业务导入、迁移、采纳或生成决定，业务增量 0；并发真实用户评论保留。
4. 正式 3000 只做一次必要 Chrome 验收：实体三列与状态数、集场联动、素材分组及两种计数、分页、EN002 打开／左侧切换／关闭恢复、准确旧版及媒体可读。正式库不新增测试评论或采纳；不重复 96 页开发期全遍历。将实际视口、页面结果与部署版本写本机 `release/run/formal-browser.json`。
5. `material_review_release.py publish-system` 带同一 bundle、两个摘要及 `--apply`，只向冻结 upstream 正常 fast-forward 推送系统候选，再回读远端。远端分叉即停，禁止强推；故事推送结果复用 `_deliver` 回执。
6. 正式验收及推送通过后，停止 62230 预览，关闭本任务测试页，按准确目录、无专用容器挂载、文件哈希和读写占用检查删除 `.runtime/small-cards/review`、测试缓存和重复日志；保存实际数量、缺失回读及保留用途到 `release/run/cleanup-final.json`。不删 worktree、分支、正式库、受管证据、正式冻结包及必要恢复备份，不停止共享 VM 或全局清缓存。
7. 所有完成标准实际满足后 `_complete --note '逐项验收、双仓推送、正式运行与清理回执'`。完成后不再补改代码或文档；完成时间、自动授权和推送结果留任务账本／完成回执。保留 TUI 与 worktree，清理锁待退出后释放，不领取下一任务。

`prepare`／`build`／`preflight`／`apply`／`publish-system` 的完整参数可 `--help` 回读。阶段回执只写 `.runtime/small-cards/release/`，正式挂载与恢复入口为主目录 `.runtime/service-releases/small-cards-20261005-0003-<故事短SHA>-<系统短SHA>/`。源码或目标漂移时停止并重新准备，不复用旧摘要。已成功动作先回读回执，不盲目重做。

正式切换失败时同包 `recover` 带两个摘要及 `--apply`，恢复核对过的旧镜像／配置挂载，**不恢复数据库快照，不 reset Git**；新旧代码均兼容当前业务库。推送失败保留相同候选与冻结计划，按普通 fast-forward 条件重试。发布冻结包、正式前后数据库备份、旧运行镜像与准确回执保留恢复用途；较新发布基线替代且追溯用途结束后再核对移除。试验数据库、夹具及重复日志的删除不改变原件、用户评论或采用历史。

# 准备可直接审阅的制作内容

人的工作是读作品、看听准确原件、判断具体取舍并提出意见。AI 先整理完整内容和必要参考，完成专业自检；系统负责准确版本、文件、范围与执行条件。入口可以按完整工作组织，不要求人沿实体、状态、需求、用途逐层处理。

## 作者怎样交付

1. 从准确故事和制作版本开始，顺读整场动作、原词、表演、摄影、声音与剪接，再看跨镜承接。区分实际出场、随后发生和仅作背景的条件；不能把未来湿衣、持物或人物提前带入当前镜头。
2. 按当前需要作出的判断安排正文。动作和说话保留时间顺序；每镜独有的专业选择就近显示。同一共同条件可以只读一次，但必须说明适用镜头和例外。身份说明、日常状态和本镜动作不能相互替代。
3. 原件放在其用途及已有判断旁。说明本次保留什么、允许变什么、尚未决定什么；旧母版认可只适用于该准确原件。没有产出就说明没有产出，准备需求不是人工逐项待办。
4. 技术参数、输入装配、尺寸和谱系检查、生成时自检由准备流程承担；真实调用与原件追溯保持。不能把独有的表演、湿区、画面方向、原词或未定内容当作技术重复删掉。
5. 显示整合沿 `config/instance.json.production_reading` 保存准确原块哈希、Unicode 区间和逐块处置理由；动作正文继续沿 `scene_reading`。通用数据契约见审阅台 `docs/production-breakdown.md`。不得按关键词自动裁句、匹配近似新句或硬编码人物名。
6. 对每项合并，核对被省内容的意义在哪里保留。部分原块只展示一个区间时，尤其要检查其余内容。系统的哈希和区间校验只能证明身份，不能证明语义完整；必须实际连读与看听。
7. 验证新意见仍落到原修订和原偏移；原来未显示的区间、跨块草稿和历史意见仍能回到准确原块。新修订未编排时完整显示原文，不套用旧版区间。不能为整理展示改写旧调用、冻结方法或有效认可。

本剧的后台工具 [production_reading.py](../scripts/production_reading.py) 提供 `inspect`、`validate` 和 `apply`。在当前受管故事工作区运行，`--system` 指向任务账本登记的审阅台工作区，`--instance` 指向本任务隔离实例；默认配置为 `config/instance.json`。`inspect --object-id … --revision-id …` 读准确原块，`validate` 核对全部编排及伴随修订。

`apply --plan … --expected-config-sha256 …` 接受作者已逐块判断的 `authored-production-reading-v1` JSON：每项包含准确 `reference`、覆盖全部原块的 `sources` 处置及理由、原区间 `sections`、准确 `requires` 伴随对象。它校验原块、区间、全部既有编排和配置版本后才原子替换配置；配置在校验期间变化也不写入。它不自动决定语义、不改存储中的作品，不改旧原件与认可。对象编号只属于本次作者的准确交付，不进入通用运行时规则。

## 人的决定各自回答什么

| 决定 | 回答的问题 | 不自动代表 |
| --- | --- | --- |
| 原件选择 | 这次方案具体引用哪份文件、哪一段或区域 | 原件质量已认可、镜头已采用 |
| 原件评价 | 对这份准确图像、录音或视频有什么判断 | 新用途、新候选或新生成许可 |
| 设计认可 | 认可哪些准确设计及其明确子项 | 素材方案和付费调用已授权 |
| 生成许可 | 这一准确单项方案或实体完整方案是否获准执行 | 输入已齐备、结果已通过 |

状态本身不是独立可采纳对象，用途没有独立必经采纳。准确状态素材方案的单项认可与实体有效生成许可择一；普通内容认可不自动升级，实体身份自有需求不能借状态范围取得许可。场／集认可只覆盖相应准确镜头设计。撤销、部分覆盖、分歧、版本冲突和仍未选择的输入继续明确保留。

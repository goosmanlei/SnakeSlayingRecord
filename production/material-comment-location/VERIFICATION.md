# 素材意见返回准确原件的验收

`task-20261009-0016` 解决从素材意见定位时不能自动回到所属原件文件及圈选位置的问题。组成是同一素材的原件、试听预览等文件；它与生成候选不同。定位现在恢复意见所属的准确素材修订、候选、组成及范围；提交前切预览仍提交原圈选的意见，编辑器显示原评论对象的组成。文件或范围不可用时给出原因，不换文件、借用最新版或裁短圈选。

本文件保存可复查的行为、过程判断和复验路径。完整规格见 [任务规划](../../planning/material-comment-location-task.md)；准确系统身份只由 `config/instance.json.review_desk_commit` 维护，正式集成、运行版本、页面验收和清理结果沿主项目 `.codex-task/tasks.json` 中本任务完成说明及 `.runtime/task-20261009-0016/` 实际回执定位。候选通过不等于已经正式发布。

## 实际过程与反馈

1. 执行开始吸收最新主干，系统基线为 `b3bcc8308834e7ab9853775eaf7ae3d5fee6322a`。以有效正式数据的独立副本打开 M1206，真实播放 WAV 原件，用时间轴圈选 1–2 秒，写明确标注的功能测试意见，切到 MP3 后提交。数据库保存的仍是原件准确锚点。该基线定位却切到当前状态下的 M004，手动恢复历史状态及原件后再定位仍离开目标。上游截图中的手动正常对照是历史事实，本次最新基线的状态分支已不同，不能沿用旧通过结论。
2. 最小候选同步组成、卡片及准确状态后，重启隔离服务以重建内容寻址脚本包，再从正在播放的 MP3 点击意见：实际回到 WAV 原件的 1 秒和 1–2 秒选段，旧媒体停止。第一次仅刷新仍读旧脚本包，未计为候选通过。
3. 实际往返暴露两处上下文问题：旧轮次映射覆盖方案映射会丢失同一草稿；实体入口的准确历史状态只随素材的关联状态返回。分别保留两套映射、恢复与素材准确引用一致的历史状态，再原路复验。无对应状态时保留准确历史原件，不借用当前状态。
4. 关闭重开素材卡、从 EN046 的实体入口打开同一对象、在预览上再次定位、同组成定位及带未保存文字往返通过。既有 C280 文字意见与本次原件意见往返后，草稿文字和原件归属保留，没有新建重复弹层。
5. 在媒体慢载入条件下连续选择 WAV 1–2 秒与 MP3 3–4 秒，最终只保留最后的 MP3 选择；载入中关闭卡片后，迟到响应没有重新打开。阻断原 WAV 的网络读取时可见“原文件读取失败；未替换为其他文件，请返回继续审阅”，恢复网络后同一意见可正常定位。此项是受控网络失败，不是正式原件损坏。
6. 使用已有 M1133 图像实际拖选、提交测试意见，再从另一条音频意见返回：显示同一图像原件及原归一化区域。没有生成新素材、制造业务候选或进行音质／采纳判断。

## 复验与边界

在对应最终候选的独立实例中，从“生产制作 → 素材管理”查 M1206 并打开完整卡：切原件、播放后暂停；时间轴 Home、Shift+右、I、Shift+右、O 选 1–2 秒；添加明确功能测试意见，切预览后提交；播放预览再点击该意见“定位原圈选”。核对原件下拉、1 秒播放位置、1–2 秒选段、暂停状态和原件归属。再检查同组成、关闭重开、EN046 实体入口及未提交文字。正式发布后只读从原素材／实体路径回查已有准确意见，不写上述测试评论。

自动检查调用真实定位和播放器处理器，控制 HTTP 响应或渲染容器，覆盖准确修订／对象／组成／文件、越界范围、历史状态、轮次与方案映射、卡片、草稿、迟到读取及关闭后的媒体事件。公共图像定位检查准确文件和当前卡片容器。HTTP 回归核对服务端锚点和评论接口。测试入口为系统 `tests/comment_location.test.cjs`、`tests/media_location.test.cjs`、`tests/entity_review.test.cjs` 及 `test_production`、`test_production_api`、`test_entity_review`；数量及最终结果留实际日志。

没有可用的真实作品镜头视频或同需求双候选样例，因此视频时间和多候选身份仅由必要受控检查覆盖，不称真实业务实践。真正缺失修订、组成、文件身份及失效锚点的拒绝由自动检查覆盖；浏览器只实际验证受控网络读取失败。未测量节约时间或全库发生率，不作数值收益承诺。正式服务切换、远端 Git 回读、历史保护和实际清理须看本任务最终回执，不能由本文件或隔离通过推断。

过程库、复制的预览素材、缓存与临时服务完成验证后删除；保留准确提交、最小测试锚点 JSON、测试日志、必要截图、发布与清理回执。双仓工作区在当前会话及锁仍占用时保留，退出后通过受管清理退役，不能强删活跃工作区。

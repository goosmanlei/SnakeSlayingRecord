# 用评论理解意见和回查修改

阅读作品、查看图像或试听声音时，直接在准确内容上评论。作者在获授权的任务中读取原意见与上下文，实际修改后登记回应，连接准确改后版本和局部；暂不修改则说明原因。用户可以继续评论，关闭或重新打开评论只整理讨论，不决定内容是否可用。

## 当前流程

评论固定当时的对象、修订和文字／图像／时间锚点。原评论的“复核回应与改动”可打开原圈选、作者说明及准确修改，再返回原阅读位置。资料、结构与生产对象共用这条路径；旧目标缺失时说明缺失，不转到最新稿，也不移动原锚点。

生成准备检查准确来源、方法绑定、文件及哈希、参数、参考输入和输入锁，不要求逐对象审批，也不从评论推断通过。素材输入仍须落实为准确版本、候选、组成及必要片段。出现新的上游版本不自动替换有效旧输入；决定改用新输入时重新理解上下文并修订方案，冻结 CALL 的原始输入保持不变。

## 历史意见与退役

制作设定送审对象（RV，旧存储类型 REPRESENTATION）和独立审阅决定（DC，旧类型 JUDGMENT）不再是业务实体。任务 `task-20261010-0019` 对执行基线的全部 287 个旧对象、293 个修订逐项分类：131 条独有意见迁入普通评论，5 条复用已有准确评论，其余 157 个修订删除。旧对象正文和修订物理退出；来源只保存必要身份、摘要、作者、原时间、范围及去向，不保留可写的影子审批模型。

M1134 的“1. 认可；2. 不补”保留为用户在 2026-10-03 针对准确母版的历史意见，范围不延伸到派生候选或镜头效果。《三道滩》的“曲调是保留的，但是发音仍然是不准的”复用已有评论。AI 历史说明单独标明主体，不伪装成用户原话。原件整体意见可在媒体评论入口阅读，不冒充某个时间点或图像区域。

冻结 CALL 的原正文、哈希和方法快照不变；其中的旧审批引用由现有 consolidation 最小退役凭据解释。已确认剧本版本四和输入锁保留为已发生的事实，不重做作品。

## 准确发布与恢复

- [退役包](retirement.json)绑定准确旧修订、分类、意见来源及引用处理。
- [当前方法包](methods.json)追加有效方法和绑定；冻结历史定义不改写。
- [发布契约](release.json)绑定两份文件哈希、前置迁移凭据及预期当前头。
- `scripts/review_retirement_release.py` 在同一事务内应用退役和方法增量；版本漂移先拒绝，验证模式回滚，重复相同包幂等。逐表对照保护范围外历史，逐文件核对原件。
- `scripts/material_review_release.py --review-retirement-package production/comment-review/release.json` 沿受管 Git 交付与共享发布锁切换正式库和服务；不以隔离快照覆盖正式库。

完整交付使用 Schema 12，包含原件、评论、回应、准确选择及退役凭据。空库恢复须复制完整 `export/`（含 `assets/`），同时使用对应实例配置；仅把源目录传给恢复函数而不给目标实例放置原件，不构成完整恢复。恢复拒绝 RV/DC 正文及缺少本实例退役凭据的旧包。新增实例同样不能创建这两类对象。

实际验证、正式运行身份和清理结果见[本次退出验收](RETIREMENT-VERIFICATION.md)及任务账本回执。早期结构与资料的作者回应依据和验收保留在[跨版本意见复核验收](VERIFICATION.md)，不将历史候选记录冒充当前正式状态。

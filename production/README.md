# 视听制作与素材审阅

《把灯带回家》以已确认的剧本版本四为共同来源：17 集、42 个故事场、1114 个正文块。当前视听设计重新编成 17 个视听集、65 个视听场、344 个镜头，逐段覆盖正文，并为每镜及其上游素材编制需求和生成方案。镜头方案预留合计 6344 秒，即 105 分 44 秒；用户已确认允许适度加长，以动作和表演读得清楚为先。这是方案预留时长，须在真实表演和后续剪辑中复核。

当前视听设计按叙事目的、关键状态、产物生成方案组织；0016的候选和隔离验收见 [三部分验收](audiovisual-three-part/VERIFICATION.md)，0020补齐的正式应用见 [部署验收](entity-material-formal-release/VERIFICATION.md)。没有发起图像、音频或视频生成；已有媒体沿准确原件与真实调用复用。技术验证不代表用户认可新设计、方案或候选，也不表示已有镜头视频、完整预演或成片。

故事集边界保持不变。视听场按地点、时间、戏剧动作和声音组织，可拆分或组合本集故事场的准确片段。视听集、场、镜使用稳定身份与当前组成；原地修改镜头不推进父场或父集版本，文字剧本依据仍固定准确故事版本。

故事同时支撑两条制作线。一条形成实体、实体关系和实体状态；另一条形成视听集、场、镜。它们共用素材需求。故事中提到一个人、人物实际出现在画面中、状态适用于某段、镜头采用了某个素材，是不同事实。准确故事出处、出现范围、素材用途及调用输入分别登记。

## 页面如何使用

[生产制作](http://127.0.0.1:3000/?workspace=settings.workspace&production_tab=breakdown)包含“视听制作”“实体管理”“素材管理”三个子页。

在视听制作中，先选集和场，再依次读叙事目的、平铺的镜头关键状态，以及按实际制作顺序排列的产物 Tab。每个 Tab 直接呈现同一准确方案的参考、模型参数和完整 Prompt；没有方案时保留空态。状态关联素材通过共用卡打开，返回保留镜头位置。集场当前工作稿从导航悬停约一秒或键盘聚焦读取，正文不另铺计划。故事依据打开准确版本并标出引用段落。

实体管理查看身份、实体关系和完整实体状态；素材管理按需求组织方案和候选，并支持集场、媒体、状态和搜索筛选。没有现行需求但仍有用途的历史候选作为独立素材保留真实来源。素材列表的当前页集合固定，窄屏只改变排列；关闭详情、返回和切换候选保留阅读位置与未提交评论草稿。

素材卡在当前方案和真实候选间切换。当前方案没有结果时保留空态，候选始终呈现自身提交时的完整方案。图像看原件，声音和视频可播放；比较和浏览不保存参考或采用。

## 需求、方案、候选与准确参考

一个镜头可有多项独立需求，如首帧、字层工程、动作声音和视频。每项需求只有一个当前方案，模型、参数、Prompt、参考或固定种子变化时原地更新；实际提交前保存准确快照。相同参数再次调用是另一候选，回调、补充说明与多文件组成不增加候选。

实体、状态、素材需求／原件与镜头等对象使用同一个业务关系模型：一对稳定对象只有一条当前关系，不同方面与阶段形成连贯内容。实体图直接显示摘要、编号及端点；参考项与 Prompt 链接按需读取同一准确关系。具体选择、路线和范围仍由方案保存；受管方法读取完整关系与当前阶段，将适用约束写入 Prompt。操作、历史映射和恢复见 [统一关系](unified-relations/README.md)。

参考可以是必需、可选、条件满足时使用或几条路线择一。先确定执行路线与条件，再检查该路线上的缺项和循环；未选路线不误阻断。自定义但尚无机器语义的关系只供理解，不自动进入生成输入。

“选为方案参考”保存需求所选的准确候选及原件组成，可进一步保存图像裁切或音视频时间范围。只选需求或方案而未选实际原件时仍显示待选，不能生成。引用经过哪些上游素材，与某次真实调用直接传了哪些文件，分别展示；新方案不能冒充旧候选的历史生成方案。原始方案缺失时明确标为未知。

## 评论、准确选择与生成条件

作品、实体及素材方案不要求逐项审批。当前制作意见保留当时原摘录，实际整改保留必要局部改后片段；后来再次修改会明确提示。候选意见固定原件区域或时间，编辑、关闭、重开不改写原事实。

开始真实生成前，后台重新核对制作输入锁、当前能力与授权、准确素材方案、完整状态、所选路线、每个参考原件和时间范围、递归依赖与谱系。任何缺项都须先解决。本轮隔离验收使用的色块和测试音明确标记为测试，不发布到作品库。

## 后台编制与恢复

故事编制留在本仓：`audiovisual_design.py` 从逐集 reading JSON 核对准确正文、生成可读稿；`audiovisual_reading.py` 迁移目的、状态与组成；`audiovisual_materials.py` 核对已有准确产物。单项 Prompt 修订使用受管媒体方法。通用审阅台提供数据管理、展示、反馈与校验。使用方式见[全剧镜头入口](audiovisual/README.md)。

实际生成任务使用最新受管工作区和独立实例。当前制作修改、真实提交、候选及评论沿现有入口登记。增量包使用变更前摘要核对并发，范围外数据保持；新模型拒绝旧增量重放。迁移和日常增量均不能用任务快照覆盖正式活库。

当前候选恢复以完整 Schema 13 `export/manifest.json`、[制作索引](audiovisual/index.json)和[最小发布幂等凭据](audiovisual/recovery.json)为准。制作对象恢复单份当前内容，候选恢复提交快照；故事和方法仍保留原有版本。仅在任务 worktree 中向全新隔离目录恢复：

```bash
python3 scripts/production_review.py --system <受管审阅台目录> recover \
  --destination .runtime/production/fresh-review
```

恢复校验对象与全部有效修订、准确关系、评论及事件、原件哈希和发布幂等凭据。旧场准备、旧镜头编排、旧方案迁移和旧 replay 入口已退出；删除内容只保留最小身份与摘要凭据以解释真实来源缺口，不恢复其业务正文。

正式代码、数据与服务版本沿 `config/instance.json`、任务账本和实际发布回执核对。先完成两仓准确提交、受控集成及候选验证，再在串行窗口停止旧写入、事务切换、部署与真实浏览器复验。切换提交之后只向前恢复新体系，不能用旧数据库覆盖用户后续意见。

方法维护、实际执行及切换恢复见 [受管工作方法](managed-methods.md)。

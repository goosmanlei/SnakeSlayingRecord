# 实体素材统一入口候选验收

task-20261010-0015 交付共用实体／素材大卡的两 Tab 入口及“所选结果 → 准确生成方案”阅读路径。M2597 不再将 14 条旧图备选和 13 条下游依赖堆在结果旁；没有候选仍显示未生成。已有原件直接读取它自己的真实调用记录，模型、参数、有序输入及完整 Prompt 无需展开历史按钮。图像、音频、状态版本和未提交意见保持准确身份。

这是隔离候选验收。未部署、未写正式库、未调用付费生成；正式入口没有因本任务切换。准确双仓 Git 交付以任务账本为准，系统候选身份由 `../../config/instance.json` 的 `review_desk_commit` 维护。负责人独立 Review 与后续正式应用另行办理。本记录不评价声音质量或新生成效果。

## 范围与实际实现

- 实体基础信息下只有“实体素材／实体状态”两 Tab。实体级需求和未绑定状态的历史原件共用实体素材列表；状态 Tab 显示所选状态的准确描述版本及素材。空态不借另一归属补位。
- 实体列表默认当前默认状态；准确需求和原件入口按有效来源定位 Tab／状态。主动切 Tab 和记忆中的状态返回恢复各自合法素材、描述版本及阅读上下文，地址同步所读准确对象。
- 右侧固定显示素材名称、版本／候选、结果或占位、准确生成方案。实际 CALL（真实调用记录）优先属于所选候选；缺 CALL 说明历史缺口，保存方案明确不构成实际调用证明。计划输入与真实输入分别标明，输入为纯列表，裁切／时间／准确版本仍保留。
- 通用标准从准确需求原字段读取，在审阅操作旁一个“？”按需显示，支持 hover、键盘和点击固定阅读。具体作品约束和完整 Prompt 保留正文。移除默认用途关联列表不改变关系、原件、意见或许可事实。
- 浏览器实操发现并修复两个选择问题：切 Tab 后地址仍可能停留上个素材；素材版本返回时显示候选与草稿目标可能不一致。窄屏帮助框越界及 Esc 关闭外层大卡也在实操后修正。

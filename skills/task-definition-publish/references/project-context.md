# 项目任务的登记与执行交接

本文件供项目 Agent 在任务定义后完成登记、交接或恢复。正文中的代码路径以故事主项目根为基准；Markdown 链接按文件位置解析。任务账本与本次启动指令决定任务身份、回调及当前授权，业务交付沿项目既有流程。

## 读取本次入口和项目依据

进入受管澄清会话，完整读取用户给出的指令文件，先按其中的 `_media --draft UUID` 检查会话媒体并绑定草稿。执行阶段则先完整读取执行指令，每轮开始任务工作前通过本次 `_bind_session` 认证；成功核验运行凭据和锁后才允许写入。

沿主项目 `AGENTS.md` 的“跨会话恢复”使用有效规则、知识和状态入口，复用当前会话已读且未变的内容，再取与目标有关的材料。任务查询按需要选择 `.codex-task/tasks.json`、`codex.task list`、`drafts` 或 `show --task TASK_ID`，同一信息不重复用多个入口查询。先定位相关任务，再读其完整目标、结果与恢复条件。

| 用户要做的工作 | 公开入口 | 本次澄清的完成点 |
| --- | --- | --- |
| 发布待办，稍后执行 | `codex.task publish '需求'` | 需求、范围和发布授权明确后登记，不执行目标 |
| 修改已发布且从未执行的任务 | `codex.task mod --task TASK_ID '补充要求'` | 执行次数为0；重审完整需求及仓库列表，登记后不执行 |
| 整理需求并立即执行 | `codex.task do '需求'` | 信息充分时直接登记；成功即结束澄清，启动器衔接同编号、同会话 |

需要执行或恢复已发布任务时使用 `codex.task run --task TASK_ID`；`do --task TASK_ID` 也可恢复。本次启动指令已给准确回调时直接按其执行；接口缺失、版本变化或报错时才核对 `--version` 及相关子命令 `--help`，不重跑整套CLI兼容性调查。启动器参数选择澄清模型，执行使用任务登记的模型与推理强度。

按目标选择必要依据：

- 作品、协作方法或审阅系统的问题调查沿 `skills/creative-system-review/SKILL.md`，复用已有效的证据。
- 创作选择沿 `production/filmcraft/README.md` 与 `production/filmcraft/quick-reference.md` 查询适用章节；视频方案与 Prompt 先读 `production/seedance-video-handbook.md`。涉及制作输入锁时，读取 `production/source-lock.json` 与本次实际 `INPUT_LOCK`，并核对本次用户决定；代码主干更新不自动改变已确定的作品或素材输入。
- 方法版本、来源投影与执行快照沿 `production/managed-methods.md`；`production/system-vision.md` 说明创作价值与人的工作定位。
- 任务正文和必要文字证据沿既有 `planning/` 交付，调查过程留在 `.runtime/`。执行所需输入须能从任务及项目取得。

本发布 SKILL 用于项目会话，不注册系统工作类型或修改正式方法库。若另获方法注册委托，再沿方法管理流程核对来源与版本绑定。

## 明确仓库、依赖与任务类型

先根据完整需求确定所有需要修改并交付的独立 Git 仓库。故事特有创作与工具留故事仓，通用展示、评论、审阅及数据管理归经核验的同级 `../story-review-desk`。只读参考不列为交付仓库。

向用户展示主仓和全部附属仓的真实源目录、用途与修改边界、目标分支及仓库交付依赖；纯主仓明确附属为空。附属 `source` 相对故事主项目解析，历史目录核对实际 Git 身份。任务修改时重审整个列表，尚未产生路径、分支或 Git 登记的计划可以修改或移除，已有资源由工具保留并核验。

任务依赖记录哪些准确成果必须先完成；仓库依赖记录本任务各仓候选的交付顺序。两者都不能代替正式数据库、服务、账号或发布窗口的写入协调。结合在途任务，说明代码重叠如何合并、测试怎样隔离以及共享写入何时按序进行。

`publish`、未发布的 `do` 草稿及 `mod` 使用 `--type mutual|parallel|free` 确定长期执行锁：

| 类型 | 锁与并发关系 | 选择依据 |
| --- | --- | --- |
| `mutual`（独占） | 独占公共执行锁；与mutual、parallel互斥，可与free共存 | 资源不能隔离或依据不足；Git与非Git均支持 |
| `parallel`（可并行） | 共享公共执行锁；可与parallel、free共存 | Git工作区、测试数据及端口能隔离，可控代码重叠与共享写入有安排 |
| `free`（自由） | 不取这层公共执行锁；可与三类共存 | Git任务有具体依据说明无需长期公共锁，实际写入仍按各自保护和协调执行 |

三类都保留依赖、同任务防重、身份和会话写锁、账本及短期集成保护。非Git仅mutual。不能仅凭任务小、有worktree或队列为空放宽类型；未指定时有依据可选任一类型，依据不足选mutual，理由写明实际修改与资源条件。

用户指定而判断不同，先完成需求和仓库修订，再通过本次 `_type_decision --draft UUID --type-spec JSON` 记录 `action=propose`、建议 `task_type` 和具体 `reason`，在原对话说明冲突并等待真实回复。用户可以同意建议，也可以补充隔离条件坚持原类型。收到回复后重核条件，用 `action=resolve`、最终类型、理由及真实 `user_quote` 记录共识。未解决保留草稿，不发布、不静默改类型；范围改变时重新核对决定。执行入口不能覆盖类型，未执行任务的类型调整沿mod协商。

## 定义执行终点

任务目标和验收共同说明交付到哪里、需要哪些真实证据以及由谁继续处理残留：候选交付、本地集成、正式生效和阶段归档各有完成条件。澄清回合只登记的限制不缩减未来已授权的执行目标。

普通run/do默认完成本地实现、验证、提交和受管集成，报告用户核验入口、步骤及预期结果，等待用户明确确认任务完成后结项。同一目标的反馈沿原编号、工作区和会话继续。任务或当前对话明确授权的推送、部署及共享数据写入继续完成；普通入口本身不新增这些权限。

`--auto` 授权本次自行验收结项，Git任务需要有效upstream（远端跟踪分支）并完成推送。该权限不写长期配置，普通恢复不继承上次自动权限，一次执行不续领下一任务。本项目系统改进使用--auto时，按 `AGENTS.md` 和 `production/generation-workspaces.md` 完成受管集成、必要推送、本机正式发布及真实验收；用户明确指定候选、研究或其他边界时按当次要求定义。付费生成、VPS或外部发布须有相应授权。

执行者验证、正式交付、独立复验和用户接受分别记录。成功提交、Git送达或执行者报告不能替代业务生效、独立结论和最终确认。具体未完成项写明由原任务继续、独立复验或新授权任务承接。

## 完成登记

在本次草稿中形成完整目标与验收，用户原始需求完整保留。先把会话媒体逐项对应到用途或省略理由，读取实际需要的原件；必要本地文件通过指令的 `--input-file` 保存，图像、音频不能只保留不可恢复的临时引用。Markdown、JSON等文字证据沿任务规划交付，不伪装成媒体。

通过本次 `_repositories --draft UUID --repository-spec JSON` 原子保存完整仓库范围。对象含 `repositories` 数组和 `complete=true`，每项提供 `name/source/purpose/target/depends_on`；纯主仓使用 `{"repositories":[],"complete":true}`。澄清只登记附属计划，执行领取时工具统一取锁并创建目录。执行中发现需要新增仓库时，先按本次执行指令登记，保存现有受管工作区的成果，再通过 `run --task TASK_ID` 恢复启用新仓；启用前不向新仓写入。

按本次指令填写登记字段：

| 参数 | 保存的内容 |
| --- | --- |
| `--summary` | 对象与实际改变 |
| `--goal` | 原始需求、问题、改后工作、范围、依据、约束及交付终点 |
| `--acceptance` | 具体输入、正常对照、故障及恢复后的检查和完成判断 |
| `--priority` | 优先级，未另有要求时默认P1 |
| `--complexity`、`--effort` | 简单／常规／复杂／极复杂及本次模型策略对应的推理强度 |
| `--type`、`--type-reason` | 已确定类型与实际隔离、协调依据 |
| `--depends` | 必须先完成的同项目task-id，可重复传入 |

模型与强度取本次策略，通常使用相应默认强度，较高档有实际难度依据；耗时长不构成选择ultra的理由。媒体命名、选择和省略、模型策略以及修改修订号，使用本次指令中的准确参数。

发布前核对正文、字段、媒体与完整仓库声明一致，关键输入可恢复且执行者可取得。publish/mod在授权明确后使用本次 `_publish` 或 `_modify` 登记；do范围明确时简明说明目标、完成标准和修改范围，直接登记，不重复要求“确认发布”。仅询问影响这些内容的实际缺口。

内部回调只用于本次认证会话，使用指令给出的准确命令。文件仅在当前受管worktree准备，账本和媒体由回调保存；不直接改账本、猜编号或手建附属worktree。

## 结束回合或沿原身份恢复

publish/mod成功后按指令回读任务、范围和输入并报告，不追加文件修改或执行目标。do成功即简短报告编号、结束澄清回合，启动器核验发布及澄清提交、等待回合完成和会话写锁释放，再领取同任务并恢复原会话。Agent不在澄清中启动嵌套TUI，也不要求用户退出或另跑run。

| 当前情况 | 下一步 |
| --- | --- |
| 目标或必要授权缺失 | 原对话提问，保留草稿及已明确回答，补齐后继续登记 |
| 未发布草稿需继续 | 按原入口使用 `publish --draft UUID`、`mod --draft UUID` 或 `do --draft UUID`；保留账号、编号、工作区和会话。mod公开入口的--task与--draft二选一 |
| 发布失败或结果未知 | 先查同草稿、账本、澄清提交和回执，确定是否已登记或部分生效，再沿工具给出的原入口恢复 |
| 已发布但启动失败、依赖未满足或写锁未释放 | 保留已发布身份与现场，按工具恢复入口继续；发布成功不能报告成已执行 |
| 无可用终端且缺信息或类型分歧未解 | 保留草稿及恢复入口，非交互调用非零退出，不虚报发布成功 |

`--wait` 只等待领取条件，不重跑失败目标、不解除依赖。执行恢复必须经任务入口重新领取与认证，直接 `codex resume` 不取得任务运行凭据。

部分交付先查实际回执，沿同一准确候选恢复；候选或未交付目标变化时重新准备、合并并补验受影响部分，未变化证据可以复用。主目录普通未提交修改不阻止隔离开发，实际集成受阻时保留候选，不擅自提交或丢弃他人改动。主干同步、逐仓候选、业务发布和资源退役沿 `production/generation-workspaces.md`；不因恢复新建替代任务或重复未知副作用。

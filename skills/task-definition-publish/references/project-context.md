# 本项目的依据与发布衔接

下列代码路径以故事项目根为基准；本文件只连接现有入口，不另建任务账本或调度流程。

## 定义任务时

- 依次读取 `AGENTS.md`、`KNOWLEDGE.md`、`STATE.md`，遵循本次用户要求与当前有效依据。`production/system-vision.md` 说明创作价值与人的工作定位。
- 作品、协作方法或审阅系统的问题调查使用 `skills/creative-system-review/SKILL.md`；任务定义仍可继续调查，发现新的关键问题时沿该方法补足真实实践。两种方法共享证据，不互相要求重做全部流程。
- 创作取舍按 `production/filmcraft/README.md`、`production/filmcraft/quick-reference.md` 查询适用知识；视频方案与 Prompt 先读 `production/seedance-video-handbook.md`。方法资源、准确版本及执行快照的约束见 `production/managed-methods.md`。
- 编写任务说明按 `document-writing` SKILL 以执行者的理解和工作顺序成稿。任务正文及随任务交付的必要文字证据放入既有 `planning/`；本机调查过程沿既有 `.runtime/` 入口保存。不能让执行者只能从发布者私有聊天或即将退役的预览环境取得关键输入。

## 获准发布时

先读主项目 `.codex-task/tasks.json`，必要时用 `codex.task show` 查准确任务与回执；只按当前调查需要定位旧材料，不全量加载旧会话。查看澄清草稿与在途任务，避免并发派发相同目标。

使用当前安装的 `codex.task` 及受管澄清会话提供的发布指令；需要时查询 CLI 帮助。新建或恢复已有草稿沿其公开入口进行，不直接改账本、猜任务编号或手建附属 worktree。受管澄清中的素材与仓库声明沿现有 `_media`、`_repositories --draft`、`_publish --draft` 回调完成，参数以本次会话协议为准，不能把内部命令当作脱离会话的独立接口。

登记完整的必要仓库范围：故事特有创作与工具留故事仓；通用展示、评论、审阅和数据管理在经核验的 `../story-review-desk`。跨仓使用一个任务与账本。开发基线、仓库纳管、隔离预览、增量交付及清理沿 `AGENTS.md` 与 `production/generation-workspaces.md`，不复制成另一套流程。

任务说明和登记须一致表达优先级、必要依赖、复杂度、开发隔离、共享资源与发布协调；枚举取当前工具支持值，不以空依赖推断无资源冲突。正式业务数据按本次授权处理；持续 Review 的写入验证在准确版本的隔离环境，任务发布权限不扩展为正式数据写入或部署权限。

原始图像、音频沿工具支持的媒体渠道登记，保留准确原件；Markdown、JSON 等必要文字证据随任务规划提交并引用准确位置，不伪装为媒体。回读任务编号、正文与验收、媒体、仓库范围、依赖和实际状态，确认执行者能取得输入；仅发布的任务不得被本会话顺带启动。发布中断或结果未知时先查草稿、账本和回执，沿原身份恢复，不重复新建。

本 SKILL 是项目会话的任务定义与发布方法。加载它不创建系统工作类型、不更新正式方法库，也不改变冻结执行；如另获委托注册为系统方法，沿 `production/managed-methods.md` 单独核对来源投影与版本绑定。

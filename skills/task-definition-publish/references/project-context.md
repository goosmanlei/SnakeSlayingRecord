# 本项目的依据与发布衔接

下列代码路径以故事项目根为基准；本文件只连接现有入口，不另建任务账本或调度流程。

## 定义任务时

- 依次读取 `AGENTS.md`、`KNOWLEDGE.md`、`STATE.md`，遵循本次用户要求与当前有效依据。`production/system-vision.md` 说明创作价值与人的工作定位。
- 作品、协作方法或审阅系统的问题调查使用 `skills/creative-system-review/SKILL.md`；任务定义仍可继续调查，发现新的关键问题时沿该方法补足真实实践。两种方法共享证据，不互相要求重做全部流程。
- 创作取舍按 `production/filmcraft/README.md`、`production/filmcraft/quick-reference.md` 查询适用知识；视频方案与 Prompt 先读 `production/seedance-video-handbook.md`。方法资源、准确版本及执行快照的约束见 `production/managed-methods.md`。
- 编写任务说明按 `document-writing` SKILL 以执行者的理解和工作顺序成稿。任务正文及随任务交付的必要文字证据放入既有 `planning/`；本机调查过程沿既有 `.runtime/` 入口保存。不能让执行者只能从发布者私有聊天或即将退役的预览环境取得关键输入。

## 登记与恢复

先读主项目 `.codex-task/tasks.json`，用 `codex.task list`、`codex.task drafts` 和 `codex.task show --task TASK_ID` 按需核对草稿、在途任务、准确交付与恢复条件；不全量加载旧会话。按目标和行为查重，已完成或已放弃任务只作证据入口，旧结项不是本次验收，也不授权恢复撤销范围。

### 选对公开入口与本次授权

使用当前安装的 `codex.task`，先核对 `--version` 和相关子命令的 `--help`；当前适配基线为 0.9.0。公开入口与受管回调分开使用，不从旧任务复制固定工具版本、草稿编号或私有配置。

| 当前工作 | 公开入口 | 当前回合的完成点 |
| --- | --- | --- |
| 澄清并发布待办 | `codex.task publish '需求'` | 需求、范围和发布授权明确后登记，核对结果，不执行目标 |
| 更新尚未执行的已发布任务 | `codex.task mod --task TASK_ID '补充要求'` | 执行次数须为 0；按完整新需求重审所有字段及仓库列表，登记后不执行 |
| 整理需求并立即执行 | `codex.task do '需求'` | 信息充分时直接登记；成功即报告编号并结束澄清回合，启动器自动衔接同任务、同会话 |
| 执行或恢复已发布任务 | `codex.task run --task TASK_ID` | 领取、认证后继续原工作；`do --task TASK_ID` 也可恢复已发布任务 |

恢复未发布草稿沿其原入口：`publish --draft UUID`、`mod --draft UUID` 或 `do --draft UUID`；保留原账号、预留编号、工作区与已明确回答。`mod` 的公开 `--task` 与 `--draft` 二选一。目标缺口在同一对话补齐；无可用终端且缺信息或类型分歧未解时，保留草稿和恢复入口，不冒称发布成功。执行时不能覆盖类型，尚未执行任务的类型改变沿 `mod` 协商。

当前命令使用 `publish/run/do/mod/list/rm` 等帮助中实际支持的入口，类型用 `--type`，自动结项用 `--auto`；不再推荐已移除的 `add/mrun/modify/ls/delete`、`--free/-auto/--parallel/--parallel-reason`。旧资料可以保留历史用语，恢复须用规范入口，不重建原任务。读取执行指令及 `_bind_session` 认证通过后才允许执行写入；直接 `codex resume` 不代替任务领取和运行凭据。

### 按实际隔离条件确定类型

类型独立于入口、依赖和交付授权；`publish`、未发布的 `do` 草稿及 `mod` 使用 `--type mutual|parallel|free`。

| 类型 | 长期执行锁 | 与其他类型的关系及判断依据 |
| --- | --- | --- |
| `mutual`（独占） | 独占公共执行锁 | 与 mutual、parallel 互斥，可与 free 共存；资源无法隔离或依据不足时采用 |
| `parallel`（可并行） | 共享公共执行锁 | 可与 parallel、free 共存；Git 工作区及测试数据、端口等能隔离，说明可控重叠和共享写入协调 |
| `free`（自由） | 不取这层公共执行锁 | 可与三类共存；说明为何不依赖长期公共锁，以及仍需协调的实际写入 |

非 Git 仅支持 mutual。三类都保留任务依赖、同任务防重、身份及会话写锁、账本保护和短期集成互斥；free 不允许同时覆盖正式库或绕过账号限制。任务小、有 worktree 或队列为空本身不足以放宽类型。用户未指定时根据修改范围、在途任务和共享资源决定，有依据可选任一类型，依据不足选 mutual，并写具体理由。

用户指定而判断不同，先沿本次会话 `_type_decision --draft UUID --type-spec JSON` 保存 `action=propose`、建议 `task_type` 和 `reason`，在原对话说明具体冲突并等待真实回复。用户可同意建议或补充隔离条件坚持原类型；之后用 `action=resolve`、最终类型及理由、真实 `user_quote` 记录共识。未解决不发布，不能编写用户消息、以裸确认参数替代回复或静默改类型。先整理完整需求和仓库范围，再记录决定；范围改变时重新核对。

### 登记完整范围、原件与任务字段

故事特有创作与工具留故事仓；通用展示、评论、审阅和数据管理在经核验的 `../story-review-desk`。主仓由当前项目确定，只读参考不列为交付仓库。向用户展示主仓及全部附属仓的真实源目录、用途与修改边界、目标分支和仓库交付依赖；纯主仓明确附属为空。附属 `source` 相对故事主项目解析，不相对草稿 worktree 解析，历史路径须现场核验。

按新需求重新评估整个列表，通过本次会话 `_repositories --draft UUID --repository-spec JSON` 原子登记；`repositories` 中每项写 `name/source/purpose/target/depends_on`，`complete=true`。纯主仓传 `{"repositories":[],"complete":true}`。改变范围时不能只补新增项；尚未产生路径、分支或 Git 登记的计划可修改或移除，已有资源保留并沿工具处理。澄清只登记附属计划，领取时工具统一取锁并创建目录，不手建 worktree。执行中新仓先登记、保存成果，再通过原任务 `run --task TASK_ID` 恢复启用，启用前不写。

先用本次 `_media --draft UUID` 检查会话媒体并绑定草稿，逐项说明原件用途或省略理由。图像、音频及需要的本地文件按实际读取和保留；必要本地原件使用 `--input-file`，不能只给不可恢复的临时引用，也不能把未实际保存的文件说成已登记。Markdown、JSON 等必要文字证据随任务规划提交并引用准确位置，不伪装为媒体。用户原始需求完整保留于目标，结合调查补充范围、约束与验收。

回调必需字段按本次指令填写：`--summary`、`--goal`、`--acceptance`、`--priority`、`--complexity`、`--effort`、`--type`、`--type-reason`，分别保存摘要、目标、验收、优先级、复杂度、推理强度、类型及具体理由。同项目依赖用 `--depends`，素材选择/命名/省略沿指令参数。未另有要求时默认 P1，复杂度用简单／常规／复杂／极复杂，并从本次模型策略选择对应默认强度；更高档须有实际难度依据，不以耗时长选择 ultra。内部 `_publish` 或 `_modify`、模型策略及修改修订号使用本次指令给出的准确命令，不直接改账本、猜编号或把回调当脱离会话的独立接口。

发布前核对任务正文、字段、媒体和完整仓库声明一致。成功后遵守本次回合结束要求：publish/mod 只回读并报告，不追加修改；do 立即简短报告编号并结束，让启动器核验发布及澄清提交、等待回合完成和会话写锁释放，再领取执行，不要求用户退出、另开终端或另跑 run。执行采用任务登记的模型与强度，不能把澄清用的启动参数当作执行模型。

### 失败后继续原任务

发布失败或结果未知时，先查同一草稿、任务账本、澄清提交和回执，确定是否已登记及是否部分生效，再按工具给出的原入口恢复；不新建替代编号、不重复副作用。恢复后继续处理原缺口和有效回答。已发布但执行启动失败、依赖未满足或写锁未释放时保留现场，不能报告已执行；`--wait` 只重试领取，不重跑失败任务，也不解除未完成依赖。

开发基线、主干同步、准确候选、隔离预览、增量交付及清理沿 `AGENTS.md` 与 `production/generation-workspaces.md`。部分交付先查实际成功回执，沿同一冻结候选恢复；候选或未交付目标改变时重新准备、合并及验证受影响部分，未变化证据可以复用。主目录未提交改动不阻止隔离开发，实际集成受阻时保留候选，不擅自提交或丢弃他人改动。

## 交付终点与验收交接

普通 `run/do` 默认完成本地实现、验证、提交与受管集成，报告实际成果和用户核验入口、步骤及预期结果，等待用户明确确认完成后结项。同一目标的反馈沿原编号、worktree 和会话继续。执行授权不是用户已验收；成功结果或 Git 送达不自动关闭独立复验、具体残留或标记作品已被接受。

`--auto` 只授权本次调用自行验收结项，不写长期配置、不自动续领，普通恢复不继承旧自动权限；Git 自动交付需要有效 upstream（远端跟踪分支）并完成推送。普通调用本身不新增推送、部署或共享数据写入权限，但任务或当前对话已明确授权的交付义务继续完成，无需重复请求许可。任务目标须说清候选交付、正式生效或阶段归档，以及各自必要步骤、证据和恢复条件，不能互相替代。

本项目系统改进任务的默认交付终点按 `AGENTS.md` 的 `--auto` 约定：任务执行者完成集成、本机正式发布和真实验收后结项。发布者将其写入任务目标、验收及仓库范围，不误写为“仅候选／不得部署”；这不授权定义与发布会话亲自执行，也不包含付费生成或 VPS／外部发布。仅候选、研究或其他例外须来自用户明确的当次边界，不能从旧任务沿用。

最终报告与过程资源清理沿主方法和项目规则；明确未完成项由原任务继续、独立复验或新授权任务承接。发布权限不扩展为持续 Review、正式业务数据写入或部署；按当前授权调查和登记即可，不重复索要逐项许可。

本 SKILL 是项目会话的任务定义与发布方法。加载它不创建系统工作类型、不更新正式方法库，也不改变冻结执行；如另获委托注册为系统方法，沿 `production/managed-methods.md` 单独核对来源投影与版本绑定。

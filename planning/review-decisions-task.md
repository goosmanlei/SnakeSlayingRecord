# 优化任务：理解已有判断并作出准确的审阅决定

本任务优化已有人工判断的读取与准确决定路径，使审阅者能依据已有结论继续当前工作。本文是独立执行规格，完整保留问题依据、方法、范围和六项验收；任务状态以主项目 `.codex-task/tasks.json` 为唯一权威，执行不依赖持续系统 Review 的临时容器或数据库。

下文问题描述及代码行号对应上游记录时的现场版本；其中“当前”指该观察时点，不宣称问题在后续新版仍未修复。执行开始须按当时最新主干及有效正式数据重走原路径，复用已交付能力，再确定剩余改动。创建时自检、后来人工判断、方案许可、准确选择与实际采用分别成立。

文中的 ASSET 指登记的素材原件，STATE 指实体状态，CALL 指真实生成调用；JUDGMENT 是绑定准确对象修订的人工判断记录，accepted 表示该记录的认可结论。API 是程序读写接口，其成功与用户在页面完成审阅分别验收。

## 用户目标与已确认问题

审阅者打开一份素材或制作方案，应能知道已有谁对哪一版、哪一范围作过什么判断，以及自己当前动作会认可什么。然后才能决定继续审阅、要求修改、采用已有结果或推进下一步。现有数据保留了这些判断，但当前阅读路径不能充分呈现，容易让用户重复判断或误读进度。

**M1134是明确反例。** 主会话在正式 Chrome 的素材入口、与正式同版本隔离实例的实体入口查看阿蘅基础音色，正文“生成结果自检”仍写“实际听辨者尚无……不是已认可母版”。这是原件创建时的真实自检，应该保留。正式库同时存在准确指向该原件当前修订的后来用户判断：2026-10-03，actor=user、verdict=accepted，理由引用用户当时“认可；不补”。当前该原件只有这一条人工判断，主会话在两种卡片中均未见其展示。API的uses保留判断引用，卡片内容却只呈现实际调用、参考和生成时自检，没有可查的后来判断。

正式库中130个不同ASSET至少存在一条当前判断记录为accepted。这仅说明潜在覆盖，不是130项当前有效采用、130次页面失败或已经符合新方案要求。M1134过去的母版认可不能自动转授新音色需求M2669，更不代表任何具体镜头已经采用或生成。

**决定范围与后续作用不够容易核对。** 隔离 Chrome 点击阿蘅顶部“采纳”后，准确决定覆盖基础信息1项、全部6状态、24关系、6状态整体方案和1项上游依赖，不只当前可见ST088。按钮确有HTML title说明“基础信息、关系、全部实体状态及素材生成方案”，不能说完全没有范围说明，也不把没有确认弹窗本身当缺陷。但当前卡片缺少本次具体范围与已有决定的可查入口；既有文档承诺的采纳历史菜单在当前实体卡未发现。

同一页面的M2710“采纳此版”是另一项准确方案决定，用户实测后仍显示“图像·未生成”，这是正确行为。生成准备优先使用单份方案的明确采纳，没有时STATE需求可以使用所属实体的有效整体方案认可；两条是替代许可路径，不是每次必须按顺序点两次。无论哪条路径，都还要满足准确参考、原件、版本和谱系检查，后台输入包不等于真实生成。当前UI应帮助用户理解实际可做的下一步，不能用“已采纳”模糊这些差别。

**同一原件的判断操作不一致。** 实体大卡内M1133/M1134没有“记录本版本审阅结论”，直接素材管理打开M1134却有。已有准确判断难查，记录新判断又依赖入口，使用户为同一任务重新查找素材。不能简单给所有卡片堆相同按钮；应沿当前准确阅读对象复用必要的判断路径。

隔离实操进一步完成了记录结论：空保存正确要求填写审阅者和依据；填写明确标记“仅验证功能、不代表素材质量”的需修改意见后，准确记录成功且只有一次写入，采用关系保持不变。但异步刷新将同一M1134详情从1层变成2层，关闭两层后重新打开仍看不到刚保存的结论，只看到旧自检。正式库没有这条测试记录。此问题涉及保存后如何继续当前工作，不能只以API保存成功验收。

## 目标与边界

利用已有准确判断、修订、采纳和采用关系，让用户从当前阅读对象了解适用的已有结论与必要依据，清楚本次决定的范围和作用。需要回溯时可以查到取消、历史版本和此前理由；普通阅读优先呈现帮助当前决定的信息，不默认铺开内部事件日志、hash、所有旧记录或重复状态标签。

区分原件创建时自检与后来人工判断，保留两者时间和适用范围；不通过改写历史自检、删除旧判断或把最新状态回灌旧版本来制造一致。多位审阅者意见、后来相反判断、不同范围及版本变化，按既有规则明确适用关系；没有确定性优先规则时不能只按时间挑最后一条作为唯一事实。

实体整体认可、单版制作方案认可、生成结果判断和实际采用各有对象及后续作用。沿现有控件表达这些区别，必要范围和理由可查；已有标题提示有帮助但不能成为唯一理解途径。取消一项决定不擅自取消另一项独立决定，新候选不继承旧候选结论。无需默认强制确认弹窗，也不建立新的审批流程、管理页面或第二套判断账本。

统一同一准确原件从实体卡和素材卡进入时的判断可读性与必要操作，保护正在审阅的版本、候选、选段及未保存意见。方案采纳不自动调用模型、接受结果或选择新参考。历史M1134可供后续复用评估参考，选择M2669或镜头用途仍是独立决定。

预期减少重复审阅、误认待办和不清楚许可范围导致的返工，让用户能够沿已有判断继续工作。本轮没有测量决策耗时或准确率，不承诺改善百分比。

## 实施过程与过程验收

先实际完成“找到M1134→阅读生成时自检→判断是否已有人工认可→查其依据→决定当前是否还需审阅”的工作，再从实体入口重复同一目的，对照两入口的能力和理解成本。随后在隔离环境实践整体实体认可、单版方案认可及各自取消，核对当时真实范围和下一步，不把按钮成功变色作为目标已经完成。

据此提出最小改动，利用已有判断和控件制作候选。实际从已有结论继续作决定、保存、换入口、换版本、回看理由并返回，确认保存后能在当前阅读上下文看到准确结果、不会叠开相同详情，关闭重开仍能找到该决定。观察用户是否能分清原自检与后来判断、整体与单项许可、未生成与已有结果。若仍需靠猜测或离开对象查日志，继续调整；若新增表达没有帮助当前决定，删除或收敛，而非再加说明层级。

过程验收关注候选是否用于真实端到端工作，哪些观察改变了呈现或操作，以及正式发布后同路径能否继续完成。保留必要判断依据和范围变更记录，不给每个字段制造过程记录，不把最后补录的截图、测试清单或一次性渲染结果等同于实践反馈。本任务的素材质量仍由对应人工审阅决定，不通过测试替代。

## 验收标准

1. **已有准确判断可见且不改历史。** 从实体管理和素材管理两条实际页面路径打开M1134，能够理解生成时未听审自检与后来用户认可分别是什么，并查到认可的准确原件、范围和理由。原件、自检文字、CALL和既有判断内容保持不变；不得显示M2669已被认可或已采用。再覆盖一个有历史判断的图像原件、无判断原件与有修改意见的样例。
2. **版本与判断适用关系明确。** 覆盖当前原件、同素材旧版、另一个候选、后来取消/相反判断及多条判断。旧结论不串到新修订或另一候选；历史仍可查，存在冲突时不假定用户已消解。130项仅用于确定性投影覆盖检查，必须按执行时数据重新统计并说明口径，不当作人工内容认可清单。
3. **整体与单项许可可以理解。** 在隔离候选核对实体整体决定的准确范围，与一份素材方案的单版采纳对照；界面能让用户知道当前动作覆盖什么、已认可什么及何时仍需完善或重新认可。不要求重复走两条替代许可路径；独立取消的范围正确，保留准确并发校验与历史追溯。
4. **下一步与真实状态一致。** 采纳方案但没有结果时继续显示未生成；结果判断不自动建立新需求采用关系。参考未选、原件不可用、方案或状态换版等真实阻断仍阻止输出可执行包或新的真实提交，并让用户能找到要处理的对象。已有可用数据不被泛化“待完善”遮蔽，未知事实不自动补齐。本任务不发外部AI请求，不检验或声称音色质量通过。
5. **两入口完成同一判断路径。** 在隔离环境从两种入口对准确原件记录已有支持的审阅结论，空字段验证保持正确；保存后原位回显准确决定，不重复提交或叠开同一详情。关闭重开、切换入口、刷新、回看历史均能找到同一准确决定及理由。切换候选/版本或快速连续操作时不串对象，草稿保留；未保存内容不成为判断。只对目标实际支持的动作提供入口，不扩大发布、采纳或生成权限。
6. **交付和证据明确。** 完成相关准确投影、判断适用与并发保护的必要自动检查，隔离真实浏览器验收，按受管多仓流程集成、按序发布并正式只读回查。分别报告API契约、页面理解与未评估的素材质量；完成本任务过程资源清理。

## 仓库职责与任务协作

通用判断投影、准确范围阅读、已有结论与控件交互属于 `../story-review-desk`；故事项目负责实例版本、准确系统提交及发布，不重写作品、旧认可或原件历史。沿一个主任务纳管附属仓，以实际启动时最新主干和正式数据核验。

上游任务01对应 `task-20261009-0002`，已完成准确对象投影与按需求来源归组并正式交付；本任务负责用户在找到准确内容后理解已有判断并作当前决定。同素材两入口能力一致性复用其共用卡成果及已有验收，不重做来源组织。上游任务04对应 `task-20261009-0005`，旧音色候选评估可以消费准确已有判断，但其候选匹配、质量评估和新用途选择仍独立；两任务可并行准备，不因读取同一原件建立阻塞依赖。

已按澄清时最新账本及既有规划去重：`task-20261009-0003` 负责镜头动作与发声，`task-20261009-0004` 负责生成模式及输入契约，`task-20261009-0006` 负责评论润色参考，`task-20261009-0007` 负责检索导航，`task-20261009-0008` 负责状态素材必要性与准备。既有素材卡优化规划保留底层审阅、采纳及历史契约，本任务补全当前对象的已有判断可读性、范围理解与保存后继续工作，不重做卡片来源组织、音色复用评估或其他任务范围；无强制同项目 task-id 前置。

允许在两仓各自的受管 worktree、独立测试数据库、缓存、写入目录和端口中并行开发验证，浏览器控制窗口协调使用。判断投影、共用卡、准备许可和导航刷新与其他任务可能有局部代码交叠，集成时吸收最新主干、解决实际冲突，并联合复验准确版本、草稿、范围与受影响页面。共享正式数据库、配置、服务、部署入口、正式镜像标签及发布写入须互斥串行；资源无法隔离或实质语义冲突不能独立收敛时，停止对应并行部分重新评估。开发可并行不授权并发正式发布。

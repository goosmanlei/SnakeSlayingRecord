## 精修六的逐段审阅与历史程序

这个程序模拟一位首次接触正文的普通中文读者：从第一自然段开始，随着阅读积累理解，检查逻辑完整性与通俗易懂性，并把明确问题挂到精修六原文。它不改小说，不代替用户接受作品。

用户确认使用独立模型 API，并区分正常悬念与明确阅读障碍。2026-09-28 为降低费用，用户将原先“保留全部已读原文”改为每约 10–20 段总结一次，目标为预计剩余消耗降至原方案的十分之一以下。当前批次 `refinement-06-cold-reader` 从第 314 段起采用每 20 段汇总、累计摘要不超过 1,200 字符的模式；前 313 段真实请求与记忆保留。目标为 `refinement-06-lantern-home-v6`，十五章、1,032 个正文自然段，章名仅在进入对应章节时出现。完成正文后另有一次文末清理请求。

## 怎样保证首次阅读

工具位于 [scripts/reader_review.py](../scripts/reader_review.py)，只使用 Python 标准库。程序的数据读取器负责锁定正式源、切段和定位，模型只收到显式构造的请求。

- 第一请求只有通用审阅要求、书名、当前章名、第一自然段和空的读者记忆。
- 当前请求携带“此前累计摘要＋本组最多 19 个已读自然段＋当前唯一新段＋问题记录”。每完成 20 段，独立模型仅对已读内容更新摘要，随后清空本组原文窗口。摘要整理不算新读段落，也不提前开放下一段。未来章名、目录、正文、总段数、来源说明和项目路径不提供给模型。
- 模型请求不继承 Codex 会话或记忆，不提供文件、搜索、浏览器和其他工具，也不调用审阅台的 AI 润色接口。该接口会读取整稿及其他版本，不适合首次阅读。
- 人物和事件只能依据已开放正文判断；模型原有的原典知识不能用来补足本文事实。人物相信的事、正文事实与读者推测分开记录，均关联已读段落。
- 采用 Responses API、`store:false` 和显式上下文，不传 `previous_response_id` 或外部会话。默认 `gpt-5.6-sol / medium`，凭据只从 `OPENAI_API_KEY` 读取，不写日志或数据库。

首次切换的摘要只取前 313 段的读者笔记；后续摘要只取上一份摘要、本组已读正文和逐段笔记，不读取项目说明或作者会话。人物关系、关键因果、当前空间与物件状态优先保留；问题 ID、精确引文、状态与最新说明单独传递，不随摘要丢弃。完整历史留在本机，模型后续请求不再携带全部事实笔记。

摘要会省略细节，因此不能把摘要未提及当作正文未交代；审阅规则明确禁止这种判断。隔离保证针对程序提供的上下文，不声称消除了通用模型的预训练知识。审阅判断仍须有本文原文依据。

从第 454 段起增加原文核对：按当前问题检索至多 6 段、1,200 字符的较早已读原文，作为有限回看。准备发布或补充评论时，再用候选意见涉及的段号和文字检索至多 12 段、3,000 字符，由独立模型核对后才提交。检索范围始终不超过当前已读位置，不读取后文；不是把全文重新放回请求。检索不保证找齐全部相关证据，证据不足不能断言正文缺失。

该机制源自本轮实际发现的摘要误记：摘要把“跪牛石东边”压成“东墙”，读者随后提出方位冲突。第 454 段回看后已撤回这一判断，原评论保留初读历史并追加解释。原始审阅输出、核对请求和采用结果均单独保存；核对发现错误时更新读者笔记，之后的摘要吸收纠正。

## 每一步如何推进

按顺序执行：开放一个自然段 → 调用模型 → 保存真实响应 → 校验结构与引用 → 原子保存读者记忆及待发布评论 → 发布并回读评论 → 完成本段。

只有本段完成才能开放下一段。多个段落不并行审阅，也不先读完全文再补逐段日志。每步记录完整请求、哈希、尝试时间、响应、读者理解和前后记忆；这些记录保存在本机 `.runtime/reader-review/<run>/work.sqlite3`，不公开导出。冻结源与段落映射也在该库内，供确定性的切分和引用核验使用。

模型的输出包括本段理解、必要记忆更新、问题变化和文末总结。正常段落允许没有问题。程序校验所有原文引用和证据段号；不接受指向尚未开放正文的引用，也不靠猜测定位重复语句。

## 疑问与正式评论

可能在后文解释、尚不影响当前理解的问题先记为 `WATCH`，只留本机。明确的因果矛盾或理解障碍记为 `COMMENT`，直接通过既有 `POST /api/comments` 接口发布。读到后文后，可以把原问题记为已解释或撤回；已发布的评论追加后续阅读说明，保留首次记录，不自动关闭评论。

每个问题有稳定 ID，评论绑定精确对象修订、正文块和 Unicode 字符范围。同一问题继续使用原记录。评论正文说明阅读位置、当时理解、具体障碍及需要补清之处；不把作者设定补进读者视角。

文末请求在全部正文读完后执行，对剩余疑问分别作出解释、撤回或转为正式评论的判断，汇总初读困难与最终仍成立的问题。不以“所有疑问都消失”作为通过标准。

## 新运行的方法来源

新初始化的运行从所连接审阅实例冻结五种工作模式的方法包，每个实际请求记录准确阅读输入与方法；历史运行继续原 instructions、源范围、摘要和回看策略，不以当前方法常量替换。方法缺失时先修复配置，不回退自由 Prompt。接入边界与独立恢复验证见 [受管方法](../production/managed-methods.md#评论润色与独立读者)。下述精修六命令是历史运行恢复示例，不授权重新付费审阅。

## 使用与恢复

从故事项目根目录运行：

```bash
# 只在建立全新批次时运行一次。已有批次不可重新初始化。
python3 scripts/reader_review.py --run refinement-06-cold-reader init

# 从上次检查点继续，包括补发已经保存的评论。
python3 scripts/reader_review.py --run refinement-06-cold-reader run

python3 scripts/reader_review.py --run refinement-06-cold-reader status
python3 scripts/reader_review.py --run refinement-06-cold-reader verify

# 额度等问题导致下一段请求失败时，只核验已完成的阅读范围；保留失败请求。
python3 scripts/reader_review.py --run refinement-06-cold-reader verify --completed-only
```

`run --limit 3` 只执行三步后正常退出，保留同一读者记忆，下一次 `run` 继续。文件锁阻止同一批次启动两个读取进程。

`switch-summary --interval 20 --max-chars 1200 --reason '用户调整上下文策略的原话或概述'` 仅用于用户明确要求更改策略且进程已停止时。当前批次已经执行，不要重复切换。它记录策略变更与尚未得到响应的旧请求；旧尝试完整保留，新请求仍审阅同一个待读段落。摘要本身的请求、响应、用量与检查点也持久化，恢复时复用有效摘要，不重复付费生成。

当前批次已启用 `enable-grounding` 原文核对，不必再次执行。它要求停在段落检查点，不能更改正在处理的请求。普通恢复只用同一批次 `run`。

模型请求或临时网络错误最多重试三次；无效引用不发布。API 明确返回余额耗尽或额度不足时立即停止，记录服务端错误类型与原因，不进行无效重试。失败后停在当前段，不自动跳段。已经保存的有效模型响应会复用；评论写入成功但回执丢失时，按稳定评论 ID 回读，避免重复创建。正文或修订变化时停止；用户编辑过的评论不得自动覆盖。

每章完成及退出时，通过运行中容器的既有 CLI 导出正式数据。导出失败会标记 `STOPPED` 并报告原因，不把任务宣称为完成。状态、最近导出和可读报告分别为工作目录下的 `progress.json`、`export-last.json` 和 `report.md`。API 实际用量记录在 `status`，包含重试响应；请求在服务端完成但本机未收到响应时，其用量可能不在本机统计中。

## 验收与职责

自动测试入口：`PYTHONPATH=. python3 -m unittest discover -s tests -v`。测试覆盖后文隔离、旧模式原文保留、摘要间隔与长度、切换前后记忆和疑问保留、摘要恢复与篡改检测、正常悬念与文末遗漏、Unicode 引用、评论幂等、正文漂移和用户并发编辑。真实 HTTP 集成测试自动使用同级审阅台源码建立临时实例；找不到源码时明确跳过，不把跳过视为验收通过。

`verify` 从空记忆重放已保存的步骤，逐项核对实际请求、响应、记忆与时间顺序，检查评论文字确实来自对应模型响应，并回读正式评论和原有数据基线。部分阅读也可验证，但 `full_reading_complete` 只有全部 1,032 段及文末步骤都完成时才为真。最后一段请求失败、尚无有效响应时，可加 `--completed-only` 核验此前已完成范围；它明确报告待处理步骤，不删除或伪造该步骤。该模式不跳过已得到响应但尚未发布的评论。应在步骤完成或进程停止后验证，避免与正在提交的检查点交错。

完成后还需在正式页面检查评论引用和定位，验证导出可恢复，并记录实际验证范围。真实 HTTP 写入、编辑、引用及导出恢复的工程测试只用隔离实例；正式精修六仅接收真实审阅意见。

程序与测试归故事项目；通用审阅台无须依赖该工具。审阅执行保持正文、旧评论和系统配置原状；公开提交与推送按用户另行授权执行。当前阅读进度与交付结论见 `STATE.md`，验收证据见 `VERIFICATION.md`。

# 从素材意见返回准确原件组成与圈选范围

本任务让用户从一条素材意见回到当时实际审阅的文件和位置，继续核对或讨论，不必先记住应手动切换哪一个试听文件。本文是完整、独立可执行的任务规格，保留已观察事实、目标范围、真实工作步骤和五项验收。历史观察用于执行时复核，不代表最新版本仍有同一问题；执行以最新主干和有效正式数据为准，不依赖系统 Review 临时实例。

## 已证实的工作断点

上游 Review 主会话在观察时正式版本的隔离实例 3303，用 Chrome 完成 M1206“三道滩·阿蘅省段清唱”的实际流程：切到 WAV 原件，选 1–2 秒，填写明确标注的功能测试意见，再切到 MP3 预览后提交。评论 C282 于 2026-10-09 05:42:39 UTC 保存成功。只读回查证明它仍准确绑定 WAV 原件、原件文件哈希与 1–2 秒区间，没有因为提交前切换预览而写错对象。

随后在 MP3 预览上点击该评论“定位原圈选”，经过充分等待仍停在预览，播放器为 0 秒，没有出现 1–2 秒选段，也没有解释定位失败。手动切回 WAV 原件，再点同一评论，立即到 1 秒并显示 1–2 秒范围。原件可播放、评论锚点有效，缺口是定位没有主动恢复评论所属组成。这里“组成”指同一素材中保存的原件、试听预览等文件，不是另一个生成候选。

播放预览后手动切原件会停止旧播放器并从 0 开始，是已经正常的行为。此次内容只验证功能，不代表音质判断、作品认可或正式采用。正式数据库没有这条测试评论。失败定位的页面证据为 `isolated-current-audio-comment-component.jpg`，手动切回原件后正常定位的反例为 `isolated-current-audio-comment-located.jpg`；两张截图均从主项目 `.runtime/system-review/evidence/` 取得，原件随任务输入纳管。后一张只能证明手动分支正常，不能作为修复成功证据。

## 目标与范围

复用已有素材卡、组成切换和评论定位，让“定位原圈选”一次回到准确素材修订、其真实文件组成及圈选位置。用户当前看的是原件还是预览，不应改变旧意见的归属；不能因两者时长相同就把原件意见投到预览，也不能把旧版本意见迁到最新版本。

优先修复共同定位流程中的最小缺口，保留用户当前阅读与编辑上下文。准确目标可用时切换到它并显示范围；确实缺失、锚点失效或无对应媒体时，沿现有方式解释原因，不静默无动作、不冒充成功、不自动替换成另一文件。异步载入、快速连续定位和关闭卡片后的迟到响应，不能把用户带回已经离开的对象。

同一准确素材从素材管理或实体/制作卡入口打开，应遵守相同定位语义。图像区域、视频时间和文字评论沿用既有能力，只对共享逻辑真正影响的分支作必要回归，不把本任务扩成新的评论面板、素材比较或播放编辑系统。本轮 Review 的真实数据没有两个候选的可用样例，不为验收制造业务候选；不增加外部 AI 调用或费用、不生成新素材或真实业务候选、不修改历史意见或真实采纳。最小可运行候选指系统改动候选，不是新生成的素材候选。

预期减少用户为核对一句意见而手动寻找文件、重复点击和判断是否失效的成本。上游 Review 只实际复现一条音频流程，没有统计全部素材的发生率，不把共享代码可能涉及的范围写成已发生数量。

## 实施过程与过程验收

按“理解真实工作 → 最小可运行系统候选 → 实践观察 → 按反馈调整 → 正式原路复验”的顺序推进；各步解决真实操作中暴露的问题，不能一次生成后补写过程。

先从执行时最新主干和有效正式数据建立隔离环境，亲自完成“播放/查看原件→圈选→填写意见→切预览→提交→从意见返回原圈选”的全过程。回读准确目标与文件，确认保存是否仍正确；再手动切回原件定位，保留正常分支作为对照。不能只调用定位函数或改页面状态来代替用户操作。

根据真实工作断点形成最小可运行的系统候选，再实际使用候选核对意见：切到另一组成后定位、关闭再开、从另一个已有入口打开同一素材并定位，核对是否确实落到可理解的内容与范围。观察自动切换是否打断未保存意见、遗留旧播放器或引入重复弹层；据观察修正，不靠增加一套技术状态标签解释失败。

随后检查共享定位的准确版本、图像区域或其他现有锚点分支。只使用实际可用素材；数据不足的分支明确说明，以必要的受控自动检查覆盖契约，不称为真实业务实践。按受管流程集成发布，在对应最新版本隔离环境复验写操作，在正式入口只读回查已有准确意见的可达性与定位。过程记录保留断点、使用反馈及因此作出的取舍，不补录过程、不把截图清单当作工作流程。

## 验收标准

1. **提交前切组成不会改写意见归属。** 重走 M1206 流程，WAV 原件 1–2 秒的草稿在切到 MP3 预览后提交，仍保存准确素材修订、`original` 组成、原文件哈希和 1–2 秒范围。切换后的界面不能暗示意见已改指预览；不修改现有历史锚点。
2. **从其他组成可以一次定位。** 当前停在 MP3 预览时，点击该原件意见的定位动作，实际切到对应 WAV 原件并显示 1–2 秒，播放位置为 1 秒；无需先手动切回，不要求自动播放。先前预览播放器不继续后台发声。同一组成内定位继续正常。
3. **重开与不同入口一致。** 关闭重开素材卡、从实体或制作中的现有素材入口打开同一对象后，仍能从这条意见回到准确组成和范围。必要的素材版本、候选身份、当前意见与阅读上下文保持，不重复打开弹层，不误改另一条意见或未保存草稿。
4. **准确失效和异步边界受保护。** 目标文件、组成、修订或锚点真正不可用时有可理解的结果，不把预览、当前最新版或其他候选当作替代。连续点不同意见、媒体载入较慢或关闭卡时，迟到响应不覆盖当前选择；失败后可以返回继续审阅。现有准确文本、图像区域和时间定位能力不回退；无法真实实践的分支说明限制。
5. **证据与交付可复查。** 对组成选择和准确文件/范围的契约补充必要自动检查，并完成上述浏览器完整流程。回执区分页面实践、数据库/源码证据与未验证范围；测试意见明确标记且只写隔离环境，不产生音质或采纳结论。按最新主干集成、按序发布，复验并清理任务过程资源。

本任务结束时，最终可见的会话回复开头须先给出 `task-20261009-0016` 和普通语言的问题说明（从素材意见定位时不能自动回到所属原件文件及圈选位置），随后说明本次实际解决的问题、实际变化与用户收益、真实验证及其边界，以及未解决事项和下一步，让用户在多终端执行时能快速判断方向。提交、测试数量和清理回执作为必要证据附后，不能用它们替代结果说明；不能将计划效果写成已经实现。暂停或失败时同样说明实际做到哪里及尚未完成什么。

## 任务安排、去重与并行

- 摘要：从素材意见一次回到准确原件与圈选位置，保留提交归属和连续审阅上下文。
- 优先级：P1。已存在可复现的核心意见核对断点，需要手动寻找原件才能继续审阅；保存归属已有正常反证，没有数据写错或运行事故证据，不按 P0 处理。
- 复杂度：复杂；模型 `gpt-6.1-sol`，推理强度 `xhigh`。需要统一准确修订、同素材文件选择、异步恢复和跨入口上下文，并完成双仓及真实页面验证；范围与事实已明确，使用复杂档默认较低强度。没有相对 xhigh/max 明确可验的自动委派收益，不选 ultra。
- 同项目 task-id 依赖：无，`dependencies=[]`。已核对最新任务账本和既有规划；本项围绕正确保存后返回准确原件与圈选的闭环，可基于执行时有效系统独立修正，不需要其他待办先完成。
- 可并行：是。两仓使用各自受管 worktree，测试数据库、缓存、文件写入目录、端口和浏览器测试存储隔离，并协调浏览器控制。共用卡片、评论定位与草稿保护的局部代码重叠在集成时吸收最新主干、解决冲突并联合复验；共享正式数据库、配置、服务、部署入口、正式镜像标签及发布写入须互斥串行。资源无法隔离或实质语义冲突不能独立收敛时，停止对应并行部分重新评估；开发并行不授权并发正式发布。

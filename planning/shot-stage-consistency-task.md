# 优化任务：消除镜头起点倒退与失效条件继承

本任务承接 task-20261009-0003 的有效成果，修复正式复验确认的镜头阶段一致性残留及其共同原因，保留正确动作与声音设计；不在已结项任务后补改交付，也不重做其全部目标。完整方法、范围、证据和七项验收以本规划为执行依据，任务状态只认主项目 `.codex-task/tasks.json`。根 Review 指上游持续系统审阅会话；本规划收敛其必要证据，本机 Review 文件不是产品运行依赖。

## 用户要完成的判断

制作者从准确剧情准备一个镜头时，应能确定：第一幅画面里人物在哪里、手里有什么、什么尚未发生；接着怎样连续行动；镜尾留下什么状态供下一镜承接。审阅者按相邻镜阅读时，应能看清这条变化，不必自行调和首帧、起止摘要、完整 Prompt 和场级条件之间的矛盾。

0003 已改善真实发声、准确原词、动作顺序和逐镜空间等内容，但部分镜头仍把较晚的动作阶段当起点，再把完整源段落中更早的动作写为接下来执行；部分人物位置、持物与地点条件也在失效后继续继承。必要的“不得抢先”“不改身份”约束不能抵消这种冲突。

确定这些制作判断后，还须把它们转成模型可以执行的表达。根已在当前正式 ASH001/002 以及同版隔离页面读到 Prompt 含“起点和逐镜身份仍须实际原件审阅，不承诺固定首帧”等制作者审查说明；它们与场面指令混在同一文本内。这不是已经发生的生成失败，而是提交表达尚未收敛。将此纳入本任务逐镜写作步骤，不再另设一个重复改写全剧 Prompt 的任务。

## 目标与范围

沿现行 17 集有效制作稿，按集、场、镜顺序复核这一共同原因：准确源事件及完整场境、镜头可见起点、连续动作、终点、首帧、视频表达和相邻镜承接相互一致；适用条件在地点、人物、持物或行为阶段变化时结束、调整或被准确覆盖。执行时以有效全剧范围为准，不固定镜数、段数或总时长。

保留当前正确的对白、演唱、哼唱、群声、画外声及其准确原词/未定原词区别，保留正确的动作和专业设计。修正范围由逐场判断决定，不默认重分镜、不机械删除源段、不自动拆成一动作一镜，也不为证明工作量重写没有问题的内容。若确有现行镜界无法兼容的情况，说明观看任务和必要代价后作最小合理调整，并同步相关方案及交接。

采用 `production/filmcraft/01-narrative.md`、`02-coverage.md`、`05-staging.md`、`09-performance.md`、`10-editing.md` 与 `production/seedance-video-handbook.md` 中适用原理。对连续动作镜头，起点应说明可见状态，不只用“得知”“紧张”或声音名称替代画面定位；动作因果须从该状态能够开始。有意黑场、声音先入或回忆等设计按其表达目的判断，不机械要求新增画面。专业方法不转为每镜新增字段或第二套手册。

预期让用户读一组相邻镜就能判断动作如何连续、哪些条件仍有效，降低自行拼时间线的理解成本，并减少后续生成中的重演、跳步和错置风险。当前没有真实费用或耗时对照，不承诺节约比例，不以删掉多少文字或新增多少版本衡量收益。

## 必须实际进行的工作过程

先在 E01 完成一段从阅读到方案再到实际页面连读的完整循环，吸收发现后再推进。下面的内容判断、Prompt 编写与实际检查是在每场工作中衔接进行的步骤，不是先对全剧批量产出，再集中补读手册、补写理由或做末尾检查。

1. **先核有效基线，再建立一段可检查的判断。** 读取当前输入锁、已交付的视听稿和相关专业章节，核对并发任务的现行成果。先从 E01 短场按准确剧情、集场意图和前后镜理解人物目标、知情与道具变化，再形成该段起点、动作、落点和适用条件的判断；保留正确内容，不先批量改写全剧再补过程说明。
2. **按集推进，逐场解决真实矛盾。** 每场先通读完整源境，确定本场让观众明白什么，再逐镜核起始画面、连续动作和结束条件。区分本镜必须执行的动作、此前已经完成的事实、当前仍有效的背景以及仅供追溯的来源。把本集判断用于后续集；遇到新类型或相反证据，回查受影响前集。每集结束连读场镜，核人物选择、主题表达、信息揭示与跨镜状态，而非只核字段。
3. **先作制作决定，再写 Prompt 和编制。** 对需改镜头先读手册并选择适用方法/模板，核准确目的及起点—变化—落点、当前输入所提供的信息，再写模型友好的连续表达，最后与首帧、相邻镜和引用自检。不同地点、离场、换手、遮挡及有意时间跳跃按实际设计处理。脚本只汇编已明确的决定、辅助检查准确引用和确定规则，不能自行推断全剧后以通过检查代替语义审阅。
4. **用最小实际样例验证，再扩展。** 在隔离候选中实际连续使用镜头、准确故事依据、首帧及视频方案入口；确认用户能据文本判断真实动作阶段，并用下述反例检查是否修过头。样例成立后继续当前全剧同原因复核，必要时调整方法，不以一套统一删词/继承规则替代逐场判断。
5. **留下必要决定，保持过程可复核。** 沿既有制作稿、复核说明及任务回执记录关键的保留、修正、仍待确定事项和依据，说明一处认识怎样用于后续或触发回查即可。记录应来自实际先做的步骤，不补造先后、修改次数或“已逐镜确认”的泛化声明；不要求每镜长日志、新审核平台或机械表格。

第3步还须区分供制作者审查的依据与实际提交模型的表达：先说清本镜观众应看到、听到的变化，再将已确定的设计写成自然明确的动作、声音、参考职责和必要约束。准备状态、人工审查待办和证据定位沿既有方案、追溯及就绪说明承载，不能为了自我验收而写进模型指令。保留有生成价值的说话人、原词、先后或同时关系、不要朗读叙述等约束；标签和分段本身不是问题。不得用全局删前缀、统一改词或一次性全剧改写替代每场的制作判断。例如 ASH206 母亲原话与书吏读回是两次真实发声，不按文本去重合并；ASH221 门边咳声的声源有意未明，不为补齐角色字段强认人物或新增音色。

## 验收标准

1. **四个正式问题有完整闭环。** 对 ASH025/026、ASH059→060、ASH062 的准确源文、镜头目的、首帧、视频和旁镜逐项回读：第一动作可以从起始画面连续发生，镜尾可承接下一镜；已离场的人和物、别处的空间关系不再作为本镜指令。报告实际选择及原因，不仅提供字符串 diff。正文中的必要动作、发声和人物决定没有因修复被漏掉。
2. **当前全剧完成同原因语义复核。** 按现行各集逐场说明保留、修正及待准备判断，覆盖跨地点、人物进出、持物交接、动作阶段和共性条件变化。重要结论可沿准确版本及相邻镜复查。源段覆盖一次、字段非空、文件摘要匹配或程序全绿不能代替此项；不从四例通过推称全剧通过。
3. **反例证明没有机械化修正。** 至少回查以下不同情况并保留合理设计：同一空间仍适用的方向/光色无需删除；E04 病房床位在真实病房仍可用；未入首帧但稍后入场的人不被强塞进开场，画外发声者不因需要声音而强加入画；E06 明确回忆可有意改变时空，不能因前后不连续自动消除；同一物件交接与有意义的停顿、重复尝试按人物目的处理，不能为文字去重压掉行为变化。需要补足现有数据未覆盖的规则边界时，用明确标注的隔离夹具，不能修改正式剧情制造反例。
4. **正确声音与既有专业成果不回退。** ASH001–003 的唱句/接唱/尾腔、ASH032–034 的两次试唱与病情揭示，以及一个叙述式发声样例继续按准确身份、原词、顺序和停止条件成立。未确定的说唱词句保持真实待准备，不随意补词；不恢复整场动态污染，不把旁白或提及人物变成实际出场。原本无需变化的准确对象不制造无效修订。
5. **实际候选及正式 UI 验收。** 在隔离候选按场连续读镜头，打开准确来源、首帧和完整视频方案，再返回比较旁镜；覆盖四例、另一集的反例及一个历史版本。确认当前方案表达清楚，历史版本仍是原准确内容，引用和评论不会被迁给新头。涉及持久审阅操作只在隔离实例实测。完成既有增量发布后，从正式原入口再走同样的关键路径；API、导出、截图或代码检查不能替代实际浏览器操作。根 Review 回收时另作只读抽核，不把执行者自述等同于根复验。
6. **提交表达、可重现编制与边界诚实。** 以 ASH001/002 和本任务调整镜头核对最终 `generation.prompt` 与生成准备包使用的同一文字；沿准确版本核对 `package()` 原样返回 Prompt、`write_package()` 写入清单和 `validate_call()` 要求新 call 与包文字准确一致，该链路检查不等于提交真实调用：提交文本是确定的场面、动作和声音指令，不夹带仅对制作者有效的审核待办；参考分工、身份、准确原词、先后或同时关系及必要禁止项保留。“不添加对白”结合本镜已有对白明确为不新增锁定原句以外的台词，不能抹掉0003恢复的发声。缺词、原件未选或未认可时仍由原有闸门阻止假就绪，不绕过采纳生成准备包；未满足准备条件时沿准确方案和相同汇编路径检查。必要自动回归防止已明确的起点/条件决定在重新编制后丢失，同时保留准确输入、来源变化校验和声音处理。重复编制不制造无效版本。不能用自动标识“自洽”宣称专业表演已成立；无实际生成或播放，就只验方案一致性，实际时长、动作重量、口型和音质保持待验证。
7. **交付保全与清理完成。** 通过受管工作区以执行时最新主干准备候选，按准确修订和共享写入窗口增量发布；保留原件、真实调用、采用、评论和版本历史，不用快照覆盖正式库，也不自动授予新方案认可。全程不调用图像、音频、视频生成、不新增费用。完成必要过程资源清理，说明实际删除范围、回读结果和保留用途。

本任务结束、暂停或失败时，最终可见的会话回复须以任务编号和普通语言说明的原问题开头，再依次说明实际变化与用户收益、真实验证环境和边界、未解决事项与下一步，让用户在多终端执行时能快速判断实际进展。用具体例子讲清“原有现象→预期行为→实际变化→验证路径”，不能用“事件正确”等抽象结论代替。提交、测试数量和清理证据作为必要依据附后，不能替代结果说明；不能将计划效果写成已经实现，暂停或失败也须说明实际做到哪里及尚未完成什么。

例如，ASH026 原方案首帧已持歌本，视频却要求随后取歌本：结果摘要须说明实际怎样统一持本起点与取本动作，使后续行为能连续发生，以及实际在哪个环境沿 ASH024→026 连读、打开准确来源及 M3049/M3050 核对。尚未修正或尚未走通的验证路径须明确列为未完成；仅检查方案一致性时，不声称实际表演、时长、口型或音质已经成立。

## 与并行任务的接口

- task-20261009-0003 的有效动作/声音成果是应保留的输入；本任务只修本轮确认的阶段一致性及其共同原因，不重启或回写已完成任务。
- task-20261009-0004 负责生成模式、准确输入角色和准备契约。本任务给出准确镜头阶段与需要保持的信息，消费其最新有效契约，不重做选模、附件角色或渠道能力。相关方案同时变化时按准确版本协调集成，并复验受影响镜头。
- task-20261009-0008（Review 第 07 项）负责状态准备必要性与差异传递；本任务使用有效状态事实，不新增成套状态图、不重做全量素材需求。
- task-20261009-0013（Review 第 12 项）负责连续阅读的表达与交互；本任务负责内容本身一致，不能靠隐藏条件消除冲突，也不借机重做全界面。task-20261009-0010（Review 第 09 项）的准确文字制作交接继续独立。

## 目标、范围与保护条件

沿用既有实体整体采纳、取消采纳、统一卡与实体管理列表，使服务端确认的决定在当前仍有效的列表中准确反映。关卡本身不取消已经提交的决定；成功消息只说明实际保存结果，不能成为列表长期不一致的替代。

原详情关闭、切换或失效后，不再重开或重绘旧卡。与此同时，仍有效的外层列表应按当前筛选读回准确状态；如果用户切到其他卡、改变搜索/采纳筛选或转到别的页面，旧结果不能恢复原筛选、抢焦点、改写另一对象、挤掉草稿或覆盖新的决定。再次主动打开同一实体时，读取其当前准确决定，保留当前所选版本、候选和阅读位置的已有能力。

范围限于实体整体决定保存与其相关索引、详情、返回行为，包括采纳与取消的共同响应路径。执行时核对代码共享影响，只回归确实受影响的分支；不扩成所有业务写入统一同步、全站状态管理重构、轮询平台或新审批流程。不改决定范围、判断优先规则、单版方案与整体许可的独立性，不自动采纳、不生成素材或调用外部 AI，不新增收费。

失败或结果未知不能按成功刷新认可状态，不盲目补写或自动重试。成功写入而重新读取失败时，应沿既有反馈让用户知道保存与当前显示的区别，并保留可核对路径；不以乐观改一个数字替代准确业务投影。不强制用户等待关卡，也不为绕开缺口禁止正常关闭。

预期用户可以在保存后直接按列表继续筛选和审阅，减少手动刷新与重复核对。当前没有总体发生率和节约时间测量，不承诺比例，也不把功能测试当作作品认可。

## 验收标准

1. **立即关卡后无需手动刷新。** 在最终候选隔离浏览器中，以 EN002 或执行时等价的真实实体，按单实体搜索完成“整体采纳→立即关卡”。服务端成功后，当前列表的小卡采纳状态、已采纳/未采纳数量及筛选结果自动一致；继续等待或主动重开不出现相互矛盾。每次用户提交各只写一次准确决定，刷新后与刷新前已同步的结果一致。采纳与取消均验证相同保证，等待按钮完成后关闭的正常对照继续通过；不以某一次请求恰好很快替代边界检查。
2. **另一卡与当前筛选不受旧结果污染。** 保存尚未返回时关闭原卡并打开另一实体，或修改搜索/采纳筛选，旧成功结果不得把另一卡变成原实体、迁移其草稿/判断、恢复旧搜索或把焦点带走。仍在当前有效列表中的准确对象和计数按当前条件更新；原对象已不符合“未采纳”等筛选时正常退出，不为保留旧卡强改筛选。页码按现有合法分页规则保留或收敛，不任意跳到第一页。晚到读取也不得盖过较新的读取或决定。
3. **详情与返回继续准确。** 留在原卡时按既有方式回显当前决定；关闭后不自动重新打开。用户主动再次打开同一实体时，看到准确当前决定与理由，历史仍能区分；已经选择的素材方案版本、候选、阅读位置和未保存意见不因列表同步而重置。离开实体管理后，旧请求不能改变新页面、URL 或审阅对象；返回时依据有效数据继续工作，不使用原页面快照冒充最新决定。
4. **失败与未知不伪装成功。** 明确失败、版本冲突和响应结果未知分别沿已有能力保护输入及准确版本，不能显示虚假的保存成功、直接标为已采纳或自动重发。保存成功但后续读取失败时，保留已保存事实与可核对入口，不能把读取失败说成决定回滚。原详情已离开时，不用旧详情错误抢占新卡或焦点；必要受控时序覆盖成功后早关卡、先切换再返回、读取失败与新旧响应逆序。
5. **以实际工作和准确交付验收。** 提供真实浏览器完整过程与正常对照，补足该共同逻辑的必要自动回归，分别说明 UI 观察、准确判断/版本回读、模拟时序及未验证范围。吸收执行时最新主干并复验实际重叠，受管双仓集成、按序正式切换；正式原入口只读核查既有状态与准确版本，最终版本隔离写验收与正式运行身份能对应。完成过程资源清理，回读准确 ID/路径并报告实际删除范围、数量、保留用途与解除条件。

每次完成、暂停或失败的最终可见会话回复，先写实际任务编号和普通语言的原问题，再说明本次实际改变、用户收益，并用具体例子讲清“原现象→预期行为→实际怎么验”；随后说明真实环境、UI 观察/准确判断与版本回读/受控模拟的证据边界、尚未完成事项和下一步。提交、测试数量和清理结果作为证据附后，不能替代实际解决了什么的说明，不能把规划预期写成已经实现。

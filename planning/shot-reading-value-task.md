# 优化任务：让相邻镜头的变化与制作判断易于连续阅读

本任务沿现有视听制作入口改进相邻镜头的连续阅读，让同一制作信息只读一次，同时保留独立差异、准确依据和历史评论定位。本文件是完整、独立可执行的任务规划；任务发布、执行与完成以主项目任务账本及实际回执为准，产品运行不依赖本机 Review 临时文件。

## 用户要完成的判断

创作审阅者按集、场连续阅读镜头，判断观众在每镜应注意什么、人物的行动和关系如何变化，以及上一镜怎样交到下一镜。此时需要迅速发现本镜的观看重点、动作/声音变化和关键约束，再按需追溯完整场级条件、准确剧情与历史意见。

当前界面把一个制作决定重复展示，并在连续镜头之间反复铺陈共同说明。用户既要逐段排除重复，又要从共性中找出真正变化，增加注意力与比较成本。目标是让同一信息只读一次、必要差异仍清楚，而不是减少专业判断或删除制作依据。

## 已证实的样例与范围

上游持续系统 Review 主会话已在正式 Chrome 实际打开 ASH001：“叙事目的”与“表演”同为“歌本在倒扣竹篮上压河石；老汉听歌点头”，“构图”与“机位运动”同为“街侧全景，缓慢靠近门口”。继续实际阅读第 2 集 AS006「退回那一份」六镜，并从 ASH033 打开完整准确 S004 正文，确认同类双读及六镜反复呈现场级共性，使两次试唱、得知病情、失单和退米的差别不易连续比较。

上游本轮只读数据核对时，344 个视听镜头全部存在 purpose=performance、framing=movement 的完全同文。前一对分别表示叙事目的与表演，后一对分别表示构图与机位运动；344 是当前字段范围，不是固定任务镜数，也不是 344 次浏览器失败实测。编制器把作者同一列赋给两字段，`review_desk/static/production-breakdown.js` 又分别按两标题渲染，形成确定的重复展示。

这些专业概念并非永远等同：目的回答让观众明白或注意什么，表演回答以什么行动和反应呈现；构图回答画框中的关系，运动回答视点怎样改变。既有一句话可以同时说明有关选择，无需为保留两个标签而再写一份近义文案。有真实独立内容时必须保留，不能按字段名或本轮统计一律删并。

## 目标与边界

沿现有视听制作入口改进连续阅读和相邻镜比较，优先显示当前镜头真正需要用户判断的信息；相同表达不重复占据阅读位置，全场共同条件保持清楚、可按需回查，本镜差异和关键约束不能被隐藏。

应用 `production/filmcraft/` 下的 `01-narrative.md`、`02-coverage.md`、`09-performance.md`、`10-editing.md` 中关于观看任务、可见证据和跨镜关系的原则，以及项目“每项信息帮助当前判断、如无必要勿增实体”的产品原则。专业概念提供判断标准，不转成每镜更多必填字段。

本任务的主要成果是表达与交互优化，不重写全剧视听设计，不重做剧情转译，不自动补造叙事目的，不改镜头拆分、时长或生成方案，也不默认新增栏目、比较页面、工作流系统或统一折叠所有条件，不新增状态标签层级。若样例暴露实质内容缺口，准确记录并与负责内容的任务衔接；不能用 UI 隐藏矛盾后宣称内容已正确。

完整底层字段、准确版本、来源、采用与评论历史保留。历史镜头查到的共同条件必须来自它所引用的准确场/集版本及相应覆盖值，不能从最新场头补入；新旧字段或历史格式不同，应沿已有兼容行为如实展示。减少前台重复不要求删除数据或批量重发镜头版本。

预期降低阅读相邻镜时的重复扫描、记忆与定位成本，使本镜变化及待检查点更容易发现。当前无实际耗时对照，不承诺节约百分比，不以标签数量、折叠数量或屏幕高度下降代替价值验收。

## 必须采用的实践过程

先完成实际用户从连续阅读到制作判断、追溯和返回的工作，再以最小可运行候选观察反馈并迭代；过程证据随实际工作形成，不能一次生成结果后补过程，不为符合流程而虚构修改次数。执行前读取 `production/filmcraft/README.md` 及上述相关章节；本任务不编写或修改镜头视频方案与 Prompt。

1. **从 E01 的真实短场建立基线。** 在执行时当前有效实例，按第一集 A01 的五镜顺序读准确剧情、集场意图和镜头方案，实际使用来源、素材、版本与意见入口。记录用户当下要判断什么、哪些重复没有新增信息、哪些共性仍需就近看见。保留已有正确设计，不能先全量套新模板再补理由。
2. **准备最小可运行样例。** 比较少量确有差别的表达办法，选择能让同一制作选择只读一次、必要上下文仍可得的一种，在隔离实例形成可运行样例。优先复用现有阅读、展开、导航和评论习惯，不为展示原理新增独立实体。实际连续使用样例，根据误读、遗漏、查找和返回成本调整。
3. **用 E02 反测，而不是只挑顺利样例。** 连读 AS006 六镜，重点核 ASH032 第一次试唱、ASH033 再试仍接不上、ASH034 得知病情与拼残纸，直到失单和退米。检查相同场景与部分相同动作下，关键差异能否读出；再反测具有独立目的/表演或构图/运动内容的准确版本与历史意见定位。必要时用明确标注的隔离夹具补足现有数据没有的边界，不改正式剧情来制造测试样本。
4. **按实际收益扩展并回查。** 样例成立后，扩展到当前有效的同类视听阅读入口和历史阅读路径，核相邻镜、跨场、版本切换及宽窄视口。将 E02 暴露的问题回查 E01，避免只让首个样例好看。记录关键选择、发现与修正即可，不强制逐字段长表或虚构修改次数。

## 验收标准

1. **连续判断比原路径更直接。** 从同一正式依据出发，实际使用 E01 五镜及 E02 六镜的候选页面，可一次读清每镜的主要变化与关键选择，辨认两次停唱为何不同、阿蘅怎样回避目光及李寄何时得知病情；不必反复读同文两次或靠另外重建表格完成判断。说明实际改善与仍需查阅的内容，不以主观“更简洁”一句验收。
2. **去重不丢差异。** 样例中目的/表演、构图/运动完全同文时不重复占位；两者确有不同内容时均能完整理解。共同条件、镜头覆盖和本镜例外可区分；一个值在前后镜改变时可发现，不因继承、折叠或同文归并而遗漏。信息精简不强制补写同义说明。
3. **准确依据与历史定位保持。** 从当前及历史镜头进入场级条件、准确故事依据和素材方案，读到正确的版本和完整必要内容；旧评论的文字锚点仍能定位原字段及准确修订，不能迁给另一字段或最新镜头。若显示合并影响锚点，沿现有准确定位能力处理并实测，不删除旧意见或伪造新归属。
4. **交互与意见实测。** 在隔离实例完成连续切镜、切场、切版本、展开来源、打开/返回素材及评论定位，保持阅读位置和当前上下文。涉及评论、草稿或其他持久动作只在隔离实例实测；覆盖宽窄视口，必要自动回归验证准确引用和独立/相同内容边界。截图、API 或代码通过不能替代实际操作。
5. **内容与任务边界清楚。** 本任务没有借机重写全剧、改动角色选择或生成要求；发现的实质内容问题明确归给对应任务。承接 task-20261009-0003 更新后的有效镜头条件，兼容它的准确来源与覆盖值；状态展示优化与已发布的 task-20261009-0008（本轮 07）协调，避免同一页面再次出现另一套解释；准确文字归 task-20261009-0010（本轮 09），起点/阶段/失效条件及提交表达残留归 Review 第 13 项，本任务不靠隐藏这些问题降低阅读量。
6. **正式交付与回收。** 按既有受管流程集成和增量发布后，从正式原入口只读回查 E01、E02、一个历史版本和既有评论定位，说明候选与正式验证分别完成什么。保留全部原件、采用、评论和修订历史；没有媒体生成，不声明画面、节奏或音质验收通过。完成必要过程资源清理，报告真实删除与保留用途。

根 Review 回收时还需亲自走完最短路径：视听制作→E01/A01 连读五镜→E02/AS006 连读六镜→ASH033 完整准确 S004 故事依据→返回 ASH033 并与 ASH032/034 旁镜比较→切到历史版本并定位既有意见。执行者同样须实际完成这条连续工作路径。重点核“重复是否真的减少、两次停唱差异是否仍清楚、完整条件及旧意见是否仍可得”。正式数据没有特定字段的历史意见时，针对该边界的隔离夹具实操与正式现状分别说明，不在正式库制造意见或把夹具算成真实历史。执行者报告不能替代根 Review 的这次实操；未抽核时明确记为待复验，不假称通过。

## 任务字段与并行判断

- 摘要：优化相邻镜头连续阅读，减少重复展示并保留制作差异、准确依据与历史评论定位。
- 优先级：P1。重复展示已影响正式视听审阅的逐镜判断和比较，属于当前制作工作的明确体验缺口。

- 同项目 task-id 依赖：空，无强制前置。相关任务提供有效成果或协调接口，不因同仓、同组件或共享发布环境而增加内容前置依赖；执行时重新核对最新账本与主干。
- 允许独立工作区并行：是。本任务负责视听阅读表达与交互，与已完成的 0003 动作声音、0004 模式输入契约，以及 0008 状态准备、0010 准确文字和 Review 第 13 项阶段残留的内容判断分工独立；可在双仓独立受管 worktree、隔离测试库、缓存、写入目录和端口并行开发验证，协调浏览器控制。同一阅读组件的实际重叠在集成时协调、吸收最新主干并联合复验；共享正式数据库、配置、服务、部署入口、正式镜像标签和发布写入互斥串行。资源不能隔离或语义冲突不能独立收敛时，停止对应并行部分并重新评估；并行属性不授权并发正式发布。

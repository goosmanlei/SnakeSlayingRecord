# 取消制作版本链：制作内容原地维护，每次生成候选保存准确方案快照

人审阅当前作品和已有结果，提供意见；AI 持续修改制作内容。制作域目前要求沿实体／状态、集场镜、素材方案等多层版本寻找相互匹配的内容，修改一个镜头还会向上推进场、集修订。用户已确定：故事至剧本保留现有版本；制作域只维护当前内容，把有价值的生成历史保存在实际产物候选上。本任务完成数据、创作工具、生成链路、界面及正式运行的一次统一调整，不止隐藏版本按钮。

改后例子：打开阿蘅实体状态及其素材需求，直接读当前状态和当前方案，已有结果以候选切换。AI 将当前 Prompt 从方案 A 改为 B 后，不需要创建“状态第3版／素材第2版”；候选1仍展示它生成时的 A。以 B 提交生成后，即使等待期间当前方案又改为 C，返回的候选2仍绑定 B。人只需理解“现在准备怎样做”和“这个结果当时怎样生成”。

## 确定的数据与工作方式

### 保持故事版本，取消制作业务版本

原始资料、方向、故事结构、小说、文字剧本及其分集／场正文沿现有版本和独立批注机制，本任务不重做作品、不调整其版本组织。

制作域的实体、实体状态、统一关系、视听集／场／镜、镜头关键状态、素材需求及其生成方案均使用稳定身份和一份可修改的当前内容。现存独立状态继续是不同对象，例如“劳作后未擦手”和“已擦净双手”不能因取消版本而合成同一状态。编号不复用；同一需求仍可关联多个实际使用位置。关系沿0018的一对对象一条关系，内容及发展阶段合并在当前描述中。

更新这些对象、参考选择、父子组成和关系内容时原地修改，不再创建业务版本、修订全文链、冻结后的下一版或逐级向上传播的集场镜版本；移除相应活跃存储、接口、索引、派生文件与恢复入口。必要的并发标记、内容摘要、幂等操作记录可保留，不能借“底层历史／归档／事件”名义继续保存每次完整制作稿。

制作依据继续准确指向所选文字剧本版本。当前输入锁／制作依据是当前配置，实际提交采用的剧本及方法依据进入该次生成快照，不再给人增加制作输入锁版本管理。SKILL／方法正文、方法绑定及已有执行快照、系统配置、Git 提交与必要发布回执不属于本次取消的业务版本，保持原有效职责。

同时适配新制作步骤的方法输入、产物登记和校验，不能在 `NOTE`／`method.artifact` 中换名永久保存每一次完整制作稿。新步骤保留所用方法、必要执行事实与结果指向；草稿过程需要的工作检查点限于工作区及实际恢复用途，结束后清理。已发生的真实方法执行事实不伪改，必要历史快照按实际追溯用途保留；不能借此继续复制后续所有制作稿和递归上游。真正提交生成时才固定该次候选所需的准确方案快照。

### 素材需求只有当前方案；候选承载生成历史

一项素材需求只保留一份当前要求和方案，包括模型、参数、Prompt、有序参考及必要规格。首次生成不冻结这个当前工作稿；继续改稿、换参数或参考仍修改同一需求。不能保留“永远叫版本1、底下仍不断追加完整版本”的实现。

一次实际生成对应一个候选，候选保存该次输出的全部真实组成以及提交时方案快照。相同参数再次真实生成是另一个候选；同次调用状态推进、补说明、重新回执、下载重试、同一结果的多文件组成都不增加候选。同一调用服务多个需求时保留实际归属与共享调用身份，不能重复计算费用或把结果扩给无依据的需求。已有上传原件、外部制作和可编辑工程继续保留其真实来源与组成，不虚构模型调用。

快照在请求对外提交之前固定并与唯一操作／调用身份绑定，包含：当时的需求目的和实际生成所需内容、真实模型及参数、完整 Prompt、实际有序参考输入、准确候选／组成／文件哈希及必要裁切／时间段、真正使用的文字／约束、准确故事和方法依据。保留真实请求、响应、费用和结果证据；记录中的实际值与提交时尚未知的值如实区分。关系约束按0018方法融入本次 Prompt，快照保存实际所用，不事后用当前关系补写。

在途请求不因当前方案变化而更换输入。回调、轮询、进程重启、重复响应和迟到结果均归回原提交；参数或参考改变后要新发请求，不能修改原调用冒充重试。无原件的失败／未知请求保留必要调用和恢复记录，不制造可比较的空候选；未知请求先查询，不重复付费提交。本任务用隔离模拟响应验证，不进行付费生成。

保留候选的旧参数和输入不依赖整棵旧实体／关系／集场镜修订树。实际使用的原件和必要内容快照必须可取；修改或删除当前上游对象不能篡改已生成候选。被保留候选实际依赖的文件不能当作无用过程文件删除。

可以将已有候选的完整方案复用为当前工作稿的起点，再继续修改。沿已有制作工具完成，不新增选材管理页面或 AI 自动选择策略，也不强制新增面向人的方案编辑器。复制前验证当前目标、实际引用和并发标记；缺失或过时输入明确指出，不能悄悄补成最新候选或直接触发生成。原候选不变。

### 界面只表达当前工作与实际候选

沿0015的大卡、0016的镜卡和0019的评论路径，在实体管理、视听制作、素材管理、故事关联制作入口使用同一规则：

- 实体／状态／关系／集场镜直接展示当前内容，不再有制作描述版本条、历史组成切换或旧版选择下拉。
- 每个素材入口提供“当前方案”和实际候选的清晰切换；当前方案直接显示必要生成信息与已有结果入口，无结果有占位。选中候选时，结果及其提交快照一起呈现，不能将结果搭配今天的 Prompt。
- 候选沿已有切换能力呈现，参考输入仍是必要的纯列表；参数和完整 Prompt 直接可读。不要折叠，不增加版本历史面板、关系用途长说明、流程套话或逐项审批。
- 切候选、返回当前方案、跨入口重开、刷新及浏览器返回后，所读结果、参数、参考和评论目标保持一致；保留阅读位置和各自草稿。浏览候选不改变生成所选输入。

参考生成时，依赖对象仍是素材需求；实际使用什么则落实为准确候选、组成和范围，进入提交快照。保留并适配现有底层存取、解析、选择与验证能力，不以取消素材方案版本为由退化成“总用最新文件”。新的选材界面和AI自动挑选策略另行讨论。

### 评论留住原意见，不要求留整稿历史

承接0019现有评论和回应：对当前制作内容发出的意见保存当时必要原文摘录、对象身份和局部位置；对候选的意见固定候选及实际文字、原件区域／时间。正文后来原地修改，原话、作者、时间、原摘录及实际回应不能改变。

整改回应保留实际修改说明及必要局部前后片段，可回查原意见与当时整改事实，并从同一入口打开当前对象。当前内容后来又变更时不伪称它仍等于当时整改；原摘录已不能准确定位则明确提示并直接给原摘录，不误高亮相似文字、跳到最新候选或伪造旧整稿。技术实现复用评论体系，不新建历史生产版本实体、审阅决定或第二份评论状态。

- 上游制作对象只保留当前有效内容和真实归属；所有旧制作修订全文、旧方案版本／轮次及专属关系索引都按目标退出。旧候选从准确历史请求和原件提取自身快照，先验证迁移后仍可读，再清除不再需要的上游旧正文与专属数据。

- 保全已确认故事、小说、剧本、有效原件、真实调用证据、候选准确输入、原评论和回应、方法执行、费用及必要发布／恢复记录。迁移不能改写过去实际请求来符合新模型，也不能将整份旧生产树换名存进导出／恢复包。仅为迁移回退保留的本机备份须注明恢复用途及解除条件，不作为常规业务版本使用。

必要范围涉及故事仓的编制／生成／发布和恢复工具、适用方法／说明及有效数据，审阅台的存储、API／CLI、生成及参考消费、评论锚点、共用卡、导航和导出恢复。不预先安排全剧重做，不改正确的创作表达，不重做媒体。修正文档和方法里“制作改稿必须新建版本”的现行指导；方法自身按其原规则更新版本，不改过去执行快照。

## 真实工作与验收

1. **打开与修改当前内容。** 在最新准确隔离实例沿实体EN002／ST088及其需求、视听AS001／ASH001、独立素材和剧本关联制作入口实操；AI路径修改状态、镜头目的、关系和需求方案，刷新／返回看见当前内容，无制作版本控件或父级版本增长。不同剧情状态仍能独立选择；故事结构十、小说精修九及剧本四的旧稿和独立评论保持。
2. **候选始终对应提交内容。** 以隔离可控调用完成“A提交→当前改B→A返回”，实际查看结果、Prompt、参数和参考均为A；再以相同B两次生成模拟输出，获得两个候选。回调重放、下载重试、同次多文件不增候选；失败无原件不增候选；未知调用恢复不重复提交。选中历史候选后切当前方案、刷新、跨入口和迟到加载不串线。样例是预期模型说明，产品必须完成真实API、持久化和浏览器验证。
3. **历史原件与引用准确。** 实查 asset-aheng-song-01（同WAV曾有4条元数据修订）仅对应真实候选而非4次生成；阿蘅0–5.6秒和老汉2.7–7.08秒的参考范围按实际证据保留并在浏览器试听；核对真实图像参考裁切、M4081工程组成及无CALL历史分支。观看原图、操作播放器和阅读快照只证明各实际操作，不宣称生成音质／视频效果已提升。有效候选使用的原上游内容不依赖全历史树。
4. **原地修改后的反馈回查。** 对当前方案一段文字及一段候选音频保存意见；修改／删除当前原句后回查原意见与实际回应，摘录和原件范围不漂移，不把旧意见显示为今天方案意见。对回复后再次改稿、原目标已退役、相似文字和并行草稿作对照。复用候选方案到当前后原候选不变，失效输入与冲突拒绝不丢草稿。
5. **物理模型确实简化。** 覆盖全部当前生产类别和消费者；检查旧完整修订、方案版本、轮次与专属冗余数据已退出活库和常规恢复包，清理无保留用途的内容哈希节点，不能只删索引仍能从 `material_content` 还原旧树。通过实际制作方法的准备、草稿、Review、自检及完成路径连续修改至少三次，稳定身份不变，数据库、方法产物及导出不暗存三份完整生产稿；不绕过SKILL约束来制造通过。提供实际删除／迁移／保留范围与理由。没有新增付费调用，媒体原字节及实际请求证据保持；任务范围外故事／配置／方法／评论及并发新增有效数据不丢失。完整导出到新空实例并继续改稿、登记候选、评论、再次导出恢复通过；模拟中断、重复迁移、旧基线与并发冲突均正确处理。
6. **正式可用才结项。** `--auto` 执行包含双仓受管集成、必要推送、准确迁移发布本机正式库及服务，在 `http://127.0.0.1:3000/` 用Chrome只读重走当前内容、候选快照、故事版本和意见回查路径；准确提交、构建镜像、运行配置与实际数据相符。正式业务修改仅限本目标的已验证迁移，交互写入测试仍在隔离实例。源码合并、测试通过、执行者报告完成均不能代替正式发布和真实验收，根独立Review另行记账。浏览器受阻则明确正式验收未完成，不以健康检查结项。

# 故事与制作页面整体统一

本任务以用户最满意的“故事创作 → 故事采编”为视觉与阅读交互基准，统一故事结构、剧本创作、制作设定和全剧制作；让实体、素材在任何入口中采用相同的小卡、大卡、版本候选和评论交互。

本文完整保留用户原始十项说明、七项初轮澄清答复及本轮 ultra 规划选择，并将有效要求整理为可独立执行的正文。执行时先读正文，再逐项对照文末原始说明与验收表；任务账本中的目标摘要不能代替本文细则。同一事项按用户后续明确答复解释，其余原始要求继续有效，不因概括而省略。

“素材项”指一项持续制作需求；“方案版本”指该需求的制作方案版本；“同版候选”指同一方案版本下的不同制作结果；“文件组成”指一个结果包含的文件。内部修订用于准确追溯，不能把它与上述层次混用。具体数据契约承接前置任务，页面按用户理解表达这些区别。

## 基准与保护范围

- 采编页面的左侧大标题、多级目录、正文大标题与正文层次作为基准。执行开始先在真实页面记录这四处结构及滚动行为，供其他页面对照。正文大标题滑动到顶部后，后续阅读滚动发生在正文区，外层页面停止继续上移；左侧目录按采编现有规则独立滚动，切换内容保持上下文。不得为了统一风格改坏用户已认可的结构。
- 保留剧本创作现有版本、集、场的组织方式，只统一视觉、间距、选中态和阅读行为。
- 复用现有素材模型：一项素材需求 → 方案版本 → 同版候选 → 文件组成。方案版本、候选、对象内部修订各自有明确含义；不把候选或修订当作新素材计数。
- 现有正文、剧情依据、完整状态、关系、原件、真实调用、评论与锚点、采纳、明确采用和历史链接保留。采纳与镜头采用仍是不同动作；新增候选不自动改变采用。
- 共用界面归通用审阅台。故事实例仅维护任务说明、必要配置引用及验证证据，不把故事特有工具搬入系统。

## 故事创作与子页面导航（对应原始要求 1—4、9）

1. 故事结构的顶部版本选择、左侧目录沿用采编视觉语言。向下阅读时版本选择常驻可见；切换版本与目录不意外移动外层页面或丢失正在阅读的准确版本、位置和评论草稿。
2. 剧本创作保留满意的版本、集、场菜单结构，与采编统一字体、配色、边线、留白、选中态及标题层次。
3. 制作设定的制作拆解、实体管理、素材管理，以及全剧制作的各子页，复用故事创作三个子页的页签形式。页签准确标识所在页面；直接链接、刷新、前进／后退和切页保持主导航与子页选中态一致。

## 全系统共用卡片（对应原始要求 5）

### 素材小卡

用于列表与关联素材区。直接识别素材类型、媒体类型和制作状态；已有真实图片的素材展示图片，其他媒体展示对应媒体识别元素，尚未生成展示对应占位。不伪造音频或视频封面、制作结果或就绪状态。

一项素材按持续制作需求计数。同需求的多个方案版本、候选和文件不重复增加素材数量；无需求关联的历史原件独立保留，可准确进入原卡片。

### 实体小卡

用于实体列表。显示实体类型与各媒体类型的素材数量，不将素材版本／候选数量当作素材数量。先分类再列卡；在保证右侧正文可读的前提下，左侧有足够宽度时使用两列。

### 实体／素材共用大卡

页面正文与弹窗必须复用同一个卡片和交互：

- 左侧：实体基础信息、关系、完整状态；完整状态下列出素材小卡。点击素材小卡切换右侧详情。直接挂在剧、集、场、镜的素材在左侧展示相应归属信息，不虚构实体。
- 右侧：当前选中素材的信息与生成信息；已有原件在顶部展示图像、音频、视频等对应媒体。可切换素材版本，以及同版本的不同候选和必要文件组成；展示内容、真实调用、准确输入及评论目标随所选结果一致变化。
- 支持素材 ID 直接打开，并还原对应实体或制作位置；支持实体 ID 直接打开，默认选择基础状态的整体图像素材，打开当前方案版本；优先该版本已有明确采用的候选，否则最新候选，没有图像再选其他媒体。当前版本未生成时显示未生成，不自动跳至旧版本。历史准确链接不被默认选择覆盖，其他版本的已采用结果仍保留可追溯入口。
- 可评论信息继续作为可评论区域，使用现有圈选、图像区域、音视频时间范围和共用评论面板；所有意见仍绑定实际展示的准确修订和原件。
- 弹窗关闭、Esc、返回、切换素材／版本／候选保持外层阅读位置、焦点和未提交草稿；停止已关闭弹窗媒体。页面正文嵌入模式与弹窗模式不能维护两套不同内容或评论能力。

## 制作设定

### 制作拆解（对应原始要求 6）

- 顶部横向选集借鉴剧本创作的集导航；左侧仅列当前集的场，选择一场后展示该场的镜头列表，顶部展示必要场地和场次信息。
- 当前场用一张大页面卡包裹全部镜头。场卡留出可点击边缘，可选择整场；镜卡可选中单镜。选择反馈、素材联动与评论圈选不冲突。
- 按镜头先分行，再在每一镜内左右排列正文和素材。正文展示镜头设计；素材侧展示该镜关联的素材小卡，明确区隔不同镜头归属。整场逐镜左右内容始终显示，选中场／镜突出对应范围，不以选中动作隐藏其他镜行；剧／集／场共用素材在素材列顶部按归属分组，各集中显示一次，镜级素材展示在对应镜行。
- 素材区顶部提供所有镜头共用的剧／集／场／镜筛选，允许多选，默认全选，默认展示该镜对应的所有关联素材。各素材准确标识直接挂载或适用位置；只筛选勾选层级，不把其他镜头的素材混入，也不从全剧共用推定每镜实际使用。
- 素材小卡点击后，在当前页弹窗打开共用大卡。删除“全剧共用”“本集共用”“全剧风格参考”等被层级筛选替代的按钮，保留其有效数据与可追溯引用。

### 实体管理（对应原始要求 7）

右侧直接嵌入共用大卡，展示及交互与弹窗相同。左侧按类型分类后列实体小卡，右侧可读宽度优先，空间充足时两列。顶部保留平铺筛选与计数，增加“全部／已采纳／未采纳”的采纳状态筛选；按当前有效内容的采纳状态判断，不把失效历史采纳算作当前已采纳。采纳、取消、再次采纳的既有循环保留。

### 素材管理（对应原始要求 8）

筛选区复用实体管理相同样式，所有筛选项平铺，展示各选项数量。计数使用素材项口径，在计算某维度数量时保留其他组合筛选；零结果不错误移除已有类别。左侧按分类列素材小卡，右侧嵌入共用大卡；列表与详情布局、选中、空结果、弹窗及返回行为与实体管理一致。

## 全剧制作 → 镜头制作（对应原始要求 10）

顶部集导航、左侧场导航和逐镜左右布局复用制作拆解，子页页签复用故事创作。核心围绕镜头视频生成：

- 正文展示该镜视频生成提示词，上方列准确参考输入。提示词中的对应参考标记可点击查看准确输入；可点击元素不能改变圈选文本或评论字符偏移。提示词区域可评论。
- 右侧素材区只展示视频类素材；镜头生成视频、场级合成视频、集级合成视频均属于素材，分别挂在对应镜、场、集。共用层级筛选、素材小卡、大卡、版本和候选机制。
- 本任务只重构审阅页面，不增加页面提交视频生成或生成进度操作；生成继续由 Codex 通过后台执行。
- 未生成显示现有方案与真实缺项；已有结果展示所选候选的真实生成内容。不从当前方案回填历史真实调用，不将计划写成已生成。

## Ultra 执行规划

### 预期收益与判断依据

本任务的优先收益是更完整地实现用户意图，并发现跨页重构引入的评论和历史兼容问题。独立需求审查者直接从原始说明与有效答复出发，可以检查实施者的理解是否遗漏布局、默认选择和操作细节；兼容性审查者集中检查版本候选、评论锚点、旧链接和切换竞态，提供与实现者不同的检验视角。

本轮只读核对发现，通用系统已分别设置故事结构、剧本、制作拆解、素材卡片及评论基础组件等文件，导航子任务存在可独立推进的范围；制作页面同时依赖共享选择状态、候选和评论上下文，共用样式也影响多个入口。因此先统一接口，再委派边界明确的实现；共享部分由主代理负责。可核对入口以系统仓库的 `review_desk/static/` 为基准：`structure.js`、`screenplay.js`、`production-breakdown.js`、`material-review.js`、`review-ui.js` 与 `production.js`。这些位置只用于分工判断，执行时须按最新源码复核。

相对原定 max 的单主代理安排，预计可增加独立需求核对与专项审查的覆盖，并让部分导航实现、调查和审查并行。总体耗时仍受共用接口、真实浏览器与最终集成限制。委派会增加上下文传递、沟通、合并和复核成本；没有本任务对照实测，不把预期收益写成已实现提升，也不以任务规模或耗时本身证明 ultra 更好。

### 分工及修改边界

采用一个协调任务，由主代理按阶段启用最多三个职责明确的子代理；并发数量服从执行环境实际可用能力，无独立工作时不保持空转。

| 职责 | 工作范围与交付 | 协调边界 |
|---|---|---|
| 主代理 | 确定视觉基准、共用卡片接口、选择与评论上下文；负责共用卡片、制作页面核心行为、候选整合、缺陷收敛和最终交付。 | 共用状态、评论接口和全局样式指定主代理为负责人；正式资源操作统一由主代理协调。 |
| 导航实现代理 | 在接口与样式约定后实现故事结构、剧本的目录、标题、版本常驻和滚动；交付限定范围的修改及验证。 | 优先在明确归属的文件或独立系统 worktree 中写入；涉及共用样式、入口和状态的修改先交主代理协调，不各自建立第二套规则。 |
| 需求审查代理 | 先阅读原始十项说明、初轮答复和最新选择，独立形成核对意见，再检查实施方案与候选；逐项复核需求对应结果和页面证据。 | 以原始意图及有效澄清为依据，不只复述实施者的总结；提交可定位的遗漏或偏差，修复由主代理协调。 |

任务分派时记录输入依据、负责范围、输出及完成条件。代理间可以交换必要发现，但最终需求解释、共用接口和缺陷处理由主代理统一收敛。遇到共享文件反复冲突、接口频繁变化或等待成本明显增加时，缩小委派范围或收回主代理处理，并在交付中简述原因。

### 推进顺序与共享资源

1. **建立基准与约定。** 执行入口同步前置成果，核对系统和实例版本；主代理记录真实采编页面的视觉与滚动基准，确定卡片与评论接口。导航代理调查局部实现；两名审查者分别准备需求核对和兼容性检查，调查可以并行。
2. **实施与分项检查。** 共用约定明确后，主代理推进卡片和制作页面，导航代理推进约定范围的页面。审查者可以检查已稳定部分，不将未整合分支的结果当作全局通过。
3. **整合与独立复核。** 在隔离候选中统一运行全部改动，按原有 36 项检查逐项验证；需求审查者核对原文覆盖，兼容性审查者复核关键共享行为。主代理处理问题，审查者对已修复问题复验。
4. **形成交付候选。** 汇总实际改动、逐项证据及 ultra 的实际贡献和成本；达到完成标准后展示双仓候选与正式应用方案，获得最终确认再按既有流程交付。

所有开发及测试都在任务隔离范围内。并发写代码按实际文件与模块归属隔离，测试数据库和临时实例各自明确归属；不得将独立 worktree 当作共享数据库已隔离。真实浏览器操作由主代理安排明确窗口，同一浏览器控制目标同一时刻只由一个执行者操作；独立审查者可在安排的窗口复核页面，其他代理同时进行只读代码或证据检查。正式数据库、正式导出、3000 服务、部署、双仓集成和推送串行。

### 收益验收办法

在现有交付及验收记录中列出实际委派的职责、交付和主代理处理结果，记录独立审查发现且核实有效的遗漏或缺陷、修复及复验。审查未发现问题时如实记录，不设最低缺陷数量。简要记录实际发生的协调等待、冲突和返工；耗时或用量仅在可取得时记录，缺失时明确未知。

最终说明哪些独立工作帮助补齐了要求、发现了问题或完成了可并行部分，以及协调成本是否抵消收益。没有 max 对照运行时，只报告本次可观察贡献，不给出固定速度或质量提升比例。独立代理结论仍需页面或数据证据支撑，不能代替真实浏览器验收及用户视觉接受。

## 验收

1. 真实浏览器逐页比较采编基准与结构、剧本、制作设定三页和全剧制作：页签、标题、菜单、选中态、常驻版本、内层滚动和窄屏可用。
2. 大卡覆盖实体 ID、素材 ID、无实体的剧／集／场／镜归属、基础状态、其他完整状态、未生成、真实图像／声音／视频、多个版本、同版多候选和文件组成；正文与弹窗显示及操作一致。
3. 核对两种小卡数量口径、筛选选项计数、组合筛选、清除和空结果；采纳状态筛选能反映采纳、取消与内容修订后的状态。

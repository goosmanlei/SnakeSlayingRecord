# 历史原件与唯一出处的边界核对

2026-10-12。本次只读同目录 `cycle-06-reference-home-audit.md`、`cycle-06-historical-reference-ui.md`、`cycle-06-lantern-feedback-reference.md`、`cycle-06-systemic-scope-critique.md`，没有重新查库、看图、请求远端或修改任务。已有判断实质充分，没有新增问题类别；以下三点是后续定义必须守住的产品边界建议。

## 1. 唯一当前归属与准确历史出处不能混成“每个旧原件都必须有活跃需求”

对仍用于当前制作的候选，唯一需求归属必须完整。M1133已经是M2544候选1，应让人找到这一个归属。对明确退役但因真实输入或意见而保留的原件，应能解释原来的制作出处、当时如何使用、为何退出当前制作；不能为填满当前归属强行登记候选。使用既有提交、退役／删除回执及作品对象即可，不新增历史实体或历史需求树。

正例：M1469保留可看的原件，原提交曾对应M917，可沿现有记录说明它与EN079阿蘅家的历史制作关系及退役原因。M917只剩删除回执，不等于要复活为现行需求；ST187是否仍有制作职责也应独立判断。反例：把含母亲的病中居家图自动塞入M2589无人空间母版，虽得到一个编号归属，却改变了用途和退役决定。

更严格的未知边界是三段旧歌曲输入：M1202、M1203、M1386的提交没有保存需求，已有证据只能定位到EN046作品及真实旧录音／片段。不能补称它们来自今天的M1195，更不能因为“必须唯一”便新建一个需求。应明确“原提交未记录需求”，保留能够确认的作品出处。**若把目标逐字解释为所有旧输入必须绑定一个现行需求，将与这些已确认事实冲突；应把验收写成当前候选唯一归属、历史原件准确可追溯，不承诺不存在的历史事实。**

## 2. 当前引用显示需求和准确候选，历史事实仍固定在当时原件

这项确有通用展示缺口，已不限于旧迁移内容。旧灯隔离实践按现行方法和选择契约，将M2857的图片1落实为M2609候选1、original全幅；系统校验了需求、候选、原件与关系的对应，但页面仍只显示旧M1135。正确呈现应让人直接辨认“M2609／候选1”并抵达同一候选；M1135作为准确原件身份继续承接原文件、原意见和历史输入，不再被当作另一份需求。

当前计划可因新选择而原地更新；已冻结候选的输入对象、准确修订、组件、裁剪／时间范围和提交校验和不能随展示归并重写。例：M2544候选2实际使用候选1，应该能循引用查看候选1并回到候选2；不能改为M2544当前方案，也不能因两端归并到同一需求就报自循环。尚未做执行依赖环分析，现有“36次当前方案引用自身旧候选”的数量不能证明全部依赖有效或全部有环。

已有素材选择校验拒绝漏填 `material_selection` 的草稿，是保护准确对应的正常机制，不应为简化输入而绕过。未选定与显式未启用参考也不是损坏引用，不能为消除提示默认挑一个候选或伪装就绪。

## 3. 可定位缺失记录，不等于恢复了输入原件

M2736候选1的M1558应呈现可确认的名称、历史出处与不可用原因，不能只留“输入3”，但也不能跳到现洞闸候选冒充当年输入。准确缺失提示与候选自身仍可阅读可以同时成立；历史不完整不要求撤下有效输出，也不能把旧调用改成使用一张相似图。

审计中的26条是准确引用链缺组件；其中23个准确文件在已核对正式目录、清单和冻结原路径不存在，不等于所有备份或远端都不存在，也没有证明是哪次任务删除。另3个远端来源在15秒预算内未取得可核验响应，HTTP、内容和物理状态仍未知，不能写成404或永久丢失。五个有原件的明确退役输入须与这26条分开。

恢复只有取得原始证据并验证准确对应才成立；某URL后来能下载、某图看起来相似或某当前母版用途接近，都不够。即使无法恢复，系统仍应保留准确缺口和已知出处，使人知道旧结果究竟基于什么、哪里无法再核验。恢复能力不足不能靠补一条假需求、伪造组件或改写旧快照通过验收；本轮也没有“所有历史原件都能完整恢复”的证据。

这三点共同服务已有的身份、发现与引用目标，不引出新的历史管理功能、原件重生成任务或本故事内容清理。本记录只有范围建议，实际媒体判断与页面效果仍以原记录中根会话已经完成的操作为限。

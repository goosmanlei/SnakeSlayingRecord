2026-10-12，只读调查。用户明确要求：一个素材需求有唯一出处，其他实体、状态、镜头使用它属于引用，不能变成多个归属。父会话负责 EN002 大卡、六状态及候选的真实浏览。本辅助读取当前源码、0008 回执、指定对象及四个正式只读 GET；没有修改任务、产品或业务数据，没有发布任务。

## 结论与用户能理解的终态

M2544 数据中只有一个直属出处 EN002。六状态中重复出现它，来自系统把“适用／被引用”并入“拥有的素材”投影，并非产生了七份需求。应保留一个当前需求、一份当前方案、两次真实生成候选；M2544 只列在 EN002 自身素材处，状态和镜头通过已有准确引用使用它，不在每个状态重列成自己的需求。

M1133 没有丢失，也不是新的游离需求。它是保留的真实图像 ASSET，当前准确归入 M2544 的候选 1；候选 2 当年确实使用了它。现有搜索只索引当前素材编号，输入卡仍显示旧原件编号，因此用户读到 M1133 却搜不到对应当前素材。需要贯通“历史输入原件 → 当前唯一素材 → 同一准确候选”的定位，不能把历史输入改成当前方案或另一张最新图片。

## M2544 为什么会在六状态同时出现

实际记录 `material-entity-a-heng-identity@01fc3a5d1f8050f5590ad0cca7e693f2ac0f0edc063d9eb1526c7fa214e6354f`：

- `scope` 唯一指向 EN002 `entity-a-heng@77ca680362056db37a7d222e83ecefba99466d62f7119b122f029d27560a88f9`。
- `states` 只含 ST088 日常青衣、ST089 连唱嗓哑、ST090 点名后形态、ST091 脱险泪痕，表示共用身份的适用状态；没有 ST092 湿袖或 ST093 湿鞋。
- `R-M2544→湿袖需求`（对象 `relation-45560c634eb07fa0f09e202f206f122a`）的 contexts 含 ST092；`R-M2544→湿鞋需求`（`relation-8fe1210591b704d3871e114d2ff4f3de`）的 contexts 含 ST093。正文说明身份母版约束同一主体，完整状态在本阶段内变化；这两条是引用关系，不是 M2544 转移出处。

正式 `GET /api/production/entity-review?entity_id=entity-a-heng` 已返回六状态均含 M2544 的 `state_material_ids`，与父会话现场吻合。主数据没有名为 owner 或 state_memberships 的独立字段；这里的“owner”是 `scope`，多状态成员由读模型生成。

源码链（以下路径相对 `../story-review-desk/`）：

1. `review_desk/semantic_consolidation.py:169` 起，归并保留源需求的 states/entities 和状态 scope，注释称这是共享适用性、不是另一个需求。该保留本身不要求界面多列为归属。
2. `review_desk/business_relations.py:137–150` 的 `material_bindings()` 将一条关系的**两端**素材都绑定到所有 contexts，未区分哪端拥有需求、哪端只是被用作输入。
3. `review_desk/ui_projection.py:25–60` 把 scope、states 与关系 contexts 都交给 `add_scope()`，同时累积 `state_ids` 和 `entity_ids`；后续按 canonical material ID 合并并集。直属出处与使用位置在这里混成同一种归属集合。
4. `review_desk/generation.py:265–273` 明称此集合为 ownership projection，按 state_ids 产出各状态 `state_material_ids`。`review_desk/static/entity-review.js:336–338` 的 `entityStateNeeds()` 据此列出“此状态的素材与生成方案”，再用于状态计数和小卡。所以湿袖／湿鞋对身份图的引用也变成了状态拥有的一项素材。

同一局部中还有可核的相邻对照：湿袖需求 `material-form-a-heng-wet-overall` 的 scope 是 ST092，湿鞋需求的 scope 是 ST093，声音身份 M2669 的 scope 是 EN002；这些可以继续是各自的唯一出处。M2725《三道滩·阿蘅省段清唱》的 scope 则是歌曲状态 `form-boat-song-short`，却进入 EN002 的 requirements 集合，这说明跨实体的使用位置也会被混作归属；不能仅特判 M2544 的六行。

0008 的 [交付说明](../../production/entity-consolidation/README.md) 明确将实体及状态必要素材按并集统计，记录阿蘅“实体自身3项、六状态3/3/2/3/2/2项”，并写“同一需求可同时属于人物与歌曲”。其任务正文原来允许跨实体／状态／镜头的真实消费位置出现同一需求。因此这是已经交付的投影取舍与用户现在明确的“唯一出处、使用不等于归属”要求不一致，不能误写成数据库仍有七份 M2544，也不宜仅修显示数量掩盖模型含义。

## 后续彻底检查的最小全量范围

当前只读计数得到 1,291 个有效 REQUIREMENT：直属 scope 为实体163、状态86、镜头1042，三者相加等于1,291；没有缺失或其他种类的 scope。257 个保留真实候选全部恰有一个当前素材归属，257 个 ASSET 都仍有历史 M 编号。说明本次不能把“来源不唯一”直接解释为物理需求／候选重复，应核查唯一出处在读模型、计数、搜索与跳转中是否保持。

最小完整校验应覆盖现有全量当前需求及其真实引用，不扩到改写创作内容：

1. 对1,291个当前需求逐项核对 scope 的实际制作出处是否正确且唯一；对实体、状态和镜头页的“拥有素材”集合用同一规则验证。states、关系 contexts、镜头实际输入继续表达使用范围，但不得再变成另一个拥有者。不能只从某张关系图可见节点建立分母。
2. 按当前映射遍历所有适用关系和生成输入，验证引用仍可从使用处精确抵达唯一需求；图节点计数、状态行计数、小卡、素材管理互相一致。862 个需求的 states 含直属 scope 之外的状态，这是检查来源之一，**不是862个错误**，其中大量是镜头合法引用实体状态。
3. 对257个保留候选及冻结提交中的实际媒体输入，核对“历史原件身份／修订／组成 → 当前需求及准确候选”可解析；已退役无当前归属的原件明确显示历史或退役事实，不能补成假候选。搜索旧编号、历史输入点击、当前候选选择、关闭返回分别验证，不能以引用可读代替人可定位。
4. 少量真实跨页验收覆盖本例、一个独立状态需求、一个跨实体使用的歌曲素材、一个镜头直接需求，以及确已退役的历史引用；全量结构校验与这些实操证据分开说明。不得重新生成、复活旧需求、追加管理页面或为每个消费者复制素材。

本轮只形成调查依据与验收范围。仍在用户指定的发现期，不发布清查任务；后续任务要以最新数据重建分母，明确唯一出处与引用的产品规则，再实际修正、发布和独立回查。

## 父会话追加实操：同一素材按状态分裂阅读记忆

根已实读 EN002 的实体入口和六状态入口，并实际执行：ST093 选择 M2544／候选1 → ST092 选择 M2544／候选2 → 回 ST093，恢复候选1 → 回 ST092，恢复候选2。首次进入各入口默认当前方案。这里仅改变候选阅读目标，**不是正式采纳写入**，不能写成两状态分别采用不同图像。

直接实现是 `review_desk/static/entity-review.js:148–161`：`selectEntityReviewState()` 把 `selectedCandidates/selectedComponents/selectedMaterialRounds/roundDrafts` 整包保存在 `stateMaterialViews[previous.id]`，再按新状态修订恢复或清空；其中 M2544 虽然是同一 canonical material，候选阅读选择仍随状态分成多个副本。`:138–145` 的实体／状态页签也各自保存选中素材；`:129–136` 重载时保留这些状态记忆。原来这是帮助不同状态继续阅读的机制，但“共用引用被重列为各状态需求”使它放大成同一素材仿佛有多份当前工作的体验。最小修正需先恢复唯一出处，再使同一素材的工作区按准确素材／候选维护；不要为消除问题直接清空所有阅读位置、评论草稿或浏览器历史。确实不同对象的阅读位置仍可独立。

## 当前新增产品决定：状态也须按实际制作工作重判

父会话实读 ST089 和 ST091 的用途分别明确为“文字检查／不另做整体图”和“文字检查／不再生哭泣整体图”，它们的素材区却只有共用 M2544/M2669。用户明确唯一出处后，后续清查不能只把重复小卡去掉便默认所有旧状态都有必要，也不能因为没有独立图就未经阅读删除全部状态。

本轮应以用户的新决定为准：先判断该阶段是否有独立、必要的制作产物；确有才保留独立需求，并保持唯一出处。只承担表演或连续性检查的有效条件，应回到相应镜头／方案让创作者直接使用；不能为保留状态额外制造素材需求。若要撤下状态，先读其故事依据、当前消费者、上下游有效约束与历史事实，落实约束的新去处再处理，不能静默丢掉嗓哑、干湿或泪后阶段。

0008 原交付明确保留全部280个状态，并说明阿蘅六状态全部保留、差异在状态和镜内表演表达；它还允许消费位置多处列出同一需求。当前“唯一出处＋重判状态必要性”是对这套已交付安排的进一步明确取舍，不应伪称原任务曾逐项承诺删除 ST089/ST091。后续任务需显式承接这条新决定，按真实工作去理解和清理，而不是再次做编号归并、单纯改计数或换展示名称。

# 版本任务定义依据与验证边界

本记录用于确定任务目标，不代表新功能已实现。用户在本会话已确认的产品决定优先于旧实现和调查者原建议。

## 已确认决定

- 故事至文字剧本保留现有版本与独立批注；从视听制作开始，各制作对象、关系及素材需求只维护当前稿，原地修改。
- 一次实际生成形成一个候选；候选保存当次模型、参数、完整Prompt、准确参考输入等快照，当前素材需求不保留多版。
- 提交时先固定请求，返回结果绑定原提交；同参再生成是新候选，不能事后用当前稿补参数。
- 既有有效作品、原件、真实生成事实、原意见和回应保留；历史准确性由候选实际输入与评论原摘录承担，不保留所有上游旧正文。
- `--auto` 执行须完成集成、本机正式服务发布和真实验收，不能只交候选。当前会话仅定义、发布及回读，不执行产品目标；持续Review仍暂停。

## 当前事实及来源

本会话前一轮用正式 `.runtime/review.sqlite3` 的 SQLite mode=ro + BEGIN 一致读取盘点，没有初始化Store或写正式数据。随后0016已合入主干，但其验收及STATE仍明确正式未应用；0020正在部署，执行本任务须重新核对有效正式基线，不机械沿用这些数量。

| 已观察事实 | 对任务的意义 |
| --- | --- |
| REQUIREMENT 1,549对象、6,397条内部修订；素材方案表1,862条均业务编号1 | 内部修订不等于人的素材业务版，但都可能构成需要退出的历史全文链，不能仅去掉UI版号 |
| 17个视听集60次追加修订中59次只改scenes引用；65个视听场208次追加中127次只改shots引用 | 子项修改会传播父级修订，当前稿模型须贯通组成与消费者 |
| asset-aheng-song-01有4条元数据修订，实际WAV哈希一直为9edcf64a1d34914d1d406a01aff9617f3759eb51ed699e1380fde6f96993c953 | 不能迁成4次生成；不同真实调用即使文件同哈希也不能因此合并 |
| 328个CALL各有submitted与completed两条修订 | 是一次调用状态演进，不是两次作品生成；保留实际请求和结果事实即可 |
| ST088 v1→v2变化在choices及reference_mode，并非只有标题 | 可用于旧制作准备说明修改的实例，不能伪写“仅改标题” |

前一轮根实际在Chrome只读打开本机3000：实体EN002→ST088，从状态v2切v1，对应素材M2710切M1133；看到实体描述、状态描述、素材方案与候选分层切换。也读取小说精修稿列表及结构版本。只证明当时这些入口和版本层级存在；没有声称逐对象全部实操，也未将声音或作品质量作为本次版本调查结论。

## 当前代码与前置契约复核

本轮核验主仓c64579d6b083df835677fdeaad651049c09f492a、系统23defa1b4f8b2b07344d754c90effa0b83a1b38d；之后主仓b513490只加入自动任务完整交付规则。路径以下分属系统或主仓，执行时读取最新主干而非固定这些提交。

- 系统docs/material-versions.md：现行首次提交冻结方案，改定义新版本，候选编号属于版本；这正是本任务要替代的契约。
- 系统review_desk/store.py：通用生产写入追加revisions，评论外键和锚点绑定修订；需分别处理故事不可变稿和生产当前稿。
- 系统review_desk/shot_references.py inputs_for：读CALL还会回读旧REQUIREMENT补material_selection；候选快照需自足，不能继续依赖旧树。select以plan_number和旧修订保存并发及操作身份，需收敛为当前稿并发保护和最小幂等回执。
- 系统review_desk/generation.py：真实调用输入保持不变；新提交冻结与后续修改当前稿须解耦。
- 系统review_desk/business_codes.py和bundle.py：候选编号含旧素材版号，导出恢复依赖旧版本／成员表；须兼顾旧链接映射及新空实例继续工作。
- 系统review_desk/method_media.py inputs、review_desk/methods.py artifact：方法产物当前保存完整draft/result及上游内容；新制作路径必须适配，不能成为被取消版本的替代存储。
- 主仓scripts/material_review_release.py：现行保全默认历史不变，本次有意删除须用准确迁移允许清单，不能简单关闭全局保护。
- 0016保留的集场镜准确组成、0018的关系修订、0019的生产评论跳转准确新版本均由本任务后续替代；前三项原目标仍独立完成，不提前串改其产品范围。

## 边界

新任务不承接此前建议的小说版本谱系补充，不恢复撤销的0022/0023，不安排全剧重做。新模型的SQL、API、真实生成回调持久化、历史迁移、评论脱离旧修订、正式发布与恢复尚需执行任务验证。离线样例只证明提交快照与当前稿分开后，人可理解并操作候选回查，不证明这些系统能力已实现。

## 既有意图与缺失原因

以下源码定位均基于上述正式提交，可用 `git -C ../story-review-desk show ac735586575f3a0bdd319ae95d23acd188285117:<文件>` 回读；路径相对通用审阅台仓库。

1. `review_desk/static/unified-cards.js:50–69`：卡内点击关联素材，保存右侧阅读状态、更新所选素材并重新渲染；不重新读取整个卡片，也不更新左侧 `productionChildDetail`。因此 ST088 保留是当前机制的结果。`91–104` 行继续以同一实体工作区绘制左侧。
2. `review_desk/ui_projection.py:187–242` 与 `review_desk/static/unified-cards.js:165–174`：直接打开原件会重新解析准确需求来源、状态覆盖与主体，取得并选择该原件的准确来源状态。本例得到 ST089 历史版本 1。
3. `review_desk/static/unified-cards.js:71–89`：右侧已选原件正确切换，但关联用途继续使用初次打开卡片的 `reference_titles`。初始 M1134 卡的标题集合未包含 M1187 对应的两个准确旧状态标题；直接打开 M1187 时则包含。
4. `review_desk/static/material-review.js:440–445` 调用 `productionName` 显示关联用途；`review_desk/static/production.js:77–85` 按准确修订查中文标题，未命中时退回对象内部标识。因此并非 ST089、ST093 缺少中文名称或历史记录被删除，而是切换后所需准确标题未随之齐备。

旧任务确实要求“同来源需求共用左侧来源与需求列表；切换右侧准确需求、版本或候选时维持来源上下文”。这支持保持浏览位置的产品意图，但不能据此认定跨状态关联素材应该把 ST088 当作 M1187 的用途。是否自动切换左侧可由整体布局判断；必须达到的是当前原件的真实用途清楚、可读，且与保留的浏览上下文不混淆。

## 审查结果

| 风险点 | 核对依据与结论 |
| --- | --- |
| 响应丢失后将别人的采用误认为本次结果 | `readAttempt()` 从既有 API 读取当前关系头，要求对象 ID 相同、版本恰好为原 `expected_version + 1`、完整载荷相同，且同范围对象／槽位没有其他采用。比较规范化对象键顺序，保留数组顺序和全部值；没有只按素材名称、理由或部分字段判断成功 |
| 为恢复操作而偷偷提升并发版本 | 待确认请求保留原对象 ID、预期版本和完整发送载荷。回读当前头只用于分类，不用于更新 `expected_version`。并发修改后停止写入并提示核对；新建和换版均未引入覆盖接口 |
| 读取失败被当作“没有提交” | 关系头列表必须是数组。传输或响应结构错误保留原请求，不会根据读取失败自动创建新采用。已有采用对象消失也不会当作可重建对象 |
| 后台唯一性和历史保护 | 后端按范围对象 ID 与槽位阻止另一个采用对象，不因范围修订不同而绕过；更新仍受准确对象版本约束。接口返回的是当前关系头，不是历史混合集合。恢复路径没有写入新修订或删除旧采用的旁路 |
| 原请求已保存，但用户随后改了输入 | 再次点击先核实旧请求；旧请求已保存且表单已变时，保留新输入并说明它尚未提交，不把旧结果冒充新结果成功。若明确核实旧请求未保存，才允许当前新载荷按原预期版本提交 |
| 核实期间修改或离开 | 素材、版本、组成、理由、时段和裁切在提交／核实期间禁用，取消仍可用。每次异步返回均通过关闭状态、DOM 存活、工作区和阅读请求代次检查。关闭、移除或换页后的结果不会重试、刷新新页面或显示迟到错误 |

## 已独立核对的行为

| 行为 | 判断与依据 |
| --- | --- |
| A→B→A 的迟到结果 | `requestEpoch` 和当前 object_id 双重检查，不能仅因又回到 A 就接收第一份旧 A；响应落地也要求弹窗仍存在、workspace 和 reader epoch 未变 |
| 加载、失败、清空选择 | 先清 history／版本／组成，再发请求；空项不请求；加载或无有效组成时确认禁用。当前失败会提示，过期失败不会污染新选择 |
| 取消／离页／读者切换 | `closed`、DOM 连接状态和阅读 epoch 共同阻止已失效弹窗消费响应及提交；关闭后的保存响应不会刷新新弹窗 |
| 提交时准确身份 | 再检查素材 object_id、revision 和 component 成员关系；保存中阻止重复提交。既有 `productionButton` 捕捉并展示当前弹窗抛出的错误 |
| 保存被拒绝后重试 | 独立夹具让第一次 POST 拒绝、第二次成功：素材／版本／组成和确认按钮均恢复，理由保留，第二次载荷与第一次一致，只在第二次成功后刷新 |
| 关闭后迟到保存失败 | 独立测试补了现有用例未包含的失败分支：取消再开后，旧 POST 拒绝不会提示旧错误或刷新新框 |
| 空／错身份历史后恢复 | 独立测试对空 history 和 A 请求返回 B history 都禁止采用；重新选择并取得合法 A 后恢复 |
| 不完整裁切修正 | 独立测试只填一个裁切值时不发 POST、不锁死按钮；补齐后原有 `0.2–0.8` 秒时段与四个有效裁切值完整传出 |

有效裁切和时段的构造语义没有变化；后台 `validate_selection()` 仍校验组成的媒体类型、范围、实际时长与比例边界。没有把非法值吞掉后改为整段／整图采用，也没有把技术采用变成用户接受作品。

## 既有 P2：已落库但响应丢失的采用无法就地恢复

位置：`review_desk/static/production.js:441–442`，置信度 9/10，恢复体验问题。明确触发条件为：后台已经成功写入采用，响应未到达客户端，用户在原框再点确认。

```javascript
object_id: row.adoption?.object_id || 'adoption-' + crypto.randomUUID(),
expected_version: row.adoption?.version || 0
```

首次创建的重试会换 ID；后台以 `scope/slot already has an adoption; revise that object explicitly` 拒绝。即便沿用同 ID，原 `expected_version` 也已过期，返回 `object version or kind changed`。已有采用的换版同样需要先回读新头。一次性真实 `production.adopt()` 复核结果见 `independent-adoption/postcommit-retry-boundary.json`：两种重试均冲突，最终仍只有一个采用，准确 asset 和 `0.1–0.9` 秒范围完整保留。

该保护避免重复或覆盖采用，数据未损坏；当前补丁也没有恶化此路径。用户可以刷新看到已保存结果。因此它不阻断 AO-012 的选择错配修复，但应单独记录为待评估恢复改进。若后续处理，应在失败后回读准确采用头并与原请求快照比较，明确区分“本次其实已保存”和“已有另一采用／并发变化”；不要自动提高 expected_version 或替用户重作采用判断。仅复用 UUID 不足以解决后台版本冲突。

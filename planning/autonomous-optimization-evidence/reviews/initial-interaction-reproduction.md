## AO-010 的依据与必要边界

`app.js:11` 的草稿键包含修订、编辑 ID、锚点，不含素材身份／轮次。`:468–472` 让正文和“作为素材修订意见”选择共享此键。`material-review.js:100–108` 虽然按轮存了圈选与编辑状态，却没有独立保存草稿正文。

夹具并未伪造两轮同修订：由后台 `material_versions.feedback()` 开启新轮，沿用原方案。方案修订 `734aa063e8a4de74a37c29bcb035c26fdb75db0176773e3303bb7352bb58ad95` 同时属于第 1／2 轮。两轮同一全局锚点的键完全相同，返回旧轮实得“隔离新轮草稿 B”。

建议把素材身份和所选轮次纳入这类草稿的范围，保持其他页面既有键语义；取消／提交清理也只针对该范围。已有本机旧键必须有兼容处理，尤其同修订已跨多轮时不能猜测草稿原属哪轮并复制到多轮。新建评论与编辑既有评论的范围需分开核对；编辑同一个已保存评论不应被变成多份独立意见。

最小回归：两轮同修订同锚点分别输入 A／B，往返各保留；只取消一轮不清另一轮；修订／讨论选择不串轮；不同素材身份共享修订的情形也保持范围；普通资料、结构、剧本草稿继续可读。

## AO-011 的依据与必要边界

`app.js:506` 每次 `saveComment()` 都新建 UUID；`:517–518` 失败后保留草稿并允许重试。`store.py:510–522` 只对同一个评论 ID 的相同目标／锚点／正文做幂等回读。该后台能力已实测有效：重放第二次成功请求的相同 ID 后，普通评论数保持 2，没有产生第三条。

普通讨论两次真实创建 ID 为 `1f942cf5-78e0-4f0c-94e3-254343386c00` 和 `c43d9934-27b0-4853-a946-ee18a91857a8`，数据库中各有一个 CREATE。首次请求客户端未取得 HTTP 状态，但 `http-events.json` 记录后台已提交并准备返回 201，随后才主动断流。因此这不是“请求根本未到服务器”的模拟。

素材修订首次 ID `98632caa-7335-4e17-81a5-8fbcab8953e0` 已保存，归入第 2 轮 feedback；重试 ID `72bdc721-9d0d-4419-ab10-29533a67af04` 返回 `素材修订轮次已变化，请刷新后提交。`。事务回滚保证没有第二条评论，后台轮次保护应保留。

建议让同一次未确认成功的创建操作复用稳定 ID 与原始请求快照，利用已有幂等入口；成功或用户明确开始另一操作后再结束该待确认请求。不要按相似正文全局去重，用户可以在不同目标、轮次或时间独立表达相同意见。重试快照应涵盖目标修订、锚点、正文和素材范围／修订意图；后端当前幂等比较没有检查后两个字段，因此客户端不能把旧 ID 重新用于另一轮的同文评论。此处是修复边界，未将它另登记成新的现存 UI 缺陷。

最小回归：普通讨论和素材修订分别在 commit 后断流，再重试仅有一个评论／CREATE；修订仅推进一次并返回已保存结果；确实在 commit 前失败仍能重试；用户修改正文或切目标后不会收到另一操作的假成功；刷新恢复是否纳入稳定 ID 生命周期需明确。PATCH 编辑的乐观锁是另一条已存在路径，此次未声称它也会重复创建。

## AO-012 的依据与必要边界

`production.js:418` 的 `assets.onchange` 在 await 后直接替换共享 `history`、版本和组成；`:421` 从该 history 组装采用载荷，没有再检查当前素材选择与记录 object_id 一致。

复现返回顺序为 B (`voice-b`)→A (`voice`)。B 先返回时素材与版本正确；A 迟到后素材值仍为 `voice-b`，版本却变成 A 的 `589beef14a5333516e86eed2ed73b4c8fca2a07f7d7c9284e98e8ead0718461e`。两份原件哈希不同：A `0a8f76d8…`，B `412837ee…`，不是两个名称指向同一文件。后端接受该 A 载荷，最终采用修订 `854cd913f67b4f612102e8a4fdf059d227dccef614d64b939339154ff759eafb` 的准确 asset 引用也是 A。

建议在选择变化时立即清空从属版本／组成，加载期间阻止确认；用请求序号或等价方式忽略迟到结果，校验当前选中的素材与返回身份一致。确认前再检查素材、版本、组成属于同一条已载入记录。失败、清空选择、取消框后的迟到结果也应用同一规则。无需新增用户可见实体或第二套采用流程；后台应继续校验准确引用和业务兼容，不必为掩盖此客户端状态问题猜测用户意图。

最小回归：A 慢 B 快后只可提交 B；B 正在加载或加载失败时不可提交旧 A；回选空项不能残留可提交版本；取消再开不受旧请求影响；显式选旧版本、指定有效片段／裁切仍保留准确引用。真实页面复现及修复后验收沿 `coverage-gap-review.md` 第 3 组，由主协调执行。

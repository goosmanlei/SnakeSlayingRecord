# AO032／033 独立审查

复核最终冻结局部后未发现剩余阻断。配置保存不会用迟到返回重建正在编辑的表单；素材审阅在同一准确目标上保留未确认操作，断响应不会直接分配另一个 ID。独立发现的详情刷新失败静默问题已窄修并由原失败反例确认关闭。

审查者 history_audit 未实现这两项，也没有改产品、操作浏览器或共享实例。读取了真实函数、两个局部 diff、新测试及作者的真实 HTTP 记录；没有将函数夹具或 HTTP 当作页面验收。

## 独立发现及修复

**WC-01，P2：已经保存后，自己的详情读取失败被当成迟到请求忽略。** 原测试用替身 loadProductionWorkspace，只覆盖列表请求失败。实际 loadProductionWorkspace 成功读取列表后调用 openProductionRecord，后者自己递增 productionReadEpoch；准确详情请求失败时，审阅保存 catch 仍比较保存前 epoch，因而不提示列表／正文尚未更新。独立 probe.cjs 第 3 项接入真实 load、open 和素材上下文函数，已实际复现：只有“审阅已记录”，没有刷新失败提示，POST 仅 1 次。

作者获根授权后在 loadProductionWorkspace 的准确读开始处增加可选 onReadStart 回执，报告该 load 的工作区、load epoch 与实际领取的 read epoch；保存处理据此判断刷新是否仍属原操作。没有猜测 epoch+1，也没有取消新导航的所有权保护。原独立失败反例现通过。作者另用真实两层函数验证“新 openProductionRecord／新工作区接管后旧详情失败不干扰”，已通读；本审查没有再运行其整套检查。

## 已核对边界

AO032 每个配置分组保留自己的提交版本与完整值。输入框在提交期间继续可编辑；响应只更新本表单的版本基准与保存结果，不回填旧值，不替换其他分组。离开再返回新建的表单不会因旧请求成功而被擅自提高乐观版本；冲突时保留新输入。缓存分别按 scope 合并不倒退，图标元信息不会让落后的 SYSTEM 覆盖新缓存。

未知配置结果先回读，只有准确后继版本及完整 body 相等才确认；原版本和原 body 未变才允许原操作重试。独立增加两项反例：即使完整 body 相等，更高版本仍拒认；未知操作回读确认未写入后，用户明确新输入可在原版本发出新载荷。两项通过。确认旧操作不会吞掉之后的新文字。图标上传与配置保存共同锁住保存按钮，保留未保存的选择；现有不可用图标恢复语义未被覆盖。

AO033 打开表单即固定对象、准确修订、标题；在途锁字段及保存而保留取消。原样未知重试先按同 ID 回读，只认 JUDGMENT 第 1 个修订和完整载荷；不以更高版本或相反结论当成功，也不提高 expected_version。不同内容的输入不会被旧操作成功消费。取消、导航、另一准确评论焦点接管后不会重绘旧目标；真实保存成功可提示原目标名，旧失败保持安静。写入与后续读失败分开报告，已保存的旧表单不能再提交。

未确认操作仍局限在打开的表单内，没有承诺浏览器刷新后持久恢复。既有实体采纳与方向选择剩余反馈项不属于这批，不把它们写成已修。

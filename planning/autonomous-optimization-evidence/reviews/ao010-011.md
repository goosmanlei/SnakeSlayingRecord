# AO-010／AO-011 独立评论持久化审查

本审查核对素材轮次草稿与新建评论的重试身份，不包含本代理实现的 AO-012。当前结论：核心隔离与幂等方案有准确依据；独立审查发现的存储失败覆盖文字、卡片焦点与编辑器不同步、首次失败缺少未确认提示三项均已修复，并在冻结候选上重放对应反例通过。本次代码与函数审查未发现未解释的阻断问题；真实浏览器验收由根协调单独完成，本报告不代签页面结果。

## 范围与证据边界

只读审阅 `review_desk/static/app.js`、`material-review.js` 及本批新增评论测试，并追踪既有 `store.py:create_comment` 的返回次序。未修改实现、提交、浏览器或正式数据。本代理的补验执行实际前端函数及实际 `renderComments()`，使用最小 DOM 夹具；这不是实际浏览器验收。

实现者的 初始验证（本机原证据：comment-persistence-fix-evidence.json；按 source-index.json 查询是否收入）记录 33 项 Node 检查（12 项新增）、1 项真实 HTTP 集成检查，以及 18 项已有素材／结构／剧本契约检查。本审查读取测试代码和精确 HTTP 请求、数据库结果，未重复整套执行。HTTP 故障确实发生在服务端成功提交后、响应头到达前；重建 JavaScript 环境只保留持久存储，因而不是“发送前失败”或仅保留旧进程内变量的替代测试。

## 实质发现与处置

### CR-01：本机存储失败覆盖唯一新文字，P1，已修复

初始 `saveComment()` 先尝试保存当前草稿；写入失败时进入外层 catch 并执行 `renderComments()`。该渲染从旧持久值重建输入框，覆盖用户刚输入而尚未保存的新文字，且没有发出 HTTP。独立原反例（本机原证据：independent-comment-review/storage-probe.json；按 source-index.json 查询是否收入）记录了新文字变回 `older durable text`；初始实现者夹具将 `renderComments` 替换成计数器，未覆盖这条实际渲染路径。

首次修复候选 `app.js` SHA-256 为 `eca2b36f7f688aa152dd5c41d218e1ab5a3c8067f418eb63665522bc705abb48`：存储异常在发送前停止，明确提示尚未发送和复制留存，保留同一编辑器、文字和修订意图，最后解除提交锁。外层 catch 不再按旧存储重建编辑器。

本代理重放原反例，独立复验（本机原证据：independent-comment-review/storage-recheck.json；按 source-index.json 查询是否收入）确认新文字仍在输入框、旧持久值仍保留、HTTP 请求为 0。实现者另补 6 项实际渲染检查（本机原证据：comment-storage-failure-fix-evidence.json；按 source-index.json 查询是否收入），覆盖资料、结构和素材的正文／请求身份写入失败、意图选择及存储恢复后重试；已核对其断言。这里保留的是当前页面内的输入，不承诺浏览器关闭后仍能恢复尚未持久化的文字。

### CR-02：素材卡片焦点变化留下空锚点编辑器，P1，已修复

初审候选中的 `focusMaterialCommentCard()` 在切换素材卡片时清空 `state.anchor`、编辑身份和范围，但未同步重绘评论面板。`renderMaterialCard()` 把它绑到整张卡片的捕获阶段 `pointerdown`／`focusin`，因此点击另一卡片的标题或空白区即可触发，无需进入会调用 `focusProductionReview()` 的正文／媒体区。

独立反例（本机原证据：independent-comment-review/card-focus-probe.json；按 source-index.json 查询是否收入）执行实际卡片注册的捕获回调、实际编辑器输入与保存路径：锚点已经为 null，旧输入框却仍可见；继续输入写到 null 草稿键（真实 Web Storage 会转成字符串 `null`），点击提交则直接返回，HTTP 为 0。准确旧草稿键仍是点击前的旧文字。这会让用户以为正在编辑可提交的意见，实际新增文字没有准确保存位置。

修复只在素材卡片上下文确实变化时调用 `renderComments()`，立即移除已经失去锚点的编辑器，不删除旧草稿键。独立复验（本机原证据：independent-comment-review/card-focus-recheck.json；按 source-index.json 查询是否收入）重放原捕获回调：A 草稿保留，切换 B 后旧输入框消失；在 B 重新建立锚点后从空草稿开始，文字写入 B 的准确键；回到 A 可恢复原稿。同卡再点击保留原输入节点，没有产生 null 草稿键。实现者新增检查另覆盖捕获 `focusin` 的键盘路径，其代码与断言已核对；这些均是实际函数和最小 DOM 检查，标题／空白区域的真实手势由根协调验收。

### CR-03：首次网络失败后未确认提示未即时出现，P2，已修复

CR-01 删除 catch 中的整体重绘后，首次请求失败虽然已有 `:submission`，当前编辑器却不会显示“上次提交尚未确认，修改内容后会新建评论”的提示；手动刷新／其他重绘后才出现。独立检查（本机原证据：independent-comment-review/pending-notice-probe.json；按 source-index.json 查询是否收入）执行实际保存与渲染函数，确认失败当下提示为 0，显式重绘后为 1。

修复提取共同的提示函数，在初始渲染和已经发出新建请求的失败分支局部追加同一个 `role=status` 提示；不重建编辑器，不向另一草稿追加旧请求提示。发送前存储失败不进入该网络提示分支。独立复验（本机原证据：independent-comment-review/pending-notice-recheck.json；按 source-index.json 查询是否收入）确认第一次失败即时显示一条提示，原编辑器、输入节点和文字保持，第二次原样失败仍只有一条提示，两次请求 ID 相同。该提示表达提交结果未知，不声称失败请求一定已经落库。

## 已核对的正确边界

| 场景 | 核对结果 |
| --- | --- |
| 同修订跨轮次／跨素材卡片 | 新建评论的草稿键包含明确素材身份和轮次；已有评论编辑仍按评论 ID 使用原键。卡片身份来自实际点选，不把共享原件一律归到第一个需求；CR-02 已补齐卡片切换时编辑器的同步 |
| 旧无轮次草稿 | 仍保留旧键，不自动猜归属；只有存在旧文字时显示一次查看／复制入口，用户明确恢复后才迁移，不覆盖已存在的本轮非空草稿。目的写入失败时保留旧副本；不能据此称作所有浏览器存储异常均已覆盖 |
| 未确认的同一请求 | 持久保存 `{id,payload}` 后才发送；准确目标、正文、锚点、素材范围和修订意图完全相同时复用 ID。刷新后的新环境仍可读取同一身份 |
| 修改内容 | 正文、锚点、范围或意图改变会生成新操作 ID。没有以正文全局去重，也没有把两个合法独立意见合并。CR-03 已使首次失败后的当前编辑器及时解释这个边界 |
| 素材修订已推进后的原样重放 | 待确认记录保存旧 `expected_round`。既有后端先找到同 ID／目标／修订／锚点／正文的评论，再返回，不再次执行轮次推进。真实 HTTP 证据显示原轮评论只有一条 CREATE 事件、反馈只推进一次、轮次为 2／1，原意见仍属于第 1 轮 |
| 跨页迟到成功 | 清理前比较原提交身份、准确草稿键和正文；素材重载只作用于仍在同一编辑状态的页面。其他页或另一标签页的新草稿不被旧响应删除；全局评论刷新仍可能重新渲染当前页面，不应扩大成“所有跨页手势与焦点均已验收” |
| 历史与原件 | 真实 HTTP 夹具回读旧关闭评论、旧事件、不可变修订和 WAV 哈希保持；本批没有改变后端 API、数据库格式或实际用户接受语义 |

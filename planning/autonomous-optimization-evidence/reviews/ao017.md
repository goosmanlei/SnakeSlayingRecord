# AO017 评论历史定位独立审查

当前候选的主要修复逻辑可接受，未发现未解释的阻挡问题。独立审查发现的多素材范围问题与迟到错误提示，以及作者后续确认的真实卡片呈现缺口，均已局部修正并复验通过。这里审查定位、编辑意图与历史范围，不证明浏览器手势、滚动或真实保存已经通过；相关页面证据由根协调单独记录。

## 审查范围与依据

作者为 independent_review，本审查者没有参与实现。范围为 `app.js` 的 `startDraft`、`editComment` 和评论定位按钮，`material-review.js` 的素材范围选择与异步定位，`entity-review.js` 的共用轮次定位，以及 `tests/comment_location.test.cjs`。`app.js` 同时含 AO016，后者已在 `independent-structure-route-review.md` 单独审查。

核对了作者当前 29 项实际函数检查、7 个旧实现失败反例及先前相关检查日志，没有重复整套测试。独立增加的组合复验执行真实编辑、定位和打开函数，但使用轻量 DOM 与受控网络；没有浏览器、服务或数据库操作。产物在 `independent-ao017-followup/`。

## 已确认的行为

- 有明确素材范围的评论按原素材 ID、轮号和准确修订共同核对；非法轮号或轮次不含该修订时停止。无法区分多个合法范围时不猜归属。旧无范围评论继续按已有修订匹配显示，不补写历史范围。
- 历史 ASSET／CALL 加载完成前不开编辑器；响应必须仍属于本次操作、工作区和读取序号，且打开的是准确原件。取消只作废本次仍拥有的读取，不使更新的 B 导航失效。
- 新评论、新圈选、切轮或换卡使旧操作退出。自身定位成功后结束操作，再启动编辑器；不会因打开自己的编辑器而取消已成功的定位。
- 实体入口共用相同轮次核对；准确媒体组成、时段、历史目标及现有 API 写入方式没有在本批改写。

## 发现与处置

**AO017-IR01，P2，已修正。** 评论同时关联多个素材，用户已经明确选卡，随后定位旧 ASSET／CALL 需要加载新 detail；初次冻结实现要求当前卡仍指向新 detail 对象，导致原明确卡身份丢失，误报“关联多个素材”。原复现在 `multi-scope-reproduction.json`，没有发生错误写库。

窄修在等待前捕获本评论适用的明确素材 ID，等待后通过操作与读取序号检查，再在新 detail 中验证准确范围；旧卡消失时停止，用户已换卡时不恢复旧身份。独立 `recheck.cjs` 对 ASSET／CALL 各核对首卡 `need` 与另一明确卡，共 4 种组合全部通过：原评论编辑器打开、卡绑定更新为新 detail、准确轮 1、只有一次读取且没有错误提示。首卡用例覆盖材料页可见卡的身份，另一卡是逻辑兼容场景；这些结果不是多卡浏览器操作证明。

**AO017-IR02，P3，已修正。** 前一次窄修的异常提示仅检查操作对象和工作区。A 历史读取未完成时直接导航同工作区 B，B 成功后 A 失败，B 页仍会弹出 A 的迟到错误。独立 `recheck.json` 复现时 B 内容与编辑器均未改变，没有重发请求或写入；问题限于错误提示归属。

根授权后，作者把读取序号纳入操作有效性判断，使成功与失败分支统一。独立 `stale-error-recheck.json` 的 3 项通过：B 已成功后 A 失败不提示；B 仍加载时 A 失败不提示且 B 可正常完成；当前 A 读取失败仍显示真实错误。未重复无变化的其他测试。

**AO017-IR03，P2，已修正（作者准备浏览器夹具时确认）。** 前述函数检查将阅读器绘制替换，未覆盖 `renderMaterialWorkspace` 固定取第一个素材条目的行为；因此内部已选另一素材，实际卡片仍可能显示第一项。先前报告“无剩余阻挡”仅覆盖当时代码和受控绘制范围，不能作为这条真实呈现路径已通过的证据。

最新窄修仅使当前 detail 上的明确卡身份参与已有条目选择。独立 `renderer-recheck.json` 实际执行工作区与卡片绘制函数（只替换嵌入媒体和生成详情子绘制），验证当前有效的另一素材呈现其准确标题、轮 1，且仍只有一张卡；旧 detail、已不存在卡 ID、无明确卡三种情形沿既有默认卡，均为轮 2。4 项通过。作者真实历史加载结合实际卡片绘制的新增用例、定位与素材合计 50 项结果也已核对；这不替代根的浏览器定位和保存。

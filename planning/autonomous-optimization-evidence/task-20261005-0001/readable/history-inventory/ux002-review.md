# AO-UX-002：素材列表“已生成”与当前版本“未生成”的独立判断

当前候选实施及真实验证结论见 `ui-implementation-review.md`；本文保留发现时的历史规则与取舍依据，不作为当前验收状态。

结论：现有筛选计算和详情默认选择均有有效规则依据，不应判为筛选结果错误。真实页面确实存在表达歧义：同一素材的列表显示“已生成”，右侧当前版本显示“未生成”，界面没有清楚区分“此素材任何版本有结果”和“所选版本有结果”。建议登记为可做最小文案修复的体验问题，保留历史、筛选数据与默认当前版本行为；未取得用户偏好时不擅自改成“只筛当前版本”或“自动打开旧结果”。

本审查只分析已有浏览器 JSON、任务文本与当前源码；没有操作浏览器、发起服务请求、运行测试或改代码。

## 页面证据与范围

原始文件：`../browser/D3-generated-0-baseline-action.json`。独立读取完整 snapshot 的详情区域，确认：

- 当前为制作设定／素材管理；“生成状态 → 已生成 298”选中；全部素材 2,041 项、未生成 1,743 项。这里是素材条目数，不是原件数、版本数或生成次数。
- 左侧首项“阿禾·基准完整形态·整体参考 图像 · 已生成”选中。
- 同一页面右侧实体“阿禾”及基础完整状态下的素材小卡显示“图像 · 未生成”；素材区下拉明确选中“版本 2 · 当前”，另有“版本 1”，当前版展示要求与生成方案，没有借用旧版图片。
- 保存的 URL 明确包含 `material_status=generated`、`material_id=need-form-a-he-base-overall`、`material_version=2`，需求准确修订 `e1d41367c078bc766ebdbc61f198fd1e0694ab921b45b5bddee24cab598fb0a7`。

## 为什么当前行为有依据

| 来源 | 有效规则 | 判断 |
| --- | --- | --- |
| 系统 `docs/materials-and-relationships.md:33` | “已生成”要求关联版本存在非占位、含 original 组成的真实结果；明确说明它表示曾有真实产出，新版本仍可没有结果。 | 后台跨版本聚合并非由本次审查推测出的设计意图，现行文档有明确说明。 |
| 同文档 `:37` | 有真实产出不表示已采纳、已采用或就绪。 | 不能把过滤器状态改成认可／采用或制作准备状态。 |
| `planning/system-ui-unification-task.md:29,41,154` | 素材按持续需求计数，历史结果保留；普通入口打开当前方案版本，当前版本未生成不跳到旧版，准确历史链接优先。 | 点击阿禾后出现当前版本 2 的无结果状态符合默认阅读规则。 |
| `planning/ui-material-model-task.md:52,54,64` | 同需求版本／候选不重复计数；素材→版本→候选准确切换；未生成版本展示本版方案和真实缺项，不借旧结果；评论不建新版。 | 任务 9 延续并强化了版本准确性，没有要求将聚合筛选变成仅当前版本状态。 |
| `production/ui-material-model/README.md:13` | 未生成版本不显示其他版本的结果。 | 不能为消除“已生成／未生成”表面矛盾而将旧图片挂到版本 2。 |

系统文档部分相邻段落仍有旧“查看原方案”表述，那一条已由任务 9 替代；不能因此将整个文件的聚合口径作废。以上按条款逐项判断，不把文档新旧混为一谈。原始任务 8 的素材管理要求位于 `planning/system-ui-unification-task.md:223–225`，要求统一筛选样式及数量，没有指定筛选必须只看当前版本。

代码对应：系统 `review_desk/ui_projection.py:6–38` 聚合 `material_plan_members` 的结果和旧 candidate_requirements 关联，真实结果需非 placeholder 且含 original；`:75–100` 以该 `generated` 标志筛选并计算各维度数量。前端 `production-breakdown.js:146–147` 将其显示为“生成状态／已生成／未生成”；`unified-cards.js:25–27` 的共用小卡也只按 boolean 显示同一组词。另一方面 `modelSmallItem` 在 `:31–34` 使用当前模型的候选集计算状态，所以两处 boolean 的范围不同，文字却相同。

## 推荐的最小修复

保留 API 字段、URL 筛选值、条目口径和默认选择，仅让聚合筛选与列表说明自身范围。可优先验证这组文案：

- 筛选组：“生成结果（含历史版本）”；选项：“全部／有结果／无结果”。
- 素材管理聚合列表小卡：“图像 · 有生成结果”或“图像 · 无生成结果”。
- 所选版本的媒体空态沿用“未生成”，必要时只将相应短句改为“本版未生成”，不要再叠加一组重复状态标签。

这组词回答用户“哪些素材曾有真实产出”，又让右侧版本控件继续回答“当前在看哪版”。不建议用“有生成记录”：失败、结果未知或只有调用回执也有生成记录，但不满足该筛选的真实原件口径。也不建议用“有历史结果”代表所有 true 项，因为真实结果可能仅在当前版；“含历史版本”表达的是查找范围。

共用 `materialSmallCard` 同时承载聚合列表和当前状态素材，不能全局搜索替换所有“已生成／未生成”为跨版词。应由调用处传递已有场景语义，或增加纯展示范围参数；不得借机新造一套存储状态、重复版本概念或第二个过滤器。具体文字是审查建议，尚未经过真实页面验收或用户确认。

## 不建议的替代与原因

| 选择 | 代价／冲突 |
| --- | --- |
| 筛选仅当前版本有结果 | 改变已文档化的素材聚合含义，使当前稿待生成但历史有产出的素材消失；需要另讨论用户是否要这种新筛选，当前任务无需擅自取代。 |
| 点击“有结果”后自动打开最近有结果的旧版 | 违背普通入口默认当前版本及准确版本优先的明确要求；从制作判断上更容易误把旧结果当现行方案。 |
| 当前版未生成时显示旧图作为预览 | 直接违背任务 9 的未生成版本不借旧结果要求。 |
| 加一段技术解释列出内部修订、成员和索引 | 能解释原因但增加审阅负担；短标签说明跨版本范围已经足够。 |
| 不改，保留现状 | 数据正确，但首次读者仍会在同屏见到无解释的相反标签。可如实登记“符合契约，表达歧义未处理”，不能写为全部无问题。 |

## 若实施，所需验收

1. 在同一隔离数据与筛选条件下，阿禾仍出现在聚合“有结果”列表，仍默认打开版本 2；选项与小卡文字能解释范围，页面不增加重复状态块。
2. 切版本 1 时显示该准确旧结果，版本 2 仍无结果；返回、刷新、准确旧链接与草稿保持，不自动换版、采用或采纳。
3. 比对修改前后的全部／有结果／无结果数量、媒体／集／场组合筛选与分页：如只改文字，应全部不变。不能把 298 个素材条目写成 298 个文件或生成调用。
4. 回归仅失败调用／占位／无 original 的条目仍在“无结果”；有真实历史结果且当前无结果仍在“有结果”。这些可复用已有测试或必要针对性检查，审查本身未运行。
5. 核对共用小卡在实体当前状态、逐镜关联素材及准确历史弹窗中的范围，不把聚合词错误套到某一所选版。

当前结论：筛选逻辑不应修改；建议修正用户表达。实现、浏览器复验及最终取舍由主协调完成后另记录。

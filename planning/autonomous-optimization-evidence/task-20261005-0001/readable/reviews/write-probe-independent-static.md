# 写性能工具独立静态审查

结论：可以安排一次不超过180秒的独占运行窗口；执行授权仍由主协调分配。当前结论只允许执行隔离实验，不表示实际请求、完整性检查或性能收益已经通过。本次按要求没有启动服务、复制数据库、运行测试或测量。

审查者为已登记的 `/root/reset_supervisor`；未编写或修复这两份工具。检查对象为 `backend-investigation/run_write_ab.py`、`write_probe_server.py`、`write-static-review.md`，并追查实际 `Store`、HTTP handler 和实体判断函数的对应路径。

## 隔离与范围

- runner 的输入固定为本任务预览目录中的不可变 `generation-base.sqlite3`，复制前核对已记录 SHA；原件只读，副本位于全新 `write-ab/<输出名>/<端>/instance/.runtime/review.sqlite3`。路径经过规范化检查，已有输出目录拒绝覆盖，复制后核对独立 inode 和初始 SHA。
- 服务独立检查 write-ab 目录及数据库普通文件、非符号链接、marker 和副本 SHA 后才实例化 Store。Store 写入只落此副本；没有主项目、正式容器、preview 活跃库或媒体挂载写入路径。
- 服务只监听 `127.0.0.1:62607`。写入口白名单仅允许合成命名空间评论、准确合成实体的采纳／撤销，以及 PROJECT 的 audience 字段。删除、通用导入、迁移、其他配置及其他实体写入口被拒绝。合成对象与 actor 明确为技术测试，不代表真实作品认可。
- 端口先检查可绑定，最后只 terminate/kill 本进程所创建的服务 PID，不按端口或名称杀其他服务。执行前仍需主协调确认浏览器和其他性能窗口暂停。

## 时间与计量

- 计时从 main 起点开始；正常任务在剩余20秒时停止发起请求，闹钟在剩余10秒时转入收尾；独立线程在绝对180秒边界终止自身服务并留下单独的超时回执。请求、git、守卫和服务回收均有小范围超时，失败不允许换名自动重跑以占用其他窗口。
- HTTP 计时覆盖读取完整响应体；handler 与逻辑函数计时是包含关系，不能相加。SQLite execute 计时不包含后续 cursor 取行；显式 commit、活跃事务 context-exit 和无事务 context-exit 分开记录，未使用 trace 回调伪装完成时间。
- `ACTIVE` 全局容器与当前单线程 HTTPServer 相匹配。准备 fixture 时未启用请求计时；响应 JSON 和网络写入在 handler 时间内，度量日志序列化和落盘在外。每条写请求有唯一 request_id 和返回状态，runner 回查服务度量状态一致性。
- 两端固定先基线后候选，OS缓存未清；每类1次预热、5次正式样本。允许交付小样本耗时与波动，不足以宣称稳定写性能提升；合成实体结果不能外推为复杂真实素材的采纳或浏览器保存体验。

## 版本、写后可见性与历史

- 评论、配置、实体判断成功后同时通过真实HTTP和新的只读SQLite连接核对；重复旧版本要求409且完整抽取状态保持不变。撤销后仍读取第一条准确历史判断。
- 两条竞争评论与两条竞争配置请求使用相同 expected_version，要求恰好一成功、一409、只增加一个事件，并再次读回赢家结果。这证明原单线程服务的版本门禁，不证明多连接SQLite写竞争。
- 结束时双向 EXCEPT 检查原数据；排除范围限合成对象／判断及其依赖、fixture评论和事件、PROJECT预期变化与新配置事件。PROJECT除 audience 外的字段另作对比，原有配置事件仍比较，外键另查。

## 执行后必须逐项检查的回执

当前 runner 捕获异常后仍可能退出0；最后 `source_unchanged` 和 `systems_unchanged` 只是回执布尔值，没有强制异常。因此不能把进程退出0或 `completed` 含两个端当作完整通过。验收必须确认：`receipt.error`为空、completed准确为baseline/candidate、两项 unchanged为true、没有 identity/guard_after_error、没有 hard-deadline回执、全部 preservation-audit无差异、两端固定请求及确定性状态相同、服务PID停止且端口释放。任一不足均保留原输出并列为未完成。

`deterministic_state` 当前抽取新配置事件数量，没有抽取新配置事件的 body/version 明细。已有逐次HTTP/数据库当前配置和事件数量检查足以支持当前保存与冲突行为，但不足以单凭该字段声称新配置历史完整内容对照。建议补充各次新配置事件明细与预期body/version检查，或在结果中准确缩小“完整业务状态对比”的表述。此项不阻止安全执行，不能在结果解释时略去。

守卫前后原始JSON含内部租约摘要；文件留在本机运行目录，不应原样进入可分发证据包。证据包提取身份、T0、阶段、心跳和错误等必要字段即可。

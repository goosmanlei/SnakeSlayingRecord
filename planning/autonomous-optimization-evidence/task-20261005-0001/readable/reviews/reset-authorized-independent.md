## 已修复：canonical state 写入前失败可破坏重试稳定性

严重度：P2；置信度：高；原因及影响已通过独立故障注入复现。

代码首先存档旧 state、授权、回执和报告，然后清除旧活动回执并保存新 canonical state。若最后的 `save` 抛错，下一次运行仍看到已停止的旧 state。重试只比较 `archive/state.json`，没有比较已存档授权；`reset-authorization.json`、回执和 `run-report.md` 会再次写入。因此更改后的授权起点能被当作首次授权接受，重试时更新过的报告也能覆盖旧窗口报告。

在临时测试实例把第一次 `save` 替换为抛出 `OSError`，将授权 `observed_t0` 增加 500 秒并更改当前报告后重试：新 T0 实际延后 500 秒，存档授权和旧报告均被覆盖。未操作真实运行状态。原始结果见 `reset-crash-independent.json`。

建议将同一 item 的首次已存档授权作为不可变依据；重试若与之不同则拒绝。已有旧报告／回执同样不得被后续当前值覆盖；要么核验完全一致后复用，要么保留已有存档并明确处理当前文件变化。补充首次存档后、canonical state 保存前故障的测试。

根代理已实施：首次授权先存档；已有授权、旧 state、旧回执只接受相同内容；已有报告不再用当前报告覆盖。独立重跑新增后的46项测试通过（0.479秒）；再次运行相同的写 state 失败注入，改 T0 重试被拒且 state 仍旧，改回原授权后成功，报告和授权均保持首次存档内容。原始复验结果见 `reset-crash-independent-fixed.json`。修改者与复验者独立。

后续静态审查曾指出报告直接写入途中异常可能留下部分文件。根代理已将其改为同目录临时文件、完整写入并 fsync 后原子替换；异常时清理临时文件，已有旧报告不覆盖。独立逐行核对这段修订后，原推断路径已消除，未要求重复整个测试集。本次真实旧报告哈希仍以现场核验为准。

另一项后续修订允许成功后的 CLI 重试在 watcher 持锁时返回：先独占 state 锁，核对已有授权与当前授权完全相同，并重新认证真实根身份及执行方式；返回前不写 state、不触碰 watcher。非精确相同授权继续报错或走原双锁验证。进入真正重置前已经释放 fast path 的 state 锁，没有引入与 watcher 的逆序持锁等待。新增持有 watch 锁的确定性断言由根执行通过，独审在最后两段修订后仅进行静态复核，没有把根执行结果记作第二次独立重跑。

新修改只影响显式重置入口及命令路由。现有 watcher 循环使用 `tick` 和停止流程，没有调用 `reset_authorized`；这些路径未变。故当前 watcher 已加载较早脚本不影响本次修复的重置重试保护，也无需为此重启计时监督。

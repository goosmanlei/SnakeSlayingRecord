# 补测独立审查：准确交互、计时与异常边界

本次补测可以复核候选修正了组合与历史列表的选中标记，以及评论面板遮挡圈选正文的问题。性能结论须分开表述：进入 S002 的准确正文路径两轮都更快；关系卡的真实 Enter 入口仅观察到含工具往返的时间上界下降；评论重复定位在候选中多花约 850 ms，同时让整段圈选保持可见。其余补测动作未证实两轮持续提速。不能把这些结果合成“所有交互更快”。

审查由独立线程 `01a10bdc-2c5f-7550-a7fc-01f1a7401b58` 离线完成。只读取已存证据、查看原始 PNG，并在本审查目录写分析与结论；没有重新打开浏览器、启动服务、重测或打开数据库。数值与逐动作检查见 [JSON](supplement-independent.json)，复算入口为 [分析脚本](supplement-independent-analysis.py)。JSON 保存输入 SHA-256、全部动作的准确 URL／修订、正式原始数组、范围、四分位距和中位绝对偏差。

正式比较只使用 A3/B3、A4/B4 两对。每阶段 10 个方向、每方向 4 次，序号 0 是预热，1–3 是正式样本；160 次动作中，144 次为点击探针，16 次为真实 Enter 的工具时间上界。A1/B1/A2 各有完整 40 次标准动作，但跨越中断；B2 仅有 8 次 P2 动作且受外部任务负载影响，全部保留、全部不混入本次比较。R1 早期诊断也不混入。

四段服务首尾身份逐字段相等；A 对应 `b874b959af9c918a482e8488dc25cb0204ab5772`，B 对应 `204c4696f0ecd4595b395a14520eacf0c54ef2bf`。数据库 SHA-256 均为 `5c6d00ee6efa7506201bbef46ffd69bde49f7300c4697fe66036e87ace7ed4f0`，探针 SHA-256 均为 `74a80b7f730a450f4fc00f5424120f8f60406e7fe9c4c65234e3d317958a804c`。四段使用同一适配器哈希 `a018fe0667f0cac176f2e33daeee21ffa03ae8269717ac76abd2326ada6628e2`，产品目录干净，同侧产品树哈希一致；服务回执均为 SIGTERM 正常收尾、身份未变，动作时间均落在相应服务生命周期内。服务覆盖本地时间 19:30:45–19:38:37，按 A3→B3→A4→B4 串行执行。

所有动作记录的浏览器均为 Chrome 154、1440×900、DPR 1、前台；图片／媒体操作按已加载页面重复执行，属于暖缓存路径。它们不代表冷启动、慢网或正式服务绝对延迟。适配器“仅增加四个阶段标签”的改动记载在 [冻结协议](../backend-investigation/supplement-final/clean-window-protocol.json)，本审查核对了记录哈希与固定探针身份，没有取得改动前适配器副本来独立重做差异审查。[冻结基线原件](../run-baseline.json) 记录 6236 个对象，其 snapshot SHA-256 和 163000320 字节大小与四段首尾身份一致；此为原计数记录的独立交叉核对，本审查没有打开数据库重计。媒体输入首尾身份仅覆盖名称、大小和修改时间，不是对全部媒体重新逐字节校验。

实际交互与解释如下：

- **组合与历史 P2。** 两个方向的正文标题、准确对象、修订 ID 及“版本 5 · 当前”均能对应。基准进入 S002 后，8 次观测全部仍把 S001 标为选中；候选每次都只有正确目标为选中，返回 S001 也正确。候选解决了正文与列表不一致。基准的完整交互未正确完成，不能把它与候选作为同义的完整正确交互计算提速。下表 P2 数字仅比较准确正文／修订到达的路径；返回 S001 的起始状态也继承了前一步选中错误。
- **图片 M1。** 16 次放大都打开“阿禾·基准完整形态 · 内置渠道首轮基准”，随后关闭均无打开的对话框。准确修订为 `d71d936487d92793f28f793c7d6e0eca5051138762a7ee99ebb976959f793561`，大图地址为 `/assets/717c7bca7ecabeb45318ad1669d61ed0e440fdfc8567ad80c4b123cfc9de032a.png`；同名缩略图另走 `/api/production/files/`。每次观测均为 `complete=true`、自然尺寸 1086×1448；放大图元素框为 1374×759。元素框不是像素尺寸，也不是图片内容的实际铺满范围。约 20 ms 是 DOM 语义就绪，探针没有把图片解码或绘制完成当门槛；后续图片已完整的观测是另一份正确性证据，不能倒推它在 20 ms 时已经显示完毕。
- **音频 M2。** 准确修订为 `e522f05e989232e8323608cc74addd94b5e542c15c2d69692109c5fdd3e78ecb`，文件为 `/api/production/files/a7d678681c2e490de0a7dc8aca163131f68e196ceda703dc9c9282418c589272.wav`。所有播放观测均 `readyState=4`、`paused=false`、时长 14.5 秒、播放位置大于 0；位置为 0.173–0.210 秒，随后的暂停位置继续增长至 0.268–0.332 秒且 `paused=true`。逐动作有对应 playing 事件。证据支持该文件实际进入播放并推进、暂停可用；没有独立听音证据，也没有把 DOM 就绪耗时解释成出声延迟。
- **实体关系 R1。** 保存的执行函数对“打开实体：孙六”使用真实 `press('Enter')`。每次最终看到“孙六”、对应基准完整形态及可用关闭按钮，随后关闭均无打开的对话框。键盘打开没有新的 click 探针样本，旧 pending／最后一个样本可能停留在前次关闭；这里没有把旧快照当成本次就绪或失败依据。唯一计时是工具调用前到正确标题、状态和关闭可用被观察到的墙钟上界，包含工具往返。
- **评论 L1。** 每次定位的完整原文都与指定圈选一致。基准圈选只有一行，右端 1258.40625 px；面板从 1000 px 开始，遮挡宽 258.40625 px。单测中心点命中为真，仍不能证明整句可见。候选圈选分为两行，均在阅读区和视口内，均不与从 1080 px 开始的面板重叠，逐行命中也为真。本审查实际查看了 [A4 PNG](../browser/supplement-reset-01/L1-final-A4.png) 与 [B4 PNG](../browser/supplement-reset-01/L1-final-B4.png)，画面支持这一区别。

计时按冻结规则复算：点击指标为 `semantic.capture_finished_ms − trusted click start_ms`，与保存的 `scenario_ready_ms` 逐条一致；它在相关 DOM／请求结束后等待两帧，再用 180 ms 不变确认稳定，数字本身不含这段确认等待。该指标不是绘制完成、媒体解码或平滑滚动完成。下面各格单位 ms，格式为“中位数 [最小–最大]”，每格正式 n=3。分位数采用 `(n−1)×p` 线性插值；四分位距 IQR 为 Q3−Q1；MAD 为未放大的中位绝对偏差。只有中位差超过 `max(A.IQR, B.IQR, 3×A.MAD, 3×B.MAD)` 且两组四分位区间分离，才称该轮超过典型波动；两轮同向才称持续。此为既有描述规则，不是显著性检验。

S002 正文路径中位分别减少 215.9 ms、238.2 ms；分母为各轮 A 的正式中位数，相对减少 11.13%、12.17%，超过阈值 134.05 ms、15.20 ms。B3 的 1964.5 ms 是完整保留的较慢样本，不能说候选每次都更快。S001 第一轮减少 136.4 ms，阈值 80.0 ms；第二轮减少 164.8 ms，阈值 195.45 ms，未达到。A4 的 1855.8 ms 没有剔除。R1 工具上界中位减少 95 ms、106 ms，其工具开销与产品延迟没有被拆开，所以只报告上界观察结果。

L1 的额外耗时有可复核的路径差异。序号 0 从较远位置首次定位，四段都约 1.62 秒，仅保留为预热。后续刷新保留阅读位置：基准正式样本开始、结束均为 `sourceScroll=46329`，定位动作没有新的正文滚动结束事件；候选刷新先恢复 48756，打开避让面板改变排版后变为 51391，再定位回 48756，实际回滚 2635 px。候选正文滚动结束事件记录在动作后约 872–882 ms，最终几何与截图是在操作完成后取得。两轮正式中位增加 849.4/849.5 ms，分别远大于阈值 3.9/1.2 ms；这是本重复定位流程真实发生的额外等待，必须披露。它不能用于推断相同滚动距离的算法性能，也不能因为最终更可读而省略其成本。

异常与保留材料未被“通过”汇总遮掉：

- 初次 B1 服务启动后中断，目录没有收尾 receipt、HTTP 日志或 identity-after；[中断记录](../backend-investigation/supplement-final/interruption-1855.json) 记载当时进程消失、端口无监听、没有样本。B1 文件名下后续 40 次动作属于 `B1-resumed` 服务，其正常回执和首尾身份另存。该记录将直接原因标为 UNKNOWN，只能确认中断与恢复，不能把主机／工具恢复原因写成已独立定位。
- 旧 B1 的 M1 序号 0 原始断言误用了 `revision` 查询键，原文件仍保留失败；[更正记录](../browser/supplement-reset-01/M1-B1-warmup-assertion-correction.json) 指向实际的 `production_revision`，准确值与预期一致，声明没有重复动作。它不修改原件，也不作为本次正式样本。
- 旧 B2 的 P2 序号 2 保留等待超时原件；[晚到观测](../browser/supplement-reset-01/P2-record2-B2-2-late-observation.json) 是同一时间源、紧接第 6 个样本后的第 7 个事件，事件开始绝对时间落在原工具调用区间内，正式就绪 3634.7 ms。没有新增第二个事件来替换慢值，记录也明确 `actionRepeated=false`。外部歌曲恢复／验证进程的 CPU 快照分别为 83.0% 和 85.1%，精确干扰起点 UNKNOWN，因此整段 B2 排除，而不是只删慢样本。
- A3 使用旧浏览器句柄失败、后以显式 tab 参数恢复，是协调方提供的执行事实。本目录没有独立原始工具异常回执，故本审查不能仅从服务日志证明该具体恢复过程。可核实的是 A3 标准样本完整、准确身份一致、全部动作从有效服务启动后发生，没有把句柄错误作为产品慢样本。
- **新发现的服务异常：** 四段 HTTP 日志合计有 6 条准确 WAV 请求记为 `400 / BrokenPipeError`，按 A3/B3/A4/B4 分别为 2/1/1/2；控制台可见客户端连接重置后的写管道失败。它们位于媒体加载／第 0 次预热附近、早于所有正式第 1 次播放，之后每段均有同一文件 `206` 返回，所有实际播放与暂停观测成功。支持“本批正式播放功能可用”，不支持“所有 HTTP 无错”。客户端取消及 Range 重取是与日志相容的解释，但仅凭这些记录不能确认每个取消的浏览器内部原因。点击探针的 `request_error_count=0` 也不能覆盖原生媒体请求错误。

本次“clean window”仅表示已确认先前外部歌曲任务完成后重新开始四段比较。19:35 的负载快照仍有 WindowServer、iTerm、Chrome、Defender 等活动，load averages 为 6.20/5.47/5.66；不能称完全空闲机器。固定 ABAB 顺序、每格 n=3、稀疏负载快照不足以证明随机因果或生产尾延迟；收益只能归于所测候选整体，不能独归某一条优化。

实证结论是准确目标与功能观测可复核、P2 选中修正和 L1 整句可见改善成立，数值收益与慢化均有原始路径支持。仍未知的包括 R1 产品自身精确延迟、冷媒体解码／出声延迟、后台负载的逐样本影响，以及未测页面与设备上的结果。本补测不支持全面提速、无所有回退、正式发布或用户验收的声明。

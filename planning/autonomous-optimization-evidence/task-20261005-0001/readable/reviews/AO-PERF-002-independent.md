## 实际变更与边界判断

原递归展开在每层返回时深复制完整子树，重复付出嵌套复制成本。新实现由私有 `_expand_cached` 构造仅供内部使用的共享内容图，公开 `expand` 出口通过 `_clone_json_tree` 返回独立的 JSON 树。这里没有对象身份记忆，因此同一个缓存节点出现在结果的多个位置时，每一处字典和列表均重新复制，避免单次 `deepcopy` 的身份记忆将共享引用带到公开返回值中。

六项边界已逐项核对：

1. **公开出口与可变性。** 缓存命中和新解码均经过同一公开复制出口；字典、列表递归复制，JSON 标量为不可变值。不同返回值、同一返回值内重复子树、嵌套列表相互独立。
2. **缓存范围。** 未提供显式 cache 时仍复用 `_production_reads.material_content`，无读范围则只建本次本地缓存。没有新增跨请求缓存；AO-PERF-001 的完整物理字符串缓存逻辑未改变。
3. **显式 cache 与 visiting。** 原有参数及缓存先于 visiting 检查的顺序保持。当前显式缓存调用方为档案 read scope 与迁移验证，它们复用缓存但不修改内部值。调用者传入的 visiting 集合在成功或解码异常后均保留既有成员。
4. **档案格式。** token/order 压缩 recipe、旧压缩数组、未压缩 recipe 和内联 value 均保持数据内容；公开返回中原先共享的 recipe token 现在独立。`material_archives.decode` 只读取这些内容，原始字节长度和哈希校验不变。独立非 active 档案 resolver 的另一条实现没有修改，不能将本项收益外推到该路径。
5. **失败路径。** 哈希、缺失节点、重复键、格式和循环检查仍保留。父节点只有完整展开后才入缓存；失败前已成功完成的子节点可保留，不会把半成品父节点暴露为成功结果。压缩损坏及 recipe 索引失败也清理本次 visiting。
6. **历史与恢复。** 本项不改变 schema、内容哈希、归档编码、版本/评论契约或恢复格式。现有迁移、精确历史、导出与空库恢复测试随本项执行并通过。

未为调用方任意手工预填循环对象、tuple 或自定义 Python 类到 cache 增加支持；实际内容图及现有消费者的约定是合法 JSON。这不是本轮新 API。

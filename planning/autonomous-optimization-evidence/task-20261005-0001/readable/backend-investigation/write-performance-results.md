# 隔离写性能与写后正确性结果

本窗口两端全部完成：五类写操作各 1 次预热、5 次正式重复；保存后 HTTP 和独立只读数据库连接可见，旧版本重放被拒绝，准确历史与非测试数据保持。相对本轮最初系统基线，合成实体内容采纳的 HTTP 中位耗时从 985.210 降至 781.190 毫秒，减少 204.020 毫秒（以原中位数为分母，20.7%）。两端全范围不重叠；其他四项处于约 1—3 毫秒、范围交叠，未证实收益。这个结果只覆盖所测后台操作，不能称页面采纳已加速。

## 环境和测量边界

- 实际窗口：2026-10-05T05:37:49Z 至 2026-10-05T05:38:15Z，即北京时间 13:37:49—13:38:15；总计 26.443 秒，小于授权 180 秒。根代理已暂停浏览器并授予独占窗口。测量前后新守卫 T0 为 13:21:50、armed、监督有效、无停止；结束已通知根释放窗口。
- 基线：`b874b959af9c918a482e8488dc25cb0204ab5772`；候选：`e91c57a4a1136e55946d4a2a6377949a932a76fa`。比较 001+002 的整体后台影响，不把两个旧增量窗口的百分比相加。产品 Python 每个文件 SHA 前后相同；前端未纳入本后台实验。
- macOS-26.6.2-arm64-arm-64bit，Python 3.9.6，同机 loopback 62607。数据文件初始 163000320 字节，SHA `5c6d00ee6efa7506201bbef46ffd69bde49f7300c4697fe66036e87ace7ed4f0`。首次快照的数据规模为 6236 对象、10160 修订、271 评论、78889 内容节点；每个副本另建 3 个合成对象，其后仅加测试评论、决定历史及 PROJECT 配置历史。
- 两端各从同一不可变快照复制新的普通文件，初始 SHA 相同，源快照与产品源码结束 SHA 均不变。原 handler/Store 实际处理请求；不挂载媒体、没有密钥或外部调用，未写 preview、functional 或正式数据库。
- 固定先基线后候选，操作系统缓存不清；每种写操作 1 次预热后 5 次正式样本。SQLite journal_mode=delete、synchronous=2。没有测冷盘启动或多进程 SQLite 写压力。
- HTTP 从真实 loopback 请求发起到响应体读取完成；逻辑层包含原 Store 校验、处理、事务与返回。SQL 写分项只覆盖 execute/executemany 的实际调用，不包含后续 cursor 取行；其他 execute、handler 和每次原始值另存。
- 本机 Python 3.9.6 的 context-exit 会调用被包装的 commit，两类原始计时嵌套，绝不相加。下表事务边界在评论/配置路径取外层 context-exit，在实体决定路径取显式 commit。最初静态关于 C 路径不调用 override 的假定被实际日志纠正，原始数值保留。

## 正确性与保全

- 每端 93 个真实请求、93 条一一匹配服务计时：49 个 200、18 个 201、26 个 409；其中 30 个预热/正式成功写、2 个竞争成功写、26 个冲突请求和 35 个回读。两端总计 186 个请求。
- 每次创建/编辑评论检查准确对象、修订、整体锚点、正文与版本；保存后 HTTP 和新只读连接均能读取。每条 CREATE/EDIT 事件数量随操作递增；从保存日志补核了最终所有评论事件 action/body 顺序及 OPEN 状态，原事件正文保留。
- 六次配置保存每次版本和事件数仅加 1，HTTP 和新连接读回字段一致；旧 expected_version 重放均 409，之后数据库状态未变。新 configuration_events 的 body 未在循环快照中逐条保存与比对，不能声称该部分已做完整字段验证；旧配置事件通过全表保全检查。
- 合成实体按准确 scope/mode 执行六轮采纳→取消，每次决定版本递增；所有旧版本重复操作为 409，历史明确保留十二条 accepted/revoked。取消后通过 HTTP 读取首条准确 accepted 修订。该技术数据不是对任何真实故事内容的认可。
- 同版本两条竞争配置请求、两条竞争评论请求，各一条成功一条 409；仅增加一个事件/版本，写后结果可见。原 HTTPServer 串行处理，它验证客户端版本门禁，不代表多进程写入压测。
- 固定测量请求载荷、fixture SHA 和顺序样本后的确定性业务状态两端一致。只剔除方案列明的记录元数据时间戳；没有删除业务 payload 字段；竞争赢家随机，单独验证。
- 全部 23 个业务表与原快照双向 EXCEPT，在显式测试范围外没有增加/修改/丢失；PROJECT 除 audience 外字段一致，外键检查零问题。material_content、版本、候选、原件登记、旧评论和源资料均完整比较。
- 两个自有服务器经 runner terminate+wait 成功后才记完成；结束检查 62607 可绑定、无匹配存活 Python 探针进程。历史 PID 没有写入 ready.json，不补造；退出与端口证据在 server-stop-check.json。

## 限制、独审和恢复

这是一次固定顺序、单机器、每类 5 样本的暖态诊断，可能含系统调度和顺序漂移。实体夹具无媒体需求，不能外推所有素材采用、上传、导出、图标写入或真实页面保存；未测路径仍由完整覆盖矩阵说明。SQL 分项不等于完整数据库耗时，API 结果也不替代真实浏览器验收。
本 worker 修复了旧测量工具并执行，本结果仍需非本项实施者从原始请求独立复算。原 67 项正确性与旧两次 GET A/B 属于此前窗口，沿用其原时间和归属，本窗口没有重跑或冒称新增。
两个可写副本和所有日志保留在本地 `write-ab/reset-window-01/`，绝不可回写为活库。根复核时从 receipt.json 检查 error=null、completed 两端、source_unchanged、systems_unchanged，以及各 arm 的 preservation-audit.json；不能只看 shell 返回 0。
便携交付只收录 environment、receipt、comparison、工具冻结副本、requests、metrics、fixture、initial/final/deterministic-state、保全与停止检查；不带数据库副本或原 guard-before/after（含租约身份信息）。可另生成只含任务、T0、phase 和监督布尔结果的脱敏守卫摘要。

## 问题、改动与边界

此前 profile 显示内容树展开中的逐层 `deepcopy` 占有明显 CPU 时间；这是修复方向的依据，不等于候选已取得收益。候选把内部递归展开改为复用已校验的 JSON 节点，在公开 `expand` 出口按每次出现的位置复制字典和列表。内部缓存可以共享子节点；返回给调用方的树不能共享可变子节点。

没有使用标准 `deepcopy` 在出口复制：它的 memo 会保留内部共享节点的别名，让不同位置仍共享可变列表。新的 `_clone_json_tree` 不使用 memo，重复位置各自形成独立容器。缓存中的字典和列表靠内部只读约定保护，并未引入冻结类型；现有两处显式缓存调用者只传递缓存，不直接修改缓存值。

保留公开 `expand(store, key, visiting=None, cache=None)` 签名、既有 scope 缓存容器、所有缺失/哈希损坏/重复键/循环引用检查和 `finally` 清理。完成展开后才缓存当前节点；失败父节点不缓存，已经成功校验的子节点仍可复用。`hydrate`、自定义 resolver、原件还原、AO-PERF-001 的字符串复用、数据库 schema 和写入逻辑均未修改。

实际影响路径包括素材列表、实体详情、场景详情、素材模型投影/校验、活跃库原件读取和部分迁移/恢复。非活跃库 `material_archives.resolver` 有独立展开实现，未改动；不能宣称所有媒体预览路径都已优化。

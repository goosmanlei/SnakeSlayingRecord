# 故事创作与生产制作思路各用一张简洁工作图表达

“制作思路”的故事创作和生产制作页仍是8节／11节长文、目录及重复案例，后者还要求“已有调用后修改执行定义须建新版”，与已经交付的单份当前稿＋候选快照模型冲突。用户要求参照“系统构想”图片及当时任务的迭代过程，逐步简化为精简图形表达。本项最终让第一次进入系统的人直接看懂两种工作怎样推进、出现问题回哪里修改，再从既有入口进入工作。

## 从既有迭代确认的方向

读取 task-20261010-0022／0023 的规划和交付记录（均已完成），特别是0023从四块图文到“只留这张图”，再到人与AI／审阅台两层的实际收敛。只继承有用原则：图中关系自身解释工作、删除重复说明、原生中文保持可读、柔和绿色与纸面风格、按内容容器重排。不是把8节／11节原文缩小塞进框，不机械复制愿景的两层支撑形状，也不恢复被用户否定的四块布局。

两页继续在既有制作思路子页中，一页一张工作关系图。删除本页章节目录、长文、重复标题和旧进度，不将其搬进折叠、hover、详情页或新增解释实体。图下只留确有用途且已经存在的专业方法入口；工作入口优先由相应图节点直接进入，不复制一排相同按钮。系统构想、视频手册、影视知识仍各守原职责。

## 故事创作图

主线：采编资料 → 选择方向 → 结构 ⇄ 小说 → 影视剧本。每个节点用简短动作和原生图形说明产物；结构与小说的双向箭头须直接可见，表达结构指导写作，正文发现问题也会回修结构。小说旁用小循环“写一段→读回来→再修订”，剧本表达“逐场写出可见可闻”，终点连接确定制作依据与生产制作。

一条共用反馈回路表达“阅读与评论→AI修订→再读作品”，实际回连受影响的结构／小说／剧本，不能变成各阶段的审批关卡。故事稿仍按现有方式保留版本，评论对应所读原稿；不因制作当前稿原则删掉文字作品版本。删除反复出现的歌本案例、阶段责任重述、后台检查点、当前第几稿等时点内容，不在页内重新写创作手册。

## 生产制作图

用三个相连的图组解释工作：

1. 确定剧本→制作设计。人物、场景、道具、歌曲、镜头共同属于实体，镜头按集场编排并表达叙事／观看目的；不要继续画“实体一条线、镜头另一套对象树”。
2. 制作设计→素材需求／当前方案。素材需求说明要做什么，当前方案用一张可修改的纸表达Prompt、参数和素材参考。只有一份当前稿、持续原地修改，输入图标只能是实际素材；实体与状态是设计依据，不伪装成可上传参考文件。
3. 提交生成→多个真实候选。从提交处分叉出各次候选，每个候选各带当时Prompt、参数、实际参考的快照；候选不能串成V1→V2→V3业务版本。当前方案后来修改不影响已提交快照。候选经看／听／评论回到当前稿或上游设计，再生成／复验；选定的准确素材供下游使用，普通查看候选不改变当前稿。无需增加“采纳／审批通过”的门。

图中不出现 CALL、发布锁、技术恢复、固定时长进度、数据库字段等。模型生成和素材复用的意义要看图可知，不要求先理解系统内部术语。组合成片若作为方向出现，只表达后续用途，不能呈现为当前已具备的剪辑／导出产品功能。

实例正文唯一维护在 content/production-approach.json 的 story／materials；不要另建同内容Markdown权威副本。愿景仍来源 production/system-vision.md 及 sync_system_vision.py，其派生同步必须保留本次两页。通用渲染与有限安全图形结构留../story-review-desk的review_desk/approach.py、static/approach.js、approach.css；故事流程文案留实例，不能硬编码进通用系统或扩展为图形编辑器。专业手册和受管SKILL继续保持原唯一正文，本任务不修改正式方法库、不批量改历史创作内容。

真实Chrome验收以新读者能否仅看图回答为准：故事为什么来回修结构和小说；镜头与其他实体如何共同准备素材；改当前方案后旧候选为什么不变；评论后谁改哪里；从哪里进入实际作品和专业方法。两页没有目录／重复长文／折叠区，不以“减少字数”替代上述理解。桌面、760px中间宽和手机实际阅读，箭头在换行后仍指向正确对象，图形不越界、文字可选可读；应核查制作方案→提交快照→候选分叉和反馈回路，不被漂亮样式掩盖错误因果。

保留story／materials路由，旧章节深链按意义映射到新图区域，例如structure定位结构／小说、candidate-production定位提交／候选；不保留空白旧章节或假目录。键盘切页、图内既有导航、浏览器返回可用；返回视频手册／影视知识仍有正确全文、目录和原件入口。故事版本、评论、候选和方法历史不因改图变化。图形和链接需实测，自动检查仅辅助。给两页前后可看例及实读发现的迭代，不把旧0023验收当作本次验收。

与本轮镜头素材／实体图任务没有语义前置依赖：两页基于已经正式交付的当前稿和镜头实体契约。依赖空，复杂度complex，独立受管双仓工作区可并行开发；共同approach／instance配置若有变化合入最新主干复验；正式3000服务、固定镜像及发布窗口按序。

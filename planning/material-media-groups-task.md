# 素材管理按媒体类型分组，桌面五列且同类有结果优先

当前素材管理按集场再拆“已有原件/尚无结果”，图像和声音混在同一分区，同一素材跨场还能重复出现。用户希望直接按媒体类别浏览，先比较已有成果，再看尚待生成的方案。

## 改后页面

保留素材管理现有必要集场、媒体和结果筛选及打开素材大卡能力；这次删除搜索/清除/分页的要求仅针对实体管理，不能误套到素材管理。

1. 下方列表改按媒体类型区隔，顺序图像、声音、视频、工程、文档；只显示当前范围有条目的类别。取消集场及“已有原件/尚无结果”分区，集场仍作为筛选和素材真实用途，不能因同一素材用于多场就复制卡片。
2. 每个媒体组内，有结果的素材排在无结果之前；同一子集按稳定素材编号自然序，刷新/返回不随机跳序。“有结果”沿真实候选/原件事实判断，不以准备了Prompt、缩略图、失败调用或文字说明冒充结果，也不表示人工认可。按唯一素材身份计卡片与总数，一次生成多候选不拆成多个需求卡。
3. 桌面正常管理宽度下5列，复用现有素材小卡；窄屏重排但对象集合和排序不变。现有每页行数保留，按五列计算分页容量；媒体标题占独立区隔，不把两类混在一行。跨页继续同组时有可辨媒体标题，不能漏/重素材；修改CSS同时修四列分页算法和相关文案。
4. 点击素材仍打开准确的共用大卡；关闭回原筛选、页码、滚动位置。沿用当前稿/候选快照契约，不为此改候选、Prompt、原件、引用和评论。大卡内部优化由本轮“镜头纳入实体”任务承担，本任务不等待该任务才能完成列表调整，集成后复验入口兼容即可。

## 现场、前后例与验收

本轮根Chrome在正式3000的AE001/AS001看到45个唯一素材：2有结果、43无结果。旧页把M002图像和M1195声音放在同一“已有原件”区，M2973/74图像、M2975视频混在下面的“尚无结果”四列区。

改后同范围图像35项、声音5项、视频5项分别成组；图像内M002先于未生成图像，声音内M1195先于未生成声音，视频组保留5个待生成方案。数字是调查时实例，验收以执行时准确数据及真值集合为准，不硬编码。

- 在全剧、AE001、AS001和另一多用途素材范围真实Chrome操作，核对媒体分区、五列、有/无结果顺序，选媒体或结果后集合和数量准确。
- 同一需求关联多个场只出现一张；有多个候选仍是一张素材卡。媒体类型为空/未知的有效记录不能静默消失，按既有规范明确归属；只剩一种或空集合时不造空组。
- 真实翻页、改变每页行数、调整窄屏再返回桌面；页集合、各组边界和五列算法一致，无丢漏重复。打开有结果/待生成素材后返回原位置；已有真实图片预览、音频播放与准确候选入口可用，未生成视频不冒充结果。必要播放验证以实际操作为准，不对本轮音画创作质量作新评价。
- 合适自动检查覆盖分组、去重、稳定排序及分页边界；截图/真实操作验证视觉和返回位置，不仅以测试数量验收。

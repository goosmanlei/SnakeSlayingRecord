## 任务目标

以本文全部要求和三张任务原图为依据，完成实体大卡第二版优化，覆盖页内大卡、弹窗及所有复用同一组件的入口。相关现行说明采用“实体大卡”简称，仍区分左侧实体区与右侧素材区。具体目标如下：

1. **实体标题与版本。** 将基础信息顶部的实体版本列表移到上方实体标题行，与采纳按钮通过明确间距或分组区隔；基础信息区不重复放置版本选择。窄屏及版本较多时控件仍可访问，不遮挡标题或采纳按钮。此调整针对实体版本，不把状态版本混入实体标题行；准确历史链接和用户手动选择继续优先于默认版本。
2. **基础剧情依据。** 提高基础信息底部剧情依据小三角的辨识度；收起时向下，展开时向上，图标方向与实际状态一致，保持原有准确来源入口与阅读位置。
3. **关系图。** 优先保证当前实体、关系节点、说明框和连线清楚可辨，不为在初始视窗塞入更多信息而压缩、重叠。布局计入节点、完整关系说明和剧情依据的实际占用空间，说明区域按约定尺寸预留；说明中的信息直接展开，不能靠折叠、截断或遮挡获得空间。允许按需要采用曲线、不同颜色或线型疏导连线，方向和端点仍准确，不能只靠颜色表达关系。保留稳定正方形视窗和图内平移，当前实体及主要关系初始可见，其余内容可达；复杂关系允许扩大图内布局范围。保留关系编号、评论、准确依据、关联实体打开及返回上下文。
4. **历史保留状态物理清理。** 清理范围为当前实体、当前版本的大卡中标记为“历史保留”的独立状态对象，不因打开旧实体版本而把现用状态纳入。先逐项列出准确身份、全部状态修订、所属实体、历史／当前引用、素材和真实调用、评论、采纳／采用、导出及恢复影响，再形成精确删除与兼容处置清单。在隔离副本物理移除清单内冗余状态记录和正文，不能只隐藏按钮、改标签，或搬到另一份完整状态副本。核验关联需求、关系和索引的处置，不扩大为删除仍有用途的素材、原件、真实调用、用户评论或其他对象历史；必要删除凭据保留身份与原因，不携带已删除的完整状态正文，评论自身已有引文保留。历史准确引用不得跳到最新状态冒充原目标；有可证明的等价映射才迁移，否则明确显示目标已清理并保留引用来源，遇到无法兼容的重要依赖列入待解决项。同步清理当前库、交付导出和有效恢复数据中的目标内容，阻止后续写入或恢复悄悄带回已清理状态；既有 Git 提交不重写。正式删除清单及引用处置须纳入可审阅的最终候选，按项目确认与共享写入流程执行。
5. **状态双 Tab。** 将状态下的“剧情依据／关联镜头”改成居左、按内容宽度排列的两个 Tab，不撑满整行。首次进入默认都不选中、内容收起、文字右侧显示向下小三角；点一个后选中并展开其内容、小三角向上；点另一个切换内容及选中态、前一个恢复向下；再次点击已选中的 Tab 后全部收起且无选中态。鼠标与键盘均可操作；切换不跳顶，弹窗返回保持既有状态与阅读上下文。
6. **素材版本与候选。** 右侧素材区的版本行、候选行均右对齐，按真实序号从左到右由旧到新，最新项在右端。各行溢出时可横向访问全部选项，初始选中项可见；不得只倒转视觉而造成键盘顺序不一致。沿用“默认最后一个有候选的版本及其最新候选；全部未生成时选最新方案”的规则；精确链接及手动选择优先，无候选不出现候选行，选择不改变采用记录。

完成隔离实现、数据清理预演、真实浏览器验收与双仓可审阅交付；小卡重设计、场镜页面重构及全站风格任务沿各自范围处理，本任务保留与它们的兼容。正式集成、数据库应用、部署和推送沿项目最终候选确认流程串行办理。技术验收不代表用户接受作品或媒体，不包含新媒体生成。

## 可验证完成标准

1. **来源覆盖。** 对照整章与三张原图建立需求—实现—验证对应，覆盖简称及全部六组优化；原图字节、尺寸和哈希可核对，不以截图文字转写替代布局依据。
2. **标题与基础依据。** 在页内和弹窗实测实体版本位于标题行，和采纳按钮有明显区隔且不重复；基础剧情依据的小三角在收起／展开时分别向下／向上，足够清晰，准确来源可打开，标题和阅读位置稳定。
3. **关系图可读。** 以截图中的阿蘅为必测实例，覆盖简单、多关系、长名称／长说明及多项剧情依据，在记录视口的桌面与窄屏检查：节点与说明框不互相覆盖，线不穿过无关节点或说明文字，多条路径可辨别，方向和端点正确；每条说明及剧情依据无需展开动作即可阅读，内容完整可达。默认位置不挤压全部关系，平移、来源、评论、关联实体打开及返回有效；保留前后截图和必要的几何／交互检查。
4. **物理清理与保全。** 交付准确状态及全部受影响引用清单、清理前后数量和存储核查；目标状态正文与冗余记录从隔离库、导出及其恢复结果中消失，不靠界面过滤验收。无悬空引用、伪造映射或把现用状态误删；素材原件哈希、真实调用、用户评论和有效采纳／采用核对不丢失，保留的删除身份凭据可解释历史链接。重复执行无额外删除，输入冲突整批停止且无部分写入，清理后导出→恢复→再导出保持一致且不复活目标。未解决依赖必须列明，不计为清理完成；正式应用随最终候选确认后执行并回读。
5. **状态 Tab 全路径。** 真实浏览器按“默认全收起→剧情依据→关联镜头→再次点击关联镜头”验证无选中／选中、内容、向下／向上箭头四步变化；反向路径、无内容、切状态及关闭上层弹窗返回均正常。两个 Tab 居左且不撑满，键盘可操作，无跳顶或异步旧内容覆盖。
6. **素材选择。** 验证单／多版本、单／多候选、全部未生成、最新方案未生成而旧版有候选、选项溢出和准确历史链接；两行右对齐、真实顺序由旧到新、最新在右，当前选中项可达，候选只属于所选版本，默认策略及采用记录不变。
7. **联合回归与交付。** 在实体管理、素材管理、制作拆解、镜头制作及多层弹窗中验证共用大卡，覆盖常规桌面与窄屏、准确版本／候选、评论新增／定位／编辑／快捷键、采纳／取消、媒体预览及返回上下文。数据库、自动检查和静态代码结果不能替代真实页面验证；浏览器受阻项明确为未验证。交付相关自动检查结果、双仓准确候选、逐项证据、数据处置及恢复办法；用户确认后再依流程完成正式操作与回读，不将不同交付阶段混称。
8. **收尾。** 更新确实受影响的知识与使用契约，按项目规则核对并清理任务无效过程资源，报告实际删除数量／范围、回读和保留用途；未清理项说明原因与下一步。任务状态仅由账本维护，不把本次测试或删除经过复制进长期上下文。

# 工作方法覆盖、真实执行入口与页面整理调查

本记录整理复制协调主会话已完成的调查，作为[任务正文](working-methods-visible-navigation-task.md)的文字证据，不声称本发布会话重新操作过页面或执行过创作。协调调查读取了项目规则、系统构想、受管方法、创作制作方法及必要源码/API；只读 GET /api/methods 和 GET /api/methods/resolve，没有 prepare/save/edit 或正式数据修改。根协调者已亲自用 Chrome 核对三个页面：方法默认选中未绑定的旧意见措辞，方法及正文版本使用下拉；共用资料也使用下拉；工作环节默认新建表单并有方法版本下拉。正常方法页没有审批，不能编造审批删除成绩。下文数字和版本是这次调查的观察值，不固定后续执行基线；产品取舍已经用户授权确定，不退回待调查。代码路径以故事仓根为基准，附属仓路径以主项目根为基准。

## 结论

当前不是主要创作环节没有 SKILL。正式实例已有 16 个方法、12 种工作类型及 5 份共用资料；实体用途判断与视频方案方法也已经存在且实际绑定。问题应定义为：关键方法约束不足或实际重编未落实其约束，以及人难以从方法页判断、找到、评论真正生效的方法。不能用再新建一套同义方法来代替修正。

本轮独立方法的实质编制缺口由另两项任务分别承接：实体、状态、关系和素材需求抽取及命名；依据手册产生镜头视频 Prompt。应复用现有方法稳定身份并改成能完成这些工作的正文及模板，或对确有不同输入和交付的工作作有依据的拆分，不简单按对象类型另造方法。

其余环节没有发现足以要求新建独立 SKILL 的缺口。建议另发一项完整任务，将工作方法页改为三个真正子页 Tab 与可见筛选，整理当前方法目录和生效入口，验证现有方法仍能准确进入实际工作。它不重写全部故事，也不替两项内容任务编制方法，不新增审批、调度、永久草稿或执行统计页面。

共用知识只作按需资料：影视知识十二领域、视频手册、连续性、独立读者契约和 Review 适配。它们不各自冒充创作步骤或增加一套执行方法。项目本地的 `task-definition-publish` 服务任务发布，不属于作品创作链；本轮没有证据证明必须把它注册成受管创作执行类型。它继续沿 AGENTS 的实际入口使用，不用增加绑定来追求“所有本地文件都进页面”。

初始资料采编与方向比较目前不在这 12 个受管类型中，但当前用户授权集中在制作抽取、视频 Prompt 和方法管理，没有已查清的采编流程缺陷。本轮将其列为未覆盖工作，不发布虚构的补齐任务。剪辑成片同理：当前没有作品镜头视频和实际成片流程可供验证，不先建空方法承诺能力。

## 准确执行事实与薄弱点

读取正式 resolve 已核对：image → `image-plan`，audio → `voice-song-plan`，video → `video-plan`，project/document/默认 → `media-plan`。`media_method.py` 从需求真实媒体类型决定选择，外部条件不能改媒体类型；draft、review、result 最后进入准确 import 包。小说和剧本入口明确要求方法服务，并要求保存后实际 read 再继续。

实体/状态/视听等工作使用通用作者工具，系统只能证明方法、输入、阶段先后和结果摘要一致，不能证明执行者认真理解或作品已经正确。新的全剧任务必须真正按集、场和当前对象展开，保留能复走的少量判断和真实回读，不可运行一遍字符串替换后补写“已使用 SKILL”。这项验收分别写入两项实体/视频任务，不另建全系统的“方法使用打卡层”。

当前 `production/professional-methods.md`、`managed-methods.md` 部分交接文字仍有“已审方案”“采纳”等历史词。正文已有明确“无逐对象审批”的新条款。目录任务应按本次原则同步易误解的入口用语，把“AI 检查、人的评论、具体输入选择、任务授权”说清，不能因为一个旧词而移除准确选择、付费授权或并发保护。

## 页面任务的具体改后行为

保留“方法 / 共用资料 / 工作环节”三个子页，改成真正的 Tab 视觉与键盘语义，不再用下拉选择承担目录、筛选、版本或方法选择。默认进入“方法”，默认筛选“正在使用”；首次进入按“故事创作 → 生产制作 → 协作辅助”的固定业务顺序选第一个真实生效方法，当前数据应为故事结构，不能再默认未绑定的旧意见措辞。准确深链接优先于默认；返回恢复原筛选、对象、文件、版本、阅读位置和评论草稿。

### 方法子页

- Tab 下平铺“全部 / 故事创作 / 生产制作 / 协作辅助”单选筛选；另用“正在使用 / 全部方法”平铺范围筛选。分组由实际工作类型归属推导，未知新增工作类型进入清楚的“其他”，不能让它消失。
- 下方是可见方法列表，列表项只显示名称及确有助于选择的简短用途。点击直接连续阅读正文；不在页面同时铺满全部方法全文，不以折叠容器藏正文。
- 当前方法头部显示名称、必要用途，以及“用于哪些后续工作”的实际分支和准确方法版本。多分支保留真实不同选择，不凭最新版假装全部已用。
- 方法版本使用平铺版本按钮；默认当前生效选择。有多分支各用不同版本时明确当前所读版本和具体分支，不自动覆盖。待用新版可直接选读；旧评论准确链接继续读原稿。版本多时列表自然换行或独立历史列表，不使用下拉，也不默认展开所有历史正文。
- 保留查看评论、编辑正文、实际所用准确章节链接、必要维护配置入口。元数据和绑定维护仍是明确编辑动作，不默认铺开机器字段；源路径只在需要说明维护归属处简洁可见。
- 删除无价值重复解释和折叠“图示与来源文件”：必要文件通过平铺文件目录/文件类型筛选直接可达；不要把未被当前方法引用的所有源文件都当默认阅读目录。

### 共用资料子页

可见资料列表加平铺类别筛选，选择后直接读文件目录和准确章节。保留源只读属性、原评论、旧版回查、图示/Demo/附件和返回原方法位置。源投影不能反写成第二份可编辑正文。准确版本和文件选择均平铺；缺失材料仍明确报缺，不静默换当前稿。

### 工作环节子页

用相同故事/生产/协作平铺筛选和可见环节列表。点击一个环节，按实际条件展示“何种工作 → 使用哪个方法哪一版”，默认分支与具体条件分支清楚区分。编辑某分支时用可见方法候选列表及平铺版本选择替换现有 select；保持原 JSON 条件类型、精度、顺序及未改条件，不能用界面简化改变匹配语义。新建/删除条件是配置操作，不新增审批。

### 只评论与编辑应用的边界

源码正常方法页当前已有查看评论、编辑、保存/应用，没有方法审批、采纳或审阅决定按钮。根代理已实际确认正常页面这一点，不能编造已存在审批的缺陷。任务要求是不新增这些控件，若公共模式入口或命名让人误以为须审批，则方法页隐藏无关入口或改成阅读/评论表达。现有跨版评论汇总、原摘录、回应稿/当前稿、关闭/重开都继续保留，评论关闭不成为后续执行闸门。

保存有两种现有动作：保存并用于所选后续工作、仅保存待用。两者是配置选择，不是审批，须保留。新步骤取得显式选择的新版本，已开始执行保留原方法及资料；部分应用失败、并发改稿、刷新和继续操作不能丢正文或误改其他分支。

## 可直接进入任务的验收样例

1. 首次打开方法页，默认可见正在使用的方法；无需打开下拉即可选择“生产制作 → 镜头视频方案与 Prompt”，读到真实 SKILL 与引用模板。未绑定旧意见措辞不占默认入口；切“全部方法”或准确旧链接仍能读取它和原评论。
2. 从方法正文打开准确手册章节，直接读模板和原图示，返回仍在原段。快速换 Tab、筛选、文件及浏览器刷新不让迟到请求带回别的方法。桌面及窄屏目录可用，长方法和多版本不依赖下拉框。
3. 在隔离实例给方法正文连续跨段评论，改稿并仅应用一个真实条件分支；新工作经实际入口取到新 SKILL，另一分支和已开始步骤仍取原版。当前稿找到未回应旧意见，能分别读原稿、回应稿、当前稿，关闭后可回查重开；不出现逐项审批。
4. image/audio/video/document/project 的实际 resolve 保持正确；视频 case=dialogue 且 need_sound=true 能取得对应章节，未选择章节不因为 UI 切换而扩张；布尔 true 和文本 "true"、复杂条件、大整数保持原语义。无需调用付费模型。
5. 实际正文编辑、仅保存、部分应用失败和重试、并发冲突正常；正文版本、文件和执行方法选择均无 select。版本多时能读准确旧文件，不拿最新版代替。
6. 更新目录/交接文档，形成上表这种明确“复用/本轮改进/仅参考/尚未覆盖”的最终清单；每个标为可执行的环节必须指向真实入口和准确方法，不将方法存在或测试通过当成创作质量通过。

正式交付终点遵循项目 --auto 规则：双仓受管集成、必要推送、本机正式服务生效及正式只读路径验收、完整导出空实例恢复、过程资源清理。定义会话只调查和发布。两项内容任务与页面任务可以各自隔离并行，页面开发不必等待全剧重编；最终组合验收须看到它们实际新增/更新的同一方法和绑定。共享正式写入仍按序，不因无开发依赖同时写活库。

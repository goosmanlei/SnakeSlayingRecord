## 用户目标与已核现状

用户在持续 Review 第 2 轮明确要求：把每个主要创作、制作环节抽象为系统配置管理的 SKILL，AI 执行相应工作时使用对应方法；影视专业知识和视频生成手册纳入其中，通识可供多个场景共用。随后以当前已确认的故事和小说为依据，重做视听剧本、实体与素材需求、镜头制作方案及生成 Prompt；故事结构、小说方法也纳入管理，此次保留其已确认内容。本任务建立这条重做链的可用基础，不代替后续全剧重做。

根在 2026-10-09 正式 Chrome 的“系统管理→系统与 AI”实际看到：只有图标、评论润色模型、推理强度、Key 环境变量名、参考字符预算，没有工作方法管理或环节绑定。系统当时为 b3bcc830；configuration.py Schema 4 与页面一致，polish.suggest 的模型指令硬编码。制作思路中的方法正文主要供阅读。故事侧 novel_writing/screenplay_writing 是持久化检查点，实际写作者在外部 Agent 会话中；不能假设系统已经有一个自动生成全剧的服务。

现状并非“没有任何方法”：AGENTS、影视章节、视频手册、逐步创作工具与已完成的审查都有效。缺口是方法的系统管理、环节选择、准确共用知识和实际运行输入之间没有可靠连接。不能只增加 SKILL 列表、把现有 Prompt 改名，或给旧成果事后补一条“使用了 SKILL”。

## 交付范围

在既有系统配置中提供清楚、必要的工作方法管理。用户能理解一项 SKILL 用来完成什么工作、在何种情形使用，查看和维护其方法正文、所需输入、产物与检查要求，并管理所引用的共用知识及工作环节绑定。沿现有保存、冲突与版本习惯设计；不另建审批平台、调度器、角色体系或创作过程看板。

SKILL 是能被实际执行者读取的工作方法包，支持必要的 SKILL.md 和按需参考/模板/确定性工具资源；不局限于本机 ~/.codex/skills 或某一模型私有格式。共用知识具有一个有效维护源，多个方法引用准确章节；正文、文件包和页面若互为投影，必须说明权威与同步方向，不能维护两套可独立漂移的正文。系统保存不含密钥、账号或运行私有路径。

实际执行准备需从任务类型及其条件解析已配置方法，取得准确版本的方法、适用的共用资料和当前任务输入，交给真正工作的 Agent 或模型。对后台创作，提供可调用的通用读取/导出与执行关联契约，故事工具在其检查点中消费；对已有系统内评论润色，接入同一方法解析，保留其准确原文、预算、建议需手动采用等既有边界。媒体模型收到的是按方法写好的生成 Prompt 和准确媒体输入，不能把整本手册冒充视频模型需要的最终 Prompt。

在已有后台候选保存、检查点和阶段提交入口接上这项约束：新流程的 AI 产物必须关联实际解析并交给执行者的方法快照、准确项目输入和对应工作步骤，缺失或失配不能被该受管流程当作合格新交付。不能仅提供一个可选下载接口，再接受调用者自己填写 skill_used=true。历史兼容读取保留，旧产物不因无新记录被删或伪造迁移；实际控制范围限于受管入口，不宣称可以技术证明外部模型的内部理解或控制所有任意工具。

核清直接 AI 调用清单，并把故事侧 reader_review.py 的独立读者调用纳入解析接入，保留其不得偷看后文、准确原文和运行配置的保护；旧读者运行继续原冻结配置，不追填方法历史。外部 Agent 的受管启动/恢复取得方法快照，候选保存及提交校验同一工作类型、目标、运行的关联，不能随意借另一任务的读取回执。媒体准备/导出包同时保留制作方案所依据的方法快照、准确输入和来源产物关系，在受管登记、准备和后续调用适配处校验；无需付费生成，也不把方法全文传给媒体模型。

记录足以追溯“这份新产物使用了哪个方法版本、哪些共用资料与准确任务输入”的事实，避免给每个用户卡片默认铺执行日志。变更方法后，新执行使用明确选择的新版；已开始或恢复的执行保留其准确快照，需换法时显式形成新执行依据并检查受影响步骤。旧产物无记录就说明未知，不能回填虚构使用历史。

方法缺失、引用失效、输入不完整及执行恢复冲突应给出具体可修正原因；不静默退回自由 Prompt 或最新版。确定性工具能验证输入身份、方法解析和必要步骤产物，不能证明模型已理解原理；语义应用仍由真实工作和独立检查验证。不强制记录模型内部思维链，不以长日志、字段数量或勾选“已阅读”作为专业质量门槛。

## 实际工作过程

1. 从执行时最新双仓主干和有效数据核对现有配置、正文、方法页、检查点、模型调用与登记入口，列出由系统直接执行和由后台 Agent 执行的实际边界。使用 skill-creator 与 document-writing，明确最小契约及主用户要完成的动作。
2. 先完成一个可用纵向流程：系统中维护一个方法及共享章节，配置一个实际工作环节，执行者取得准确包并在隔离任务中完成一个自然工作单元，产物能反查方法版本。根据使用中的理解/操作成本修正后，再覆盖所需的后台创作与既有评论润色入口。
3. 复走方法编辑、引用共用章节、切换有效版本、同时编辑冲突、恢复旧执行和查看历史产物。用两个不同环节引用同一知识，检查只改一处、旧执行不变、新执行可使用新版。必要单测验证契约，真实页面验证用户动作；模拟请求不当作真实外部 AI 效果。
4. 让独立执行者在只给方法、真实工作请求和最小准确材料的条件下实际完成一个小单元，不给预期答案或先前修正结论。以实际资源读取、前后依赖的阶段产物、回读发现和真实修订反馈观察是否正确应用；执行者自报“已使用”不算充分证据。发现缺口再修订。无须付费生成媒体；采用会话内实际工作可与受控外部请求测试分别报告。
5. 受管双仓交付、正式配置增量发布与真实入口回读，交付后续方法库和全剧重做可实际使用的契约、示例及恢复方式。保留现有作品、评论、认可、原件和准确引用，不以任务快照覆盖活库。

## 核心验收

1. **用户可维护，执行者可取得。** 在最终候选真实页面完成新建/编辑一个方法、绑定实际环节、引用共用资料、保存并重新打开；后台通过正式支持入口取得同一个准确版本和完整必要资源。改为另一适用方法后，新工作确实读取新选择，而非仍用代码中的旧指令。不存在“页面已保存、执行仍自由发挥”的双轨。
2. **知识能共用且按情景加载。** 两个方法共用同一段连续性知识；修改形成新版后，旧执行与旧产物仍指向原文，新执行明确取得新版。视频 Prompt 工作可加载手册的适用模板与参考方法，普通评论润色无需加载全套影视知识。失效章节不可静默跳过，方法和知识的可移植包可恢复同样内容。
3. **真实运行有证据，历史不伪造。** 外部作者的启动/恢复与至少一项现有创作检查点、评论润色和独立读者请求构建、媒体准备包的必要方法关联实际接入。准确输入、方法版本与必要资源可回查，错误工作/目标/运行的回执不能通过新流程提交。受控请求证明发送内容确含所选方法，独立会话工作证明能按方法完成步骤，两者分别报告。没有真实外部调用时不宣称模型效果已验证，旧产物不被假标为使用新方法。
4. **编辑与恢复不改写过去。** 保存冲突不覆盖别人修改；方法更新不改变正在执行的输入；恢复不混用方法新旧版。未知或不可用方法阻止依赖它的新工作并说明怎样恢复，既有只读审阅与非相关功能继续可用。输入锁、原词未定、准确参考和真实生成许可检查仍有效。
5. **为后续重做交付可用基础。** 正式页面与后台读取/准备入口对应同一发布版本；现有方法阅读入口正常，默认审阅卡不增加无助判断的技术栏。以实际迁移和导出恢复核对 Markdown、方法管理与阅读页只有一个生效正文源，旧执行仍恢复其准确资源，旧成果只读审阅不被新方法阻断。主仓/系统仓职责、源与投影关系、接入边界和已验证/未验证范围清楚。完成必要回归、最新主干集成及本任务资源清理，报告具体删除数量、回读结果、保留用途与解除条件。

## 协作与完成边界

primary source=.；desk source=../story-review-desk，目标均 main。通用系统承载方法/共享资源数据管理、配置与读取契约；本故事编剧、逐集判断、制作工作流和工具适配留故事仓，系统不反向导入故事脚本。不把方法内容硬编码在通用 UI。按执行时最新主干，启动、阶段保存和最终候选前吸收实际变化；登记准确跨仓提交引用及工作区守卫，整组受管集成。

本任务无人工制造的同模块前置，可与独立 UI 修复并行准备；正式库、配置、服务和正式镜像标签写入串行。后续方法库任务依赖本任务实际可用契约；本任务只以少量实际方法验证能力，不一次性重做全剧、不重写已确认故事小说、不发起收费媒体调用。既有独立任务保持各自授权。

最终可见回复先写任务号、实际解决的问题和用户可见变化，以“原先改配置不改变创作方法→现在某环节实际取得某版方法”等真实例子说明；再报真实页面、执行关联、受控请求与独立实用的结果和边界、未解决项及下一步。提交号、测试数和清理仅为证据，不代替效果，不把未来全剧收益写成已经实现。

## 执行交付、失败恢复与报告要求

执行阶段遵循上述渐进过程，使用 `skill-creator` 和 `document-writing`；先设计能完成真实工作且保持边界的最小契约。为外部执行者建立的方法入口必须能在受管启动或恢复时取得准确资源，并在后续保存、检查点和提交中核对同一工作类型、目标、运行及必要步骤。包的可移植性通过实际导出和新环境恢复核验，不能依赖创建者机器的私有技能目录或运行路径。

独立实用检验安排在方法可用后。独立执行者只收到方法、真实请求与完成该单元必需的准确材料，不继承作者会话、预期答案或先前修正结论；由实际读取、前后依赖的阶段产物、回读发现和真实修订形成证据。允许在隔离候选中完成小单元，不替换已确认作品。若没有暴露真实问题，不虚构反馈或修订。真实会话工作、受控请求内容检查和外部模型调用分别记录；没有真实调用即保持“外部效果未验证”，不用付费媒体生成补造验收。

启动、阶段成果保存后和准备最终候选前，核对两仓本地目标分支及远端 upstream，吸收实际变化并复验受影响行为。执行中通过任务回调登记准确约束：

```json
{"commit_references":[{"repository":"primary","file":"config/instance.json","pointer":"/review_desk_commit","equals_repository":"desk"}]}
```

同时登记 `scripts/task_workspace_guard.py` 的执行时实际 SHA-256，不能照抄本轮或旧任务摘要。先提交 desk 成果，再更新主仓准确引用，准备整组候选；按 [工作区与交付流程](../production/generation-workspaces.md) 由任务工具负责 Git 集成与必要推送，项目发布脚本消费逐仓回执，在共享窗口增量发布正式配置/业务数据和服务，完成真实页面、后台入口及恢复验证后再结项。冻结或部分交付失败先核对同一回执并沿原包恢复；候选变更须重新准备和验证，不重复未知结果的写入。

迁移方案须明示唯一生效正文源，以及 Markdown、方法管理、阅读页和可移植包的同步方向。以实际迁移、导出和空实例恢复证明没有两套可独立改写且互相漂移的正文；旧运行仍能读取当时的准确资源，旧成果继续可读且方法历史未知，不补造迁移使用记录。既有作品、评论、认可、原件和准确引用保全，不从任务快照覆盖正式活库。

本任务创建的预览容器、过程镜像、测试数据库、缓存、草稿、一次性脚本及外部临时目录均按实际归属和用途收尾。先核对正式/其他活跃任务及恢复引用，再按准确 ID 或路径移除无效项并回读；不做全局清理。交付报告写明实际删除数量和范围、回读结果、保留项用途及解除条件。必要交付和恢复资料保留；活跃会话仍使用的 worktree 先清理无效过程数据，退出释放锁后由受管入口退役，不强删，也不以未来任务基线为由永久保留。

最终可见回复（失败、暂停时同样适用）必须先给任务号、原先的问题、实际完成到哪里和用户可见变化，并给一条真实的“原先改配置不改变创作方法 → 现在具体环节实际取得某版方法”的前后例子。随后分别说明真实页面操作、执行关联、受控请求内容、独立实用检验的结果与边界，以及未解决项和下一步。提交号、测试数量、清理记录只作证据，不能代替效果；本项没有完成的全剧重做或未来收益不得声称已经实现。

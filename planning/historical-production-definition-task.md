# 优化任务：在历史设计中核对当时的准确制作需求与方案

本规划用于本受管任务的独立执行与验收。用户比较旧镜头或实体状态时，需要知道当时要求什么、准备怎样制作，再与当前准备方案作判断。当前历史镜头正文准确，但素材区可能展示同一素材身份下已经更新的准备方案，既没有解释它属于新版设计，也没有在这条路径提供当时方案的阅读入口。本任务修复这段历史制作读取与操作归属，不重做作品内容、素材质量或全站历史管理。

本规划中，Prompt 指生成提示词，CALL 指已登记的真实模型调用记录，UI 指用户实际操作的页面，DB 指数据库，AV 指视听制作。设计修订与素材制作版本是不同对象，具体约束见下文。任务编号、状态、仓库和附件位置以主项目 `.codex-task/tasks.json` 为准，不在正文预写任务编号。除明确注明的附属仓文件外，项目内路径均相对故事仓根目录；仓库 source 始终相对主项目解析。

## 目标与保护要求

历史设计中的素材阅读首先要能回答“这版设计当时有哪些准确需求，方案是什么”。沿已有准确归属和不可变修订提供相应内容；若用户还需要看同一素材身份的当前准备方案，让两者的关系与当前审阅对象清楚，并能返回原设计上下文。利用现有历史读取、共用卡、准确引用及返回能力选择最小方案，不预设新增页面、额外审批、比较看板或到处增加版本标签。只加标签、仍让用户看不见原方案，不算完成。

“当时方案”指能由该准确设计修订和明确关联证明的需求／方案记录，不按时间最近、同名、同一素材版号或当前对象头猜测。若同一设计修订下有多个需求修订，沿现有可证归属明确默认选取及进一步读取，不把“最新绑定此准确设计的需求”冒充未经保存的某次时间快照。已有准确旧记录可读；没有记录的字段或方案明确缺失，不用当前定义填充，不反推一次未发生的真实调用。

当前准备方案仍可在原未冻结制作版本继续修改。当前方案、历史需求、实际调用和真实候选保持各自身份；不为显示历史强行冻结草稿、复制素材、修改原件、增加虚假候选或新建一套版本账本。已冻结 CALL 的输入、参数、Prompt 和原件不改，旧人工判断、采纳、采用与评论不自动迁移到新版。

评论只能绑定用户实际阅读的准确对象、修订和块；查看旧方案时可用的评论能力沿既有规则保留。历史阅读不新增采纳或参考编辑许可：旧设计／旧需求不可变，转到可编辑的当前方案必须使用户知道目标；参考调整必须属于明确的当前消费者、方案版本和槽位，旧画面下的操作不得暗中修改另一版。历史已有候选的读取或比较不等于采用；采纳内容、选择参考和认可原件继续分开。

同类实体状态历史入口需要核查，但没有已证全站故障。独立 Review 此前在 EN101 全实体卡读到当前状态、再切 ST268，属于全实体阅读，不足以证明历史状态替换错误。执行时从真实状态版本控件或准确旧链接取一个有前后需求的实际样本，核对是否共用同一问题机制；成立时纳入相同契约修复，正常则保留对照。不得据共用函数名扩展为所有历史页面重构、所有状态失效或自动继承旧素材任务。

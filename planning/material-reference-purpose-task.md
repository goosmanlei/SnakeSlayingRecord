# 素材参考、旧备选与沿用用途的审阅任务

让用户打开一张素材卡，就能理解它参考了什么、哪些只是待比较的旧素材、哪些方案准备沿用它，以及已有真实结果时如何检查并留下准确意见。用户不应靠逐个打开“上游／下游／适用位置”、记忆来源和重复阅读模板来还原含义。

本文是 task-20261009-0017 的完整执行规格；澄清会话只整理并发布任务，产品修改和验收留给后续执行。本文未另注的文件路径以故事任务 worktree 为基准；仓库 source 和证据来源路径明确以主项目为基准。任务发布、执行和完成状态只认主项目 `.codex-task/tasks.json`，不复制到 STATE.md。

## 任务字段与判断

| 字段 | 内容 |

| 摘要 | 让素材参考、旧备选与沿用用途直接可读，保留准确关系意见和未生成事实 |

复杂度来自参考语义、准确版本、关系意见归属、导航上下文及真实页面验证需要共同收敛，超过局部文案替换；范围清楚，沿用已有能力，无需升级为极复杂。按当前模型策略采用复杂档默认 xhigh。没有相对 xhigh／max 明确可验证的自动委派收益，不选 ultra，也不因材料多或能够分工而升级。减少辨认与重复查找成本是预期，具体效果以实际工作观察验收，不承诺固定提速或质量提升。

并行判断：本任务负责素材参考用途的准确表达与关系审阅，与 task-20261009-0007 检索返回、0008 状态准备、0009 人工判断、0011 准确选取、0013 逐镜阅读、0015 并行草稿和 0016 媒体定位职责可分，无强制前置。两仓各用受管独立 worktree、测试数据库、缓存、写入目录、端口和浏览器测试存储，可并行开发验证并协调浏览器控制。共同素材卡、评论和导航的实际重叠在集成时吸收最新主干、解决冲突并联合复验；共享正式数据库、配置、服务、部署入口、正式镜像标签及发布写入必须互斥串行。资源不能隔离或实质语义冲突不能独立收敛时停止对应并行部分重新评估，并行属性不授权并发正式发布。

## 目标和设计范围

围绕同一次真实工作：理解当前素材方案／结果 → 核对其依据与参考职责 → 比较确有价值的备选 → 查看沿用它的相关方案或结果 → 留下准确意见 → 返回继续审阅。整合现有素材详情、参考输入、候选与关联用途的表达，不增加另一套关系管理页面、永久看板或新概念体系。

1. 当前素材方案声明的参考和逻辑依据可直接识别名称、内容与用途。明确区分方案声明直接参考、已经选定具体原件、真实调用确实使用：M2710／M2887 列出了计划输入，并不证明已选好文件或完成调用。仅用于解释设计的逻辑依据、尚未选中的旧候选也不与它们混淆；无需因此强制新增一套状态标签，已有列表能承载时优先复用。展示的参考职责与准确 Prompt 字段相互对应，不把所有关系自动塞入 Prompt 或上传为输入。
2. 沿用当前素材的下游能直接看出对象及所处阶段，并可查看准确方案／结果。尚无原件、已有候选、已有准确判断分别保持事实，不把依赖计划当成调用回执。选择某一素材版本后只陈述可证的关系，历史关系、实际输入或准确版本不明时如实处理，不从最新版本反推旧生成来历。
3. 待比较旧素材仍可发现和打开，但不与已采用参考混淆。相同的复用前提可以共同表达，个体条目展示识别与判断所需差异；不重复六遍相同说明，也不擅自删除候选或替用户采纳。
4. 审阅入口由判断对象决定。同一决定的重复嵌套评论边框、空按钮和回到当前对象的无效导航应收敛；需要评论“参考用法”和“生成结果”时，清楚保留其不同归属。删除低价值展示不删除准确关系、历史意见、版本或回执。
5. 未生成图像不占用一幅高大空画布；实体／状态引用下的“记录修订 1”等内部标签不默认占据主要阅读位置。必要的版本选择、历史区别及准确追溯仍可用，不把所有编号和版本一概隐藏。

本任务调整现有内容的准确表达，不重新决定参考适用性、选择或采纳，不批量重写 Prompt 或视听稿。发现制作决定本身矛盾时记录并交对应内容任务。本任务不生成素材、不扩展付费调用，不根据“参考”二字自动串起所有间接关系。与下方列明的同项目任务复用共同能力；这些目标未完整覆盖本问题，不设置没有实际必要的串行前置。全程不生成媒体，不调用外部 AI 或付费服务，不消耗历史生成授权。

## 实施方法与过程验收

先阅读项目产品价值规则、`production/filmcraft/README.md` 和 `production/filmcraft/08-design.md`，以及 `production/seedance-video-handbook.md` 的准确参考、参考职责和逻辑／实际输入部分，再以执行时最新双仓主干和有效正式数据在本任务隔离环境复现上述工作。采用“真实理解 → 最小可运行候选 → 实践观察 → 根据反馈调整 → 正式原路复验”的完整方法，过程随实际工作保留，不事后补写成已经实践。依次走角色母版→状态需求→已有旧原件，再走场景母版→状态图，最后走镜头的直接参考和逻辑依据。每一步记录用户此时要作的判断、现有信息是否支撑、多付出哪些查找或记忆成本，以及已经正常的分支。

据这些观察明确最小信息组织方案，比较保留／整合现有参考区的可行方式，先在代表性真实卡片上完整走通。对不同语义作必要区分，而不是每个内部关系类型都新增一种 UI。实际打开参考、返回、展开下游并检查既有意见后，再据体验修正。若当前没有真实历史关系意见，明确该事实，用隔离测试意见和必要夹具验证保护契约，不声称已经实操过不存在的旧意见。批量替换标题、一次性生成一堆说明文字或只数 DOM 节点，不能代替上述过程。

审阅写入只在隔离实例使用明确标记的测试意见；正式入口只读复核。至少实践一条“参考用法意见”和一条“结果图意见”，检查列表、定位及重开后的归属，不能因界面简化把二者混为同一评论。无法实际覆盖的历史／缺失分支，用最小必要自动检查验证契约并说明边界，不伪造真实素材或过程。

## 可验证的完成标准

1. **M2544 的 12 个关系能被正确理解。** 不查看实现、无需逐个点击匿名按钮，就能认出六个旧候选的名称及“尚未选择”的含义；六个状态需求是准备沿用它的计划，未生成时不声称已有衍生图片。M1189“嗓哑”旧候选仍可查看；M2710 可以打开其准确方案，并能返回原卡继续比较。不得为了让列表漂亮而将六个候选都写成已用输入。
2. **当前参考能与 Prompt 对照。** M2710 的身份参考 M2544、M2887 的布局参考 M2624，在列表中的名称、用途、准确版本与 Prompt 对应；没有第二套重复关系列表要求用户自行对账。M1516 中 EN101／ST269 的文字依据仍可打开，但不假称曾作为图片上传。镜头直接媒体输入与逻辑参考同样不混用，不自动把全部间接来源展开成输入。
3. **下游是检查结果的入口。** 从母版查看沿用对象时，可以识别具体状态或镜头、打开准确方案或已有候选；能看清“待生成”与真实原件的差别。没有生成回执就不写“已生成”；旧候选未被选用时不伪造生成血缘。必要版本追溯及返回上下文可用，不用三枚相同抽象按钮代替对象名称。实际重走 M2710 展开 47 条关系→沿视频关系打开 M2975／ASH001 的路径，能扫描具体状态／镜头用途并核对图片2＝M2710及各输入职责；不把计划引用当已选原件或真实调用。
4. **评论对应实际判断。** 对“这张母版是否适用于日常青衣状态／应保持什么”这一准确决定不出现重复入口，新提交的用途文字意见不被误称为历史整体意见；对 M1516 的画面问题仍用现有图像圈选或整图评论。针对 M1189 的适用性写测试意见，再切到 M1133，意见和草稿不能跟过去；返回、重开及定位后仍指向原关系。共同复用说明不让单条意见无依据覆盖六个候选；不同实际决定可以有各自必要入口。结果图意见仍落在准确原件，不重复显示，不丢旧关系意见，不把用途意见迁成图像意见。先给出选定审阅对象的理由，再以真实操作验收，不能只以“嵌套层数减少”通过。
5. **无图与有图均方便审阅。** 在实际桌面窗口和一种窄窗口中检查 M2544 与 M1516：未生成图像用紧凑方式说明状态，素材要求与方案不再被高大空白挤走；真实图像保持完整查看、放大、圈选与下载能力。实体／状态参考不再每项重复“记录修订 1”，但需要识别准确旧版本时仍有明确办法。检查内容不溢出、按钮可点及必要返回位置，不以截图尺寸代替实际操作。
6. **结果、边界与正式交付可核查。** 实际核对角色、场景、镜头；无原件与有原件；直接输入、逻辑依据、旧备选；准确当前与历史引用。保留正常反例，逐项区分页面实践、自动契约检查与仍未验证项。过程须有真实理解→最小可运行候选→实践观察→据反馈调整→正式原路复验的实际记录，不能以批量改标题、数 DOM 节点或事后补截图代替。测试评论只写隔离实例；当前没有真实历史关系意见或已生成下游时如实报告，用最小必要夹具检验保护契约，不能伪造历史或声称已覆盖真实业务。按执行时最新双仓主干集成、共享写入窗口串行正式发布，再从正式原路径只读复验；API／自动检查不代替页面验收，浏览器受阻保留待验。执行阶段登记并验证准确系统提交引用和实际 cleanup 检查器摘要；完成项目规则要求的清理，报告实际删除数量／范围、准确 ID／路径回读和保留用途及解除条件，不能拿候选预览当成正式交付。全程无媒体生成、外部 AI／付费调用或批量 Prompt 改写；保留历史、版本、原件、评论、采纳及真实回执。

本项同时验收最终可见交付说明：每次会话结束，最终可见回复先给 task-20261009-0017 和普通语言的原问题（素材卡把参考、旧备选和沿用计划混在抽象关系里，用户难以判断用途及正确留言对象），随后说明本次实际解决了什么、用户现在能怎样使用，以及真实验证环境、验证边界、还缺什么和下一步。至少给一处真实前后例子，例如“原来 M2544 六行看不出是哪张旧图；现在直接看到名称与待比较身份，并能打开准确原件”。预期效果不能写成已经实现；暂停、失败或部分完成时也要说明实际做到哪里。提交、测试数量和资源清理证据附后，不能代替结果说明。

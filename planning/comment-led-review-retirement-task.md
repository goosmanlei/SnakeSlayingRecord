# 取消逐项审批：清理送审对象与审阅决定，用评论承接意见和整改回查

人在审阅台阅读作品、看素材、听声音后，应能直接表达意见，AI 根据意见理解问题、修改并给出可回查的结果。当前系统把这项工作拆成评论、实体送审包、设计／方案采纳、原件认可、变更决定等多套记录；页面有“认可此设计”“记录本版本审阅结论”等操作，后台还会因没有采纳而阻断准备。用户已决定取消这种逐对象审批工作。本任务在前置任务交付基础上完成全系统退出，不只删按钮。

改后，以 M1134 阿蘅基础音色为例：用户打开准确版本和候选，试听并评论；AI 读取该原件及相关上下文，整改或解释理由，把实际改变及对应版本回到这条意见下。用户可以继续评论，不需要再点通过、拒绝、撤销认可或确认整改通过。旧有“认可；不补”保留为当时针对该准确母版的历史意见，不再成为后续生成的批准凭证。

## 已定范围和取舍

### 1. 送审包装与审批实体退出整个系统

制作设定审阅对象（业务编号 RV，存储类型 REPRESENTATION）、旧实体送审包，以及独立审阅决定（DC／JUDGMENT）不再作为有效业务实体。删除其新建、写入、查询投影、页面入口、编号类型说明、独占数据及正常恢复再生能力。全系统检查包括故事结构确认、实体及状态、视听集场镜、素材方案、原件与变更复核，不能只处理生产制作某一个卡片。

当前正式数据只读盘点有 95 个 RV，全部为 entity-review-v1 的旧实体送审包；193 个 DC、202 个修订。数字是调查基线，不作为执行时固定删除数量。对通用 REPRESENTATION 曾允许的身份、声音、布局等描述，若执行时确有独有有效内容，归回对应实体、状态或实际制作方案后再退出包装；不能随包装丢掉作品信息，也不能为了保留空泛可能性继续保留 RV。

界面删除“认可此设计”“采纳此版”“记录本版本审阅结论”、同义审批／撤销操作、待审批／已批准状态、采纳范围与理由、审批历史面板及无价值提示。不将它们改名、折叠、搬进新页面或换成隐含审批。保留前置任务已经形成的必要作品、生成结果、方案、版本／候选浏览和评论；普通保存、版本浏览、评论润色的“采用建议”等不是审批，不按文字匹配误删。

### 2. 复用评论完成反馈与回查

沿现有准确评论、评论事件和回应／历史意见复核能力承接，必要时补齐生产对象适配，不新建审阅任务、处理决定或新调度框架。

- 用户从正在看的文字块、图像区域、音视频片段或生成方案发出评论，绑定当时准确对象、修订和锚点。评论列表沿既有独立右侧浮窗，打开、关闭不改变正文宽度、阅读位置及未提交草稿。意见内容直接可读，不折叠。
- AI 在实际获授权的创作／执行步骤读取意见及必要上下文；修改后，用现有回应方式说明哪条意见、改了什么、对应哪个准确新版本和局部；暂不修改则解释原因与剩余问题。回应不触发自动审批，不要求用户必须关闭评论才继续工作，不自动启动付费生成或无人值守整改。现有评论关闭／重开只是意见整理状态，不改变对象可用性或“已通过”状态。
- 在原评论可以打开实际修改的准确内容，并返回原阅读现场；切换当前版本不把旧意见冒充对新版本的意见，也不偷偷改原锚点。缺失旧目标明确说明缺失，不跳到最新版本。
- 用户未评论不等于认可质量；AI 自检、真实用户反馈、机器检测结果分别如实表达。不要增加遍布正文的“未审阅”“待比较”“无意见”等提示。

当前系统的回应复核实现主要面向资料与故事结构，并不能声称已支持全部生产对象。补齐它仅为本任务所需的“原意见→实际修改→回到原文”路径，不扩张为评论管理平台。通用能力放审阅台，故事特有的读意见和创作执行方法留故事项目。

### 3. 删除审批前提，保留准确输入与底层选择

从生成准备、执行包、发布／登记校验、故事推进和变更复核中去掉“未采纳”“未认可”“需要人先消解影响”等审批前提。没有 DC、没有用户评论的完整方案，在已有任务授权内可以通过准备和校验。这个结果不能靠自动补写 accepted、根据评论推算批准，或把审批记录改成另一种实体实现。

保留真实技术和内容一致性约束：来源和方法绑定、准确对象／修订匹配、文件存在及哈希、参数和参考输入可用性、依赖环、输入锁、已冻结方案定义等。新上游版本出现时，旧方案仍明确固定旧引用，不能静默变成新版本；这以准确旧输入仍有效可用为前提，真实缺失、已撤回或输入不一致继续按实际约束处理；切换新输入应由 AI 按方法重读并修订方案和依赖，系统验证新引用一致，不让人填写一次变更通过决定。已冻结调用不原地换输入。

素材需求是依赖对象；真正用于生成的输入落实为准确素材版本、候选、组成／文件及必要片段或裁切。**本任务仅保留、解耦并验证这些底层数据的存取、解析、冻结和校验，以及现有有效选择能力；不设计新选择界面，不新增 AI 自动选择策略。**若旧“采用”同时写审批和准确选择，拆掉审批副作用，保留选择事实。未来选择体验由用户另行提任务。

任务授权、付费额度、正式写入和部署权限仍按原委托管理，不把内容免审批解释为无限执行授权，也不另建逐对象授权界面。

### 4. 历史迁移有明确去向，不留一套影子审批库

迁移在准确隔离库先完成，并随候选交付可复跑、可核验的增量和恢复能力。按准确对象及修订盘点、分类后处理所有 RV/DC 历史修订，不能只删当前头。

| 原有内容 | 本任务处理 |
| --- | --- |
| 用户真实意见、带理由的认可或异议 | 已有准确评论则复用并补必要来源，避免重复；只有决定中存在时迁入现有评论体系，保留原话、原作者、原发生时间、准确对象／锚点和原记录来源。标为历史导入，不能伪装成今天的新发言。 |
| AI 检查结论或转述 | 有独有判断价值的，作为 AI 历史说明／回应保存并标明主体；不得变成用户意见或伪称已看听。已有作品说明／评论完整覆盖时不再复制。 |
| 只有通过、取消、待审等流程状态和套话 | 删除，不逐条转成评论。没有实际意见的批准／撤销循环不形成评论垃圾。 |
| 准确版本、候选、组成或片段的选择 | 保持在原准确选择机制；不能靠保存 DC 才能读取。 |
| 冻结调用曾引用旧审批 | 保持真实 CALL 原始正文、修订身份、方法快照、调用及原件事实；复用现有最小退役身份／摘要和失效引用凭据解释旧引用，不复活决定实体，不替换为新批准。 |

具体两例必须处理正确：DC060 的“1. 认可；2. 不补”目前没有原件评论，迁为 M1134 对应准确原件的历史意见，并保留“仅此母版、不代表派生或镜头效果”的原范围；《三道滩》短样“曲调是保留的，但是发音仍然是不准的”已有准确评论，不能再复制一条。作品中的“已确认剧本版本四”及输入锁保留其已经发生的事实和准确制作依据，不因取消审批重做故事或撤销有效成果。

已核实有 139 个 CALL、278 个修订的 492 条历史依赖引用 DC。审阅台已有 consolidation 退役凭据，能保存旧身份／哈希和调用中的失效引用路径；优先复用这条路径，物理移除 RV/DC 对象正文和修订，同时保持真实 CALL 哈希与原件不变。迁移来源可用现有 comment_events 或最小评论来源元数据表达，不另建可写历史审批模型。不能保留整份旧实体正文到新表、恢复包或所谓兼容实体里，宣称已物理清理。

迁移回执记录准确输入、分类和每条旧记录的去向／删除理由、引用处理、保护数据对照及实际数量，作为必要交付证据，不进入创作界面。旧导入端点不得重建 RV/DC；准确旧链接可以解释已退役及对应历史意见，不能映射到另一个最新对象。正常完整导出→新空库恢复不复活审批。

### 5. 当前方法和入口一并改正

同步仍生效的 SKILL、工作类型方法绑定、生成手册／工具、导入导出与恢复、项目 KNOWLEDGE／STATE 和系统说明中的审批要求，明确以评论理解和整改、准确输入及实际质量检查推进。按现有受管方法规则追加当前方法版本／绑定，旧执行使用的冻结方法仍按历史保留，不伪改为新流程。已确认故事、小说、剧本、有效素材和原始意见保持；本任务不重做全剧、不改变审美或改写作品正文。

## 真实工作与验收

先在执行时最新双仓主干和有效正式导出的隔离副本中，核验已交付前置迁移，再完成以下工作。前置任务 completed 不代表正式库已部署，要验证从有效正式导出经过前置迁移到本任务终态的完整路径。方法、模型和浏览器写入均只指隔离环境。

1. **阅读并评论，不再逐项审批。** 覆盖故事结构、实体／状态大卡、视听镜头、素材方案与真实原件。从 M1134 打开准确原件及评论，看到原历史意见的作者、时间、范围；从实体和镜头进入同一准确原件看到同一评论，不复制意见。所有入口无 RV/DC 入口、审批按钮、审批状态与审批折叠面板。前置 0015／0016 简化后的必要布局不退回。
2. **走完一次实际反馈和回查。** 隔离环境里针对一个可确定的非创作性方案说明问题发一条标明测试的评论，依正确上下文作真实局部修订，登记实际回应；从原评论打开准确改后版本、核对差异、返回。保存、刷新、退出重开，原意见和回应仍在准确目标。评论面板打开前后正文位置／宽度保持，草稿和其他对象评论不串。另用文字、图片区域、音视频时间锚点分别核对迁移与定位；实际声画检查须打开观看／试听，不能以字幕或 API 成功代替。无必要不生成新媒体。
3. **免审批准备和真实错误的对照。** 同一完整方案无任何 DC 和评论也能通过生成准备／包校验；正常准确输入选择读写和冻结有效。至少验证跨对象错修订、缺失文件、过期／改变的冻结输入、依赖环或无效参数仍被准确拒绝。上游改版后旧引用不自动切新，新方案换输入无需人工批准。不付费发起生成，仅验证准备契约与已有真实 CALL。
4. **历史归属与物理退出。** DC060 成为准确历史意见；《三道滩》已有意见不重复，用户意见不被改为 AI 判断或相反结论。纯审批循环不形成评论。输入锁、已确认作品及全部有效原件、准确选择、无关评论／事件不变。RV/DC 当前和历史对象正文、修订及可写入口全部退出，删除范围和异常有回执；冻结 CALL 原正文哈希不变，旧引用可解释且不阻断新的正常准备。
5. **完整恢复与反复迁移。** 包括现有历史 CALL、上述用户反馈、生产回应、准确候选／片段在内的完整导出在新空库恢复成功；再次运行迁移不重复评论、不二次删除有效内容，旧包／旧端点不会复活审批实体。新实例与迁移实例都没有 RV/DC 活跃能力。自动检查覆盖必要迁移和引用约束；Chrome 实际验证关键路径，不能只有源码或测试数量。

任务定义样例 [sample.html](comment-led-review-retirement/sample.html) 只验证评论浮窗、历史意见可读和关闭／重开／刷新路径，演示回应是预置文本，未加载声音，未连接真实后端，不能算本任务实现或跨类型验收。模型、依赖和原件准确身份见 [证据入口](comment-led-review-retirement/README.md)。

## 依赖、隔离与交付

本任务唯一直接依赖 **task-20261010-0018**，传递依赖 0015、0016。0018 正在统一关系和其准确输入、生成准备、恢复消费者，并明确保留旧许可／采用；本任务在它交付后按用户新决定替代其中审批部分，保留其关系和准确选择成果。不修改前置任务承诺，不因同文件就另加依赖，不恢复 0022／0023。

一个任务覆盖 primary 故事仓与 desk 通用审阅台（主项目相邻 `../story-review-desk`），两仓写入并交付 main；按 [工作区与交付规则](../production/generation-workspaces.md) 由受管工具纳管。执行时登记准确 `config/instance.json` 的 `/review_desk_commit` 等于 desk 候选提交的引用约束及 `scripts/task_workspace_guard.py` 的现行摘要。使用本任务独立库、服务端口、媒体目录、浏览器存储、容器和镜像标签；正式业务库及服务只读，共享发布另行协调。

优先级高，复杂度极高：关键工作是撤掉跨对象审批依赖，同时保存历史用户意见、准确选择和不可变真实调用，不是大规模改写内容。建议 gpt-6-astra／max 承接这一次跨模型清理。

本次授权终点是双仓受管 Git 候选交付、隔离迁移与真实交互验收、可用的迁移／恢复包及收尾。**不部署、不改正式库、不改正式创作内容、不付费生成，不恢复持续 Review。** 正式生效要另获授权，不能把候选验收写成用户正在使用的页面已改变。

最终回复必须先写任务编号和实际解决的问题，再用具体前后例说明变化、收益、准确版本与环境、验证边界、未解决事项及下一步。明确执行者验收、正式交付／部署和负责人独立复验的不同状态；按 AGENTS 给出本任务过程资源实际删除数量／范围、回读结果和仍保留资源的用途。无效过程资源清理完成，保留必要原件、历史来源、准确回执和验收证据。

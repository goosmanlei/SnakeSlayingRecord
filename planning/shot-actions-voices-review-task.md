# 优化任务：从准确镜头事件形成动作与声音方案

本文件为镜头动作与声音方案优化任务的正式规划，供执行者按准确故事依据修正编制流程和制作内容，并供审阅者核验成果。任务发布、执行和完成状态以主项目 `.codex-task/tasks.json` 为唯一权威。本次澄清会话仅整理规划并发布任务，不执行优化；后续执行以本规划、执行时有效制作输入和项目既有权威入口为准，不依赖系统 Review 的临时容器、数据库或本机调查文件。

## 任务字段与执行边界

- 摘要：从准确镜头事件形成动作与声音方案，修复整场事件混入及叙述式发声遗漏。
- 优先级：P1。
- 复杂度：极复杂；模型 `gpt-6-astra`，推理强度 `max`。全剧逐场、逐集及跨镜语义复核需要与故事编制共同原因修正统一收敛，不能只修八个示例，因此使用高于默认的推理强度。未见相对 `max` 可验证的独立委派收益，不选择 `ultra`。
- 同项目强制前置：无。与 `task-20261009-0002` 的通用素材卡、来源投影及准确引用目标独立，不添加人为依赖。
- 可并行：是。故事编制与制作内容可在独立受管 worktree、测试数据库、缓存、写入目录和端口内开发与验证；与 `task-20261009-0002` 集成时复验准确引用及正式页面路径。共享正式数据库、服务、部署入口与正式镜像标签写入必须协调串行；并行属性不授权并发正式发布。
- 本任务不提交真实图像、声音或视频生成，不消耗历史额度，不把方案修正写成素材就绪或作品成片通过。执行完成仍须满足下述隔离及正式 UI 验收。

## 用户目标与已证实问题

制作者需要从准确剧情得到可直接判断和准备的镜头方案：本镜谁做什么、谁先说或唱、在哪里停下，以及哪些条件需要延续。审阅者应能从同一方案看懂这些关系，无需反复从整场说明和正文中重建时间线。

当前制作稿已包含有价值的逐镜设计，但生成编制将不同层级的内容机械拼合，造成两类同源转译问题：

1. 整场动态事件直接进入每镜执行指令。ASH001/M2975 仅覆盖 s001:1-3，却要求后续的李寄入场与老汉接唱扑空；ASH152/M3435 当前是放饵、撤手、关前门、上闩和推验，却混入前后镜的验北栓、提闸及撞门落闸全过程；ASH218/M3651 的夜间卧铺镜混入后续摆碗、夜转晨和黎明声音。额外的“不得抢先信息”不能消除同时存在的相反命令。
2. 叙述中已明确的发声没有完整进入声音方案。ASH206/M3615 漏梁书吏读回母亲证词的声音身份；ASH315/M3989、ASH325/M4019 漏母亲哼唱；ASH322/M4010 有阿蘅念词和母亲低哼，却只有首帧输入；ASH328/M4028 仅配置窗外呼唤者，漏李寄回答“来了”。这些不是尚未写好的新剧情，准确正文与逐镜稿已经要求发生。

共同原因是未把准确来源中的镜头事件、必要背景、镜间交接和真实发声完整转译为制作选择。具体线索为 `scripts/audiovisual_design.py:297-306` 的整场字段继承、`scripts/audiovisual_materials.py:258,286-289` 的 Prompt 拼接，以及同文件 `speakers()` 的冒号正则加 `production/audiovisual/voices.py` 中少数 `EMBEDDED` 补充位置。执行时复核最新代码和正式数据，不仅对示例加硬编码。

当前没有本剧已生成镜头视频。已证实的是方案内部矛盾与必要声音身份遗漏，不能写成实际成片已错人、串戏或漏唱。现有方案采纳和准确参考就绪闸门应保留。

## 目标、范围与预期

以执行时全剧当前有效剧本输入锁及制作成果为依据，修正动作与声音方案形成的共同原因，并逐场语义复核当前全部镜头和相关首帧/视频方案。保留适用的固定空间、轴线、风格与持续状态；整场事件只在应执行的镜头发生，声音顺序、说话/演唱身份、明确原词和未指定原词各自有正确依据。发现现行拆镜无法承接时允许有依据调整，不能锁死本轮观察到的镜数、段数或总估时。

从已读影视知识中按问题采用叙事信息、调度、表演、剪辑、声音及 AI 转译原理，并应用 `production/seedance-video-handbook.md`。这些文件是现成权威，不重写知识库，不把十二领域变成每镜必填字段。作者稿里已有的正确设计优先保留；不从零重做已完成的 task-20261008-0004。

声音检查覆盖对白、叙述中答话、读回、哼唱、接唱、画外声及群体声音。复用准确角色和既有音色需求，区分明确原词、仅明确含义及非语言声音；不编造未锁定词句，不为每次声响强制新增人物、实体或逐句台词库。参考暂未生成或未选时如实标待准备，不将方案修正等同于素材已就绪。

预期减少审阅者重建动作/发声顺序的理解成本，减少后续生成时提前演出、遗漏发声和角色声线不一致的返工风险。当前没有真实耗时或生成费用对照，不承诺节约百分比。优先让现有方案表达准确，确需改变界面交互时先以可运行候选验证用户判断是否更容易，不默认添加新栏目。

本任务不包含渠道模式与首帧角色契约重构、连续歌曲制作、机位需求去重或所有参考路线重构；这些仍由 Review 独立澄清。不得提交真实图像、声音或视频生成，也不消耗既有历史授权。无需外部研究或重建参考手册。

## 验收标准

1. **具体情景回归。** 上述八个镜头按准确来源和相邻镜复核，记录实际采用的处理与依据。ASH001/ASH152/ASH218 不再执行分属前后镜的事件，仍保留本镜所需空间与持续条件；五个发声样例中，说话或演唱身份、顺序、已给原词及出声方式均与来源一致，图像、声音输入职责与 Prompt 对应。未指定词句保持真实不确定性，缺声音素材明确待准备。
2. **全剧语义范围。** 复核执行时全部有效制作稿，以场汇总保留、修订和待准备判断；每集连看镜头顺序，再核跨集持续状态与重要人物知情关系。检查起点—变化—落点、物品归属与接触顺序、声音发出/持续/停止、前镜落点与后镜起点。不能仅以段落无遗漏、字段非空、正则命中或八例通过替代全剧复核。记录应足以复查，避免逐字段制造机械留痕。
3. **共同原因修正。** 编制流程可重现本次正确方案，后续重新编制不恢复整场污染或丢掉叙述式发声。必要自动回归覆盖层级事件混入、一个叙述段内多个发声者、读回、哼唱与画外回答等语义边界；同时保留场级固定条件、纯提及不新增出场、背景群声无需无差别独立选角等反例。
4. **真实审阅闭环。** 在隔离候选中实际打开修正后的视听镜头、准确来源及相关素材完整方案，检查用户可读的动作顺序、声音身份与参考职责；必要评论/采纳测试仅在隔离实例进行。按现有发布流程完成正式增量发布后，从正式 UI 原入口只读回查上述情景及另一集代表场景，核对实际运行版本与准确方案。代码、接口或导出通过不能替代页面读回。
5. **历史与状态准确。** 当前方案变化按现有不可变修订与方案版本机制发布；保留已有真实调用、原件、评论、采纳和准确来源，不把旧认可迁给新内容或自动采纳新方案，不用任务快照覆盖正式库。原内容正确且无需改变时不制造无效修订。报告区分方案验收、接口检查、候选页面和正式页面验收；无实际视频时明确保留真实表演/音质待验项。
6. **交付与清理。** 遵循项目任务隔离、最新主干集成、正式写入串行和过程资源清理规则。说明实际变更范围、验证证据、尚未准备的参考及实际清理结果；不能因没有付费生成而把必要方案与 UI 验收留空。

# 镜头视频 Prompt 方法与全剧重编调查

供本轮任务定义与发布使用，2026-10-12；完整任务见[任务正文](video-skill-full-work-task.md)。本文代码与数据路径相对故事仓库根目录。原资料／数据调查仅查阅项目方法、当前正式数据和相关工具；未操作页面、未观看或试听本次引用媒体，未修改正式数据、注册方法或生成视频。页面实践由主会话独立承担。下述方案样例是文本层面的任务验收方向，不是已完成、可直接提交或实片效果通过的 Prompt。

## 应怎样定义这项工作

已有专门的“镜头视频方案与 Prompt”SKILL，问题不能定义成系统尚无视频 SKILL。应把现有 `method.skill.video-plan` 实质编成可执行的镜头视频 Prompt 创作方法，并用它按集、场、镜重新完成全剧 344 项当前视频方案的 Prompt。保留同一方法身份、评论与旧执行，升级其正文、模板引用及实际入口，不再造第二个作用相同的方法。

应交付两个相互兑现的结果：系统管理中能读、评论、优化这份方法；新作品确实通过该方法理解镜头、选择参考职责、拟稿、回读修订，最后形成清楚且无内部说明的模型指令。只更新 SKILL、给旧 Prompt 加几个标题或一段共用前缀，均不完成本项任务。

## 当前证据与范围

本次来源为故事主干 `828a5799e683f0146a419a5967011cd4b9a7bdaa`、审阅台 `7ea9b4af85e87bfc613658f0c4f893c296dac00f` 和正式 SQLite 只读查询。执行任务仍以实际启动时最新主干及当前正式数据为准。

- 正式有 17 视听集、65 视听场、344 镜，每镜一项视频需求，共 344 项；98 项使用 `seedance2.0_fast_vision`，246 项使用 `Seedance_2.5`。344 项均声明 `reference` 普通参考，`start_constraint=reference`，没有当前已采用的首尾帧、编辑或延长方案。不能为了覆盖方法分类而把现有镜头机械改成首尾帧。
- `method.skill.video-plan` 当前第 10 版，准确修订 `0d526daa80380b4983a77c5bf79f0fcba5e0dfbfeb7b248cf030445aca9a51a8`；`method.binding.media-plan` 第 15 版准确绑定 `media_type=video`。方法已经要求先读手册、选路线、看听参考、形成草稿、重读并产出 review/result。
- 方法引用的 `method.resource.video-handbook` 为第 4 版、修订 `f6d816a895c2463eaa119e8efa2f736e33d16aacd003ef82cd2e50df901055b8`，固定加载 use/models/modes/load/references/prompt/checks；action/dialogue/extension/style/song 案例及声音等按条件加载。
- 全量文字模式统计：344 份都有“意图与表演”“轴线”及同一参考说明骨架；134 份重复出现“声音（依序；注明同时者重叠）”段头。344 份都在 Prompt 中重复 720p。统计证明共有编排痕迹，不等于每条剧情都错误，也不能用“没有一镜到底四字”判全剧不合格。
- 344 项中 37 项保留原词、唱段或读回文本等 blockers；全部方案输入共 1,041 个引用条目，其中 728 条明确未选原件，其余 313 条沿准确旧原件引用。后两数是引用次数，并非独立文件数；未选参考与未定原词不能因重新生成文字就变成已就绪。
- 当前 342 项 payload 只留 relation-contract 的 `method_adjustment`，2 项有明确 `method_basis`，分别为 M3164、M3170。这只证明当前记录中的方法依据分布，不能倒推旧工作从未用过方法。两项有依据也仍保持旧式拼接文本，说明“有执行身份”不等于已经写出好 Prompt。

## 当前 SKILL 为什么还不够

现有 SKILL 的原则基本正确，但缺少把手册模板转为本项目最终交付形态的具体写作与审稿办法。尤其缺少对“同一信息只说一次”“动作和对白编成连续表演”“制作说明不得混入模型正文”的正反例及真实改稿练习。它允许把已有旧稿大体保留，再补一层关系说明；有方法快照也不能证明逐镜从表达目标重构过。

方法与工具之间另有实际冲突：

1. `scripts/audiovisual_events.py` 的 `ReviewedEvents.render()` 为源文事件加上“动作”“声音”“说唱原词”等固定前缀。`scripts/video_input_design.py::video_plan()` 添加共用参考职责前缀。它们原本用于确保事件完整，保住原词和正确起点有价值，但固定渲染输出不能成为最终 Prompt 唯一写法。
2. `scripts/scene_reading.py::descriptor()` 要求旧事件渲染全文在已保存 Prompt 中恰好出现一次，才建立评论文字区间。自由重编后可能不再匹配。任务必须同步适配准确事件覆盖与文字区间定位：校验说话人、原词、先后和正确引用，定位最终实际正文；不能为了通过旧串匹配把新稿恢复成旧壳，也不能删除准确评论能力。
3. 手册“接入本项目的准确参考”第 7 项还写“已锁定或已提交的方案发生变化时建立新版本”，与当前制作单份当前稿、真实候选保存提交快照的契约不一致。应更新这一局部项目接入说明及准确资源投影，不重写旧执行，也不维护第二份手册正文。

手册模板是“目标—参考分工—初始空间—连续事件／镜头—声音—必要约束”的组织方法，允许自然先后替代秒数分段。不是强迫所有镜头照抄八个标题或每一动作固定到秒；必须保住实际需要的内容，删掉冗余和冲突。

## 三个可以直接写入任务的前后例

已完整读取准确剧本 S001、S007、S030、S037；读取相关镜头与当前方案、准确输入元数据。视觉及声线适配仍需要执行者按原件实践，以下不编造已看听结论。

### 1. ASH009 / M2999：动作对白顺读，摄影指令一致

来源 `material-av-e01-a02-s04-video`，修订 `8eda58648c1d3a32c555f0f1291b362bd8d5e37c2a07b93338203a2c8541e186`，20 秒、2.5；剧本 S001 b026—b029，前镜添米，后镜才开始米袋／歌本交接。

当前先写“女孩双人中近景，固定”，同一行又要求“同侧跟随”，之后分三块“声音”从 1 重新编号，末尾再讲工钱与婚事预付的跨镜解释。动作、发声、连续性分散，人和模型都需要自行重组。

预期改法：参数仍在参数字段；参考职责一次说清图 1 提供两人在柜边的起始关系，音频 1、2 分别对应李寄、阿蘅。结合当前设计选定相机在临街侧同侧轻随两人走到檐外后停住，与“全程固定”二选一。连续表演段可写成：

> 阿蘅将刚添过米的袋口扎紧，自己拿着袋子，与李寄一起让到檐外。相机留在临街侧轻随两人，停成双人中近景。李寄这才凑近歌本，轻快地说：“最后那段，你还得看词呢。”阿蘅自然看向她：“晚些你陪我一起练。”李寄答：“好啊。”留一次自然反应，袋子仍在阿蘅手里，本镜不开始交本。

完整交付仍须含风格、准确起点、所需声源与必要不变量，但不重复套用镜外事件。重点验收相机没有自相矛盾，扎袋在起点之后，三句各只出现一次，交本仍留给后镜。上面是具体方向，不是已验证完整 Prompt。

以下为同镜可完整阅读的调查示例，选择“轻随至檐外后停住”这一相机方案，供任务检验表达。图 1 和李寄音色尚未选定，原件未看听；它不是正式稿或就绪提交。20 秒、2.5、720p、16:9 和 reference 仍放参数字段，不在正文重复：

```text
目标：白昼米铺柜边，阿蘅收好预付的米，与李寄约定晚些一起练唱。二维人物与轻手绘背景，干净轮廓、清楚色块，延续本场自然的生活气息。
参考分工：@图片1 提供起始构图中两人的可见身份、衣着、站位和柜边空间，作为普通参考；@音频1 只约束李寄的声音身份，@音频2 只约束阿蘅的声音身份，不复述音频内容。
起点：预付米已经添进阿蘅的袋中，袋口还敞着。两人仍在柜边，歌本在阿蘅这边；李寄尚未凑近歌本。相机位于临街侧，保持两人及袋口可辨。
连续表演：阿蘅先扎好袋口，自己拿着米袋，与李寄一起让到檐外。相机在临街侧同侧轻随，停成双人中近景。李寄这才凑近歌本，轻快地说：“最后那段，你还得看词呢。”阿蘅看向她，自然回答：“晚些你陪我一起练。”李寄答：“好啊。”每人说话时，另一人自然听着，不抢话。
落点：两人仍在檐外，米袋归阿蘅；保留应答后的自然短停顿，不开始下一镜的提袋、递本或收本动作。
声音：近处对白清楚，衣料与扎袋声轻，量米和街声留在较远处；无配乐、旁白或额外台词。
约束：一镜连续，不跨越柜台至门口的主轴；两人身份与衣着保持，李寄手上干浆糊仍在；米袋不提前换手，不新增画内文字。
```

示例新增的具体构图应在执行时对照上游机位和实际首帧判断；如果原件不支持这一路线，要修订方案并回读，而非为保示例硬改原件或声称已验证。对待定输入的说明保留在方案准备信息中，不复制进给模型的文本。

### 2. ASH002 / M2978：演唱、接唱扑空和尾腔合为一个过程

来源 `material-av-e01-a01-s02-video`，修订 `c1fabafdcd461be21805f0b93f0ee99936168984ec1abd782bc6e0bb91c1169a`；14 秒、2.0 Fast。参考为一项起始图、阿蘅声线、老汉声线和《三道滩》曲调，起始图／曲调均尚未选定原件。

当前将归家句、老汉半句和尾腔拆成三个相同“声音”标题，附加“说唱原词”“无新增词句”等数据库分类用语，容易把朗读任务、演唱任务和尾腔延续割裂。

预期改为完整表演：阿蘅唱出归家句；老汉按照熟悉曲子刚起“二道——”便发现她已经唱到归家，改口惊讶问“哎，到了？”；阿蘅忍笑收住自己刚才的尾腔，老汉扬下巴。唱句只完整出现一次，尾腔是延续而非重唱。音频分工一次声明：阿蘅／老汉各自声线，曲调参考承担本段旋律；是否允许具体重叠按准确歌曲和自然表演核对，不能用固定秒数遮蔽尚未试听的事实。保留原词、换气和尾部余量，当前 14 秒只是原预留，不以文字长度自动判定能唱完。

验收要连读 ASH001→002→003：上一镜翻页后才到归家，本镜不能补唱二道滩，下一镜再有老汉完整打趣；缺曲调、声线质量或原词的事实继续体现在准备边界。

### 3. ASH066 / M3170 与 M3974：文字工程与制作依据各归其位

M3170 当前为 `material-av-e04-a01-s05-video`，修订 `d45ece3e12b33d90bd5deb3c8d0301b65916342e8caae41def9739d49c73c14e`，8 秒。正确之处是起点仍没有第二笔，先写第二笔再圈两笔，不把工价标题算为第三笔收入；这应完整保留。冗余之处是模型正文仍讲“阿蘅只做白日工”“母亲仍需照护”“嗓音按日程推进”等该静默近景不需要处理的制作依据。改后只保留本镜可见账页、书写／圈账动作、手笔遮挡、同向机位和纸笔声。准确字层仍走已有工程及真实揭示时机，不能为了短 Prompt 让模型自由猜字，也不能将静图正确宣称为运动中已可读。

M3974 当前为 `material-av-e16-a02-s02-video`，修订 `37c7303caffc1f8af83fea802ed1417e1ca1b1c24205ee567e16ec4a044393e6`。末尾“纸张去向”整段把 S026:4、S037:13–18、S038:1 等来源编号和研究论证发给模型，直接违反 SKILL 的“模型 Prompt 不接收内部编号”。相关事实有效，不能简单丢掉：原记工纸留证、新清账凭据此时才递来。改后融入明确的当前物件与动作，不附来源论证。最后一行读回原词仍未知，必须交回负责表演原词的工作形成准确输入；本任务不擅改锁定剧本，不靠删掉读回事件解除 blocker。

## 全剧的真实工作顺序与边界

1. 用现有 video-plan 身份升级方法，正文以手册为唯一专业依据，引用准确章节和适合的模板；同步改掉上述旧项目版本用语。方法本身交代：先读整集及当前自然场，取得前后镜、当前完整状态与关系，划定本镜目标和不能改的事实；再组织准确参考，最后写 Prompt。
2. 先完成 ASH009、ASH002、ASH066 三类实际样例的 draft→磁盘全文 read→review→result；用本轮新稿实际跑通原词核对、输入指代、准确评论区间和当前方案阅读。必要时用正常非对白动作、未定原词、后显人物／空间、长镜动作作为补充反例，修订方法后再推广。
3. 按 17 集推进，每集完整理解后按自然场、镜顺序重编当前 344 项 Prompt；每镜都在自己的当前输入和方法步骤下拟稿、回读、检查，场末／集末连读，发现后文约束时回修前文。脚本只整理已经作出的判断、校验覆盖与准确引用，不一遍批量改串后补写逐镜过程。
4. 正确声画和已定原句保留；将相机、动作、对白、听者反应和落点写成互相兼容的连续表达。模式、模型与参数在原字段表达，Prompt 只用必要的一致说明。附件指代按实际顺序使用 `@图片1`／`@音频1` 等，界面可显示素材名字但提交稿必须可解析回真实附件。
5. 既有全剧均为普通参考是当前事实，不等于方法只能处理普通参考。用有界离线契约对照说明固定首尾、编辑、延长为何与普通参考不同；没有真实端点或本镜必要性就不迁移路线，不伪造演示为已生成。
6. 现有 37 个原词等缺项逐个核对：仍真实缺失则保留相应事件与明确负责人／准确源范围，不能在模型正文放“待准备”，也不能把含待定事件的稿称为可执行完成。未选原件亦同。报告应区分“当前 Prompt 已按方法重编”与“真实调用准备已就绪”，不要求此无付费任务把二者合并。
7. 使用更新后的全剧实体／状态／需求准确身份及命名；同步必要编制源、引用索引和场镜产物关联，不复活已退役对象。记录本次实际方法依据，旧方案、候选提交快照、真实调用、原件、旧评论不补造历史。
8. 在隔离环境完成全部一致性和样例真实页面验收，最新正式数据复核后做受管集成、必要推送、本机正式增量发布；完整导出能恢复到新空实例。执行者用正式页面复走样例、普通镜、长镜、未定原词、工程类和末集镜，保持评论、候选和返回上下文。不得用任务快照覆盖活库。

## 任务依赖建议

本任务的全剧 Prompt 重编应依赖本轮“实体／实体状态／素材需求抽取与命名、全剧重新执行”的交付，因为它会改变实际参考身份、状态必要性、当前名称与引用链。未完成前可以研究方法及样例方案，但不能冻结全剧输入后再只批量替换新名字；相关语义变化须重新读参考与状态。

方法页面交互优化不必强制成为本文任务的前置：video-plan 现有入口已能读取和使用，只需双方协调方法绑定与登记包，保留每项新方法的准确版本，不能用旧全量配置覆盖另一项修改。开发与正式写入冲突分别处理，正式共享数据库按序发布。

范围同时涉及故事仓的手册接入说明、创作工具及编制源、方法登记和全剧当前方案；如准确评论／方法执行接口需通用支持，再纳管审阅台仓。任务正文应明确默认 `--auto` 终点包含本机正式服务生效及真实验收，不只交隔离候选；不授权付费图像、音频、视频生成或 VPS 发布。

## 完成条件

- 系统管理实际可读、可评论新的同身份视频 SKILL，正文及手册模板来源唯一；真实 media-plan/video 调用取得准确新方法和适用资源。
- 344 个当前镜头需求全部有本次实际逐镜处理结果和方法依据；17 集、65 场的连读覆盖完整，不把 37 个未定输入悄悄消失，也不把技术覆盖当作创作通过。
- 上述三类前后例的具体问题均消失，正常保留部分不受破坏；额外抽查未定原词、长镜与后显参考。句段完整、说话人、相机指令、输入编号和前后状态真实一致。
- 旧模板字符串不再是新 Prompt 的保存或评论定位前提；新稿可准确圈选评论、刷新回查，范围不混入未选内容。对实际不存在的旧定位诚实报缺，不迁移旧评论到新措辞。
- 未改变故事结构、小说和锁定剧本；历史生成候选、提交时方案、原件、真实调用及原意见保持准确。当前制作不恢复多版本体系。
- 报告先写任务编号及实际解决问题，附可读前后例、方法实际使用及全剧覆盖、本机正式与恢复环境、仍未就绪的输入及负责人、未做的实片／听审，以及过程资源清理结果。文字方案优化不能宣称生成视频质量已提高。

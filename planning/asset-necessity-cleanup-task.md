本任务执行时明确允许主协调者安排子代理：按代码、数据、接口、文件及运行资产划分有界调查，必要时由未实施该项修改的代理复核处置依据与实际结果。主协调者维护唯一覆盖清单，统一跨领域依赖和删除决策，避免重复扫描；有重叠的修改先明确写入归属，互不影响的实现使用隔离工作区。同一共享正式资源的操作仍串行。不继承此前实验的六至十小时时限、计时守卫或持续 Goal 授权，也不增加监督界面或新调度框架。

## 扫描范围与必要性判断

以执行时两仓最新集成版本和实际运行环境为基线，覆盖全部资产类别：

- 全部源码、前端组件、后台工具、CLI 命令、脚本、测试、夹具、依赖和构建产物。
- 全部受管及未跟踪文件、配置、文档、设计稿、导入包、发布包、公开导出、媒体与证据文件；包含隐藏目录和 `.runtime/` 中属于两项目的本机资产。
- 数据库及全部表、列、索引、视图、触发器、迁移、备份、业务记录与运行元数据。扫描表结构和用途不等于允许删除历史记录。
- HTTP 接口、静态资源入口、内部调用、配置兼容、历史链接、导入导出及恢复契约。
- 两项目所属的进程、服务、容器、镜像、卷、挂载、端口、代理、部署配置、发布目录、定时／监督入口及临时预览实例。
- 两项目其他任务工作区和发布现场的资产归属、引用及活跃情况。不得把嵌套 worktree 当普通垃圾目录递归删除，也不得修改其他任务的未交付成果。

通用系统从主项目根目录定位相邻 `../story-review-desk-python`；不要相对嵌套任务 worktree 直接套用此路径。读取系统仓库规则，建立本任务的系统仓库隔离工作区；故事特有的创作工具继续归故事仓库。共享正式库通过一致性副本审视，测试、迁移预演和页面验证只在隔离实例与独立端口进行。

建立完整资产清单与覆盖统计。文件以可追溯路径登记，表结构和接口逐项登记，服务及运行资产按具体实例登记；相同目的的资产可以成组论证，但清单必须能定位每个成员。对于媒体等大量同类文件，可用逐文件清单承接分组结论，不要求对每份文件重复写同样的长说明。无法读取或归属不明的资产记录范围、原因和影响，不能算作已经完成审视。

每项资产记录用途、调用／引用关系、保留理由或冗余证据、处置结论及必要验证。结论分为保留、合并、清理、待判断；合并清理项说明前后职责和依赖如何承接。检查显式引用、动态加载、数据库关系、配置、历史导出恢复、旧链接及运维用途；仅凭代码搜索没有命中、表为空、文件陈旧或当前页面不可见，不能判定无用。低频迁移、恢复工具和真实调用回执也可能有明确价值。

## 已确认的处置边界

用户于 2026-10-04 明确选择：清理冗余实现、废弃结构、无引用临时资产，保留有效历史轨迹；内部实现自主合并清理，取消正向能力时先展示具体取舍判断。这里的正向能力指仍对用户、后台创作工具或运维流程提供实际作用的功能、接口或服务。

可自主实施的范围包括重复内部实现的合并、经核实废弃的代码与配置删除、已迁移且无必要数据的旧表结构清理，以及没有业务、历史、恢复、活跃任务或运行引用的临时资产清理。合并后更新全部相关调用方、文档和配置，不以新增抽象层、兼容层或管理界面抵消清理收益。

作品正文、图像／音频等业务原件、评论及事件、不可变修订、真实调用、准确依赖、采纳与镜头采用记录，以及支撑它们的历史证据保持有效且可追溯。合并存储或表结构时允许迁移，保留原身份、语义、准确关联及原件哈希；不能把“不是最新版”“未接受”“已撤回”当作无用理由。重复物理副本只有在必要版本、恢复入口与历史读取仍可用时才可清理，不删除最后一份必要原件。不得改写作品或代用户接受素材。

取消现有功能、删除仍被使用的接口、停止仍有用途的服务或放弃兼容／恢复能力前，展示具体资产、现在用途、取消理由、受影响用户或调用方、替代方式及取舍，取得该项明确判断。等待期间继续独立的内部清理；未获同意的项保留并说明原因。明确无调用且已废弃的内部接口可按内部实现处理，不能仅因近期无访问就认定接口已废弃。

检查 Git 和 `.codex-project` 仅用于理解版本、任务与引用。任务账本、媒体输入、Git 元数据、活跃工作区、账号锁、配额回执、结果未知调用、恢复必要备份和当前部署依赖不得当垃圾删除。已完成 worktree 的退役若确有必要，先展示具体清单，再沿已有 `codex.project task cleanup` 流程处理；不能手工删除管理目录。外部平台、其他故事项目和整机资源不在清理范围；项目所属运行资产先确认归属，禁止全局容器、镜像或卷清理。凭据只核对引用和必要性，不回显或纳入公开交付。

## 实施与交付

执行时先记录两仓提交、系统版本引用、实际服务版本证据和数据库一致性基线；配置引用不能代替运行版本证据。全面盘点后分批实施，每批复核依赖并保存结果。正式库、部署和运行目录的删除／迁移清单先在副本预演，并形成准确操作步骤、恢复依据及失败处理方式。

交付 `planning/asset-necessity-cleanup-report.md` 作为唯一报告入口，关联完整资产清单及必要证据。私有快照、调试材料与检查点留在本 worktree `.runtime/asset-cleanup/`，公开清单和证据脱敏后进入受管交付。报告说明扫描边界、实际覆盖、每类资产的保留／合并／清理结论、实际修改、未处理项的依据，以及哪些变更已验证、哪些未正式应用。删除文件数、表数、接口数或磁盘字节数仅报告可核实的前后差异，不能替代用途论证或完整性验收。

受管文档更新直接吸收当前有效结果；稳定知识归既有知识入口，状态归既有恢复入口，不另建账本。不在创作审阅界面增加资产盘点、执行日志或清理进度展示。

双仓最终候选和正式操作方案先完整交用户审阅。执行阶段获得最终确认后，才按原任务流程串行集成、推送、必要数据迁移、运行资产清理和正式服务应用；重新核对当前头、最新数据库与活跃引用，不拿旧快照覆盖活库。任务发布确认只发布本说明，不代表已验收执行成果。

## 可验证的完成标准

1. 提供执行时两仓代码、文件、数据结构、接口及运行资产的完整清单，包含隐藏／未跟踪及本机运行资产；清单可定位具体成员，覆盖统计有明确分母，每项有用途证据和处置结论。遗漏、不可读取及归属不明项单列；影响删除安全或核心能力的未知项未解决时，不宣称完成全部资产审视。
2. 每个合并／清理项有可复核的冗余或废弃证据、调用方与引用分析，以及实际 diff 或运行操作回执。已获授权且证据充分的清理落实，相关调用、配置、文档同步更新；无必要变更的资产保留并说明用途，不为凑清理指标删除有价值内容。
3. 清理后不存在由本次修改导致的失效调用、文件引用、历史链接、发布依赖或部署挂载；对动态入口、旧版兼容、CLI 与低频恢复路径做相应验证。若取消正向能力，交付中有该项明确用户决定和实际承接结果；未获同意的能力仍保留。
4. 用准确身份、修订、关系、事件及原件哈希核对有效业务历史。作品、评论与锚点、真实调用、素材轮次、采纳和镜头采用记录没有非授权丢失或改写；表结构合并／删除先完成必要数据迁移并验证关系完整，不能只以总行数相同证明历史未丢失。
5. 数据／导出契约变化完成旧格式读取、迁移预演、当前完整导出→空实例恢复，并核对必要历史与媒体哈希。部署和运行资产变化验证启动、健康、挂载、重启及恢复步骤；必要的备份和失败现场没有被提前清理。无相应变化时说明为何不需要该专项验证。
6. 运行与改动相适应的两仓自动检查，并在真实浏览器回归受影响路径；共用代码变化覆盖故事采编、结构、剧本、制作设定、素材管理及全剧制作的相关阅读、评论、版本、采纳和媒体入口。受前置任务影响的接口性能在可比数据与配置下复核，不能因清理破坏已确认的性能目标。浏览器受阻依 AGENTS.md 报告原始错误和未验项，接口或静态检查不代替页面验收。
7. 报告完整、独立可读，逐项说明保留、已合并、已清理、待用户判断或未处理的原因；提供双仓候选、覆盖清单、验证证据及准确正式操作方案。没有未解释的核心历史／能力丢失或高影响清理风险；剩余项说明影响和处置，不把待定能力删除计作已清理。
8. 执行阶段最终确认后完成必要的串行集成、推送、最新正式数据迁移、经批准的运行资产清理及服务应用；回读版本、重点功能、历史和运行依赖。正式数据保留最新并发业务修改，确认实际效果后沿唯一任务账本办理完成。没有必要的正式变更则给出依据，不为验收制造数据库或部署操作。

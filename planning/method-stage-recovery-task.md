## 原问题与预期工作

当前制作采用单份当前稿，服务仅保存新执行的输入与产物摘要，完整过程留任务工作区。这个数据边界应保留，但作者工具尚未接全：本轮为 ASH010 保存 711 字符的 understanding 正文后，`creative_method.py read --stage understanding` 成功返回的只有摘要，本地 stage 文件也只有服务回执。作者靠另存的原文件继续工作，工具没有完成“保存后实际回读”的职责。

媒体方案同样存在衔接缺口。ASH008/M2996 的草稿、回读意见和定稿靠作者手工另存；实际回读才纠正“上一镜量米”为“此前量米”，并删掉误放进本镜的下一镜扎袋、练曲事件。`media_method.py finish` 已能输出完整导入包，review 的 assessment 也仍保留在服务回执，不能称所有正文都丢了；缺的是步骤目录内可准确回读、在中断后续接的完整链。

改后，作者按方法取得准确输入，逐步保存产物，用作者工具读回其原始全文或结构化值，作具体判断再继续；进程中断后沿同一步恢复原方法、输入、草稿、意见和定稿，无需记住外部文件。服务继续只存约定摘要，不恢复制作全文历史，不新增审批、阅读确认或恢复管理实体。

调查基线为 task-20261011-0008 正式交付后的主仓 `6a14c238`、审阅台 `123e7d009124`；执行以最新双仓主干及有效正式数据为准。

## 完整必要范围

覆盖当前压缩契约的六类工作：视听设计 `audiovisual-design`、素材评估 `material-assessment`、字层 `text-layer`、生成准备 `generation-preflight`、结果审阅 `result-review`、媒体方案 `media-plan`。阶段以准确方法包的真实阶段和依赖为准，不只修 understanding，也不硬编码所有方法只有 draft/review/result。小说、剧本、结构和读者不在这份压缩名单，保持其正常入口，不扩成所有创作工具重构。

复用 `scripts/method_runtime.py` 的现有交付目录、`delivery.json`、请求、准确方法及资源文件；在共用能力中补齐保存、回读和恢复，供 `creative_method.py` 和 `media_method.py` 一致使用。内部文件布局由实现决定，但须满足以下结果：

- **保存真实原值。** 提交阶段时，把作者原始字符串或 JSON 值、原执行/目标/阶段身份及服务确认关联保存。字符串的换行和 Unicode、对象的类型与值不被转成摘要或显示文本；不能用文件名相同推定内容相同。未获服务确认的本机产物不标成已完成，服务接受后的同阶段产物不能被新正文覆盖。草稿、回读和定稿是同一步的不同阶段，可以因实际修订而不同。
- **回读真的返回内容。** `creative_method read` 返回经核验的原始值；媒体命令体系提供明确的阶段回读入口，能读 draft 的完整 requirement/generation、review 的原 assessment、result 的完整定稿和对应待导入包。不以多落一个文件、要求作者自行找文件代替工具回读。已有媒体 begin 输入和 finish 导入包能力保留。
- **校验对的摘要。** 压缩回执的 `output.sha256` 表示原提交值，外层 `output_sha256` 表示压缩后的输出，两者不能混用。按服务相同的规范 JSON 规则计算，字符串也按 JSON 值计算，不拿文件原始字节哈希替代。媒体 requirement/generation 的各自摘要及 execution、target、stage、前置产物引用一并核对。阶段原值与加入 method_basis 的待导入包分别校验，不把后者当作服务收到的原提交值。校验成功只证明内容和归属一致，不证明作者理解。
- **中断沿原身份恢复。** 覆盖服务接受但响应丢失、回执未落盘、产物文件写入中断，以及 finish 导入包写入中断。先核对原执行、原阶段、原正文和已存在回执，准确重取或幂等继续，不能新建步骤掩盖未知结果，不能用新绑定重建旧方法。输入、范围、条件或支持材料变化时明确另开步骤；同一步不漂移。
- **缺失和冲突诚实处理。** 本机全文缺失或与摘要不符时指出具体缺失/冲突，保留可恢复现场，不能从当前方案、相似稿或哈希补造。仍有准确原文件或旧服务完整产物时可核验后接入原步骤；没有证据则保留不可恢复状态。保持目录越界、符号链接、内容漂移和错误归属保护。恢复不自动发布，不跳过 method_basis、输入 guards、baseline_marker/并发标记，也不让已经前进的当前稿被旧导入包覆盖。

过程全文只在有实际恢复用途的任务工作区保存。公开作品导出不携带私有草稿；本任务不建立长期草稿档案。必要使用说明和示例同步到 [受管工作方法](../production/managed-methods.md)，使后续作者按工具完成真实保存和回读，不再把手工补救写成推荐方法。

## 真实工作与验收

在最新准确隔离实例运行真实 CLI 链路，不能只测辅助函数或只读源码。

1. **视听字符串与结构化产物。** 用随任务 ASH010 准确输入创建明确标注的回归步骤。先读方法与作品，记录理解正文，再由工具 read 得到逐字相同的完整内容；记录原则、设计、交接、回读等实际方法阶段，字符串及 JSON 产物分别核对。关闭客户端进程后恢复，同一方法、输入和已确认产物保持；作者实际重读后说明人物动机与物品交接的判断。0008 已修正正式 ASH010，仅在隔离回归，不回灌旧错误或改正式作品。
2. **完整媒体阶段链。** 以 ASH008/M2996 的已保存准确原记录、草稿和定稿作回归输入，重新取得对应方法及必要作品依据，依次 draft→read→review→read→finish→read。读到真实草稿差异，理解量米时点及下一镜事件边界，再保存定稿。工具恢复出的待导入包与正常 finish 包相同，包含准确 method_basis；有必要时只在隔离库验证一次并发保护下的导入。首帧缺原件、音频未听和 14 秒未合排的边界保留，不生成视频，不据文字修正声称声画效果通过。
3. **当前压缩六类同契约。** 逐类核对准确阶段配置和原值形态，实际保存/读取至少覆盖字符串、结构化对象与 assessment；验证所有六类共同路径，不要求为每类创作一套新作品。服务仍只保留约定摘要，不能为了让测试通过改回远端存全文。
4. **关键异常真实恢复。** 在隔离环境分别制造“服务已接受、本机未落回执”和“finish 包未写完”，重启客户端沿原步骤恢复，无重复执行或伪完成；再检查缺全文、内容被改、异目标、异阶段、前置未完成、输入或条件变化、路径越界、目标并发前进。每种情况给出具体可理解的处理结果，错误不得破坏原有效文件或跳过发布保护。不同阶段的正常修订不能被误拒绝成同阶段覆盖。
5. **旧执行正常对照。** 使用现有 ASH066/M3170 的旧完整输出或等价准确旧包，仍能取得原正文；该旧执行发生在摘要化前，不能反证新模式正常。已有摘要但本机全文不在的旧步骤明确不可完整回读，不伪造补齐。方法绑定改版后恢复旧步骤仍为原包；私有执行和公开作品导出的边界保持，现有 begin 部分交付恢复、旧完整作者入口继续可用。

验收记录提供两条完整 CLI 过程的准确身份、输入/原值/回执对应、实际回读后的具体判断和前后例；测试、回执、作品判断分别报告。不能把“保存后能打开文件”当作整个恢复链通过，也不能用作者一句“已回读”替代读取结果。涉及系统迁移或导出契约时，从正式交付包恢复新空实例并核验旧方法和业务保护；不为私有阶段全文强加公开备份。

## 交付、并行与边界

仅依赖 `task-20261011-0008`。登记故事主仓与 `../story-review-desk`：作者工具及说明属于故事仓；通用方法契约、必要兼容性测试与运行发布由审阅台范围承担，避免反向导入故事工具。可与人的 SKILL 阅读/应用任务并行，两项原因和验收独立，均复用已经可用的冻结方法包；最后在整轮回收中用一次新方法→实际创作→工具回读→作品判断联合验证，不以此制造开发硬依赖。

执行时登记上述提交引用约束与 `scripts/task_workspace_guard.py` 的实际摘要。沿现有流程准备逐仓候选与准确发布包，再由任务工具整组集成和必要推送；项目发布器消费实际回执，核对合并后的准确代码与数据，完成必要本机发布和最终验收后才结项。受管文件在最终候选前收敛，成功完成回调后不再补改。

共享资源仅为本机正式 `.runtime/review.sqlite3`、3000 服务及既有发布/恢复入口；版本以执行时配置、冻结发布包和回执确认，由本任务执行者申请并持有串行写入窗口，核对其他写入者与恢复能力，完成正式切换和只读验收后解除占用。私有回归的数据库、端口与阶段目录由本任务执行者在受管工作区内创建并负责，不借用根 Review 或其他任务预览；最终准确 CLI 验收与必要证据收敛后清理。没有新增外部环境、付费服务或 VPS 占用。

按 [项目规则](../AGENTS.md)、[受管工作区与发布流程](../production/generation-workspaces.md) 使用受管隔离工作区并合入最新主干。`--auto` 执行终点包含受管集成、必要推送、本机 3000 正式服务发布、发布后正式只读方法/作品入口验收，以及最终准确隔离环境的完整 CLI 恢复验收。共享正式数据库和服务写入串行；正式仅发布本任务必要系统及方法工具变更，不导入试作，不进行付费生成、VPS 或外部发布。不能只交候选结项。

历史任务的已解决部分与准确边界见 [输入与历史说明](method-stage-recovery-inputs/README.md)。本项不重做人的方法页面，不恢复已撤销的全剧制作任务；实现和正式交付残留由本任务继续，整轮联合验收和负责人独立 Review 分别承接，不因本任务结项代签通过。新作品改写、实际生成或范围外缺口需要新的明确授权。

最终回复先写任务编号和实际解决的问题，用“原先 read 只有摘要→现在能读完整原值并恢复原阶段”“媒体定稿包中断后如何恢复”说明变化、收益、准确环境与边界、残留及下一步。提供正式交付与独立回收入口，记录实际清理的本任务容器、镜像、测试库和临时文件、回读结果及保留用途；仍需验收的阶段资料保留到用途结束，不能提前删除后声称无法验证。

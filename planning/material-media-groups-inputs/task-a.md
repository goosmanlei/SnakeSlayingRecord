# 镜头纳入实体：统一大卡与视听素材工作区，实体管理改为关系图

## 解决的问题与改后工作

现在从素材打开ASH001，只能看到“镜”和“打开完整镜头”，要离开大卡才能读叙事目的；视听页又把首帧/视频的长方案直接铺在正文中。实体大卡还夹着关系图、下拉出处和散落的歌词选段，当前方案与历史候选混在一起，M003甚至只有历史候选入口。

本任务将镜头定义为实体的一种，以同一对象、同一大卡和同一素材部件完成阅读。人在实体管理按全剧/集场看关系、点对象；或在视听页沿集场镜阅读；两条路径都能直接读基础信息、按素材分组选择素材，在右侧查看当前方案及历史候选。无需“打开完整镜头”二次跳转。关系图只在实体管理保留。

本任务承接用户本轮除“素材管理五列与媒体分组”外的全部明确要求。后者独立发布，可并行开发。用户原话、两张原图及调查和可操作样例随本任务保存；样例用于说明工作结构，任务正文为最终产品约定。

## 已确定的产品与数据取舍

### 镜头成为实体，但不复制对象

统一实体契约增加镜头类型。一个镜头仍只有一个稳定对象和一份当前内容，原object_id、ASH编号、评论锚点、关系端点及素材归属继续解析；不另造与AV_SHOT并行可编辑的影子ENTITY，不为整齐把ASH重编号为EN。集场仍负责镜头顺序和所属位置，并引用这个对象。存储表是否合并、旧kind如何兼容由实现者决定，但读取、写入、校验、管理索引、关系、导出恢复和故事工具均须承认镜头是实体，不能只把前端标题改名。

保护现有叙事目的、关键状态、主/反机位、首帧、视频、字层工程和引用。调查基线344镜有1115项直属素材：344主机位、72反机位、344首帧、344视频、11工程；products只列699项，不能据此漏掉416机位素材。351个镜头关键状态仍是镜头内部的有意义状态及其素材关联，不强制复制成351个角色式STATE对象。与其他实体共有的一套素材查看能力，不等于把所有类型字段机械抄成一样。

### 实体管理：以关系图作为主内容

1. 正常首次进入默认“全部集/全部场”；普通从其他生产页切入，不默默继承正在阅读的一场。明确带集场定位的链接按其范围打开；从大卡返回保留本页已选范围和图位置。选择集时场重置为该集全部场；选择场时集与场一致；点全部可直接恢复范围。
2. 删除顶部搜索框、清除筛选按钮、内容分类筛选、类型分组列表及其分页/每页行数组件，不另加替代搜索面板。
3. 复用原实体大卡关系图的交互和视觉基础，支持全剧与集场范围、多连通分量和无关系节点。节点使用当前实体小卡样式，可适当收窄，保留名称、编号、类型/预览；点击直接打开统一大卡。镜头是节点之一，不因没有旧ENTITY类型而漏掉。
4. 范围中的镜头按集场归属确定；其他实体沿当前真实制作关联口径筛选（直接引用及实际素材用途，不能擅自缩成只有直接引用）。只显示范围内节点之间的关系，不沿图递归引入全剧节点。全部范围保留所有有效对象；已撤回对象按既有退出规则处理，无关系对象仍可打开。
5. 实体—实体复用已统一的真实关系、方向与摘要。镜头与角色/道具/场景等的连线从既有镜头实体引用及状态归属派生为“本镜涉及”，说明制作关联，不声称已实际入画或已经生成使用；不为展示另存一套重复R关系。状态引用归并到所属实体，同一对节点不画多条重复线。素材依赖图不混入本页。
6. 连线说明只保留足以理解这条关系的一句简要说明。删除原关系hover浮层、其无用明细和展开入口；不在卡片里堆关系ID、来源修订、旧状态日志。关系原始信息和约束仍保存在统一关系数据中。延续拖动、滚动和缩放，不以分页、折叠组或“展开更多”隐藏范围内节点。布局要能分辨线的两端和摘要，不能只交付数百节点互相压住的截图；全剧密集时需可缩放定位、局部阅读，不能私自只显示前N个。
7. 从所有实体/镜头大卡删除关系图模块及“展示完整关系图”入口，关系数据不随展示模块删除。

### 共用大卡和视听镜头：基础信息＋素材分组/列表＋右侧素材

- 大卡左侧上部是对象基础信息。普通实体沿有效基础描述；镜头呈现现有叙事目的等必要镜头描述、所属集场和故事出处。取消“打开完整镜头”，信息在本卡读完。
- “故事出处”始终按真实引用平铺为可点条目，多时自然换行，不下拉、不折叠。显示场编号与可辨标题。点击直接打开所选准确剧本场的完整正文，保留顺序，引用的准确文字高亮；不先给省略选段，不保留“读完整场”的二次动作。退出引用回到原大卡位置。多场引用分别打开各场，不能把“全文”误解成每次展开整部剧本。
- EN046等歌曲的完整歌词、段落和剧中演唱选段融入基础信息，删除大卡底部独立“歌词原文与段落”。完整词稿与剧本实际引用片段清楚区分，准确来源仍可点，去掉重复呈现而不删除只出现于选段中的事实，不改已确认歌词或音乐方向。
- 下方为与内容相连的真正页面Tab：普通实体保留“实体素材/实体状态”，有清晰选中页签和连续内容边界，不画成两个孤立按钮。实体状态中平铺可选状态，选状态后显示该状态描述及素材列表；切Tab/状态只改变所选范围，不跳到无关实体素材。
- 镜头使用同一部件，按制作次序显示实际存在的“机位参考/镜头首帧/镜头视频/字层工程”等Tab。首帧下呈对应关键状态描述及素材列表；多状态和一状态多素材均可访问。同一个首帧需求被状态和产物引用时仍是同一个素材。无实际内容的额外Tab不凑数。其他有效直属需求按真实用途归组，不能只硬编码首帧和视频两项而丢主/反机位。
- 选Tab先呈该范围素材列表，点击素材后在右侧显示该素材，不再在Tab正文另铺一份完整Prompt。第一次默认选当前组第一项，之后同一对象切回组/状态恢复有效的上次选择；原选择已删除才回到该组首项。空组明确无素材，不借用邻组内容。
- 视听页保留集场镜阅读顺序及必要导航，在当前镜头内容位置嵌入同一基础信息和素材部件；两入口同一镜头、素材、候选、评论定位和出处行为一致。切到下一镜读到该镜信息，不残留上一镜方案。不要再复制一份“镜头关键状态/长生成细节”置于同部件之外。

### 当前方案与历史候选分清，当前方案始终可进入

顶部独立呈“当前方案”入口，旁边用明显分区/间隔和“历史候选”标题承接候选切换。选择候选后查看真实生成结果及当时快照；选择当前方案后查看当前参数、参考和Prompt，未生成用准确占位。保留当前入口，不把当前稿和候选伪装成同一版本序列；不同时重复铺两份长Prompt。

有无候选、有无模型方案都不能令当前入口消失。已有当前方案原样保留。M003这类旧素材只有ASSET身份（调查17个素材对象），为原素材身份补齐当前方案能力，不与另一个同角色的素材需求合并：从最近一次确切真实候选的可用工具、参数、Prompt及真实媒体输入初始化可修改当前稿；非媒体文字依据不转成上传输入。无法准确还原或纯导入原件时，明确“当前方案尚未编写”，不伪造参数、输入或生成事实。工程素材没有模型Prompt是有效状态，展示工程制作内容/结果，不硬造模型调用。初始化不能覆盖已有当前稿、重编号候选、改写候选快照或原件。

### 参考只呈素材，Prompt用@名称打开同一准确素材

生成参考列表仅呈素材小卡，桌面两列，窄屏可重排；卡片具有可辨名称、媒体预览/占位和准确素材目标。当前方案允许引用待生成素材需求，但不能把未选原件伪装成已可上传；候选回看绑定当时实际输入/片段。无参考则简洁空态。不把实体、状态、剧情依据或“用途与意见”等说明混入媒体列表，也不增加新的折叠信息。

Prompt中的图片1/音频1及已有素材引用显示为可点“@素材名字”，与列表的同一素材对应；同名以必要编号区分，点开准确原件/片段或该素材当前方案，关闭返回原位置。保留底层提交文本和token映射、真实槽位顺序及候选快照原始字节，显示名替换不能破坏评论选中文字的定位。素材引用/Prompt上的必要关系摘要沿现有能力保留；本次删除hover指关系图上的冗余浮层，不新增一堆用途文字。

当前正式generation.inputs已全部是素材。M003出现的ENTITY/INPUT_LOCK是候选历史“文字依据”，不是允许实体上传：从生成参考区域移除这类非媒体卡，必要创作依据回到基础信息/故事出处，已有候选快照中的原始文字事实仍保留用于准确历史回查。约束已经在Prompt里的不再重复；不得为清界面物理清除候选真实历史或把失效依据冒充当前内容。

### 评论消息在当前弹窗上清楚可见

修复大卡内评论保存、取消、校验失败等消息层级，特别是用户原图的“本次未提交评论已取消”。在原生模态dialog上层/内部正确显示，不能只调BODY toast的z-index。取消不产生新评论；保存成功/失败消息符合实际结果。兼顾引用弹窗、候选/素材大卡嵌套、Esc关闭及非模态页面，消息不残留遮挡下一对象。

## 执行与交付

按项目AGENTS、production/generation-workspaces.md和current-candidates契约执行；本任务不是重做故事/小说/剧本、全剧创作或付费生成。必要契约迁移、索引、创作工具读写适配、方法文档/有效入口、导出空库恢复和本机正式服务生效都在范围内。不要借统一之名恢复版本链、送审包、审批、采用按钮或新增管理页面。

先在最新准确正式数据的隔离副本完成迁移和页面路径，写入验证只在该环境。保护准确候选快照、原件/片段、真实调用、评论与其摘录、故事版本及作品输入锁。正式迁移用受管增量/事务与并发校验，不用任务快照覆盖活库。

双仓：故事primary与通用审阅台desk，目标main。从执行时最新主干起步；无未完成任务硬依赖。与素材管理任务可隔离并行，共用material-review/management-cards等修改在集成时合并重验；正式库、3000服务、发布锁、镜像标签和读缓存按序发布。按原生多仓流程登记配置提交引用与清理检查器，不手工造附属worktree。

--auto必须完成双仓集成及必要推送、正式数据库迁移/本机3000部署、真实Chrome验收和过程资源清理后结项。不含VPS/外部发布、付费调用和未授权内容改写。最终回复先写任务编号和实际解决的问题，再用下面具体前后例说明收益、准确提交/正式环境、验证边界、未解决项和下一步，给出清理实际数量/范围及保留用途。执行者完成、正式交付、根独立复验分别表述。

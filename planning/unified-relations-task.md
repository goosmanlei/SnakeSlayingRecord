# 统一业务关系：一对对象一条关系，摘要按需呈现，约束融入生成方案

## 要解决的问题与交付结果

当前实体关系、素材需求关系和素材对镜头的适用关系使用不同模型、编号与展示方式。同一旧音色原件与同一复用需求还会分别建立“备选”和“复用”两条关系；关系说明、参考选择和生成约束混杂，人在读作品时又要面对大段用途文字。

按用户已确认方案，将这些业务关系统一为一个关系模型：同一对数据对象只有一条当前关系，不同方面、依据和发展阶段融合在同条关系内容中。编号直接表达端点；页面只在关系图连线、参考列表和 Prompt 的素材引用处给摘要；AI 编制生成方案时理解当前目的、阶段与准确参考，把适用约束融入 Prompt。本任务覆盖模型、现有有效数据、全部消费者、展示、创作方法及导出恢复，不以换名称、样例页或仅改 CSS 交付。

本任务交付到本机正式可用：准确双仓 Git 候选与隔离验证完成后，由执行者完成受管集成、必要推送、任务目标所需的正式库准确增量迁移、本机正式服务 `http://127.0.0.1:3000/` 部署、正式 Chrome 原路只读验收、恢复验证和资源清理，再 `_complete`；`--auto` 执行同样须走完。源码合并、测试通过或候选完成均不能单独结项。正式写入保全范围外内容、用户原意见、准确历史、真实调用及原件，不用任务快照覆盖活库。付费生成、VPS／外部发布及超出任务目标的内容改写未获授权。定义与发布会话只修改任务、发布和回读，不执行实现、集成、推送、部署或正式数据写入，不恢复持续 Review。

## 已定的关系规则

### 一对对象一条关系

统一范围包括当前 `RELATION/relation_type=entity`、`MATERIAL_RELATION`、`RELATION/relation_type=applicability` 三类业务关系，并支持实体、实体状态、素材需求／真实素材、镜头等实际有关系的异类端点；首先接住现有真实用途，再支持用户明确提出的实体—素材关系。不能为验证接口而向正式作品杜撰关系，也不生成所有对象的两两组合。

按两个对象的稳定身份确定同一对，不按修订、关系类别、发展阶段、生成模式或端点书写顺序另建当前关系。同一对兼有身份、服装、空间等方面，或前后阶段有变化，都写入同一份连贯说明，保留必要准确依据和适用条件。不得以子关系、阶段关系或多套类型表变相恢复多条业务关系。关系内容可以沿既有准确修订机制迭代；旧修订不是第二条当前关系。

统一的是创作与制作的业务关系。明确采用／撤回、原件认可、真实调用、对象版本、父子归属和底层引用完整性继续承担各自作用，不把所有数据库外键、采纳事件或调用输入变为通用关系。关系的存在不等于选定参考、已认可或已生成。

### 编号与方向

面向人的编号按用户语法使用 `R-端点编号<连接符>端点编号`，沿对象现有业务编号，不重新编号实体或素材：

- `R-EN012->EN055`：EN055 依赖 EN012。
- `R-EN012-EN055`：两实体相关，不声明生成依赖。
- `R-M012<-EN055`：M012 依赖 EN055。

这三个是用户给出的语法示例，不代表实例已存在相应事实。`A->B` 和 `B<-A`、无向关系的反写均解析到同一关系；同一对改方向或融合说明不换业务身份。规范显示保留稳定端点顺序，箭头相对该顺序表达依赖；旧 RL/MR 编号及旧对象引用有可追溯映射，不另保留一套可写当前关系。

旧实体关系的 forward 常表示人物行为方向，例如“阿蘅抄写并持有歌本”，不是制作依赖，不能机械转换成 `->`。此类用 `-`，人物角色与行为写入摘要和正文；真正提供制作依据、参考或复用输入时才表示依赖。不同阶段方向不同时，在同条关系描述中讲清；无法用一个全局单向箭头准确表示时以相关编号呈现，由具体生成方案表达本次依赖，不虚构双向执行或绕过循环检查。

关系语义与是否参与执行仍需准确区分，但不因此产生多条关系或要求用户填写类型矩阵。未知用途不自动当作生成依赖，自关系及不存在的端点拒绝；删除、撤回和重新建立同对关系不会产生并行身份。

## 人怎样阅读和使用

实体大卡继续使用既有关系图：同对对象一条连线，连线上直接给简短、可读的关系摘要和可辨认编号，端点显示对象名称与业务编号。摘要讲清为什么有关、必要时体现阶段变化，不以字段名、孤立“相关”或截断半句话代替。删除图中把每条说明、依据和评论铺成大卡的方式，保留选择关系、打开准确相邻对象、平移缩放及返回位置的能力，不增加关系管理页面。

素材生成方案的参考列表保持纯列表；鼠标停留在具体参考项、或 Prompt 中对应的 `@图片1`／`@音频1` 等链接词时，显示“该参考与当前生成对象”这条关系的摘要。两处读取同一个准确来源，摘要按本次用途取重点，不能展示参考对象自身全部关系，不能复制成长段用途正文。摘要可移入阅读，键盘聚焦等价可读，Esc／移开能关闭；窄屏沿同一引用附近的按需浮层读取，不增加常驻说明区。原有点击打开准确素材的行为继续有效，返回仍在原方案、原版本和阅读位置。

同一 Prompt 内多次出现同一素材链接时对应同一准确关系；多个文件或片段属于同一上游对象时共享关系身份，具体文件／范围仍按各输入位置保存。版本、候选、产物 Tab 切换及迟到加载时摘要不得串到另一方案。没有明确关系或历史说明已经清理时保持真实未知，不拿当前说明替换旧执行；只显示有依据的摘要。

完整关系信息继续供 AI 及准确数据读取，不默认进入其他创作正文。现有关系意见和依据回查从所选连线／当前摘要的既有交互就近承接，必要时点击后固定当前摘要再打开原有评论或来源浮层；不将完整关系档案铺入 hover，不新增独立关系大卡或必经审核。摘要不是原文逐字引用，不能把摘要的字符偏移当成完整关系正文锚点；评论必须保持准确关系、修订与实际所评文字，旧意见仍回查原依据，不迁移到素材原件。

## 关系怎样进入生成

沿既有方法取得准确作品、当前场镜／状态、完整关系及具体参考，AI 先理解哪些方面和阶段适用，再写入人物、空间、动作、声音及必要约束所在的 Prompt 位置。关系摘要只服务人阅读，不能成为唯一生成依据；也不把关系正文、通用检查、前后阶段和后台审批提示整段拼给模型。

以 M2710 日常青衣图 → M2974 ASH001 首帧为例，当前关系包含身份和衣着保持、站位手位可变、整镜“摊本压石再唱再翻页”的检查文本。新关系可融合描述各方面；首帧 Prompt 应按实际起点表达“阿蘅保持参考中的身份与干燥青衣，站在竹篮旁，歌本仍在手中，河石在篮面”，不把镜尾翻页写成首帧已经完成，也不向人物图塞入“不要给动物套衣饰”等无关模板。这是局部拟稿示例，执行时须读准确来源与完整方案，不覆盖原镜头表演设计。

关系的生成应用必须落实到真正的方法入口与读取包：明确本次读取的关系修订及端点、当前适用范围，按方法完成理解、拟稿、回读与修订。沿 `production/seedance-video-handbook.md` 及适用图像、声音方法编制，更新对应受管方法和新步骤绑定；冻结执行继续原方法与准确输入，不补造历史。系统负责身份、修订、引用、范围、路线和一致性校验，语义取舍由 AI 按创作方法完成，不用关键词截取或机械模板代替。

现有有效生成方案也要检查：正确的约束表达保留；关系遗漏、冲突、阶段提前、纯粘贴说明等问题逐个理解后在候选中修订。按实际对象／场景分组推进、回读上下游，不批量把每条关系正文追加到全库 Prompt，不重写已确认故事、小说、剧本或安排全剧重新生成。

必需／可选、条件、择一路线及是否启用、准确版本、候选、组成、裁切和时间范围，是具体生成方案的使用选择。合并关系后这些选择仍按具体方案保存、校验和冻结；不能因合并一对关系而把所有备选变成必需、把全部阶段约束同时执行，或使图谱中的普通关联自动进入上传清单。只验证当前实际路线的缺项和循环，保持真实 CALL 的输入及许可不变。

## 真实工作顺序与验收

发布前已在真实页面读取并选择关系，另在本机独立样例走通连线摘要、参考列表与Prompt引用共享摘要、键盘聚焦、Esc关闭及打开素材后返回。样例只验证这些操作取舍，没有接入正式数据、原件或生成调用；全量迁移、版本切换、评论及生成编制的效果须在本任务中完成。详见 [样例与验证边界](unified-relations/README.md)。

1. 从执行时最新双仓主干和有效正式数据建立隔离实例，按上节区分前置代码交付、正式迁移和服务状态，核清迁移基线及顺序。读取本任务原始决定、模型证据、浏览器观察、样例，以及适用创作方法。复现上述实体、首帧、双音色关系和文字工程四条工作路径。
2. 先做一组贯通小样：实体无向关系、M2710→M2974依赖、M1134→M2669重复合并、一个M→EN或EN→M异类关系的隔离夹具、M→ASH适用关系。验证一对一身份、摘要、准确引用与生成准备可共同成立后，再迁移全部有效范围。夹具不能冒充正式作品事实。
3. 数据验收按当前关系与端点清单全量核对：同对反写、跨类别、跨阶段、版本变化和撤回重建不新增第二条；并发重复写入拒绝或更新同身份；三种编号语法正确，无向图示不自动建立生成依赖；同一关系在不同阶段有不同方向时，具体方案明确选择的本次依赖仍按准确输入方向参与缺项与循环校验。旧RL/MR和准确历史可查。不能只检字符串或只测六个样例。
4. 真实浏览器验收：实体图选择连线、读摘要、打开对象及返回；参考列表和Prompt链接hover／键盘聚焦显示同一准确关系；移入、关闭、窄屏及素材原点击工作。实际切方案版本、候选、产物Tab、打开原件和返回，验证摘要不串、位置与草稿保持。关系意见仅写隔离库，保存／刷新／重开准确回查；旧意见与原件意见归属不变。正文没有复活折叠用途或多余关系块。
5. 创作验收实际阅读原关系、当前对象与前后阶段，再读完整新Prompt，比较应保留／不应继承的内容：首帧不先翻页；阿蘅声音只取身份，真实试听原0–5.6秒确认入口和范围保持，不据此声称新声画生成效果；记工按ASH064/066各自阶段露字，不把约定算工钱。缺素材和声音未知如实保留，未授权不发生成调用。提供至少这些不同用途的具体前后文字及方法过程依据，再检查其余有效消费者，不能以数千条机械拼贴代替创作。
6. 在独立数据库完成迁移、重复迁移、失败回滚／冲突拒绝、旧准确输入读取、完整导出到新空实例后的恢复及继续写入。新恢复仍一对一，旧双模型不复活；原件哈希、真实CALL、参考范围、采用与有效评论保持，必要依赖校验不被放松。报告实际合并、整理、删除和保留范围，不把历史修订数量算作现行关系数量。
7. 隔离验证通过后，吸收两仓当时最新 main／upstream 并复验受影响行为，冻结准确双仓候选与迁移发布包，沿既有受管流程先 desk 后 primary 集成并完成必要推送。在协调后的独占正式写入窗口，核对已合并提交、准确原件哈希、当前对象／评论／引用及幂等回执，只应用本任务目标所需的准确增量；保全范围外内容、用户原意见、冻结输入、真实 CALL 与原件。随后部署本机正式服务 `http://127.0.0.1:3000/`，核对实际镜像／挂载与数据状态，在正式 Chrome 按上述实体图、参考列表、Prompt 链接、版本／候选／产物切换、准确原件及返回路径只读复走。评论保存与冲突制造仍在隔离库完成，正式验收不制造测试意见或采纳。
8. 正式发布后按最新正式数据生成完整导出，在新空实例恢复并核对一对一关系、准确旧输入、评论、原件和继续写入能力。失败或中断先核已生效的集成、推送、数据库事务与服务切换，沿同一准确发布包和回执恢复；候选确需变化时重新准备、验证，不混用新旧包。服务回退与数据恢复分别判断，不能以回退镜像代替数据恢复，也不能回灌旧库覆盖后续意见。

# 让生成方式与准确输入兑现制作意图，贯通模式约束和镜内后续身份依据

本任务贯通制作意图、生成模式与准确输入，使制作者能够判断方案能约束什么、哪些原件将提交给模型，以及镜内后续显露的身份是否有依据。本文完整承接已审定的问题、范围与六项验收，供受管任务执行和交付使用，不依赖调查时的临时容器、数据库或记录目录。任务状态以主项目 `.codex-task/tasks.json` 为准。

下述问题是 2026-10-09 已核对的正式方案事实、隔离合成检查及渠道只读配置，分别说明证据层级；本次澄清未重新执行调查，也未生成媒体。执行时须按现行准确版本和渠道能力重新核对。文内代码及文件路径默认相对所指仓库根目录。

## 用户目标与问题

制作者需要明确三件事：这次生成要保住什么、所选渠道模式实际上能约束什么、哪些准确原件会提交给模型。审阅者应能分清计划采用、已经选定、准备可执行以及实际生成结果。当前存在以下差距。

1. 当前镜头视频统一写“@图片1是已选首帧”，而正式方案样本 M2975、M3435、M3651、M4043 的原件仍未选择。方案是通用 generate 加普通图像输入，参数只有比例、时长、分辨率，没有对应的渠道模式或输入角色依据。普通图像参考不能仅靠“首帧”称呼变成固定起点约束。
2. 统一只将首帧传给视频，会丢失镜内后续需要的视觉身份依据。ASH004/M2984 先有李寄的手、后有完整人物，M2983 首帧还明确禁止把后续入场者提前放进画面；ASH012/M3008 从手部近景抬至双人。两例视频都只输入首帧和李寄音色。人物完整状态图在首帧上游，但不会自动上传给视频；符合镜头设计的局部首帧无法凭空携带未显示的面容信息。当前尚无这些首帧或视频结果，只证实方案信息缺口，不声称已经实际变脸。
3. 系统局部输入检查只覆盖部分数量、时长、附件编号等规则，不能证明模式组合有效。纯内存合成负例使用 2.5、20 秒、720p、16:9、`generate_type=1`、一图加 4 秒音色，当前 `check_parameters` 不报错、`input_contracts.check` 返回 `verified=true`。这不是正式库中的真实方案或调用；它证明现有检查未覆盖模式条件。2026-10-09T04:12:27Z 的只读模型配置明确 2.5 首尾帧模式只用 adaptive 且禁止独立音频。
4. 手册第 61 行 `pippit-tool-cli generate --help` 在当前 1.0.38 返回 unknown command；实际是 `generate-video --help`，提供 `--task-type auto/reference/edit/extend` 与 `--generate-type 1` 等入口。同版能力核对说明应与真实命令一致。

已存在且应保留的正确行为：四个正式样本的 readiness 全部为 false，准确阻断未采纳设计/方案和未选参考；准备包只包含明确选择的直接输入。上述核对未发现未选参考直接调用或采纳绕过。图像谱系限额也仅用于图像生成，不应误修成视频无法接收第二代图像。

## 目标和范围

根据 `production/seedance-video-handbook.md` 及当前渠道只读配置，使生成意图、模式/输入角色、准确参考选择、Prompt、准备包和检查结论一致。按所需保留的信息选择实现方式，确需固定起点时采用有依据的渠道方法；允许仅作普通参考的方案准确表达它的约束程度。未知或不支持的组合保持待判断/待准备，不能通过改标签或给出 `verified=true` 暗示已核实可执行。

逐场检查当前全剧视频准备路径中，起始画面与镜内后续显露的信息是否得到所需身份、状态、空间和动作依据。重点覆盖入场、局部抬至全貌、转身与遮挡揭示；保留原表达意图，不为凑单张首帧提前让角色露脸，也不要求每镜添加更多附件。选用干净身份图、必要关键图、既有素材或调整路线均需说明适用条件；间接来源应可追溯，但不自动将所有祖先上传。

模式约束按具体模型和当前渠道处理，不把 2.5 规则机械套给 2.0。只读配置表示该入口声明的能力，不代表账号权限、额度或实际效果已验证；不更新或重写历史真实调用。修正手册的实际操作入口和必要核验说明，不另建第二套方法正文。

预期降低“方案看似就绪但实际模式不支持”及“开始画面正确而后来身份无依据”的准备错误，减少用户推断参考职责和提交后返修成本。未有真实生成对照，不承诺节约金额、比例或质量提升已经兑现。

本任务不重做镜头动作与发声事件转译，不制作歌曲，不批量去重机位或重写全部素材需求。它与“从准确镜头事件形成动作与声音方案”交接当前有效镜头意图、动作边界与发声身份，两项可并行准备，集成时对受影响准确版本复验。无需强制前置依赖。

## 验收标准

1. **普通参考与固定起点可区分。** 正式样本及另一集代表镜头的方案能看清计划方式、各输入职责与未选状态，未选原件不被宣称已选；若设计要求固定首帧，实际准备信息包含可核对的渠道角色/模式或明确记录无法满足的原因与替代选择。不能把普通参考的自然语言承诺当作接口约束。
2. **后续身份有依据。** ASH004、ASH012 及全剧同类揭示镜头的实际输入计划，覆盖首帧未显示而镜内需要保持的身份/完整状态；编号随准确输入顺序一致。首帧和视频分别执行其职责，后续入场不提前，音色不冒充视觉身份。无需额外参考的镜头能保留简洁路线，不自动上传间接祖先。
3. **契约检查结论准确。** 用只读渠道能力和隔离合成方案验证普通参考、固定起点、含音频参考较长镜头及不支持组合。上述合成首尾帧负例得到明确不兼容结论；未知模式不得冒充已验证。允许的组合通过相应层级检查，但结论说明它验证的是参数/输入契约，不是账号可用或实际效果。独立采纳、准确候选、文件存在、版本和谱系闸门仍有效。
4. **准备与登记闭环。** 隔离候选中从方案选择到准备包读回准确模式、参数、原件、候选、组成与必要范围；调用登记继续防止实际输入偏离已认可准备依据。检查必要模式数据是否在各层保留，不为支持新路径修改旧调用回执。采用合成夹具时明确标记，不混入正式作品素材。
5. **真实页面与文档验收。** 在隔离候选实际使用相关镜头和素材方案、参考选择及准备状态，检查创作审阅用户能理解当前可作的决定；不默认把内部校验日志堆入界面。正式增量发布后从原入口只读回查准确版本与样例。按手册只读命令能得到正确 help/model 入口；API、代码或文档自检不能替代页面验证。
6. **范围与交付。** 全程无真实图像、音频、视频生成，不消耗历史授权或新增费用；没有真实结果就保留身份稳定性、动作、口型和音质待验。保留原件、评论、采纳和修订历史；通过现有受管任务流程以执行时最新主干集成、按序发布、完成过程资源清理，报告实际验证层级及限制。

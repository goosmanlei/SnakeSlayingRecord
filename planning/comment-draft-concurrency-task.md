# 并行审阅时保住各自草稿，并在冲突后继续处理准确意见

本任务保护同一意见并行编辑时各自的草稿，改善保存冲突后的核对、人工处理与恢复。本文是完整、独立可执行的任务规格，保留已观察事实、准确归属、实施过程和六项验收；只处理评论编辑、保存冲突与草稿恢复，不建立新的多人协作工作台。历史观察用于执行时复核，不代表最新版本仍有同一问题；执行以最新主干和有效正式数据为准，不依赖系统 Review 临时实例。

## 用户目标与实际观察

用户可能同时打开两页审阅同一条意见。一个页面先保存后，另一个页面尚未提交的文字应仍然可找、可核对，并由用户决定如何合并或放弃；正常切页和刷新不能悄悄替换这份草稿。保存应保护开始编辑时所依据的评论版本和准确目标，不能仅因后台数据刷新就把旧草稿当作针对新版的修改。

主会话在 Chrome 的隔离实例 3301，对故事采编白话译注的功能测试评论 C282 完成两轮实际操作，正式评论未写入：

1. 第一轮，两页从同一版本编辑不同文字。A 于 2026-10-09 05:16:21 UTC 保存成功，评论成为版本 5；B 保存被正确拒绝，提示原样英文 `comment version changed; refresh before editing`，编辑框保留 B 文字。按提示刷新后没有自动回到原编辑框，但点击该评论“编辑”能恢复 B 草稿。因此本轮没有覆盖已保存意见，也没有删除 B 草稿；存在的是冲突说明和继续处理路径不清楚，不能把它写成文字丢失。
2. 第二轮，两页均从版本 5 开始编辑；B2 在 A2 保存前已填好不同文字，一直没有提交。A2 于 05:18:33 UTC 保存成功，评论成为版本 6。随后 B 页实际点击“故事结构”再返回“故事采编”，打开评论时，编辑框恢复为此前缓存的 A 第一轮文字，B2 输入不见；评论卡正文也仍为该旧内容。随任务保存的截图 `isolated-comment-draft-return.jpg` 留存返回现场。数据库仅有 A2 的一次编辑，B2 未保存，不能从数据库重新取得这份草稿。

根因线索与实际路径相符：同一准确目标、评论和圈选共用 localStorage（浏览器本机持久存储）草稿键，没有区分正在编辑的页面。B2 输入写入该键后，A2 的保存入口先把 A2 文本写到同一键，成功清理时看到的是自己刚写的值，因而清掉该键。B 页当时仍有编辑框中的 B2；切页只记录圈选、编辑对象和目标等定位信息，不保存正文，返回读取不到草稿便退回本页缓存的评论正文。第一轮 B 的保存尝试会在冲突前重新写入 B 文本，解释了其刷新后仍能恢复的反证。此处说明机制，不预设必须采用哪一种存储架构。

另有一个尚未实操证实的风险：现保存代码在提交时从当前评论列表取 expected_version（提交时声明所依据的评论版本），而非显式保留开始编辑的版本；窗口获得焦点后会刷新列表。原生窗口焦点验证受工具限制未完成，不能据此声称已经发生静默覆盖。执行时应核查并验证这项版本边界，但不需要为重现假设注入伪造 focus（获得焦点）事件或修改页面内部状态。

## 范围与边界

保护每个实际编辑过程的正文、准确目标、原圈选和开始编辑依据。一个页面成功保存、取消或处理提交回执，不应误清理另一个页面尚未提交的不同内容；不同素材版本、故事版本或圈选的草稿也不得串用。沿既有编辑器和本机恢复能力实现最小改动，必要时提供清楚的冲突解释和恢复操作，不默认添加同步日志、协作成员、锁定流程或管理页面。

发生版本变化后，让用户知道什么已经保存、当前草稿尚未保存，以及如何查看最新意见并继续自己的修改。用户可核对后人工合并，或明确放弃自己的草稿；不能自动合并覆盖、把草稿偷偷升级为新版本修改，或因点击刷新而丢掉尚未处理的内容。冲突后保存应再次基于用户实际核对的准确版本，并继续保留服务端并发拒绝。

保留当前准确目标与圈选、评论编辑历史、关闭/重新打开、提交防重与失败保护，以及查看润色参考、润色前后文字和人工采用建议的既有能力。此任务不修改真实评论内容或状态，不改 AI 上下文选取方法，不新增外部 AI 调用费用。功能测试使用隔离测试意见，正文明确标注不代表作品质量或用户采纳。

预期降低跨页丢稿和冲突后的返工，使用户能完成正在进行的审阅。当前两轮只是明确复现路径，没有统计发生频率、影响人数或损失比例，不将局部观察推算为全库问题。

## 实施过程与过程验收

先在执行时最新版本的隔离环境创建明确标记的评论，按上述两轮真实路径工作：打开两个页面、各自编辑、另一页先保存、当前页提交或跨页返回，再刷新并寻找自己的文字。核对哪些保护已经正常，记录丢稿或无法继续的位置；不以构造存储键、直接调用内部函数或单次 API 冲突代替浏览器中的实际流程。

提出最小可运行改动后，实际完成“写意见→另一页保存→带草稿去另一页再返回→查看新版→人工合并并保存”的完整工作，再走“发生冲突→刷新/重开→找到草稿→明确放弃”的分支。观察用户是否能区分已保存内容与自己的未保存修改，是否仍需猜测隐藏入口，新增说明是否确实帮助当前动作；据观察调整，而非先铺一套状态标签再补测试。

然后核查同一评论的准确旧目标、另一条评论以及现有润色入口的草稿边界。自然焦点刷新、请求迟到和保存失败只按真实可达路径或必要受控自动检查验证，分别报告，不把工具模拟当作原生操作。无需为本任务真实调用收费模型；润色建议的状态保护可使用已存在结果或隔离可控响应，说明证据边界。

按受管流程完成集成与发布，在对应最新版本隔离实例完成写操作复验，正式入口只读核对准确评论导航与版本边界。过程记录保留实际断点、候选使用反馈和由此产生的取舍，不补录过程、不机械逐字段留痕，不用截图或测试清单代替实际工作。

## 验收标准

1. **一页保存不会清掉另一页不同草稿。** 两页从同一评论版本开始写不同文字，B 先填、A 后保存，B 未提交时跨工作区返回、刷新或重开，应能继续找到完整 B 草稿及其准确目标。A 保存成功与 B 尚未保存的事实可理解，不能用旧 A 正文冒充恢复成功。覆盖另一页取消编辑的边界，不误清不同编辑过程。
2. **冲突后可以继续完成审阅。** 重走第一轮正确 409 拒绝的路径，保留服务端已保存 A 和 B 原稿。界面用可理解的语言说明冲突，用户能找到自己的草稿、核对最新内容并选择人工合并或放弃。合并后按准确新基线保存一次；放弃只清理明确选择的草稿，不删除评论或其他页面的输入。
3. **开始编辑的版本不会悄悄改变。** 编辑期间另一页保存、列表刷新或迟到响应发生后，旧草稿不能仅因客户端拿到新版本号而无提示覆盖新版。用户核对后的重试仍受服务端版本校验；再次变化继续拒绝并保留输入。自然 focus 路径若未完成真实验证须明确保留限制，不能声称已复现原基线静默覆盖。
4. **准确归属和恢复完整。** 保持目标修订、文字/图像/时间锚点、评论版本与历史，不把草稿移到当前最新作品或另一素材候选。覆盖故事采编实际文字评论，以及共享评论编辑器的一个现有制作入口；换评论、换版本、关闭重开和浏览器返回后，当前编辑与恢复对象清楚，必要阅读上下文保持。
5. **现有失败与润色保护不回退。** 本机存储失败、网络失败或响应未知时不丢当前输入，不制造重复提交；提交成功后的清理只处理自己的已提交内容。保留关闭/重新打开操作与准确历史，查看润色参考、生成建议等待、人工采用到草稿及返回编辑时，不误清或覆盖另一页面的草稿；本任务不产生外部 AI 调用费用。
6. **实际交付可以复查。** 相关草稿归属、开始编辑版本与并发保护有必要自动检查，且完成上述隔离浏览器真实工作闭环。回执区分页面实践、代码/接口证据、未完成验证与测试专用写入；按最新主干集成、按序发布，完成过程资源清理。不得把旧隔离实例通过当作新正式版通过。

每条任务结束时，最终可见的会话回复须先给出任务编号，并用普通语言说明本次实际解决的问题、实际变化与用户收益、真实验证及其边界，以及未解决事项和下一步，让用户在多终端执行时能快速判断方向。提交、测试数量和清理回执作为必要证据附后，不能用它们替代结果说明；不能将计划效果写成已经实现。暂停或失败时同样说明实际做到哪里及尚未完成什么。

## 已核对的共同原因与范围

- `review_desk/server.py:326` 的 HTTP 缓存键包含完整路径和排序后的全部查询参数，搜索词变化会成为不同键。命中可直接返回；未命中进入 `server.py:447` 的材料投影。
- `ui_projection.py:135` 先取得 `material_entries`；它虽有可复用的共享投影缓存，失败、无缓存或失效时仍构造全量素材、关系、准确输入、旧调用用途和搜索字段。
- `material_list` 随后调用 `production_scope.projection`，最后才使用检索词、集场、媒体和结果条件筛选。当前 `production_scope.graph` 即使指定 AE001 也保留并遍历全剧各集场镜；`projection` 在无 `focus` 时处理全部位置，重复读取准确关系与输入。素材页没有把一个已检索词的全局投影复用为下一个词的轻量筛选。
- 这既包含无共享缓存时的全量目录成本，也包含共享目录命中后仍会发生的范围投影成本。正式两次新搜索究竟分别命中了哪层缓存，本专项没有观测，不能只凭 cProfile 宣称“正式每次都重建 material_entries”。

已有 [视听切集切场任务](../av-switch-performance-task.md)（task-20261011-0007）明确只优化视听制作切集切场，验收是目标镜头可读时间；不是全站性能巡查，素材管理搜索及筛选不在它的明确范围。当前可以定义素材管理首次检索／筛选的独立性能目标，不应重开 0007 或把新症状称其未交付。

应针对单次需要完成的素材查找，消除不随查询改变的重复目录／关系计算，把必要筛选前移或复用准确派生结果；实现方式由后续隔离测量决定。不能仅预热每个关键词，不能靠删真实输入、关系、历史候选、分组或评论计数换速度。复用必须保持准确集场修订、规范素材身份、必要历史输入、写入后新鲜度与跨进程失效，缓存不可用时仍正确。有必要记录首访、换关键词、切集场/媒体、写入失效与重复读取的同条件对照，保留失败，真实页面可操作时间与 HTTP 时间分开。

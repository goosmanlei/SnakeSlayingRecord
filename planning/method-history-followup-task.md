# 方法改稿后仍能找到旧意见，读清原文、回应和当前修改

人在系统管理审阅 SKILL 并提出意见，AI 改稿以后，人应从当前方法的“查看评论”继续找到这条意见，读原圈选和回应，核对当前改动，再回到原阅读位置。当前只有已经关联作者回应的旧意见能进入“历史意见复核”；尚未回应的旧意见从当前页面消失，恰好阻断最需要继续处理的反馈。

## 任务字段与交付终点

- 摘要：方法改稿后仍能从当前页发现旧意见，准确回查原文、回应与当前修改。
- 优先级：P1。反馈已经保存却从后续工作入口消失，阻断继续处理；目前仍有准确旧数据和回应后的正常路径，未证实数据丢失。
- 依赖：`task-20261011-0008`、`task-20261012-0003`。前者提供本轮准确归并基线，后者提供方法／资源阅读、原文评论、回应与所选后续应用；依赖成果按准确回执核对，不固定执行基线。
- 复杂度：复杂；模型 `gpt-6.1-sol`，推理强度 `xhigh`。需协调跨修订查询、计数与列表、文件锚点、三份稿件的回应关系、异步返回、完整恢复及双仓正式交付。方向和复用机制已查明，没有明确高于 xhigh 的自动委派收益，不选 ultra。
- 并行：允许独立 worktree 开发。与状态契约简化草稿的主体修改、数据范围和验收不同；公共评论／方法代码发生实际重叠时，吸收最新主干后联合复验。可写库、端口、缓存、临时镜像和浏览器存储各自隔离，浏览器控制另行协调；无法隔离的部分暂停并行。共享正式写入和服务发布串行，不以空依赖或独立工作区推导正式资源可并写。
- 完成：受管双仓集成及必要推送、本机 3000 正式生效、真实 Chrome 验收、完整导出到新空实例恢复与过程清理。仅交候选、提交代码或阶段归档均不满足本任务。
- 本会话授权仅为澄清与正式发布任务；执行会话按上述终点交付。本轮不运行任务、不改产品或正式业务库、不部署、不恢复持续 Review。

## 已查明的现场与选择

根 Review 在六项任务合并后的准确隔离实例中，实际阅读“镜头目的、关键状态与产物方案”第10版，在 purpose 段圈选66字并评论 C413；编辑增加具体行为/对白自检，保存且只用于后续视听设计，得到第11版。新步骤确实取得11版并用于 ASH009 的逐步创作。可是刷新11版，“查看评论”显示0，正文版本只列11，没有普通入口找到未回应的C413。

诊断时手动打开准确10版，C413及高亮原摘录完整存在。根通过原意见保存对实际11版修改的回应，再用页面切到11版，“查看评论”才出现历史意见复核；其中原圈选、当前改动及返回阅读能力可用。原意见未丢，问题在跨修订发现与回查。手改链接只能证明数据尚在，不能作为用户路径通过。

本任务是 task-20261012-0003 已承诺的“改稿后回查原意见”确切残留；不重开旧任务，也不重复方法阅读器、条件应用或作者阶段协议。复用现有评论侧浮窗、历史意见复核、准确方法/资源修订和返回阅读位置，不新增审批、管理实体、专门历史页面或新评论副本。

## 改后的完整工作

1. 在当前方法或共用资料点“查看评论”，默认能看到该对象仍未关闭的意见，包括当前稿及旧稿的、已回应和未回应的意见。旧意见简明标出所针对的版本和文件，直接展示意见正文；不要先要求人选中未知旧版或展开隐藏区才能发现待处理意见。当前稿与旧稿身份清楚，不把旧锚点迁到同名新段落。计数与所展示范围一致，不能有未处理旧意见却只提示“暂无待处理评论”。
2. 点旧意见，沿现有复核入口读取准确旧文件的原摘录和必要上下文；原文件在当前版被改名或删除，也使用原修订。没有回应时明示尚未回应，并可沿已有回应功能处理；有回应时读其实际修改版本与当前稿。原圈选、回应所对应稿件、当前稿三者可以不同，不能把最新稿冒充回应当时的稿件。列表不用提前平铺所有历史全文。
3. 返回保留当前方法、文件、阅读位置和评论上下文；刷新、重新进入该方法、再次改成12版以后，未关闭旧意见仍能找到。关闭只整理意见，旧原文与回应仍可从已有已关闭历史入口回查；重开后回到正常待处理范围，不阻断创作、不变为审批。
4. 同一规则适用于实例方法和只读共用资料（系统内均为 GUIDANCE 对象）。共用资料更新后，旧意见仍落在原准确源投影，维护权仍在项目源；不开放另存可编辑副本。现有正文版本切换是否补全可按实际需要实现，但最终路径必须由普通页面完成，不能以手填修订ID、浏览器地址或开发工具为前提。

这是对现有反馈工作的一次修复，主阅读区仍以正文为主。无需增加响应进度标签、执行日志或另一个历史树；技术加载失败与“没有评论”要明确区分，恢复后可重试原准确目标，不换最新版补缺。

## 技术范围与现有能力

实例方法与共用资料在系统内均是 GUIDANCE（受管方法／资料对象）；以稳定对象身份汇集其各准确修订的相关意见，再按原修订和文件读取。既有评论仍是唯一状态来源，不能复制为另一份“历史待办”。同一评论在当前和历史集合合并时只计一次，关闭／重开后计数和列表随同一真实状态更新。

当前源线索为 desk 的 `review_desk/comment_review.py`、`review_desk/methods.py`、`review_desk/static/comment-review.js`、`review_desk/static/methods.js` 及 `review_desk/static/app.js` 的相关评论范围和计数。调查版本的历史复核只通过回应关联纳入方法旧意见；准确旧方法文件可读。执行者可选择实现和组件组织，须补全没有回应时的查询、发现与复核，不能只修版本下拉框或一张截图上的计数。通用能力留 desk，必要源投影、恢复交接、准确实例引用和本剧验证留 primary。

适用范围是当前打开的同一个方法或资料对象，覆盖其所有准确文件；引用到其他共用资料时，进入该资料自身再查其意见，不能把关联资料或别的方法意见混进当前列表。同一方法跨文件的旧意见标明文件。原文件在新稿重命名或删除，旧意见仍指旧修订中的旧文件；准确旧目标确实不可用时说明错误，不能按同名段落猜配。读取失败与合法空列表分开，迟到成功／失败不得覆盖后来选择的对象或文件。

正文版本控件可按普通回查需要补全，但不是独立建设全量版本树的授权。保留现有方法阅读、编辑待用／所选应用、类型化条件、源同步和新旧执行契约；不重做作者阶段全文保存恢复、不改变专业方法的创作含义、不替本轮状态契约任务整理状态或 Prompt。

## 实施与验收

先在执行时最新准确隔离版本重走“读10版→圈选意见→改11版→尚未回应”的核心例，记录修前断点并验证修后普通入口能找到原意见；再用同一意见保存真实修改回应并回读前后。根已验证现有回应后复核可复用；本任务须补全回应前与连续改稿情形。必要输入随任务放入 planning 证据目录，截图走受管媒体登记；C413是根私有实例编号，执行者重现实例不必复用同号，不得写入正式意见。

以下验收均使用真实 Chrome；版本 10／11／12 是根样例的历史编号，新隔离实例可使用对应的连续修订，但须记录实际身份：

1. **尚未回应也能继续处理。** 原稿准确文件圈选并保存评论，改下一稿且不保存任何回应；刷新并重新进入当前方法，直接打开“查看评论”即可看见旧意见正文、原版本和文件，并读原66字及新增自检条款。再改一次仍不回应，重开后仍可发现同一条，不能预制回应来通过。
2. **原稿、回应稿和当前稿分别准确。** 使用原评论对第一次实际修改保存回应，再产生后一稿。复核时可分别读原稿圈选、真实回应及当时修改稿、当前稿；后来改掉已回应文字时不能继续暗示当前稿保留该改动。返回恢复进入时的方法、文件、阅读位置、意见上下文及未提交草稿；不把当前稿冒充回应稿。
3. **状态与文件对照。** 当前稿新评论、无任何评论、旧稿未回应／已回应／已关闭、关闭后普通历史回查及重开分别验证；重开回正常待处理范围。对同方法多文件、不同方法同名文件／同文段、当前已改名和删除的旧文件，核对评论身份、摘录、去重及计数，不能跨对象串入。
4. **错误恢复仍指原目标。** 在隔离环境使准确旧文件读取失败、评论请求失败或延迟，再恢复原件／请求；页面报真实错误并可重试原准确目标，不能显示“暂无评论”或替换最新版。等待期间切另一对象、文件或关闭复核，迟到结果不串入。关闭／重开遇保存失败或并发前进时，沿既有冲突机制保住意见和输入，重新读取后再作选择。
5. **共用资料与完整恢复。** 用实际由项目源维护的一项只读资料，在隔离源及实例沿既有同步入口产生新投影，走未回应旧意见、准确旧文件和返回路径。新评论、两次改稿、真实回应与关闭／重开状态完整导出，恢复新空实例后再用普通 Chrome 页面复走。核对评论 ID、作者、时间、锚点、事件、准确文件字节、回应对应修订、旧执行快照和未选绑定，不能仅核对数据行数。正式源不带入试验改稿。
6. **正常路径不回退。** 已回应例的原圈选／回应／当前修改及返回继续可用；必要时展开准确全文而非平铺所有历史。改动共用评论逻辑后，以故事正文历史回应和制作当前评论各走一例，包括准确定位、列表计数、草稿和返回。方法普通阅读、编辑待用及所选后续应用保持，关闭意见不成为审批或创作前提。

适当自动回归覆盖跨修订查询、状态／对象／文件过滤、去重、准确旧文件与错误恢复；不以单元测试、接口“仍存在”或手填链接代替真实UI路径。所有评论、编辑、关闭／重开和故障试验只在自有准确隔离库进行；历史回查不重新启用旧方法，也不重建评论或改原锚点。

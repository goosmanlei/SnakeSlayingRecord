# 优化任务：按实际用途准备状态素材，并将必要差异传入镜头

本任务规定按实际用途准备状态素材的目标、方法、证据与验收。任务登记、执行及完成状态以主项目 `.codex-task/tasks.json` 为准；当前澄清仅整理并发布任务规格，不实施目标、不提交媒体生成。用户已授权发布本项已审定的优化任务。除另有说明，文中项目内路径相对故事任务工作区根目录。

## 用户目标与已核实问题

制作者需要知道哪些状态差异必须在画面或声音中成立、为此需要准备什么，以及准备结果会支持哪一步制作或审阅。准备事项应有可理解的用途，实际镜头则应得到足够且准确的状态依据。

当前编制对全部已使用、允许图声参考的实体状态建立必需的“整体参考”生成需求。本轮统计其中 54 项标为 `required=true`、`usage=generation_input`，却没有当前素材关系中 reference、variant、reuse 三类可执行下游：45 项空间、4 项歌曲、4 项道具、1 项人物。统计排除了用于最终剪辑的视频，也未把候选比较关系当作实际输入。54 是本轮定位范围，不是无用素材数量；没有生成下游的图仍可能用于全局审阅、结果核对或制作交接。

正式 Chrome 已实际打开 EN070 渡口的 ST167 货船临岸装货/M2783 整体参考与 ST168 船板撤离岸边/M2784 整体参考。两者分别要求独立生成，前后差异清楚且具有剧情价值；页面和当前路线没有说明这些整体图随后用于哪一步。制作选择却都沿用“未写换装、湿痕消退、伤愈程度”的人物说明，图像检查也统一要求“身份、配色、服装与伤侧”，增加理解成本而没有帮助判断船板、岸沿和通路。

辅助数据与实现核对发现：

- ASH096—098 的主机位 M3258/M3261/M3264 都只引用渡口根母版，不引用 ST167/ST168 的布置；首帧 M3259/M3262/M3265 排除了所有空间状态。ASH098 首帧有“水拍空石沿”，并非完全没有撤板提示，但没有明确传入“同一货船、船板已拖回”的准确布置，反而继承整场动态“船板从左收向右”。尚未生成实际镜头，不能宣称已经出现船板复原或画面错误。
- `scripts/audiovisual_materials.py` 的 `forms()` 为使用过的状态统一创建必需整体参考；`shots()` 的机位仅取空间根母版，首帧排除空间并按每主体第一项状态建立输入，视频曲调直接取独立歌曲。当前的状态描述、状态图用途和执行输入因而可能脱节。
- 渡口实体及两个状态另有真正的“制作描述缺失”阻断：它们有 blocks/dimensions 中的空间文字，但缺少 `production_description`，当前 preparation 契约据此报告三项 description_missing。这与方案未采纳、输入未选择不同，不能靠自动采纳消除；也不能为满足字段机械复制一份内容，须判断现有描述的职责与实际充分性。

主会话已另用正式 Chrome 检查 EN117 庙后封闭小院：ST312 刀缝已开长杠待绑/M2930 明确“盖石外段已凿窄刀缝，其余盖严；长杠抬到立柱旁尚未绑”，关联 ASH190—199 共 10 镜；ST313 刀缝长杠已好/M2931 明确临时盖条、已绑长杠及后门到石道无工具阻道，关联 4 镜。两项新整体参考均无候选，但能查到各自已有旧原件 1 份；实体和 5 个状态都显示制作描述待完善，并有同样的人物模板误用。证据为主会话 `formal-courtyard-state.jpg`，此前只列少数关联镜头的样例不能当作完整范围。

其他待逐项判断的代表包括 EN032 孩子 ST330 掉一只鞋/M2950、EN049 半块饼 ST116 缺角/M2730、EN084 李家 ST208 夜归门未闩/M2825。目前它们只有辅助数据证据，不能冒称本 Review 已实操。现有歌曲状态参考也须判断实际声音职责，不把歌曲尚未完成工作等同于本次新缺陷。

## 目标和范围

从镜头与审阅需要反推状态素材准备，核对执行时当前全剧有效状态需求。完整判别本轮 45 项空间及另外 9 项的实际职责，并检查同一编制原因影响的其他现行需求：确需准确视觉/声音参考、已有成果可评估复用、仅需文字或结果检查、用于全局审阅、可选准备，或确无当前用途。没有下游不自动删除，有一个关系也不自动证明有价值。

将重要状态差异以最低合理成本传给需要它的机位、首帧或视频方案。可复用已有准确候选、保留充分文字、选择必要参考或调整合理制作路线；按具体条件决定，不强迫每个状态都先生成图再生成机位和首帧。空间关键关系不能因追求少步骤而丢失，也不能为了“全覆盖”增加图像传递代数、超限附件或不必要的待审项。

修正共同编制原因和有误导性的跨类型模板。人物、空间、道具、歌曲的检查服务其实际作用：例如渡口检查岸船位置、板是否连接通路及撤板先后；空间不要求服装伤侧，道具和歌曲也不机械继承人物表述。优先复用已有状态、描述和审阅入口，不新增一组机械字段、重复管理页面或平行状态账本。

在本任务涉及的镜头状态呈现中，围绕真正要核对的变化、不变约束和已有素材卡表达，减少同义名单的重复扫描；没有额外决策价值的背景引用不必独立铺在前台。保留全部有效准确状态、来源、转换和后台校验，完整内容按需可追溯。不要仅更换两个标题或给所有背景增加一段模板说明；也不扩大为全 UI 改造。

预期减少无用途的生成准备、重复审阅和检索成本，同时降低关键状态未传入镜头导致的返工。分别报告取消或降为可选的准备、复用已有成果、补足真实缺口及保持不变的合理项目。没有实际执行的计划不能计作已节约调用或费用。

本任务不提交新增付费图像、音频或视频调用，不动用历史授权。需要新素材而尚无结果时形成准确待准备方案，保留输入未选、方案未采纳等真实状态。

## 必须采用的状态用途判断过程

按集顺序阅读准确剧本与已有视听设计，先理解人物选择、主题表达和本集场面任务，再逐场、逐镜判断状态差异在何处可见或可听、何时变化、如何接续，以及它需要哪种最低成本的准备或检查。每集完成后复核人物、主题和跨镜连续性，把已确认的用途判断应用到后续集；新条件影响先前选择时回查相关前集。已有正确成果与准确候选优先保留，不批量重建状态。

对每项有疑问的准备，先明确使用或审阅目的，再比较已有文字/图声是否足够、是否值得复用或补充，最后形成需求和路线。脚本仅检查覆盖、依赖、谱系和汇编已确定的判断，不按一次全剧推断或出度统计自动删除/生成。涉及逐镜 Prompt 时，先读手册并选适用模板，读准确目的与起点—变化—落点，核输入，再写模型友好表达并自检；模板不变成每镜机械字段。

### 实际工作、最小候选与反馈迭代

先重走制作者的实际工作：从状态查看必要差异，追到使用它的镜头或独立审阅目的，比较现有文字与准确候选，判断是否仍需准备，再回到镜头确认起点、变化和落点。记录具体哪里需要反复扫描、哪里无法判断准备用途、哪里确有信息缺口；不为凑指标假设耗时或节约比例。

在准确基线上形成最小可运行候选，先让渡口及必要反例完成“看状态差异→判断用途→比较复用或待准备→读回镜头所需依据”的完整操作。观察实际页面反馈，再调整准备判断、描述职责、路线或展示表达，重走受影响路径及其他类型反例。最小候选服务于验证方法，不代替全部当前范围；不能先一次性生成全剧判断或最终界面，再补写观察、迭代、截图或测试作为过程。

全剧判断按上述逐集顺序继续，集末复核后将所得应用到后续；出现新条件时回查必要前集，原结论仍合理时保留，不人为凑修改。正式增量发布后从同一原入口只读复验，分别说明辅助检查、隔离实操和正式页面证据；本会话对上游截图的读取不冒充正式浏览器实操。

这些过程要求共同约束第 6、9 项验收。验收中会写入数据的配置或选择操作只在隔离实例进行；正式页面只读回查，浏览器受阻时保留待验，不能以接口或静态检查通过替代。新增图像连接按最深实际输入核对，谱系仍不得超过两代；必要时回到干净母版重定路线，不以新增第三代图像补齐状态。

## 验收标准

1. **当前全量判别有依据。** 对当前有效状态参考逐项核对制作或审阅职责，本轮 54 项全部有可回查结论；其他同源问题同步处理。区分缺少连接、合理的独立审阅依据、可复用成果与不必要准备，不能用出度、字段齐全或固定数量替代语义判断。已经没有用途的必需项受控撤回或调整，不破坏历史。
2. **空间差异贯通。** 渡口 ASH096—098 能说明板仍在、收板过程、板已离岸各阶段由什么准确依据保证；刀缝与长杠等关键空间按相邻镜、场、集检查，确认不提前揭示、遗漏或复原。机位与首帧中所需空间状态足够明确，既有合理固定拓扑继续保持。允许有依据地不再单独做整体图，不要求每镜上传全部空间状态。
3. **不同职责的反例成立。** 至少实际核对一个镜内变化后的道具状态、人物状态、独立空间审阅用途与歌曲状态声音用途。结束状态只用于验收时，不因未成为首帧输入判为漏接；确需端点参考时给出理由与有效路线。歌曲已有未完成计划保持准确衔接，不为满足本任务新建无意义音频。
4. **描述和模板准确。** 渡口已有空间描述能以清楚的权威职责进入准备判断；确实缺少的内容才补足。不会仅因内容放在旧入口而要求用户再填相同文字，也不放宽真实缺项检查。当前全量同源人物模板误用被修正，检查重点能回答该对象的实际判断问题。制作描述通过、方案认可、候选选择和实际效果分别成立，不自动转授。
5. **路线成本受控。** 拟保留的图声准备有明确消费或审阅用途；已有准确候选可进入评估，不默认重复生成。图像谱系按最深实际输入计算，新增状态连接不能使母版→状态→机位→首帧形成未经处理的第三代。附件职责与模式限制准确，未知效果不写成已验证；不为降低数量删掉必要依据。
6. **操作与交付验收。** 在与候选一致的隔离实例实际使用代表空间、道具、人物和声音状态的查看、用途追踪、复用比较与必要配置操作，回读准确状态。正式增量发布后只读回查渡口、关键空间及其他代表情景，从状态和镜头两端能理解所需准备及待办原因。分别报告辅助检查、隔离操作和正式 UI 结果，未生成处不声称实际连续性通过。完成必要回归、受管集成发布及过程资源清理。
7. **历史保护。** 保留用户评论、采纳判断、原件、真实调用、准确版本和已采用关系；调整需求或描述生成新版本，旧方案及其判断不自动变成新方案认可。准备减少不等于抹掉有效状态事实，旧候选不因需求调整被删除。
8. **状态展示确有用。** ASH001 的米袋背景与本镜实际状态能围绕当前应核约束理解，用户无需在两组同义列表和素材卡反复扫描；完整准确引用仍可按需追溯。真正影响当前判断的画外连续性约束仍能被看懂，不能无差别隐藏或删除来缩短页面，也不为制造反例添加本来不需要的约束，更不能把所有背景强塞进首帧。只改标题、加模板解释或改变数量不算完成。
9. **专业判断按集迭代。** 有按集顺序、场镜落实的状态用途判断与集末人物/主题/跨镜复核，后续应用和必要前集回查可追溯。没有修改需求的合理项目可保留原结论；不得以一次模型输出、批量规则填充或自动检查通过替代实际判断。

## 任务安排与去重边界

- 摘要：按实际用途准备状态素材，贯通必要差异并减少无效准备与重复审阅。
- 优先级：P1。现有准备要求和下游依据脱节会增加制作及审阅成本，应在实际制作前收敛；没有证据表明当前正式服务不可用，不按紧急故障处理。
- 复杂度：极复杂；模型 `gpt-6-astra`，推理强度 `max`。需把全剧逐集状态语义、描述职责、最少准备、跨镜连续性与图像谱系限制统一判断，并跨故事编制、通用准备契约和真实用户路径迭代验证。较默认 `xhigh` 提高强度是为处理这些相互约束及反例，不以材料数量或耗时作为升级理由。逐集结论有前后依赖，当前未见相对 `max` 明确可验的自动委派收益，不选择 `ultra`，不承诺固定提速或质量提升。
- 同项目 task-id 依赖：空。下述任务均不作为强制前置；任务状态只读主项目 `.codex-task/tasks.json`，执行时重核当前范围与结果。
- 并行属性：允许。在两仓各自受管 worktree、独立测试数据库、缓存、文件写入目录和端口准备与验证，浏览器控制窗口协调使用。故事编制脚本、通用准备及展示组件存在可协调重叠，集成时吸收最新主干并复验准确版本、状态用途与受影响路径。共享正式数据库、正式配置、服务、部署入口、正式镜像标签与发布写入须互斥串行；无法隔离资源或实际语义冲突不能独立收敛时，停止对应并行部分并重新评估，不把无前置或独立 worktree 视为并发正式发布许可。

去重以最新账本的完整目标、完成标准及各自受管工作区中的规划为依据；主项目已交付的来源卡、旧素材准备和全剧视听设计规划仅按现行职责承接，不重新发布旧任务，也不更改其他任务。

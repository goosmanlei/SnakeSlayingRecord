# 以基础流程组织 SKILL 管理，建立文件独立版本比较，并用关系图讲清数据模型

## 要解决的问题与改后工作

用户认为 task-20261012-0010 的“工作方法”页仍把方法、共用资料、工作环节等内部分类交给人理解。人想改进某项创作能力，应从创作流程找到对应 SKILL，读具体文件和历次变化，再发表评论。系统管理的另一基础是数据模型，应能直接看懂各类创作数据的关系。

将本次需求作为一项完整任务交付，承接用户对0010的新定位，不恢复或重做其旧三Tab方案。正式页面改为“SKILL管理”和“数据模型”。前者左侧为可点击的创作基础流程图，右侧为相应 SKILL 的文件结构、文件正文、独立文件版本及评论；后者保留准确编号说明，在下方呈现核心数据实体关系图。最终在本机正式服务生效。

调查、流程与方法对应、旧图迭代依据见同目录 `skill-admin-data-model-investigation.md`。该文件是必要输入；调查时的版号是证据，不是开发锁定的旧基线。

## SKILL管理：先找到能力，再读文件与变化

1. 系统管理导航、页标题及相关入口统一称“SKILL管理”。取消“方法／共用资料／工作环节”顶层组织、旧业务筛选和整包方法目录。页面仅服务阅读、文件/版本导航、比较与评论，移除新建方法、编辑正文、维护执行配置、保存/应用及下载等无关操作，不另藏进菜单或弹窗。AI维护、来源同步、方法取得与准确执行等后台能力继续有效，不迁移成另一套人工配置页。
2. 左侧以自上而下的图展示完整基本流程：采编与方向 → 故事结构 → 小说创作 → 影视剧本 → 视听设计 → 实体、状态与素材抽取 → 素材方案 → 生成准备 → 生成与制作 → 结果检查与返修 → 剪辑成片。结构与小说可以回读修订；素材方案内并列图像、声音、视频、字层、其他素材五个能力节点，不误画成必须逐一完成的五道工序。独立读者、意见表达置于阅读反馈支路，创作协作Review置于系统改进支路，清楚连接所支持的创作过程，不成为每项作品的强制审批。
3. 有真实已固化SKILL的节点可点击并明显选中；没有已固化SKILL的流程节点以普通流程文字/图形显示，不制造空方法、假能力或无效按钮。当前15个被使用方法及12种工作绑定见调查映射。读取实际注册与绑定，同一能力后续升级仍自动落在原节点；不得硬编码当前文件内容或旧版号。不把本项目任务发布SKILL擅自注册为作品创作阶段。无绑定旧方法不挤入当前流程，但原准确链接、原评论仍能读到对应历史内容。
4. 首次无准确链接进入，选中流程首个有SKILL的节点，打开其 SKILL.md 最新版。点击另一节点进入该SKILL，右侧显示文件结构与正文；右侧内部用可见目录体现 SKILL.md、references、templates、附属图文及真实引用，不再让人先切“共用资料”。目录层级默认可读，不折叠正文或必要文件；长目录正常滚动。目录和正文位置、选中态、返回路径清楚，不增加大段使用说明。
5. 保持文件唯一维护源。视频手册/影视知识和Review的源投影从对应SKILL文件结构或正文引用直接可读，不复制第二份正文；阅读源投影必须覆盖实际正文、适配、图示、模板，不能只展示一段入口。从目录普通选择文件默认最新；任何带准确版本的引用、执行快照和评论链接一律读取指定目标，包括当前SKILL明确固定的旧资料引用，不能偷换最新版。若文件已删除/改名或准确原件缺失，清楚展示该事实并允许回查现存历史，不猜测替代文件或静默换最新版。
6. 评论复用已有浮窗、圈选和历史回查能力：意见落到准确文件及其版本，能从原评论回到原摘录、实际回应稿与当前稿。切节点、文件、版本或关闭比较弹窗后，保留应有的阅读上下文和未发评论；不把它们迁移到另一文件/版本。没有审批、采纳或编辑入口。

## 每个文件独立维护版本与比较

当前整包方法版号不能改名冒充文件版号。建立真实文件级历史：文件稳定身份、该文件的准确版本和历史内容可以独立取得，目录/来源关系及方法执行所用的准确文件组合仍能追溯。

- 只修改A文件，B文件版本不增加；只改绑定、用途或其他包元数据，不推进文件正文版本。重复提交相同当前字节不造新文件版本；A→B→A真实内容回退仍产生新的变化。历史迁移保留每次真实变化的先后及旧整包修订到当时各文件内容的映射，不能靠全历史按哈希去重抹掉回退。
- 文件正文区右上角呈现该文件的版本列表，最新默认选中。其左侧用间距/分隔明确区分“版本比较”；一个版本时按钮可见但置灰，不能打开空比较。版本选择直接可见，不新增下拉选择或折叠正文。
- 点击“版本比较”打开弹窗，只比较当前文件；默认左侧上一版、右侧最新版，即使外层正在读旧版也采用此默认。弹窗中分别可选两个准确版本，并清楚标识版本。显示实际增删改及足够完整上下文，不只是并列两份全文或只比元数据；中文Markdown正文、代码/模板、链接变化均可读。同版比较明确无差异。SVG/图片等附属文件按可实际阅读的原件并列比较，不能声称未实现的图像语义差异。
- 关闭弹窗回到原节点、文件、外层版本与位置，不更改外层阅读选择或方法执行配置。比较层的键盘退出、滚动和窄屏布局正确，不压住无法关闭的评论浮窗。
- 旧方法/资源整包修订、评论原锚点、历史链接和已冻结执行继续准确可用。新执行取得完整准确文件组合；文件“默认最新”是阅读行为，不自动改写已冻结步骤或偷偷改变执行绑定。源同步、方法保存、导出/恢复等真正写入口都遵守文件历史契约，不只做页面过滤。

## 数据模型：编号说明与核心关系图一致

将“编号前缀”导航与标题改为“数据模型”。保留原编号查阅功能及准确旧链接，校正已过时的现状说明：制作集场镜不再独立滚动设计版本；素材需求有一个当前方案，候选是一次真实生成/制作的结果并保存当时快照，旧MV链只属于历史兼容，不作为当前模型主干。实际已分配编号和历史身份不重新编号。

在编号说明下方增加图形化数据实体关系图，让人理解业务模型，而非数据库表结构。以分区和线条直接讲清：

- 故事资料/方向支撑故事结构、小说与剧本；故事稿保留各自版本，剧本包含集、场。视听集、场和镜头以准确剧本内容为依据；视听场可组合故事场/局部，不能误画一一对应。
- 镜头属于实体范畴，与人物、场景、道具、歌曲等兼容，不再另画一个影子实体。实体可以有确有独立制作需要的状态；有效状态至少拥有一项以它为唯一出处的真实素材需求，仅关联或被引用不算拥有。按0009负责落实的现行规则表达，图文任务不代做其全剧状态清理。
- 每项素材需求的制作出处唯一，来自某个实体、状态或镜头；多个地方引用同一素材不意味着多个拥有者。图的连线和简短关系词须让这一约束读得出来。
- 一份素材需求维护一个当前方案，可产生多个候选；候选保存当时Prompt、参数、实际输入及原件，当前方案后改不重写候选。首帧、视频等是素材需求的用途，不另造实体种类。
- 统一关系连接相关/依赖对象；素材引用和实际选用不同，关系不等于审批或生成调用。评论指向准确内容/文件版本/候选；SKILL由文件组成、文件各有版本，执行取得准确组合。图中不出现已退役的送审包、审阅决定或当前MV方案版本链。

图使用类型和少量关系词，不把本剧数百个具体对象画进去，不增加额外管理交互或说明折叠区。复杂线条可通过分区、位置和少量并行关系整理，不通过删掉关键归属和快照关系追求表面简洁。

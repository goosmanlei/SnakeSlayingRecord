## 要解决的问题与改后阅读方式

当前“制作思路 → 愿景与协作”将正文分成四个长章节，旁边重复显示章节目录，页面及正文还重复标题。读者要通读较长说明才能概括系统为什么存在、怎样协作和希望交付什么。

改后，默认首子页名称和主标题为“愿景”。读者进入即看到一句目标总述，下方左侧是细线方框与连接箭头构成的流程图，右侧是与各大块逐行对应的短说明。图示直接说明实践、协作、沉淀与复用的关系；全部核心信息直接展开，不依赖点击、悬停或折叠才能理解。

采用四个主块组织现有含义，标题可在不改变意思的前提下精炼：

1. **真实作品实践**：以《李寄斩蛇》的故事到影视制作检验协作方式，不把一个故事的设定当作通用要求。
2. **人、AI 与系统协作**：人把握方向与表达、提出判断；AI 按方法创作、自检和修订；审阅台连接作品、素材与反馈，可靠保存和交接，使人专注作品。
3. **方法与系统持续改进**：从真实使用中发现问题，沉淀可复用的工作方法和知识，用作品效果、执行可靠性与人的判断负担检验改动。
4. **支持新的故事**：目标交付可使用、可调整的系统雏形与协作方法，让新使用者带入自己的故事独立开展创作。这是方向，不冒充当前全部能力已实现。

图左、文右按同一四块对齐，连接表达“实践 → 协作 → 沉淀 → 复用”，用一条清楚的回连表达继续实践和改进。它是愿景中的成长关系，不是要求每个创作者照搬的强制制作步骤。线框简洁、文字可读，不做装饰性大图或复杂交互。实现可选择合适的 HTML/CSS 或 SVG，不需付费图像生成。

正文采用一句总述加四个短块，每块通常一至两句。删去重复论证、展开例子和技术过程；不只是把原长文换成卡片、搬进提示框或藏起来。保留理解愿景必需的因果、分工、双重交付和目标边界，不增加术语、日志、内部状态或重复标题。窄屏可按同样顺序改成上下或逐块排列，仍能直接看出图文对应关系，不横向溢出。

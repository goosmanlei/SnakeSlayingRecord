# 优化任务：让评论润色参考聚焦准确对象与当前意见

本任务优化评论润色的参考选择、版本依据、阶段表达和总预算，使审阅者能够围绕当前准确对象核对并表达意见。本文是独立可执行的任务规划，保留完整问题、实施过程和六项验收；执行不依赖持续系统 Review 的临时容器。

文中的“本轮”观察及数量来自上游 Review 的准确快照，属于已记录的输入和页面证据，不代表本澄清会话重新实测，也不替代执行时的当前状态核对。本次会话仅澄清并发布任务；实现、隔离验证、受管集成、正式发布及资源收尾由后续执行阶段完成。任务状态只以主项目 `.codex-task/tasks.json` 为准。

## 用户目标与问题

审阅者使用润色，是为了把对当前准确内容的意见表达清楚。系统应提供理解这条意见所需的参考，保留原意，让用户能快速核对参考是否正确。当前系统将可读取的资料几乎全部加入，增加理解、核对和推断成本，并引入互斥与过时背景。

1. 本轮隔离 Chrome 实际在《李寄斩蛇·白话直译与词语说明》圈选文字、撰写意见、打开“查看润色参考”。核对当前译注语气时，参考包含所有45份资料：当前译注1份、民间故事32份、互斥扩写方向3份、小说版本9份。后端仅将目标资料排第一，其他按ID顺序截取开头，没有按当前意见所需内容选择，也没有明确当前依据、比较材料和被取代历史的角色。
2. 资料和结构评论使用全局项目阶段作为当前“创作阶段”；本例显示“素材准备”。全局项目进度与正在核对译注的任务不同。剧本评论已分别保存任务阶段和项目阶段，说明已有可复用的区分方式。
3. 项目配置v15仍写“四首歌曲……尚未进入当前审阅台”，但正式库已有四首完整歌曲的原件记录。这条现状信息过时，并随每次参考再次注入。另一句“首轮新增369图像、42录音，共411原件”是历史批次数，本轮未将其判为错误的当前总数，不能据此改写历史批次。
4. 系统设置标签是“AI 参考上下文字数上限”，帮助文字说明“限制润色参考的上下文字数”。配置12000时，实际只限制各资料正文之和；本例正文7805字符，完整context约25988字符，项目背景、来源、标题和其他信息不受此预算约束。资料开头片段按剩余预算分配，还使后排列的当前小说版本仅获得很短截取，篇幅分配不代表相关性或权威程度。

已存在的保护应保留：准确目标修订与圈选校验、上下文摘要变化时拒绝提交、建议必须人工采用到草稿并另行保存。真实界面已验证1000下限检查、模型与推理强度联动、配置并发写入拒绝且保留草稿，这些是正常行为，不属于本任务缺陷。生产制作评论目前没有开放润色入口，本任务不新增该能力。

本轮没有调用真实AI，也没有观察到错误模型输出。已证实的是输入范围、时效与口径问题；现有模型指令已禁止新增事实、改变原意和补全UNKNOWN，不能把输入混杂直接等同于模型必然出错。

## 目标和范围

以被评论的准确对象、所选范围和当前意见为核心，形成最小充分参考。优先提供准确原文、必要邻近内容及该版本实际依赖的依据；只有当前比较目的或理解意见确有需要时才加入历史或其他方向，并明确这些资料的用途与适用边界。不能用“当前项目已选方向”替换原典、未选方向或旧稿自己的事实，也不能让旧稿反向成为当前稿事实。

全局阶段仅在有帮助时作为项目背景，当前审阅任务按准确目标和当前动作表达。无需为了阶段增加新的流程入口或要求用户反复选择同一上下文。

整理故事配置中的稳定创作背景与易变化制作进度：稳定设定以当前权威内容和明确确认衔接，动态进度避免重复手工维护或无关注入。修正已确认失效的现状表述，同时保护历史稿、历史批次、原意见和已存在的用户决定，不清除不相关配置或改写作品正文。

明确参考预算的统计对象，使配置、界面说明和实际构建一致；必要准确内容应优先获得预算，无法容纳时明确说明，不能截坏圈选身份或用小上限掩盖仍塞入的大量元数据。预览应让用户容易判断采用了哪些必要依据及其作用，预览与实际提交使用同一准确参考快照。不要以更多标签、折叠层级或更长说明把原有大包原样暴露，也不能只缩短预览而继续向模型发送无关内容。

预期减少用户核对不相干资料的阅读成本，降低旧设定与互斥设计进入润色输入的机会。尚无真实模型对照，不承诺错误率、费用或耗时改善的量化结果。

## 实施过程与过程验收

先在当前版真实页面重走“打开译注→圈选→写意见→查看参考→回到意见”的完整工作，说明审阅者原本要判断什么、在哪一步开始阅读无关内容。再选一条确实需要比较历史稿的意见作为反例，区分“必要比较”与“全部资料都可读”。不能从45份资料数量直接推导统一保留数量。

以两条路径提出最小改动并做成可运行候选，实际圈选、改写意见、切换目标版本、查看参考再返回，核对是否既减少无关阅读又保留理解意见的依据。此过程不调用外部AI；用明确标记的本地模拟检查实际发送内容与预览一致，不能把模拟写成润色质量验证。根据实际出现的误解、遗漏和返回成本调整选择策略及表达，再重走受影响路径。

过程验收看执行者是否在改动前识别了具体判断任务、用候选实际完成工作、依据观察修订方案并在正式发布后从原入口复验。保留能说明关键取舍及尚未解决问题的简短证据，不逐字段填表，不用最后集中跑一份测试清单或补截图替代真实使用和迭代。

## 验收标准

1. **当前译注的意见聚焦。** 在隔离候选重走本轮圈选、写意见、查看参考路径，能看到准确译注、必要上下文及意见；不再无条件加入32则故事、3个互斥方向、9版小说，也不把当前漫剧设定当作原译注事实。用户能够从实际预览判断参考为何必要。
2. **跨版本有边界。** 覆盖未选扩写方向、历史小说、当前结构和具体剧本修订的评论；默认以所选准确版本为依据，不因项目阶段或最新指针切换事实。必要的比较例能带入被比较文本并明确角色，普通语气润色例不带无关历史。完整准确目标与圈选校验保持有效。
3. **配置事实有效。** 已确认失效的“四首歌曲未入台”不再作为当前事实进入参考；现行权威来源及维护职责清楚。411批次记录未经核验不改写，动态制作进度不再无关复制到各类评论参考。项目阶段与当前任务不会混成一个误导性标签。
4. **预算口径一致。** 对1000下限、12000现值及较长目标内容进行确定性检查，输出统计与界面口径一致；必要准确文本优先，超限/截断行为可解释，来源元数据和背景不能成为预算外无限扩张部分。继续保留字段下限、模型/推理联动和并发配置保护。
5. **安全与人工决定不退化。** 准确修订失效、上下文变化及旧响应到达时，不把建议关联到其他对象或覆盖新草稿；核对后仍需人工采用和保存。使用本地确定性夹具或已有隔离模拟验证调用数据与预览一致，明确标记模拟，不声称真实模型效果。全过程不调用外部AI，不使用凭据或产生调用费用。
6. **交付可复验。** 完成相关自动检查和隔离真实浏览器验收，按项目受管多仓流程集成、按序发布，正式页面只读回查参考构建与准确版本。报告区分输入契约、页面验证与未进行的模型输出评估，保留原文、评论、历史和采纳事实，完成任务过程资源清理。

# 将李寄斩蛇项目资源迁入阿里云 OSS，完成访问优化与 Git 退出资源保存

## 目标与完成边界

将本机与现有 VPS 的全部项目业务资源迁到阿里云对象存储 OSS，并完成图片预览、视频封面、音频波形、缓存及访问链路的改进。图片、音频、视频和其他受管资源按项目组织，未来生成、上传、编辑渲染、正式发布、部署与恢复均走新链路，Git 当前版本不再保存业务资源字节或媒体 LFS 指针。

当前资源依赖 Git/LFS 和本地文件，正式发布与恢复也以原件已经合入 Git 为前提；小卡还会请求完整原图，音频波形需要浏览器下载并解码整个文件。仅替换 URL 或上传后删除 Git 文件会破坏制作、准确引用和恢复。本任务同时改变存储契约、访问方式、制作发布门禁及恢复方式，保留业务身份与完整历史。

完成终点是云端迁移、双仓受管交付与必要推送、本机和现有 VPS 正式切换、真实 Chrome 验收、在线与离线空实例恢复、独立复核和准确清理全部落实。适配代码、可审候选或阶段归档均不算完成；执行者验收与用户接受分别记录。普通执行后等待用户明确接受，未来 `--auto` 另授。

## 存储、访问和预览设计

1. **准确资源身份。** 保持 `object_id`、`revision_id`、candidate、component、原逻辑 file、原件 SHA256、评论和成片冻结引用不变。统一资源目录与解析层记录 project、provider、bucket、region、key、必要 version_id、逻辑 SHA256／bytes／MIME、旧路径映射及所需物理表示。签名 URL 只在运行时生成，不写入不可变业务记录、Git 清单或历史评论。
2. **统一读写契约。** 同一层承接元数据、读取／范围读取、上传、下载、校验、浏览器地址、制作工具本地落地及导出恢复。旧 `/assets/`、`/api/production/files/` 和文档业务引用继续可解析；兼容路由经目录指向 OSS，不依赖 Git 媒体目录，不在各处自行拼地址。非哈希命名资源同样具有准确版本和内容摘要。
3. **浏览器访问。** 应用按现有权限与 publication 发布身份解析准确资源，默认返回短时签名地址，浏览器直读 OSS；旧链接可受控跳转，确需兼容时有界流式代理。必须证明实际数据来自 OSS，不能靠残留本地原件掩盖漏迁移。应用 Cookie、认证头、`X-Review-Publication` 不发送给 OSS；签名、响应头、跨域规则和浏览器下载方式按实际接口验证，不能用 public-read 解决读取失败。
4. **权限和交互保持。** Bucket 私有并限制公开访问；迁移管理权限与服务运行权限分开，运行凭据仅获本项目必要对象与操作权限。沿现有应用访问范围，不另造登录系统，不宣称签名让原有公开体验页变私有。CORS 即浏览器跨域访问规则，只覆盖实际本机、隔离验收和 VPS 来源以及必要方法／头。验证 GET／HEAD、Range／If-Range、206／416、响应元数据、下载文件名。签名过期仅有限刷新重试，保留播放时间、暂停状态、开卡位置、选择和未提交评论；权限失败不能换 latest 或串项目。
5. **完整性与版本保全。** 上传前后校验真实逻辑 SHA256 与长度，OSS ETag 不作为 SHA256，尤其不能用于代替分片上传后全量校验。不可变键、并发幂等、版本保留一起设计；实际验证版本控制与防覆盖参数是否可同时生效，不能把不兼容选项当保证。开启合适版本保全，运行身份无批量删除历史权限，不为正式原件或历史引用自动设置过期删除。必要原件／快照保留与临时上传／失败分片清理分别管理。能力边界见[Bucket 概述](https://help.aliyun.com/zh/oss/user-guide/oss-bucket-overview)和[PutObject 契约](https://help.aliyun.com/zh/oss/developer-reference/putobject)，执行时按实际调用复核。
6. **图片预览。** 给现有图片批量补预览尺寸，小卡／大卡按显示尺寸选源，完整原图用于原件检查和生成输入。优先 OSS 图片处理样式，可受管持久化派生结果；超出实际原图大小、格式或尺寸限制时本地确定性派生后上传，不跳过、不压缩覆盖原件。主会话查到基础图片处理原图上限为 20 MB，执行时沿[图片处理与限制](https://help.aliyun.com/zh/oss/user-guide/overview-17/)核当前能力，私有图处理沿[签名调用方式](https://help.aliyun.com/zh/oss/user-guide/img-implementation-modes/)验证。预览保留比例、方向和区域评论坐标对应，不能默认裁掉内容；派生 key 绑定原件 hash 和处理参数版本，不增加实体或候选。
7. **声音与视频预览。** 视频封面、必要时间线缩略资源和轻量音频波形均作为同素材派生；音视频按需读取播放，准确原件仍可下载。仅实测需要时生成预览代理媒体，不改变原件时序、声道和精确帧定义。0002 的大卡、跨轨范围评论和当前影片不能因缓存或预览串版；不接入付费转码平台、不重新制作正式成片。
8. **实际前端边界。** 当前区域评论是 img＋SVG 归一化坐标，不把不存在的 canvas 污染当现状；若新加像素读取，再验证跨域可读。音频 fetch 不能复用会注入应用 header 的 `reviewFetch`，优先使用预计算波形，必要原媒体读取走独立受控请求。

## 制作、发布与缓存

FFmpeg／ffprobe、生成输入打包和其他需要本地文件的工具，经统一解析层下载准确原件到 Git 外受控缓存：流式临时写入、全量 hash 校验、原子启用。缓存按内容 hash 定位，容量和并发有界，使用租约保护正在运行的输入；本机、VPS、任务工作区边界明确，不默认整批复制全部媒体。离线时可按明确规则使用已有准确缓存，缺失不能伪称可用。

新制作顺序为：本地候选 → 完整校验 → 幂等上传 → 远端确认 → 准确资源清单／候选登记 → 受管发布。上传存在不等于采纳；正式数据库不能引用未经验证的云对象。上传结果未知先查询，再恢复或重试；凭据及完整签名 URL 不进日志、Git、导出或镜像。

将“原件 Git 已合入”门禁替换为“准确代码／资源目录已合入＋OSS 对象准确版本与字节验证凭据”。保留主干同步、任务锁、准确引用约束、正式发布事务和幂等。网络读取及大文件校验在事务外预检并冻结对象身份，不能在 SQLite 写锁中下载全量媒体。后台 AI 编辑、渲染 worker、失败恢复和已有 CLI 均继续可用。

工程 JSON 的归档指针区分物理表示和逻辑原件。优先在 OSS 存可直接读取的准确逻辑原件，同时保留旧 archive 配方／内容图恢复兼容与双层校验映射。缺必要依赖、版本或 hash 不符时阻止迁移／恢复，不能把 JSON 指针当完整原件，不改旧业务 revision。

剥离 Git 资源后，新任务初始化、跨仓交付、生产发布器、导出器和 VPS 部署器都沿新资源目录工作，不再自动 `git add` 媒体或要求媒体 `git lfs pull`。必须用下一次新资源登记、上传、渲染和恢复证明未来链路，不能仅证明已有资源能读。

## 实施顺序与恢复保护

1. **冻结准确输入。** 等两个前置任务完成，核双仓最新本地目标与远端 upstream、两端正式状态及全部引用，冻结迁移清单和比较口径。核云身份、地域、建桶／上传／读取所需实际权限；记录预估存储、初始上传、全量验证／恢复及预览请求量与成本依据，不声称费用为零。
2. **实现并完成全量上传。** 在隔离工作区实现预览／缓存及统一 OSS 链路，用任务独立暂存／测试前缀验证；先上传受管原件，再逐项远端完整性回读。传输有界、可断点恢复，失败未知状态可查。全清单上传与校验必须覆盖所有逻辑原件和必要物理表示，不只抽样，不以 HEAD 存在或自写 metadata 代替字节校验。
3. **替换 Git 职责。** 取得完整云对象和最新元数据恢复依据，准备双仓候选、轻量资源目录与旧路径映射，验证不依赖旧本地媒体。按精确清单解除当前 Git 资源追踪，并用 `.gitignore`、`.gitattributes` 及 CI／发布检查阻止回流；不得删除唯一可恢复原件。保留历史 commit 和既有 LFS 历史，不 force-push、不 `git filter-repo`、不全局 `lfs prune`，不宣称历史仓库容量已经回收。
4. **在线空实例恢复。** 全新 clone、空 SQLite、空缓存，不从旧 `export/assets` 借文件、不 pull 媒体 LFS；仅凭 Git 代码、准确清单与授权 OSS 恢复作品、素材、历史、评论、工程、输出及 0002 新增关联和访问能力。版本化资源目录与恢复 schema 兼容旧完整本地包；缺对象、错版本、错 hash、无权限均须阻止不完整恢复成为正式状态。
5. **离线完整恢复。** 保留 Git 外完整包导出，含准确元数据、真实逻辑字节和所需依赖；另做禁用 OSS 网络的新空实例恢复。恢复包不能是过期 URL 集合，OSS 版本控制不代替独立恢复介质。恢复包与原件目录互校，选择并实际交付具体存放和保留策略。
6. **受管双端切换。** 两仓受管集成和必要推送后，协调窗口切换本机与 VPS。本次是保留业务数据的存储升级，须先核对并保全两端各自最新评论、采纳、工程与发布身份；必要时升级部署器支持此路径，不能机械沿旧 VPS 全量重置方式抹掉 0003 之后的体验修改，也不能用本机库覆盖 VPS 或反向回灌。仅修改本项目服务和资源配置。
7. **回退与清理。** 切换前保留必要可恢复本地原件及准确数据库备份；失败切回准确配置／映射和兼容代码，不用旧库回滚掉迁移期间新数据。真实验收成功后清理本任务明确归属的重复本地媒体、临时上传、失败分片、测试前缀、私有服务和无用缓存；正常按需缓存和离线介质保留，不以清空缓存为完成条件。其他任务仍引用的文件不可删除，阻断与保留用途、责任人、解除条件逐项说明。

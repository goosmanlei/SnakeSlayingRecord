# 优化任务：用可读名称和准确编号找到内容，连续完成跨页审阅

本任务统一可读名称与编号搜索、按查找目的组织素材结果，并贯通准确跨页导航和返回上下文。本文是完整、独立可执行的任务规格；问题事实来自 2026-10-09 系统 Review，执行时按最新主干和有效正式数据复核，不要求 Review 临时容器、端口或数据库继续存在。按下述实际工作过程逐步形成候选、观察反馈并迭代，完成正式原路径复验。

## 用户目标与问题

审阅者记得人物、动作、地点或页面上的编号时，应能找到对应内容；沿实体状态反查镜头时，应能继续判断该镜如何使用此状态，再回到原来的审阅位置。当前名称、搜索和跨页链接的契约不一致，迫使用户记住内部位置或关闭当前内容后重新寻找。

1. 正式 Chrome 素材搜索输入 `M2624` 返回0，输入“周家米铺”返回5个独立素材、9个展示项；输入 `ASH001` 返回0，输入“阿蘅翻过两页”返回3个需求。同正式版本隔离 API 复核一致。对象真实存在，搜索只匹配素材标题，未匹配自身编号或准确需求来源编号。这与打开 M2624 时的准确投影假缺失是不同断点：本任务解决“找到现存对象”，来源卡任务解决“打开准确对象”。
2. 场次筛选只显示 `S040` 等编号，缺少能帮助识别内容的名称。正式数据已有 S040“这一页我来”、地点“阿蘅家窗下”等信息；无需创造新业务实体或让用户另背一份编号表。应按当前导航所引用的准确剧本场或视听场取名，两类场次不能相互冒充。
3. `ASH001 · 01 · A01 · 01 阿蘅翻过两页` 是持久业务编号叠加存储标题中的集号、场内部码、场内镜序。四段不是四层新的用户概念，主机位、首帧、视频标题又重复该前缀。现有集场导航已经承担位置选择，标题应突出有用的身份与动作，不把位置、来源、状态和技术信息全部塞进一行。
4. 正式 Chrome 实测“实体管理→搜索渡口→EN070→ST167→关联镜头2镜→ASH097”，只出现“剧情依据”弹窗及一句“先拒接后收板，不拍成收钱诈骗”。准确版本能读，但没有完整镜头和制作方案入口，用户必须关闭、换页、重找。完整 ASH097 设计与其准确视听目录均存在；这是跨页定位选择了摘录阅读路径，不能报告为404或内容丢失。
5. 正式实体管理搜索“渡口”有结果，改搜页面显示的 `EN070` 返回0。实体搜索实际使用实体与状态 payload 的整体 JSON，没有加入另行展示的业务编号。辅助数据检查也显示 `EN002` 不在其搜索文本中，而中文人物名和某些内部ID可以匹配；EN002是辅助覆盖样例，不计为另一次页面实操。
6. 同正式版本隔离页面搜索“阿蘅 · 基础音色”，只找到1个独立M1134，却按30处真实用途展示30张相同卡片，默认每页10行需跨3页。API复核30组各1项。用途关系真实，但具体素材查找不应要求重复辨认30次；“不是重复生成”的解释不能代替对查找价值的判断。
7. 从正式结构第10稿实际URL仅将`structure_revision`改为未知值，页面无提示展示第10稿，地址仍保留未知值且评论入口正常可见；从剧本版本四E17实际URL仅将`scene`改为`s999`，同样无提示展示E17/S040。实际评论目标由展示状态决定，不能将此报告为后端跨修订串写；风险是用户误以为正在审阅链接指定的内容。两例为受控构造的失效目标，只证明处理方式，不推算真实历史坏链接数量。

已有正常行为应保留：中文标题搜索可用；素材数按独立身份计数、同一素材在不同真实关联分组重复展示，因此5与9不等于重复生成。准确引用拒绝替换成同名或最新版有价值。实体状态依据和历史素材的准确弹窗已有使用场景，不能为跳转便利取消它们。关系图单击选择直接关系，双击或Enter打开实体；主会话实际双击“船家”成功打开新实体大卡，关闭后保留渡口ST168选择，不能误报为关系链接失效。当前列表已有筛选、分页、路由记忆和迟到响应保护，应复用并验证，不能先假定全部失效。

## 目标和范围

建立一致、可解释的搜索和定位行为：页面显著展示的稳定编号、对象中文名及已有别名可以定位该对象；在素材管理中，可以用准确来源镜头编号或动作找到属于该镜头的需求。按现有关系组织必要检索字段，不依靠整份技术 JSON 的偶然命中，不要求用户输入内部对象ID，也不引入付费模型或语义搜索作为前置条件。保留筛选条件及其与搜索的交集语义；确实没有结果时，让用户能够理解并调整当前条件。

寻找具体素材时，结果优先让用户按独立身份一次识别并打开目标，各处真实用途可以按需查阅和定位；M1134的30处用途不能因此删除或合并成虚构关系。按集场浏览仍可保留适合位置任务的分组，不强制所有视图采用同一种组织方式，也不另建搜索管理页。

统一可读标题和场次选择。镜头标题可以用“ASH001 · 阿蘅翻过两页”这样的稳定编号与动作表达；集场位置沿既有导航提供。场次选择使用已有内容名称或地点中足够辨识的一项，并保留必要编号；具体选择应以实际页面宽度和重名样例验证。不要给每项添加第二套标题、冗长解释或重复标签。底层稳定标识、准确修订和历史引用保持不变，不为整理显示重编号或重写制作内容。

按目标对象类型与当前动作决定阅读方式，不因当前页面恰好没有缓存镜头就将它当作剧情摘录。实体状态的“关联镜头”应能到达该准确镜头的完整审阅与制作内容；仍需要快速查依据时复用已有准确预览。跨页后能返回原实体、状态、搜索条件和阅读位置，草稿与版本选择不丢失；不能默默改为该镜头最新修订。

区分未指定目标的普通导航和显式准确定位失败。普通导航可以默认当前稿或首场，用户主动切换版本也可以明确选择对应首场；显式指定的修订、集或场不存在时，应让用户理解原目标无法打开，再选择可用目标，不以无提示替换冒充定位成功。复用既有失效引用与导航交互，不增加第二套错误管理入口。

预期减少从记忆线索寻找内容、重复关闭打开和重新设置筛选的成本，使从实体状态反查实际镜头用途形成完整路径。本轮未测量用户操作耗时，不承诺节约比例。

## 实施过程与过程验收

先重走三种真实工作：记得编号/动作找素材；记得场景内容按集场浏览；从实体状态反查实际镜头用途再返回。记录用户为了辨认、翻页和重新定位不得不做的步骤，尤其比较M1134单素材查找与按集场查用途的不同目的。不能因为分组计数正确就认定组织有效，也不能把所有结果统一去重当作完整设计。

针对这些工作提出最小改动，先用可运行候选完成“输入线索→辨认结果→打开准确对象→看实际用途→返回原位置”的端到端操作，再观察哪些名称、分组和位置提示帮助判断，哪些增加记忆或重复扫描。依据实际反馈调整候选后，重走改变过的路径及另一种浏览目的，保留已有正常的版本、草稿和退出恢复行为。

过程验收要求展示改动前遇到的具体成本、候选中实际完成的工作及观察导致的必要迭代，正式发布后再从原路径只读复验。无需机械记录每个控件，不用一次性生成界面后补测试列表、截图或设计说明冒充逐步实践。

## 验收标准

1. **编号和内容都能找到。** 隔离候选实际页面验证 M2624/小写 m2624、ASH001、“周家米铺”、“阿蘅翻过两页”；前两类能定位相应素材及准确来源需求，中文标题匹配保持正确。实体搜索 EN070 与“渡口”均能定位该实体，再覆盖 EN002、既有别名、实体状态和另一镜头，不为样例硬编码，建立清楚的一致契约。
2. **筛选与结果组织服务当前目的。** 搜索和集、场、媒体类型、结果状态筛选一起使用；清除单项/全部、翻页、刷新与返回仍正确。搜索“阿蘅 · 基础音色”可一次识别M1134，不必跨3页重复辨认同一素材，并能按需追溯30处真实用途；按集场浏览保持位置组织的价值。只返回符合实际关系的对象，不将同名内容或上下游所有素材当成同一对象。独立素材与展示项计数含义保持一致，当前样本5/9、3/3、1/30仅作为本轮基线，执行时按有效正式数据重新核对，不靠删关系改变结果。
3. **名称帮助识别而非增加记忆。** S040等场次选择可据内容辨认；重复地点、重名场、历史剧本场与视听场均能正确区分。ASH001及同类镜头不再重复四段内部位置，关联需求沿同一可读命名方式。编号、引用和历史版本的数据身份不变，退役编号不能映射成新对象。
4. **反查与准确定位不冒充成功。** 重走 EN070→ST167→ASH097，能进入准确镜头的完整设计及既有素材制作内容，不止一行purpose。再选另一状态、跨集镜头和历史准确镜头，核对目标版本与关联关系；真实不存在的对象/修订明确拒绝，不回退为最新。重走显式未知结构修订、E17未知场次的路径，失效原因与实际当前目标可理解，不能无提示替换后继续让用户误认原链接；恢复到可用目标后地址、标题与后续意见目标一致。对照无参数普通入口、用户主动切换版本、有效历史链接以及已有评论的准确定位，保留合理默认和原有失效保护。快速依据预览仍能准确读取。
5. **连续路径保留上下文。** 从搜索结果、实体状态关联镜头、素材需求来源等本任务涉及入口进入并返回，搜索词、筛选、页码、展开状态、选中对象、版本与阅读位置保持可预测；未提交草稿不丢失或串到另一对象。验证后退、关闭嵌套预览、连续快速选择与迟到响应，不增加第二套导航系统。
6. **交付证据分层。** 完成必要的搜索字段/关系、准确路由及历史版本自动检查，隔离真实浏览器实操，再按项目流程集成、按序发布并正式只读回查。明确 API、源码推断与页面证据边界，保留原件、评论、采纳和准确引用；不调用外部AI，不产生生成费用，完成过程资源清理。

## 任务安排、去重与并行

- 摘要：用可读名称和编号查找内容，按目的组织素材结果并保留准确跨页审阅上下文。
- 优先级：P1。编号查找、具体素材辨认和实体状态反查镜头存在明确断点，显式失效链接又会造成目标误认，影响核心审阅工作；尚无运行事故或评论串写证据，不按 P0 处理。
- 复杂度：复杂；模型 `gpt-6.1-sol`，推理强度 `xhigh`。需要把双仓名称来源、检索字段、准确历史路由、跨页状态与多类浏览器路径统一验证；范围和证据清楚，使用复杂档默认较低强度。没有相对 `xhigh/max` 可验证的自动委派收益，不选 `ultra`，不以材料量或耗时推导收益。
- 同项目 task-id 强制依赖：无，`dependencies=[]`。各问题可基于执行时有效系统独立复现和修正，无须人为等待其他待办。

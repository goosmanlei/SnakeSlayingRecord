# Seedance 2.0／2.5 视频生成方案选择与 Prompt 编写手册任务

本文件是任务范围与验收依据，不是研究结论或已完成的手册。任务授权、依赖、执行与完成状态以主项目 `.codex-task/tasks.json` 为准。

## 要交付什么

深入研究用户指定的三份飞书文档，交付一份完全独立可读、可用于实际方案判断的 Seedance 2.0／2.5 视频生成手册。Prompt 指提交给生成模型的文字指令；手册需要同时指导模型与生成方式选择、输入素材组织、镜头设计、指令编写及结果检查。

手册成为本项目后续镜头生成方案与 Prompt 编写的基本原则，并在现有“制作思路”中新增“视频生成手册”独立子页完整呈现。沿用现有菜单，不另建工作区，不改现有主入口名称。

正式手册建议放在 `production/seedance-video-handbook.md`。沿用 `content/production-approach.json` 的实例内容与通用系统只读展示分工；正文只能有一个权威来源，页面内容如采用派生文件，须通过确定的生成或一致性校验避免两份手工稿分叉。具体存储适配以执行时核实的系统能力为准。

## 手册应支持的判断

1. 区分 Seedance 2.0、2.5，以及实际调用渠道暴露的型号与功能。解释文本、图像、视频、音频参考，首尾帧、延长、编辑等方式的适用条件；只列经来源或实际接口核实的能力，不把一种版本、渠道或历史示例外推给另一种。
2. 按镜头目标、动作复杂度、连续性、风格、时长、声音和输入可用性组织方案选择。说明为什么选择、需要哪些输入、何时拆镜或减少单次任务，以及失败后怎样调整。
3. 说明参考素材各自约束什么：角色身份、完整状态、场景与道具、风格、构图、动作或镜头、音色与声音。处理多参考对应关系、冲突、输入顺序、质量与准确版本；衔接项目已有的准确参考规则。
4. 给出能直接使用和修改的 Prompt 组织方法、模板与完整原创示例，明确主体、空间、动作先后、时间、镜头、风格、对白／说话人、音乐／音效及必要约束，解释每一项如何改变预期结果。
5. 覆盖来源中的高频视觉与声音问题，包括身份与风格漂移、多角色对应、文字／字幕、水印、纹理／闪烁／卡顿、延长跳变或画质衰减、任务过载、对白与发音、音色冲突、噪音及背景音乐控制。区分已知限制、建议与可验证的修正，不保证文字约束必然生效。
6. 给出提交前检查、结果验收、返修顺序和停止条件。明确模型能力、用户期望、方案估计、真实调用结果及实际认可分别判断。

涉及模型规格与参数时，执行期核对当时的权威文档及 `pippit-tool-cli` 等实际入口，只做只读核验。标明适用版本、渠道、核验时间和缺口；不虚构调用结果或实测成功率。

## 范围边界

- 本任务研究、编写、离线走查、实现阅读子页并交付其运行结果；不调用付费生成，不生成新镜头视频，不批量重写现有镜头方案或 Prompt，不迁移或删除业务数据。
- 在项目规则与知识入口中建立后续任务必须读取和应用手册的明确约定，只引用正文权威入口，不复制整本手册或新增另一套方法。
- 通用审阅台只扩展方法文档读取与展示，不包含故事特有研究、生成或决策逻辑，不建立研究素材库或反向依赖创作脚本。
- 本澄清会话只准备范围并在用户确认后发布任务；实施、集成、正式发布和推送由执行会话沿既有任务流程完成。

## 可验证的完成标准

1. 三份文档的完整相关正文与直接相关案例／原件都有研究覆盖记录。视觉和声音结论能回查实际资料，关键缺口或来源冲突已解决或在手册中说明其具体影响，不能以只读目录代替深度研究。
2. 独立手册完整覆盖上述六类判断。新读者不依赖来源链接或本次聊天，能够选择适合的生成方案、组织输入、写出 Prompt 并说明验收和返修条件。
3. 至少完成五类离线走查：单角色动作、多角色对白、镜头衔接或延长、风格保持、声音或歌曲。每类包括需求、选择理由、输入分工、完整 Prompt、检查点和失败后的修订；核对 2.0／2.5 的适用边界。离线走查不冒充真实生成验证。
4. 后续执行入口明确要求生成方案与 Prompt 编写先读取手册；手册与现有输入锁、准确参考、完整状态、制作与采纳规则一致。没有改写既有业务方案或真实采用记录。
5. “制作思路”新增独立子页，完整正文、模板和示例可读，未缩成摘要或外链。真实浏览器在桌面与窄屏验证子页切换、目录定位、直接链接、刷新、前进后退、长文本与表格／Prompt 格式，并回归已有两页及旧链接。页面完整内容与手册权威正文一致。
6. 提交前逐项审计全部新增／修改文件、截图、测试材料、派生内容和发布包：没有 B、C 的链接或原媒体，没有私有抓取响应、令牌或研究原件；真实页面不请求或加载这些来源资源。必要的来源追溯只在本机私有记录中保留。
7. 按双仓任务流程登记并验证准确系统提交引用，完成针对性检查、集成后的正式页面验收及运行保全；不以 Git 合并替代服务发布，不以接口通过替代浏览器验收。按项目结项规则清理无效过程资源，记录实际删除与回读，说明必要研究与恢复资料的保留用途和移除条件。

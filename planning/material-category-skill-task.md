# 按制作用途统一素材分类、SKILL 选择与全剧当前方案

## 要解决的问题与改后工作

素材管理目前按“声音、图像、工程、视频”筛选，而 SKILL 管理已分别提供图像、音色、演唱、视频、字层方案。素材的真实制作目的没有稳定地连接到所需方法：阿蘅音色 M2669 与完整演唱 M1195 同属 audio，需求自身没有 voice/song 信息，作者须另传条件选择方法；11 项准确字层又以工程出现，无法从现行分类理解它们的用途。图像方法混合角色、空间、道具与镜头要求，缺少适用分支。

完成后，AI 根据素材的实际制作目的确定唯一具体分类，系统自动取得相应 SKILL 和专项要求，再维护该素材的一份当前方案。人从“素材分类”找到所需内容，打开同一套当前方案与候选阅读，不需另选 SKILL、学习内部条件或逐项审批。既有素材须全量归类、逐项审查当前方案并修正实质不符之处，不以改标签和筛选文案代替重构。

本任务是用户讨论后明确授权的新任务，硬依赖 `task-20261012-0011`。等其完成并核对正式交付回执后，从当时最新主干及有效正式库起步，消费其已重编的视频方案。本任务发布会话只定义与发布；执行者在 `--auto` 下须完成本机正式交付。

## 一套按制作用途组织的分类

分类是当前素材需求的制作职责，与原件格式、素材出处分别表达。只维护一份权威具体分类及其确定的大类；不能同时维护互相冲突的 media_type、audio_type、用途标签和另一套分类真值。物理媒体／MIME 继续服务播放、文件与模型输入校验；例如 WAV 不会因业务归“人物音色”而改变文件属性。

| 大类 | 具体分类 | 方法与主要检查 |
| --- | --- | --- |
| 图像 | 角色图像 | 人物身份、轮廓、体态、服装、表演状态与参考清晰度；动物角色采用其物种、解剖、体态和真实状态要求，不套人物衣饰规则 |
| 图像 | 场景图像 | 空间结构、尺度、出入口、行动通路、地标与跨机位一致性 |
| 图像 | 道具图像 | 结构、尺度、材质、持用和操作方式、准确状态 |
| 图像 | 镜头画面 | 叙事目的、构图、调度、机位、动作起点及前后镜关系；机位参考和首帧沿原有制作职责区分，不再新增第二套素材身份 |
| 声音 | 人物音色 | 角色声音身份、发音及说话表现，兼容实际独立对白制作；音色参考与表演台词的职责分清 |
| 声音 | 场景音 | 环境、动物、动作及物件音效的声源、距离、空间、持续／变化、同步和对白关系；只有真实独立制作需求才建立素材 |
| 声音 | 演唱 | 准确歌词、旋律、节奏、演唱表现、声部、伴奏与音乐交接 |
| 视频 | 视频 | 沿 0011 正式交付的方法和手册组织连续事件、镜头及准确输入；含歌唱或文字的视频仍是视频 |
| 字层 | 字层 | 准确文字、出现时点、排版、遮挡／透视／跟踪、可读性和可编辑工程交接；可用于静图或视频 |

图像采用共同 SKILL 正文与四个适用专项文件／分支，共同工具、参考规则不复制四遍。声音的音色、场景音、演唱分别约束；沿用现有 voice-plan、song-plan 身份，补齐真正独立的场景音方法。视频、字层保留独立方法。内部枚举与文件组织由实现决定，以上含义与自动选择必须稳定。

分类依据是“独立交付什么”，不能机械从所属实体、scope、文件后缀、名称关键词或 Prompt 中出现的人物／歌曲推断：镜头含人物的首帧属于镜头画面；归镜头所有的独立角色表演参考仍可属于角色图像；角色状态下的清唱仍属于演唱。准确字层工程不硬塞图像，背景中有文字也不把整幅图自动改为字层。不增加新业务实体、多归属或素材副本。

## SKILL、抽取和真实作者入口贯通

1. 更新现有实体、状态与素材抽取 SKILL：在抽取必要需求时确定制作用途与唯一具体分类，写清名称、出处、复用与独立制作依据，并由系统校验合法组合。保留“状态必须有独立需求、素材唯一出处”的现行规则。
2. 在素材方案和生成准备的真实入口，从素材取得分类，自动解析适用 SKILL 和图像专项资源；缺失、非法或与目的冲突时准确报错，不能默默走通用兜底。调用者另传 audio_type 或方法条件不能把音色伪装成演唱；合法明确修订素材分类后，新的准备必须重取方法和输入。旧冻结执行、候选快照仍取原组合。
3. 方法必须说明输入、理解与拟稿、全文回读、自检修订、产出交接；图像各专项写各自不同的要求和正常／反例。场景音先判断已有原件复用、镜头原生音频还是确需独立制作，再写真实方案；能力或原件未就绪就保留具体缺口，不虚构工具支持或调用。通用声音知识沿 `production/filmcraft/11-sound.md`，视频方法沿 `production/seedance-video-handbook.md`，不复制另一份冲突正文。
4. 生成方案按真实制作路径表达。新生成保留适用模型、参数、Prompt 和准确有序参考；复用方案保留原件及确切区间，不强补无意义 Prompt；字层本地制作保留准确文本、排版、工程组成及交接参数，没有模型调用时不虚构 model、CALL 或音视频输入。统一当前方案可读性，不强制所有类别具有同一模型字段。
5. 当前 SKILL 管理基础流程中的“素材方案”按上述制作大类组织现有／新增能力，能直接读到图像各专项及三种声音方法；延续左流程、右文件、逐文件版本／比较／评论，不恢复编辑、审批、下拉分类或第二份方法库。方法读取与真实执行须指向同一有效正文，普通阅读最新不暗改旧执行。
6. 同步实际作者工具、条件契约、源投影、导入导出、恢复与有效说明，包括 `production/managed-methods.md`、`production/professional-methods.md`。现后者仍把声音写成合并 voice-song-plan，应随真实绑定修正。删除当前入口已被取代的选择逻辑；历史兼容仅作明确边界的输入转换，不维持第二套创作规则。

## 补全镜头属于实体的表达

用户指出的现场已确认：SKILL 管理“实体、状态与素材抽取”产出只写实体 EN（角色、场景、道具、歌曲），遗漏镜头；抽取方法正文已经部分包含镜头，数据模型页也有镜头实体 ASH，但总称不一致。

流程产出明确表示“实体（角色、场景、道具、歌曲 EN；镜头 ASH）· 必要状态 ST · 素材需求 M”，以实际页面可读为准简化排版。视听设计形成的镜头由抽取步骤沿同一身份承接并组织需求，不重复抽一个 EN 镜头。同步抽取方法、基础流程图、数据模型图和相关当前说明，让用户能理解镜头也是实体、拥有其需求，同时编排在视听场中。保留已有 ASH 编号、编排、唯一出处、关系和准确链接，不开展编号迁移或另造镜头业务对象。

## 导航与集场镜代号

五个主入口仍在左侧；当前子页统一放入固定顶栏，与“当前视图”同一行，移除原位置重复入口。窄屏允许页签横向滚动，并能看到当前项。覆盖：制作思路的“故事创作／生产制作”；故事创作的“故事采编／故事结构／剧本创作”；制作设定的“制作拆解／实体管理／素材管理”；全剧制作的“镜头制作／组合与历史”；系统管理的“故事项目／系统与 AI”。

页签统一字体、尺寸、间距、边线、选中态和焦点样式。直接链接、刷新、前进／后退恢复准确子页；切页保持阅读上下文及既有草稿，系统配置切页保留未提交字段，不增加自动保存。

界面生成的集、场、镜指代统一为 `E02 / S003 / SH004`，集号至少两位，场／镜号至少三位，超出位数不截断。场沿用全剧场编号，镜沿用现有镜编号，不按场重新编号；跨上下文显示完整组合，集场明确时可只显示局部代号。修改可见标签和系统描述，保留正文、评论原文、稳定身份和历史链接；总集数等数量不属于某一集的指代。

排查五个页面及弹窗的按钮、选择器和筛选，统一剧情依据按钮、关系版本选择、素材版本与候选等控件。复用已有视觉语言，不增加重复状态说明或技术入口。

## 制作拆解与镜头制作

两页保持顶部集导航、左侧场导航和整场逐镜阅读。每镜独立成行，行内正文与素材有明显留白、边线或背景区隔；同镜两侧对齐，相邻镜边界清楚。窄屏按每镜正文、素材顺序排列，不将全场正文与全场素材分成两段。

场标题、说明、剧情依据和素材归属筛选放入持续可见的场标题栏，避开全局顶栏与集导航。筛选复用实体管理平铺按钮，支持剧／集／场／镜多选、初始全选，不使用 checkbox 外观；空选显示无匹配素材，正文仍可读。

移除场顶部剧／集／场素材列表及预留空白。只有该镜明确关联的需求、计划参考、实际输入或采用进入其素材列表，不由上级归属、同场出现或适用范围推定每镜使用。同一素材可在多个实际使用镜头出现，每镜按素材身份去重；筛选按素材实际归属判断，计划与实际使用仍保留准确事实。

制作拆解展示相关媒体；镜头制作右侧继续只展示视频，图像、音频等参考在左侧准确输入区查看。提示词及引用对应所选方案或真实调用，不能用最新方案替代历史。

移除正文场／镜区域的点击、键盘选中功能和选中视觉状态；保留左侧场导航当前项、准确链接定位、评论圈选及准确目标。剧情依据使用统一按钮和来源弹窗，关闭后恢复原阅读位置。

## 实体与素材卡片

页内展开和弹窗复用同一大卡，桌面左右等宽，窄屏按实体区、素材区顺序排列。实体区的基础信息、关系信息、状态列表、选定状态信息四块有明显边界与层次；状态内部素材列表另有区隔。

关系图按节点、连线和文字完整边界布局并留必要边距，初始和容器变化后均不能裁切底部；版本控件统一。双击关联实体打开新一层大卡，键盘提供等价操作；各层保留实体、状态、素材、版本、候选、位置与草稿。关闭或后退仅关闭顶层并恢复下层焦点；关闭媒体停止播放，圈选关系文字不误触打开。

状态列表只保留短名称和识别所需信息，完整描述在选定状态区显示。全部列表中的实体／素材小卡采用共用紧凑单列，不在宽屏变两列；覆盖管理列表、状态素材、逐镜素材与弹窗列表。小卡保留名称及必要类型、制作状态或数量，删除重复长描述和内部字段。已有合适图像使用真实缩略图，缺图用类型图标；音频不伪造人物封面，未生成不伪造结果。长名称可截断但完整名称可访问。素材按独立需求计数，版本、候选、文件及多状态关联不重复累计。

素材区明确表达“素材→版本→候选”，切版本同步更新候选；单候选也能理解所属版本，未生成版本显示本版方案与真实缺项，不借旧结果。准确链接优先于默认选择，快速切换不被晚到响应覆盖。

不显示 `original · original` 等内部组成名称；确有多个可预览媒体组成才提供“原件／预览”等易懂选择。技术请求与回执保留后台追溯，不占创作审阅选择器。已生成素材移除“查看原方案”按钮及无效说明；所选版本的要求、Prompt、参考与参数直接准确展示一次，调用独有事实按候选读取。既有可评论内容继续绑定准确记录或文件，不因移除入口丢失历史或评论。

## 素材版本与历史物理去重

实体拥有完整状态，状态关联素材需求；多个状态可以明确引用同一素材；素材拥有版本，版本拥有多次实际生成及候选。无结果的调用保留事实而不虚构候选。相同原件或名称本身不足以证明需求相同。

每个版本集中维护一份完整定义，包括素材要求、检查要点、输出要求、制作方法、模型、Prompt、有序准确参考、参数与随机策略。调用、候选和复用关系引用它，不分别维护可漂移的正文。参考固定准确修订、候选、组成及必要裁切／时间范围。

首次实际提交生成即锁定，失败或结果未知也锁定；随后修改上述定义创建新版本。同方案再生成增加同版候选，评论、审阅和选择候选不建版。实际随机种子属调用，改变显式固定种子属方案变化。未生成草稿只有一份当前定义，旧修改保存为可还原历史，不成为第二份当前方案。

按明确复用证据合并跨状态重复需求，状态专属要求不同则保持独立。提供旧需求、版本、候选到新结构的对应；旧链接、评论、认可与采用准确还原，不能将一状态采用推定给其他状态。计数按独立需求计算，并解释合并造成的数量变化。

用户选择连历史副本一起去重，范围含当前系统管理的数据库历史、公开导出及受管请求／回执归档。媒体原件保持原字节，已提交 Git 历史及其他任务隔离副本不在重写范围。不能只隐藏显示，也不能新增引用却继续保存整份重复定义。

使用按内容校验值标识的定义存储与引用，历史保留差异和还原信息；内容不同的历史不强行合并。旧逻辑记录、修订身份、请求和回执原始字节必须无损还原。旧哈希以还原后的准确内容核验，不能给变更内容沿用旧哈希；文件读取与旧链接通过兼容层还原，不把引用容器冒充原文件。

同步修正全部需求／版本写入、生成登记、读取、评论成员资格、关联和采用校验，以及 HTTP／CLI、导出恢复和后台工具。新导出集中保存定义和引用并升级格式，兼容已知 Schema 1—5，执行时复核最新格式。缺失或冲突历史如实保留证据缺口，不能用最新方案补造。

先在正式库的一致性隔离副本预演，交付逐项对应、合并依据、缺口和回滚方案。正式迁移核对当前头及准确依赖，单事务增量操作；重复执行无新增、冲突整体回滚、无关并发业务修改保留，不覆盖活库。

## Ultra 执行安排

以下仅在未来执行阶段启用。主代理按阶段使用最多三个子代理，服从实际并发能力，不保持无独立工作的空转。

| 职责 | 范围与交付 | 边界 |
|---|---|---|
| 主代理 | 统一契约，共用卡片、逐镜布局、关系弹窗上下文、缺陷收敛、双仓整合和交付 | 负责共享状态、评论上下文、全局样式及正式资源 |
| 导航代理 | 接口明确后实现五页顶栏、代号、限定控件统一及路由验证 | 共享入口和样式先协调，不建立第二套状态规则 |
| 数据代理 | 版本定义、共享需求、历史去重、迁移恢复与隔离验证 | 先明确读写契约；不写正式库或独立部署 |
| 独立审查代理 | 直接对照原始要求和有效澄清，审查覆盖、数据与历史兼容，记录可定位发现并复验 | 不只阅读实施者总结，关键改动不能只有实施者自检 |

相对 max，预期增加独立需求与数据审查覆盖，并让导航与数据在契约明确后并行。依据是导航、后端存储和验收可分工，而卡片、评论和版本选择共享状态，需集中协调。前期契约、浏览器、最终迁移仍是串行环节；交接、合并与复核增加成本，持续争用时缩小分工或收回主代理。

浏览器安排独占窗口；正式库、导出、服务、部署、双仓集成和推送由主代理串行处理。交付记录实际委派、有效独立发现、修复复验、实际并行区间、协调等待、冲突和返工；耗时及用量只报告可取得值。没有 max 对照，不承诺固定提速或质量提升；没有发现缺陷也如实报告。

# 优化任务：从当前稿复核跨版本意见处理，并作出下一步决定

本任务改善从当前稿复核历史意见处理并作出人工决定的工作过程。本文是可独立执行的完整任务规格，涵盖实际观察、范围、方法、六项验收和双仓交付。历史观察用于启动核对，不代表执行时问题仍未修复；以最新主干、有效正式数据和准确引用为准，不依赖持续系统 Review 临时实例或仅存在于会话中的说明。

## 用户目标与实际观察

用户阅读当前稿时，需要知道旧意见中哪些已经有作者回应或修改依据、哪些仍缺回应，以及自己还需要复核什么。沿准确旧圈选和新稿修改作出关闭或继续讨论的决定后，应能回到原来的阅读位置。保留旧评论是必要基础，但“未关闭”本身不能回答内容有没有处理。

主会话在正式 Chrome 完成两条实际路径：

1. 结构第10稿显示“本稿尚无关联意见处理说明”，顶部“本稿评论0 · 历史待决11”点击后仅打开当前0意见的空面板。切至第9稿可看到5条真实回应；“石道太长”回应可以准确进入第8稿C134，并定位原石道图，浏览器后退能回第9稿。这是已有可用能力，不能说回应或准确定位丢失。问题是从当前稿仍需自行猜到应去哪个历史版本，才能核对所谓待决意见的处理情况。
2. 故事采编进入精修八C138并定位“下午多添”的原句，再切精修九第1章，实际读到已改为“先前多添”。旧意见没有处理说明或对应新稿入口，新稿来源只概述参考两条评论；用户必须记住问题、寻找对应段落并自行建立联系，才能决定是否关闭旧意见。

正式库的11条OPEN结构意见分别在稿1、2、5、8；11条全部有后续稿的明确回应，分别在稿2、3、6、9。这里11表示尚未关闭，不表示11项未修改，也不表示11项已经解决。当前第10稿没有直接回应记录，因为父稿9没有新增结构评论，现结构导入契约只允许回应直接父稿评论；旧回应仍准确保存在旧稿。

C134的具体修改有证据：稿9回应缩短石道并把闸板向外留位，spaces-3写明“闸外石道不足成人一步”和封闭短接段，稿10保留这段；精修九第5章也写出短道长度及两侧站位。用户仍应自行核对图文是否满足意见，不能以文字已修改代替最终接受。

精修八C138的时间指代已局部修正；C137的人手调度意见则被作者有限吸收为实际求援、李寄主动请试、成人核看和可停手。既有逐条处理记录明确这是文学判断分歧下的选择，不把“只能让孩子上”当事实，不能将C137标成已经解决。结构10与精修九同步处理该设计，正式旧意见保持OPEN符合既有规则。

## 目标与范围

复用现有评论、作者回应、准确版本和圈选能力，让用户从当前稿找到有关系的旧意见及其处理依据。清楚区分原意见仍待人工决定、作者已有回应或修改证据、尚无可用回应证据；这些事实可以同时成立，不强行压成一个状态，也不新增第二套评论账本。没有记录只能说明证据未登记，不能自动断言作者没有修改。

用户需要时能查看准确原意见、作者实际回应及回应所针对的版本，进入对应新稿内容核对，再回到原意见人工选择关闭或继续。旧回应的存在不能证明当前稿仍保留修改；当前稿继承的修改、后续再改或无法确定时，按真实证据表达，不把回应过等同已解决。正常阅读优先呈现有助于本次判断的信息，历史明细按需展开，不把所有日志、旧意见或对照标记塞入干净正文。

故事项目负责核对并交付既有处理依据，包括结构稿响应关系和精修八至九的已确认作者处理记录；通用审阅台负责准确读取、关联、导航及人工决定。必要时沿既有导入/发布接口补齐可持久核对的关联，不反向依赖后台创作工作目录。历史证据不足的条目保持不确定，不能批量编造回应、让模型猜测对应改动或把当前内容差异自动认定为作者采纳。

本任务不改故事正文、结构设计、旧评论或作者既有判断，不自动关闭、自动接受作品或授予制作许可，不新建项目管理页，不做全稿AI评审或外部模型调用。预期减少跨版本记忆和反复查找，使用户能把已完成的修改转成自己的明确审阅决定；没有测量耗时，不承诺节约比例。

## 实施过程与过程验收

先按“当前结构10→历史待决→C134原意见→稿9回应→当前稿相关图文→回原意见”和“精修九→C138旧意见→精修八原句→精修九改句→回原意见”实际完成复核。记录哪里已有可靠能力，哪里需要凭记忆或离开当前工作查找；同时读取C137的有限处理依据，避免把所有回应都设计成已解决。

提出最小可运行改动，先在隔离候选完成一条复核及人工决定闭环，再用于另一条跨版本关系。观察哪些信息能支撑判断、哪些只是重复当前版本按钮或增加扫描成本，依据实际使用调整。增加关联前必须核对准确对象和真实处理依据，不把先生成一套状态标签再填数据作为设计过程。

在隔离数据副本中实际关闭并重新打开一条准确意见，回到新旧稿核对状态、引用和阅读上下文；回执明确这些动作仅验证功能，不改原意见正文，也不代表用户认可作品。正式发布后只读重走真实意见路径。过程验收保留具体断点、候选实际完成的工作及观察导致的取舍，不机械逐字段记录，不以最后补测试清单或截图替代实践。

## 验收标准

1. **当前稿可以找到需要复核的历史意见。** 从结构10当前入口能理解11条仍未关闭，其中已有后续回应可查；不再由“历史待决”进入只能看到当前0条的死路。实际核对C134所属稿8、回应稿9及稿10保留的相关内容，避免把总数作为未修改数量或自动完成数量。执行时重新读取有效数据，本轮11仅是基线。
2. **对应修改可准确核对。** 重走精修八C138原圈选与精修九第1章“先前多添”，可从当前审阅工作找到作者处理及准确内容，再返回原意见。结构图像圈选和小说文字圈选分别保持准确；没有改动、仅部分采用、明确不采用及缺少证据时如实表达，不凭相似文字伪造对应。
3. **回应与人工判断分离。** C137显示或可查作者有限吸收的理由和对应处理，不擅自标记已解决；所有既有OPEN/CLOSED状态、评论版本、编辑历史与原圈选保持。作者发布新稿、登记回应或继承修改不会自动关闭旧意见、确认故事或认可下游制作。
4. **人工决定能完成并读回。** 在隔离环境复核后使用既有关闭/重新打开动作，当前稿与原意见入口、刷新和重开读到同一准确状态。保存失败保留当前输入，并发版本变化不得覆盖新决定；只更新明确选择的评论，不批量迁移或关闭其他意见。未保存意见不混入处理结论。
5. **连续阅读与版本边界保持。** 从回应进入原圈选、再看改动、返回，所选版本、章节/图像、阅读位置和未提交草稿可预测。历史准确稿仍可单独阅读，缺失目标可理解地拒绝，不回退最新版冒充成功。当前稿后来改掉旧修改时，不能仅因曾有回应就显示当前已经满足意见。
6. **交付依据可复验。** 完成必要的准确关系、状态/版本和并发检查，加上述隔离真实浏览器工作；按受管多仓流程集成、按序发布并正式只读回查。给出实际补齐的关联范围及原有记录未改证明，区分作者处理、功能测试和用户决定；无付费调用，完成过程资源清理。

最终可见会话答复要求：任务执行完成或未完成时，面向用户的最终答复开头必须先写准确任务编号 `task-20261009-0012` 和原本要解决的问题（从当前稿难以复核旧意见、作者回应与实际修改并作出人工决定），随后清楚说明实际发生的变化及用户收益、真实验收环境和边界、尚未解决的事项与下一步，让用户在多个 `c task mrun --auto --wait` 窗口中一眼辨认方向及成果。未完成时如实说明已完成与未完成部分；没有实际变化或收益尚未验证时明确说明，计划及预期收益不能写成已实现，不能只报告提交、测试数量和清理。

## 任务安排与并行判断

- 摘要：从当前稿复核跨版本意见、作者回应与实际修改，支持人工决定并返回阅读位置。
- 优先级：P1。当前稿无法直接支撑历史待决意见的复核，影响核心审阅与决定；已有准确历史定位和回应仍可用，没有据此升级为运行事故或评论损坏的证据。
- 复杂度：复杂；模型 `gpt-6.1-sol`，推理强度 `xhigh`。需要统一双仓持久证据、跨版本关联、图像和文字圈选、状态与并发保护，并通过两条真实工作路径迭代验证；范围明确，采用复杂档默认较低强度。任务内关系设计与连续工作验证耦合，尚无相对 `xhigh/max` 可验证的自动委派收益，不选 `ultra`，不因材料多或耗时长推导收益。
- 同项目 task-id 强制依赖：无，`dependencies=[]`。基于执行时有效系统与真实处理记录可独立推进，相关任务的共用能力按实际交付吸收，不人为制造前置。
- 可并行：是。与润色参考、通用检索导航、素材/方案判断目标分明；两仓使用各自受管 worktree，测试数据库、缓存、文件写入目录和端口隔离，浏览器控制窗口协调使用。评论面板、结构回应和共用导航组件的实际重叠在集成时吸收最新主干、解决冲突并联合复验准确版本、草稿和返回上下文。共享正式数据库、正式配置、服务、部署入口、正式镜像标签及发布写入必须互斥串行；无法隔离资源或实质语义冲突不能独立收敛时，停止对应并行部分并重新评估。开发并行不授权并发正式发布。

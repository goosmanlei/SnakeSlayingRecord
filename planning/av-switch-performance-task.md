# 视听制作切集切场性能优化：压缩首次读取与重复聚合

## 人要完成的工作

用户在视听制作中切集、切场，应该及时读到所选场镜的叙事目的、当前素材方案并继续操作，而不是等待整集或整场所有历史和关联资料组装完毕。本任务专门解决这条切换路径，不扩大为全站性能巡查，不改变已有阅读结构或作品内容。

根会话真实 Chrome 已复现：从第一集切到第十七集，目录请求2639ms后再发场请求4649ms，关键网络链约7308ms；同集从AS062切到AS065，场请求6533ms，其中约6525ms发生在响应头到达前。回到已读AS062仅19ms。同场切ASH323不重读目录或场，但仍有36ms评论请求。快速AE015→AE016→AE017时，最终目标正确，已放弃的两次目录请求仍运行约2872/2708ms。准确样本与边界见 `planning/av-switch-performance-inputs/browser-network.json`，源码调查见同目录 `source-investigation.md`。

这些是各一次正常浏览的网络样本，不是P75或严格冷缓存测试；正式缓存没有清空。主要样例是2—3个业务请求，尚未证明HTTP请求数量多是主要原因。性能目标是缩短真正能继续阅读的等待，不能只合并接口、提前显示空壳或用热缓存掩盖首访。

## 优化范围与已定取舍

1. **目录只承担导航所需工作。** 当前目录会遍历全剧各集场镜汇总素材评论目标。切集不应重复展开全剧完整素材／评论上下文才能取得该集导航；复用已有目录和准确汇总，按实际依赖批量或一次计算必要信息。评论计数必须正确，不能删除、写成0、永久过期或要求用户额外打开页面才得到正确计数。同集已知准确场的切换继续复用目录；同场已挂载镜头继续直接定位。
2. **减少场响应中的重复详情与无关工作。** 当前旧 `context` 完整详情与新 `entity_workspace` 都会组装每镜素材，当前工作区还展开所有需求和候选。清点当前渲染、评论定位和历史入口各自真正使用的字段，消除重复查询、聚合、序列化和解码；同一请求中的准确对象/修订结果可复用，必要集合批量读取。完整历史、未选素材方案和未打开原件不应全部成为目标镜头可读的前提。保留所有直属需求，包括主/反机位、工程；原数据与准确快照不删，不借此移除必要内容或恢复旧版本链。
3. **当前目标优先，保持连续阅读。** 切集默认目标和切场/镜头的准确深链按当前规则。所选镜头的基础内容、当前选中素材组/素材、生成方案及必要控件先准备到可读可操作；其余内容可按实际可见范围有界读取、合并和渐进挂载，但不得增加折叠、手动加载按钮、分页或新的管理实体。滚动继续读本场各镜无需额外动作，目标镜头可直接跳到，内容加载不把人滚回顶部、不连续跳动，不用删掉后续镜头来达标。避免从大响应变成每镜/每参考一串细碎HTTP请求。图片、音视频原件和波形按实际审阅需要加载，不阻塞正文，也不影响播放与评论定位。
4. **停止浪费过时读取，保持最后选择。** 快速切集切场时合并重复在途读取，取消已无用途且尚未开始的工作；可取消的旧请求及时取消，不再串出其后续详情/媒体工作。已经运行的后端读取要有界，不采用杀线程或放开无限并发。保留现有迟到响应保护：旧结果不覆盖最新集场、不串对象/地址/评论草稿，当前失败仍可准确提示和重试。界面只表达当前切换，不叠加多个相同加载提示，不限制用户继续导航。
5. **性能与准确性一起成立。** 复用现有有界缓存和线程模型，按剖析选择必要改动，不预设新缓存系统、数据库迁移或全站架构重做。当前API、投影与请求内缓存分别核对；评论、参考选择、后台发布后的首次读取也须快且新鲜。可收窄失效范围，但必须有完整依赖及跨进程失效验证，不能直接去掉现有版本/事务/缓存守卫。缓存关闭、未命中、损坏回退都能从权威数据正确读取；不把缓存当权威数据。避免为加速引入无界内存复制、解压、并发或预加载全剧。

上述产品结果已定；具体字段拆分、批量查询、缓存键、取消机制及组件组织由执行者结合隔离剖析决定。实现先沿实测最慢链路做最小有效改动，复测后再扩大到同一调用路径。不以调大并发或堆长期预热任务作为唯一结果。

## 性能验收：看真正可读，不只看接口

在执行时最新两仓主干和同一准确正式数据副本上，为基线与候选建立隔离实例；保持机器、数据、浏览器、窗口尺寸和测量方法一致，记录实际服务代码/配置/镜像身份。协调测试窗口避开其他任务的发布、批量测试与浏览器控制争用，不对正式服务做压力测试、清缓存或测试写入。

定义“目标可用时间”为真实点击到准确目标镜头基础内容、选中素材及完整生成方案（含参数、Prompt和准确参考列表）与必要Tab/评论入口可操作并稳定绘制的时间。只出现标题、占位或新选中样式不算。媒体原件加载、音频可播放时间另列，不用它们掩盖正文，也不假称已播放。不要将工具往返耗时或网络完成时间冒充绘制完成。

测量四条代表路径：AE001→AE017/AS062（跨集）、AS062→AS065（9镜较长场）、AE001/AS001→AS003（10镜较长场）、AS062→AS063（较短场），加同场ASH322→ASH323快速对照。对于每条主路径，分别测隔离业务缓存为空的首次读取至少5次、相关写入后失效至少5次、重复读取至少10次；静态资源与业务缓存条件分别标明。不在正式库制造写入，使用原有接口在隔离库创建/修改一条准确评论或参考选择后回读，并保留实际测量样本。

- 冷读取及写入失效后：每条主路径目标可用时间P75不超过2秒，且候选与基线同条件对照显示首访慢链确有降低。
- 重复读取：每条主路径P75不超过500毫秒；同场已有内容切镜P75不超过200毫秒，且不重新请求目录/整场。必要评论读取单列。
- P75按各路径各条件分别排序后取第ceil(0.75×样本数)个值，报告样本数、全部原值、中位数、P75和最大值；失败/超时保留，不从样本中静默剔除。不得把冷热样本混在一起稀释慢值，也不能把这份有限本机样本称为线上SLA。
- 分段记录目录/场等业务请求、评论、媒体/其他请求数量和字节，服务端队列/查询/聚合/序列化，浏览器解码/DOM挂载/绘制及长任务，说明真正减少的工作与仍在等待什么。分段统计只用于必要剖析，不新建常驻产品监控页面。
- 连续AE015→AE016→AE017及同集连续点多个场，最终准确目标可读，不等已放弃目标的整场队列排完；检查取消/合并结果、剩余工作及资源上限，最后选择的延时按其冷热条件达到上述目标。此前根样例未证明最后目标受阻，执行者用受控隔离慢响应/实际冷读取补验，不把潜在问题写成已证现象。

这些数值是本次优化的验收预算，不是根会话已实测的结果。若仍未达到，继续查明并优化；不能以一次热命中、测试通过或改称“环境限制”结项。发现确实不可达的外部条件，保留证据、实际值和未完成状态并说明，不自行放宽门槛。

## 正确性、恢复与真实工作验收

沿上述路径实际阅读切换后的叙事目的、当前生成方案，切机位/首帧/视频，打开一份准确参考、历史候选和评论后返回。核对所选集场镜、素材及候选、参数/Prompt/参考范围、原评论/草稿、阅读位置与地址，异步补齐不串对象。深链和刷新进入场内非首镜、后续镜头连读、窄屏滚动也必须成立；不能只验默认第一镜。

在隔离实例验证评论/参考变动和后台导入的缓存失效；目录/场/详情失败、失效引用、快速切换与迟到响应正确处理。解除故障后用既有重试/重开继续原工作。缓存停用或损坏退回权威读取，性能退化如实记录，内容不能错误。验证候选和基线作品、真实调用快照、原件及历史评论无改写。性能代码与必要索引/缓存升级如有恢复要求，沿现有完整导出恢复入口验证，不用测试快照覆盖活库。

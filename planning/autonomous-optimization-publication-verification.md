# 自主优化实验任务的发布前验证

本记录验证任务交接材料和专用时间工具，不能作为审阅台已经优化、真实截止操作已经验收或长期运行达到预期的证据。未来运行结果另写 `autonomous-optimization-run-report.md`。

## 发布配置

本机现有 `codex.project` 普通“极复杂”校验仍只接受 Astra 的 xhigh／max。本任务使用一次性发布进程例外：只接受已审核的完整字段及指定任务／草稿，临时允许 ultra 后调用原校验；其他字段、修改已有任务和普通 ultra 请求仍按原规则处理，成功或异常后均恢复。真实 launcher、媒体、会话及工作区校验、原子账本更新和澄清提交仍由原 `_publish` 执行。

一次性程序及本机检查材料留在主项目 `.runtime/autonomous-optimization-publication/`，不写入通用工具源码。三项发布检查通过：准确字段放行与普通校验恢复、其他校验失败时恢复、真实 `task_mrun.execute` 构造器在新启动及恢复时传入任务记录的 `gpt-6-astra / ultra`。启动测试替换了进程和存储副作用，没有执行真实 mrun。

## 时间工具

针对性测试命令：

```bash
python3 -m unittest discover -s tests -p test_autonomous_optimization_guard.py -v
```

32 项时间工具测试通过。用受控时钟、临时目录和模拟传输验证 6 小时前不能正常收敛、6 小时后正常结束、9 小时收尾提示、10 小时停止、首次 T0 恢复、手动结束、后代身份和无关线程排除、服务离线与部分停止重试、停止回执持久化。根回合在子代处理之前中断，避免子代超时拖延根的停止；服务接受中断请求还须回读确认活动回合已停止。

使用本机 Codex CLI 0.160.0 生成的公开接口描述核对字段。真实只读探针验证既有 mrun 会话的身份、分页历史、准确执行标记、首次执行回合时间、当前活动回合和 Goal 读取；验证了从分页历史恢复时间与澄清时间无关。没有对该会话发送提示、设置 Goal 或中断。

每次 RPC 有总时限，长会话采用分页读取，不周期性加载完整历史。实际进程启动与停止的操作方式及故障边界见 [运行工具说明](autonomous-optimization-runtime.md)。后续首次 mrun 必须实测监督心跳；机器离线、服务不可达或中断未完成时保留准确状态，不能声称硬截止已经执行成功。

## 文档与独立审查

任务指令、六类历史依据、报告模板与发布例外经过独立审查；计时逻辑和测试经过独立代码审查。审查提出并修正了有限重叠一概串行、子代理登记责任不清、根中断顺序，以及只在最后聊天回复提供报告入口的问题。

报告规范要求实际变化、预期收益、验证证据和未处理原因逐项对应，不把预计收益当实测。任务说明明确两仓隔离、真实页面验收、准确历史保留和最终集成确认。发布阶段没有创建持续 Goal、启动实验监督进程、执行系统优化、生成媒体或写正式业务库。

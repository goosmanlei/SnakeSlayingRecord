# 故事创作三个子页面的 UI／UX 统一

本任务统一故事采编、故事结构和剧本创作的导航选中态、搜索入口及评论数量展示，方便用户判断当前所在页面和哪些资料已有审阅意见。本文件记录已发布的任务范围；实施、验证及待确认候选见 [交付说明](story-creation-ui-unification-delivery.md)。

## 目标与范围

1. 三个子页面均选中左侧一级导航“故事创作”；子页面 Tab 仍准确标识当前所在页面。直接打开链接、刷新、切换 Tab 和浏览器前进／后退均保持一致。
2. 移除故事采编右上方的搜索框，使三个子页面均无该搜索入口；处理相关事件绑定和布局，资料列表不受残留搜索条件影响。
3. 移除故事采编正文区的“审阅意见”按钮，继续通过现有共用“查看评论”入口及正文评论高亮打开评论区；保留圈选添加评论、编辑、关闭／重开、定位、草稿和快捷键。
4. 故事采编左侧每条资料、扩写方向和精修版本显示自身评论数；“民间小故事”“扩写方向”“故事精修”等分类标题显示所属资料的评论总数，明确区分“资料项数”和“评论数”。章节目录继续用于导航，不增加章节级计数要求。
5. 故事结构中上部的每个“第 N 稿”版本按钮显示该稿评论数，切换版本后与相应评论内容一致。

评论数按用户已确认口径统计：全部现存评论，包含未关闭和已关闭评论；不计已删除评论或评论编辑／状态变化的历史事件。资料计数与该资料正在展示的内容修订对应，结构计数绑定该稿精确修订；不同资料、版本和稿次互不串计。每条评论只计一次，分类总数等于其所属资料计数之和。结构稿的文字、整篇、整图和区域评论均计入该稿总数。无评论时显示“评论 0”，通过可见说明或提示明确“包含已关闭评论”。本次口径与现有剧本分集评论总数一致，不改共用评论面板已有的“未关闭／历史待决”含义。

计数与标题形成一致、简洁的视觉层级，不能挤掉标题、破坏选中态或展开／收起操作；新增、关闭／重开、编辑评论及重新取得评论数据后，相关数量与当前数据同步。其中新增评论增加总数，编辑与关闭／重开不改变总数。

## 可验证的完成标准

1. 在浏览器逐页验证故事采编、故事结构和剧本创作：一级“故事创作”持续选中，当前子页 Tab 正确选中；覆盖直接链接、刷新、切换和浏览器前进／后退。
2. 三页均无右上方采编搜索框，采编正文区无“审阅意见”按钮；列表展示完整，页面初始化、切换和评论面板打开／关闭无相关空元素引用或事件错误。
3. 采编所有资料条目及分类显示规定口径的评论数；在隔离实例覆盖零评论、多评论、含已关闭评论、不同资料与内容修订。分类总数与所属条目之和一致，资料项数与评论数可区分。
4. 结构每个“第 N 稿”按钮显示对应精确修订的评论数；在隔离实例覆盖至少两稿和零评论，以及文字、整篇、整图、区域评论，不把历史稿评论计入其他稿。
5. 隔离实例新增评论后相关数量更新，编辑及关闭／重开后总数不变；重新取得数据和刷新后数量一致。删除重复按钮后，共用评论入口、正文高亮、圈选、编辑、定位、草稿和 ⌘+Enter／Esc 行为仍正常；剧本已有集场导航及评论数量展示保持有效。
6. 浏览器核对桌面和窄屏下的标题、计数、选中态及菜单展开／收起，避免遮挡、错位或无法操作；完成与并行成果合并后的相关回归。浏览器受阻时记录原始错误及未验证项，不以接口或静态检查替代页面验收。
7. 交付通用系统改动、必要使用／验证说明及故事实例系统版本引用；按既有受控流程串行应用到本机正式 3000 服务并只读回查三页。正式故事、剧本、结构、评论及配置保持有效，测试评论仅写隔离数据库。记录实际系统版本与验证范围，任务完成及集成／推送分别按当次授权处理。

## 实施与并行边界

通用界面修改归通用审阅台，定位路径以故事主项目根目录为基准为 `../story-review-desk-python`，不能从嵌套 worktree 直接套用。故事项目只承载任务说明、实例版本引用及必要交付证据。执行前读两个仓库的有效规则、核对最新系统代码和任务账本；故事仓库复用本任务 worktree，系统仓库另用本任务独立 worktree。隔离数据库、实例及端口，不以旧快照覆盖正式数据。

源码只读核对表明：一级导航当前只按 `story.sources` 判断选中；搜索框、正文“审阅意见”入口及相应事件在 `review_desk/static/index.html`、`app.js`；结构版本栏在 `structure.js`；现有剧本集数计数在 `screenplay.js`，已包含关闭评论。以上是澄清时的源码证据，尚未验证改动后的页面行为，执行时须复核最新版本。

- 同项目 task-id 依赖：无。当前故事结构、剧本集场阅读及评论快捷键相关前置能力已完成；本任务不需要尚未完成的 favicon 或制作体系设计成果。
- 优先级：P2。现有阅读审阅能力可用，本任务改善界面一致性和评论可见性。
- 复杂度：常规；执行模型 `gpt-6.1-sol`，推理强度 `high`。改动有限，但需处理删除入口后的共用事件、计数刷新和版本隔离，并完成三页浏览器回归及双仓交付。
- 并行：允许。与 `task-20260930-0002` 的配置／图标加载可能在 `app.js`、`index.html` 和实例版本引用有限重叠，但主要改动区域不同；与 `task-20260929-0003` 的制作体系设计无前置依赖。各自独立 worktree 开发，有限代码与文档冲突在集成阶段解决，对合并版本复验。
- 共享资源互斥：双仓集成、正式数据库／导出、3000 服务与部署入口由单个会话按序协调；开发可并行不代表可同时发布正式服务。执行开始及集成前重新核对其他任务状态和修改范围。
